# v26.55.2

### 1. 文档解析：新增 TextinParse 后端（与 MinerU 平行）

#### 背景

原有解析后端仅支持 MinerU（云端）和本地方案（PyMuPDF/PaddleOCR）。新增 TextinParse（合合信息）作为第二套云端解析后端，与 MinerU 共用同一套 Task / Admin / API / Workbench 体系，用户可按需切换或作为备份方案。

#### 改动内容

**新增 TextinBackend**（`services/backends/textin_backend.py`，+545 行）

- 基于 `xparse-client` SDK，支持 PDF / DOC / DOCX / PPT / PPTX / XLS / XLSX / 图片 / OFD / RTF / HTML / CSV / TXT 等格式
- 自实现轮询逻辑覆盖 SDK 全部终态（completed / partial_completed / failed / stopped / deleted），避免 SDK 内置 wait_job 对部分终态导致超时死等
- 13 种异常类型映射：认证失败、余额不足、密码保护、文件损坏、不支持的格式、文件过大、限流、请求超时、API 错误、配置错误等
- 异步方法 `aparse_document` / `aextract_text` 通过 `asyncio.to_thread` 将同步 SDK 卸载到线程池
- 凭证从 `SystemConfig` 读取（`TEXTIN_APP_ID` / `TEXTIN_SECRET_CODE`），不硬编码

**全链路接入**

| 组件 | 改动 |
|------|------|
| `ParserFactory` | 新增 `"textin"` 分支，按需实例化 TextinBackend |
| `parsing_api.py` | `parse_document` / `extract_text` 全程支持 `backend="textin"`；`TaskStatusResponse` 支持 textin 任务状态查询 |
| `document_parsing_admin.py` | Admin 上传增加 `backend` 表单字段，支持选择 auto / textin / mineru |
| `workbench.html` | 后端选择改为二选一（MinerU / TextinParse），默认 MinerU |
| `schemas.py` | `backend` 字段枚举增加 `textin` |
| `exceptions` | 新增 `TextinAPIError` 异常类 |

**新增依赖**

- `xparse-client>=0.3.0`（`pyproject.toml` / `uv.lock`）

#### 兼容说明

- 默认值不变：`backend="auto"` 仍走原有逻辑
- 显式指定 `backend="textin"` 时走异步路径（含 HTTP 上传 + 轮询）

### 2. 文档解析：修复 Ninja API multipart 上传时 backend 等参数无法解析

#### 问题

通过 frontend workbench（HTML form multipart）调用 `/parse` 时，`backend`、`extract_tables` 等参数由 Ninja `File(...)` + Schema `body` 接收，但 multipart form 字段与 JSON body 混用导致参数丢失，实际始终使用默认值。

#### 修复

在 `parsing_api.py` 中新增 3 个 helper：

- `_form_str(request, key, default)` — 字符串参数
- `_form_bool(request, key, default)` — 布尔参数（支持 "true"/"1"/"yes"/"on" → True）
- `_form_int(request, key, default)` — 整数参数

**解析优先级**：multipart form 字段（`request.POST`）优先 → JSON body 其次 → 默认值兜底。

两个端点均修复：

- `POST /parse`
- `POST /extract_text`

使 workbench 的反选框和 backend 选择器实际生效，与 admin `upload_view` 的解析逻辑保持一致。

#### 修复

- `case_types` 扩展为全类型：`civil` / `administrative` / `criminal` / `execution` / `bankruptcy` / `all`
- `case_stages` 改为 `all`
- 新增 2 条 folder 绑定关系：
  - 东莞第三法院账户确认书 → 民事一审起诉文件夹
  - 东莞第三法院账户确认书 → 申请执行文件夹
