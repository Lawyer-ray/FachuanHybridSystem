# v26.55.6

## 移除未启用的 java-services (Apache POI 微服务)

---

### 背景

POI 服务在 v26.51.6 引入,定位为 Java Spring Boot + Apache POI 微服务,通过 HTTP 与 Django 集成提供 DOCX 文档生成能力。评估发现该服务处于"代码已落地、运行未启用、业务不依赖"状态:

- docker-compose 未启动 poi-service 容器
- settings.py 未配置 `POI_SERVICE_URL`
- 前端无任何 `/api/poi/*` 调用方
- 合同格式化实际走 Python 版 `DocxFormatNormalizer`,POI 包装类 `ContractFormatService` 为孤儿代码(仅单元测试 mock 引用)
- `format_normalize_admin` 按钮文字根据 POI 健康检查切换"使用 POI"/"格式化(Python)",但点击后永远走 Python,存在 UI 误导
- POI 自身的合同自动编号是空壳实现(`setupChineseNumbering` 只打日志、`renumberHeadings` 算出的编号不写回段落文本)
- 合同自动编号已确定走 trae + claude code + skills 路线,与 POI 的 Java 正则方案方向相悖

---

### 后端

#### 移除：POI 客户端与 API 路由

- 删除 `apps/core/services/poi_client.py`（`POIServiceClient` HTTP 客户端 + 单例工厂）
- 删除 `apps/core/api/poi_api.py`（Ninja 路由 `/api/v1/poi/*`，包含起诉状/尽调报告生成端点）
- 移除 `apiSystem/apiSystem/api.py` 中 `poi_router` 注册

#### 移除：合同格式化 POI 包装层

- 删除 `apps/contract_review/services/contract_format_service.py`（`ContractFormatService` 孤儿代码,无业务调用方）
- 合同格式化统一由 `apps/contract_review/services/format_normalizer/DocxFormatNormalizer` 承担

#### 修复：format_normalize_admin 按钮 UI 误导

- `format_action` 移除 POI 健康检查,直接显示"格式化"按钮（不再误导用户"使用 POI"）
- `changelist_view` / `upload_view` 移除 `poi_status` / `poi_status_text` / `poi_status_color` context 字段
- 删除 `health_check_view` 及对应 URL 路由 `health-check/`（仅返回 POI 状态,已无意义）
- 模板 `format_normalize.html` 删除"服务状态"提示框及相关 CSS（`.service-status` / `.status-dot` / `.status-text`）

#### 移除：相关测试

- 删除 `tests/ci/unit/core/test_poi_client_coverage.py`（POI 客户端覆盖率测试）
- 删除 `tests/ci/unit/contract_review/test_contract_review_coverage.py`（仅测 `ContractFormatService`）
- `test_contract_review_extended.py` 删除 `TestContractFormatService` 类,保留 `TestDocxFormatNormalizer` 等
- `test_contract_review_targeted.py` 删除 `TestContractFormatService` 类
- `test_format_normalize_admin_coverage.py` 合并两个 `format_action` POI 分支测试为一个,删除两个 `health_check_view` 测试,移除 `upload_view` 测试中的 POI patch

#### 修复：mypy 配置遗漏根目录 tests 模块

- `mypy.ini` 新增 `[mypy-tests.*]` 规则,让根目录 `tests/ci/*`、`tests/unit/*` 等模块享受与 `apps.*.tests.*` 相同的宽松规则（`disallow_untyped_defs = False`）
- 原配置 `[mypy-*.tests.*]` 模式不匹配 `tests.ci.*` 路径,改动这些测试文件时 mypy-changed 会误报 pre-existing 的类型注解缺失
- `format_normalize_admin.py:358` 补充 `# type: ignore[misc]`（pre-existing,`FormatNormalize.annotations` 字段 mypy 不可见）
