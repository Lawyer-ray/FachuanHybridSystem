## fix(court-filing): 修复 async context 中同步 ORM 调用

### 问题

`POST /api/v1/court-filing/execute` 接口在执行立案时返回 500 错误：

```
SynchronousOnlyOperation: You cannot call this from an async context - use a thread or sync_to_async.
```

### 根因

调用链：`execute_court_filing` (async) → `_abuild_execution_request_text` (async) → `ExecutionRequestService().generate()` (sync) → `Case.objects.filter(...).first()` (sync ORM)

`_abuild_execution_request_text` 是 async 函数，但直接同步调用了 `ExecutionRequestService().generate()`，后者内部使用大量 Django ORM 查询，在 async context 中触发 `SynchronousOnlyOperation`。

### 修复

`backend/plugins/court_automation/filing/helpers.py` — `_abuild_execution_request_text` 中：

```python
# 旧版
generated = ExecutionRequestService().generate({"case_id": int(case.id)})

# 新版：用 sync_to_async 包裹同步调用，委托到线程池执行
generated = await sync_to_async(ExecutionRequestService().generate)({"case_id": int(case.id)})
```

与同文件中 `api_endpoint.py:172` 的 `sync_to_async(organization_service.get_credential_for_lawyer)` 用法一致。

### 影响范围

| 文件 | 改动 |
|------|------|
| `plugins/court_automation/filing/helpers.py` | 新增 `from asgiref.sync import sync_to_async`，`_abuild_execution_request_text` 中 1 行改动 |
