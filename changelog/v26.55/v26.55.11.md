### 3. feat(contracts): 新增合同当事人增删 REST 端点（Closes #366）

#### 背景

合同创建后无法通过 REST API 变更当事人，service 层的 `add_party` / `remove_party` 未暴露端点。需要在合同详情页支持「增 / 删 / 改」当事人。

#### 新功能

新增两个 REST 端点：
- `POST /api/v1/contracts/{id}/parties` — 添加当事人（含 `role`，已存在则更新 role，覆盖「改」场景）
- `DELETE /api/v1/contracts/{id}/parties/{client_id}` — 移除当事人

扩展 `ContractPartyService.add_party` 支持 `role` 参数。均复用 `access_policy` 权限校验，与 `update_contract_lawyers` 设计对称。

#### 涉及文件

| 文件 | 变更 |
|------|------|
| `backend/apps/contracts/api.py` | 新增 `POST /contracts/{id}/parties` / `DELETE /contracts/{id}/parties/{client_id}` |
| `backend/apps/contracts/services/contract_party_service.py` | `add_party` 支持 `role` 参数 |

### 4. fix(documents): 修复二审维持原判判决书主文被截断为空

#### 背景

解析 `(2026)粤06民终7433号` 二审维持原判判决书时报错：

```
[INFO] 在'驳回上诉，维持原判'处截断，提取主文长度: 1
[INFO] 提取主文长度: 0
[ERROR] 未找到判决/调解主文
[WARNING] 解析裁判文书业务异常: JUDGMENT_KEYWORD_NOT_FOUND
```

#### 根因

[`judgment_pdf_extractor.py`](backend/apps/documents/services/extractors/judgment_pdf_extractor.py) `END_KEYWORDS` 中 `"驳回上诉，维持原判"` 本身就是二审维持原判判决书的主文内容，被错误地当成截止关键词。

`_extract_main_text` 找到 `判决如下：` 后，在归一化文本剩余部分的位置 0 命中该关键词，截断后只剩前导空白（长度 1），清洗后长度为 0，最终触发 `JUDGMENT_KEYWORD_NOT_FOUND`，Ollama 兜底也不可用。

#### 修复

从 `END_KEYWORDS` 删除该误判项。已有 `"本判决为终审判决"` 作为二审终审截止关键词，足以覆盖该场景。

#### 验证

- 单元测试：新增 `test_extract_main_text_keeps_second_instance_affirmation`，原有 3 个测试不受影响
- 端到端：用真实 PDF `(2026)粤06民终7433号` 实跑，主文正确提取为「驳回上诉，维持原判。」（截断关键词变为「案件受理费」）

#### 涉及文件

| 文件 | 变更 |
|------|------|
| `backend/apps/documents/services/extractors/judgment_pdf_extractor.py` | 从 `END_KEYWORDS` 删除 `"驳回上诉，维持原判"` |
| `backend/tests/ci/unit/test_judgment_pdf_extractor_cleanup.py` | 新增二审维持原判场景测试 |
