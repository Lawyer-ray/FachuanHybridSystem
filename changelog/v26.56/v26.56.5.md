# v26.56.5

> 分支：`feat/local-aggregate`（Django 6.1 升级配套的 UI 兼容适配、CourtSMS 表单重构与文档/归档修复）

## 后端

### 修复

#### fix(admin): 适配 Django 6.1 语义化面包屑结构（div → ol）

**问题**：Django 6.1 管理后台仅识别语义化的 `<ol class="breadcrumbs">`，项目内 17 个模板仍使用旧的 `<div class="breadcrumbs">` 结构，升级后多个页面面包屑渲染异常。

**修复**：批量将自定义模板迁移到 Django 6.1 标准 `<ol>` 结构——每项包裹 `<li>`，当前页追加 `aria-current="page"`；并在 `base_site.html` 兼容样式中补充分隔符 `›`。涉及 `automation`（courtsms/assign_case/submit_sms/test_court_list/test_court_result）、`cases`（materials/batch_add）、`contract_review`、`core`、`enterprise_data`、`document_recognition`、`doc_convert`、`doc_converter`、`express_query`、`pdf_splitting`、`chat_records`、`reminders/calendar` 及子模块 `plugins/doc_convert` 工作台模板。

#### fix(admin): 适配 Django 6.1 管理表单横向布局（flex-container）

**问题**：Django 6.1 将管理表单字段套入 `.flex-container`（`flex-direction: column` 并增加约 10px 行间隙），导致每个字段的标题与输入框之间出现多余的换行与空隙（如 client/contracts 等 add/change 页面）。

**修复**：`base_site.html` 兼容样式中将单字段行与多字段行的 `.flex-container` 覆盖回 `row`，label 固定左列、输入框紧随同行，help/错误提示仍正常换行到控件下方，恢复 Django 6.0 时代的同排布局；checkbox 字段保持原有横向布局不受影响。全局生效。

#### fix(admin): Django 6.1 详情页隐藏自动页面标题（titles-and-tools）

**问题**：Django 6.1 起 admin 页面标题渲染到新的 `.titles-and-tools` 容器内，合同/案件详情页此前依赖旧的 `#content > h1:first-child` 规则隐藏 admin 自动标题，升级后规则失效导致一级标题重新出现，与页内自定义主标题重复。

**修复**：在 `contract_detail_layout.css`、`case_detail_layout.css` 补充隐藏 `#content > .titles-and-tools`，仅保留详情页头部自定义主标题，并同步更新两个详情页模板的 CSS 缓存版本号（`?v=20260902a`）。

#### fix(automation): CourtSMS add 页面适配 Django 6.1 扁平化字段集并重构手机号后6位虚拟字段

**问题**：升级 Django 6.1 后 `/admin/automation/courtsms/add/` 报 `FieldError: Unknown field(s) (sfdw_phone_tail6)` 500：6.1 的 `_changeform_view` 会把 `get_fieldsets()` 展开后的字段显式传给 `get_form`，包含未落在模型上的虚拟字段，导致 `ModelForm` 构造失败。

**修复**：

1. 在 `get_form` 中先剔除 `get_fieldsets` 展开出的虚拟字段，`ModelForm` 构造后再按渲染需要重新注入，兼容 Django 6.1 的字段展开机制。
2. 使用标准 Django 虚拟字段实现重建"手机号后6位"读取 UI，替换此前非标的 `readonly` + 视图拼接方案。
3. 适配 Django 6.1 扁平化字段集结构，保证 add 页字段集展示正确。

新增自动化回归测试；`FieldError` 及 add 页 500 均消除。

#### fix(automation): CourtSMS 新增页移除冗余 help_text 文案

精简 CourtSMS add 表单展示：移除 content 字段的"请粘贴完整的法院短信内容"与 `sfdw_phone_tail6` 字段的"用于睿法智达下载加密文书时的身份验证"两条 help_text（输入框内 placeholder 提示保留不受影响）。

#### fix(contract-numbering): 一级标题间段落自动推断为二级编号

**问题**：合同编号检测器此前只能对紧跟一级标题后的内容正确编号，一级标题之间的普通段落会误判层级，导致编号层级错误。

**修复**：一级标题之间的段落自动推断为二级编号，修正层级识别逻辑，与既有一、1.（1）① 层级约定一致。

#### fix(cases): CaseLog 新增 event_date 字段，修复文件夹扫描工作日志日期丢失

新增迁移 `0030_add_caselog_event_date.py` 及 `CaseLog.event_date` 字段，内部服务/仓储/适配层同步写入，修复归档文件夹扫描生成工作日志时日期信息丢失问题。

#### fix(zxfw): 法院文书签收确认，修复下载不生成查收记录

新增 `court_document/_zxfw_direct_api_mixin.py`，为法院文书下载补充签收确认链路，修复此前下载后不生成查收记录、签收信息缺失的问题；下游归档生成、监管卡提取路径同步调整。

### 新功能

#### feat(documents): 新增专项法律顾问聘用合同模板

在 `docx_templates/1-合同模板/` 下新增 `专项合同.docx` 模板，内置 `{{年份}}`、`{{委托人信息}}`、`{{对方当事人名称}}`、`{{律师姓名}}` 等占位符，供专项法律服务合同生成使用。

### 优化

#### refactor: 替换弃用的 `import fitz` 为 `import pymupdf as fitz`

PyMuPDF 新版废弃顶层 `fitz` 导入，全项目（文档处理、PDF 提取/导出、归档生成、OCR 等各服务与对应单测）统一替换为 `import pymupdf as fitz`，消除弃用告警并适配新版本 API。
