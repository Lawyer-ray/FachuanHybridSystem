# v26.56.21

> 分支：`feat/readme-paid-deployment`

## 后端

### 新功能

#### feat(document_parsing): 文档解析平台多凭证并发 + 多服务配置

- 新增 `DocumentParseProvider` 模型与「文档解析平台」管理页（`/admin/core/documentparseprovider/`），集中管理文档解析服务配置，不再使用「系统配置」下的文档解析项
- 支持**多凭证并发**：TextinParse 每行填一组 `app_id|secret_code`（管道符分隔），MinerU 每行填一个 API Key，多凭证自动轮询分配
- 凭证失败后进入 **30 秒冷却并自动切换到下一个**；支持设置**每凭证并发上限**（默认 3，`0` 表示不限制）
- 新增全局 `CredentialPool` 凭证池（线程安全，跨任务共享、按平台隔离），复用 AI 平台的多 Key 并发 + 失败冷却机制
- 后端接入凭证池：`TextinBackend` 动态按凭证构建 SDK 客户端，支持解析 `app_id|secret_code` 格式配对；`MinerU` 移除类级 Key 轮转、改由凭证池管理
- `ParserFactory` 支持 `backend="auto"` 按**优先级自动选择启用解析平台**；未配置任何平台时自动回退本地解析（`local`）
- 新增 `ParseProviderService` 进程内 TTL 缓存（300s）读取平台配置；Admin 保存/删除后立即失效
- 数据迁移：将旧「系统配置」`MINERU_API_KEY`、`TEXTIN_APP_ID/SECRET_CODE`、`DOCUMENT_PARSING_BACKEND` 迁移到「文档解析平台」记录并删除旧键；「系统配置」初始化按钮跳过解析配置

#### feat(core): AI 平台配置彻底脱离 systemconfig，所有 AI 调用仅走 `LLMProvider`

- 「LLMProvider」管理页新增「初始化 AI 服务」按钮：自动把 systemconfig 中的旧 `OPENAI_COMPATIBLE_*`、`MODEL_LIST` 迁移到新模型并删除旧配置键，保持向后兼容
- 移除 `LLMConfig` 中 `get_openai_compatible_*` 对 systemconfig 的兜底 fallback，严格从 LLMProvider 读取全部配置
- 修复 `OPENAI_COMPATIBLE_DEFAULT_MODEL` / `VECTOR_MODEL` fallback 逻辑：向量模型留空即不启用（原文案：「留空沿用默认模型」→ 改为「留空不启用向量模型」，并调整后端对应逻辑）
- 移除所有 litigations 对 `systemconfig` AI 配置的直接读取，统一通过 `LLMProviderService` + `LLMProvider` 路由
- 样式优化：AI 平台管理页去除 inline 编辑（对齐对齐问题），删除冗余说明文案，提示移到输入框 placeholder；「初始化 AI 服务」按钮改为原生 Django admin 样式
- 修复「初始化 AI 服务」点击无反应的问题，确保幂等性（重复点击只会跳过已存在记录，不重复创建）

### 移除

- 移除「系统配置」下的 `MINERU_API_KEY`、`TEXTIN_APP_ID`、`TEXTIN_SECRET_CODE`、`DOCUMENT_PARSING_BACKEND` 等项目及文档解析配置定义（`_system_config_data/_document_parsing_configs.py`）
- 移除 litigation_ai 中 systemconfig AI 配置 fallback 逻辑，所有 AI 请求严格走 `LLMProvider`

- 后台「解析平台」更名为「**文档解析平台**」；`document_parsing` 下的 `CONFIGURATION.md` / `README.md` 同步改为「文档解析平台」管理页用法，彻底移除对 SystemConfig 解析配置的引导
- `INSTALL.md` 新增付费部署流程说明文档，补充完整部署操作
