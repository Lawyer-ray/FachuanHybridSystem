# v26.56.14

> 分支：`fix/llm-layer-hardening`（LLM 层加固：调用审计落地 + 客户端缓存复用 + 配置缓存 TTL + 响应日志脱敏）

## 后端

### 新功能

#### feat(core): LLM 调用审计落地（LLMCallRecord）

- 新增 `LLMCallRecord` 模型及 Admin 只读审计视图（禁用新增/修改/删除），每次 LLM 调用记录后端、模型、调用方、成功/失败、token 用量与耗时，供用量与成本分析
- 支持同步与异步调用审计（`record_llm_call` / `arecord_llm_call`，异步走 `acreate` 避免 `SynchronousOnlyOperation`），best-effort 写入，任何异常仅记日志、绝不影响主调用流程
- 开关为 SystemConfig 键 `LLM_TRACKING_ENABLED`（默认开启）；支持捕获调用方模块路径与错误类型/摘要，并分别对 `success`、`model`、`created_at` 建索引

### 优化

#### perf(core): LLM 客户端缓存复用

- OpenAI 兼容后端 sync/async 客户端按配置缓存复用，避免每次调用重建连接池；异步客户端按事件循环隔离缓存
- 缓存键加入 `(api_key, base_url, timeout)` 配置指纹，Admin 轮换密钥或改 base_url 后自动重建并清理旧客户端，防止使用过期凭证；提供 `close_clients()` / `aclose_clients()` 显式清理

#### fix(core): LLMConfig 配置缓存增加 TTL 与失效方法

- 配置缓存增加 300 秒 TTL，过期自动重读库；新增 `invalidate_cache()`，Admin 修改 SystemConfig 中的 LLM 配置后调用即可立即生效

### 修复

#### fix(core): LLM 响应日志脱敏、HTTP 客户端切换 httpx2 及异步审计修复

- 响应内容日志由 info 降级为 debug 并截断预览（限 80 字），避免全量敏感法律文书内容写入日志
- 后端 HTTP 客户端由 httpx 切换为 httpx2，同步/异步异常映射与测试同步适配
- 修复异步非流式 LLM 调用（`achat` / `aembed_texts`）审计未走 `acreate` 导致在事件循环内触发 `SynchronousOnlyOperation` 被吞掉、审计记录静默丢失的问题
