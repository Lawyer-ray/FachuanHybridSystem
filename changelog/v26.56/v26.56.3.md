# v26.56.3

## 后端

### 新功能

#### feat(labor_arbitration): 新增劳动仲裁文书爬虫（佛山市人社局仲裁裁决书公开）

> 分支：`feat/labor-arbitration-crawler`

**背景**

佛山市人社局在各区公开「终局仲裁裁决书 / 非终局仲裁裁决书」列表（市直、禅城、南海、顺德、高明、三水 6 个来源）。列表页为服务端渲染的静态 HTML，详情页正文是扫描图片。此前系统没有针对该类政府公开文书的采集能力，律师需要手动逐页查看与摘录。

**变更**

新增独立 app `apps.labor_arbitration`，复用项目既有基础设施（Playwright 公共服务 `create_browser`、文档解析 `get_document_parser`、Django-Q `submit_task`、Media 路径工厂），而非另起炉灶：

1. **数据模型**（`models/`）
   - `ArbitrationDocumentSource`：爬取来源（区县 / 列表页 URL / 启用 / 解析后端 / 最大翻页数 / 详情图容器与图片选择器 / 上次爬取状态与摘要），含 `District`、`ParseBackend`、`CrawlStatus` 枚举与 `trigger_update()` 方法。
   - `ArbitrationDocument`：单篇文书（标题 / 案号 / 详情 URL / 发布日期 / 内容指纹 / 爬取与解析状态 / 解析文本与 Markdown），`detail_url` unique，含 `trigger_parse()` 方法。
   - `ArbitrationDocumentImage`：文书扫描图片页，`image` 为 `FileField(upload_to=DatedUUIDPath(MediaEntity.LABOR_ARBITRATION_DOCS))`，注册 `post_delete` 信号清理物理文件。

2. **爬虫**（`services/crawler.py`，`FoshanLaborAwardCrawler`）
   - 通过 `create_browser()` 打开浏览器，翻页抓取列表（`a[href*='content/post_']`）。
   - **增量爬取**：已存在的 `detail_url` 直接跳过，只入库新条目。
   - 详情页为扫描图片，自动探测正文容器（`#content`/`.article`/`.TRS_Editor` 等），**同域过滤 + 模板关键字过滤**丢弃站外徽标 / 二维码（conac、jiucuo、wxgzh 等），仅下载真实文书图。
   - 图片经 `default_storage.save()` 落盘到 media（符合 Media 规范），按魔数/URL 推断扩展名。

3. **文档解析**（`services/parsing_service.py`）
   - 直接调用项目的文档解析服务程序入口 `get_document_parser(backend=...).parse_document(...)`（即 `http://127.0.0.1:8002/admin/document_parsing/documentparsingtool/` 背后的能力），逐页 OCR 后拼接文本与 Markdown 写回模型。支持 local / mineru / textin / auto 后端。

4. **Admin 按钮（用户明确要求）**
   - 来源 Admin：详情页「**增量更新**」按钮 + 列表批量「增量更新选中的来源」，提交 Django-Q 爬取任务。
   - 文书 Admin：详情页「**调用文档解析**」按钮 + 列表批量解析，提交 Django-Q 解析任务；详情页按 `MEDIA_URL` 渲染图片预览；禁止手动 `add`。

5. **管理命令**
   - `seed_labor_arbitration_sources`：幂等写入 6 个佛山来源。
   - `crawl_labor_arbitration`：CLI 全量/单来源/限条数爬取（便于测试）。

**验证**

- `ruff check apps/labor_arbitration`：**All checks passed!**
- `manage.py check`：**System check identified no issues**
- 迁移 `0001_initial` 已 `makemigrations` 生成并 `migrate` 应用；6 个来源已 seed 入库。
- 用真实站点（plain Playwright，绕过沙箱浏览器启动限制）实测：列表页每页 55 条、分页 `index_2.html`/「下一页」；详情页强化过滤后仅保留真实文书图 `https://hrss.foshan.gov.cn/img/0/776/776769/6031614.png`（793×4529 PNG，下载成功）。

### 修复

#### fix(labor_arbitration): 详情图下载健壮性（慢链路/大图）

> 端到端实测（真实站点）发现并修复：

**问题**
1. 详情扫描图体积可达数 MB（实测单图 `content-length: 3512643`），原 `page.request.fetch` 默认 30s 超时在慢链路下必失败，导致大量文书**有记录无图片**。
2. 详情页在浏览器内完整加载大图，导航慢（20–35s/页）。

**修复**（`services/crawler.py`）
1. `_download_image` 超时提至 90s 并允许重试（最多 2 次），兼容大图慢链路。
2. `_crawl_with_page` 通过 `page.route` 拦截图片资源加载（仅读 DOM 的 `src`，图片改由 `request.fetch` 单独下载），加速详情页导航、降低内存。
3. 列表页 / 详情页 `page.goto` 显式 `timeout=60000`，避免无限等待。

**验证**
- 佛山真实站点 limit=6 端到端：图片成功落盘、无模板图泄漏、增量二次运行 0 新增、调用 `document_parsing`（RapidOCR local）成功把扫描图 OCR 为 2062 字文本，`RESULT: ALL_PASS`。

#### fix(labor_arbitration): 排除列表页页脚导航页（联系我们/隐私保护/免责声明等）

> 用户实测（Admin 列表）发现「联系我们、隐私保护、免责声明」被当成文书抓入。

**问题**
- 列表页页脚含导航链接，同样带 `content/post_` 路径，例如：
  `https://hrss.foshan.gov.cn/wzdh/lxwm/content/post_677633.html`（联系我们）、
  `…/wzdh/mzsm/content/post_677997.html`（免责声明）、
  `…/wzdh/ysbh/content/post_677880.html`（隐私保护）、
  `…/wzdh/wzdt/content/post_615.html`（网站地图）、
  `…/wzdh/sybz/content/post_677798.html`（使用帮助）。
- 原 `_extract_list_items` 用 `a[href*='content/post_']` 全页扫描却**未调用 `_is_same_list_dir` 过滤**（该函数此前只用于翻页），导致这 5 条页脚导航被当作文书入库。

**修复**（`services/crawler.py`）
1. `_extract_list_items` 增加 `_is_same_list_dir` 同目录过滤 + `_is_nav_title` 导航标题黑名单（联系我们/隐私/免责/网站地图/使用帮助/关于我们/版权等）双重拦截。
2. `_is_same_list_dir` 收紧为「必须在本来源列表子目录内」（`base.path` 含尾斜杠），避免跨来源串味。

**新增**（`management/commands/purge_labor_arbitration_nav.py`）
- 清理命令：删除「`detail_url` 不在其来源列表目录内」的误抓导航页记录（含级联图片），支持 `--dry-run` / `--source`。

**验证**
- 佛山真实列表页实测：`_extract_list_items` 返回 **50 条真实文书**，`导航标题命中=[]`、`/wzdh/ 误伤=[]`（此前误报的 55 条含 5 条页脚导航，真实为 50 条/页）。

#### fix(labor_arbitration): 抓取详情页发布时间（列表页日期 + 详情页时分）

> 用户指出详情页有「发布时间：2024-06-11 16:06」但爬虫抓不到。

**问题**
- 发布日期实际在**列表页兄弟节点** `<li><span class="time">2024-06-11</span><a>…</a></li>` 和**详情页正文 meta 行**「发布单位：… 发布时间：YYYY-MM-DD HH:MM」两处，而原爬虫只在列表 `<a>` 的标题文字里找日期，两处都没读 → `publish_date` 全为空。

**修复**
1. `ArbitrationDocument` 新增 `publish_datetime`（DateTimeField，可空）存完整时间戳；排序改为 `-publish_datetime, -publish_date`；Admin 列表/筛选/详情同步展示。
2. `services/crawler.py`：
   - `_extract_list_items` 从 `<li>` 父节点读日期（`closest('li')` 的 `innerText`），列表阶段即拿到日期。
   - 新增 `_extract_publish_info`：从详情页正文 `document.body.innerText` 用 `发布(时间|日期)：YYYY-MM-DD [HH:MM]` 解析，优先作为 `publish_date`，并填 `publish_datetime`。
   - 增量跳过时回填：已存在记录若 `publish_date` 为空，用本次列表页日期补上（不重下图片）。

**新增迁移**：`migrations/0002_alter_arbitrationdocument_options_and_more.py`（新增 `publish_datetime` 字段 + 索引 + Meta 排序变更）。

**验证**（真实站点）
- 列表页首条日期 `2024-06-11`；详情页 `post_6031614.html` → `publish_date=2024-06-11`、`publish_datetime=2024-06-11 16:06:00`，`RESULT: PASS`。

#### fix(labor_arbitration): 网络中断自动恢复 + SynchronousOnlyOperation 崩溃修复

> 用户要求「迁移 + 清空 + 全量重爬」时，真实运行 Django-Q 任务暴露两个问题。

**问题**
1. 爬取任务在 Django-Q worker 里**全部失败**，报 `SynchronousOnlyOperation: You cannot call this from an async context`。根因：Django-Q worker 用 asyncio 跑任务，且 crawler 用 Playwright sync API（内部起事件循环），Django 同步 ORM 检测到 running loop 即拒绝执行。
2. 网络中断导致任务失败后，无「网络恢复自动续爬」机制（Django-Q 虽有 `retry=1200`/`max_attempts=3`，但超过约 1 小时就彻底放弃）。

**修复**
1. `tasks.py` 模块顶部 `os.environ.setdefault("DJANGO_ALLOW_ASYNC_UNSAFE", "true")`，与 `legal_solution/tasks.py` 既有约定一致，放行同步 ORM。
2. `services/crawler.py` 新增 `_goto_with_retry`（列表页导航 3 次指数退避 2s/4s），网络抖动不立即让整批失败。
3. 新增 `tasks.auto_resume_crawl` 自愈任务：扫描「上次失败 / 存在 pending|failed 文书」且「非 running」的来源并自动 `trigger_update()`。
4. `apps.py` 的 `ready()` 幂等注册 30 分钟间隔 Schedule 兜底长期中断（参考 message_hub 模式）。

**验证**
- `async 上下文内同步 ORM 调用` 设置 env 后成功（`SynchronousOnlyOperation` 消除）。
- `auto_resume_crawl` 正确识别 4 个 failed 来源并续爬、跳过 running 来源。

#### feat(labor_arbitration): 改用 HTTP 接口抓取（提速 + 不再下载图片）

> 用户发现列表页有 JSON 接口，且图片后续都要 OCR 成文字、无需保留原图。

**改造**
1. **列表用接口**：`services/crawler.py` 整体重写为纯 HTTP（requests）版——调 `postmeta/i/{category_id}.json` **一次拿到全部文章**（title/url/date/publish_time，最多 50 页 × 50 = 2500 篇），无需 cookie、无需翻页、无需浏览器。
2. **详情不下载图片**：requests 抓详情页 HTML，正则提取扫描件图片 URL（`img/.../post_N.png`），只存 `source_url`，不再落盘（`ArbitrationDocumentImage.image` 改为可空）。
3. **OCR 按需拉图**：`parsing_service.py` 解析时从 `source_url` 下载到临时文件再 OCR，用后清理。
4. **模型/配置**：`ArbitrationDocumentSource` 新增 `category_id`（6 区映射：市直 42087/禅城 41998/南海 41999/顺德 42000/高明 42001/三水 42002）；seed 命令幂等回填。
5. Admin 图片预览改用原图 URL 渲染。

**新增迁移**：`migrations/0003`（source.category_id + image 可空）。

**验证**：市直接口返回 88 篇、详情页提取图片 URL `…/6031614.png`，`RESULT: PASS`；已删除 224MB / 198 个本地图片文件。

**注意**：站点 `pages_limit=50`（接口与 HTML 一致），单区最多拿最新 2500 篇；南海(21140)/顺德(12667)/禅城(3666) 超过部分拿不到。
