# v26.56.22

> 分支：`fix/core-documentparseprovider-options-migration`

## 后端

### 新功能

#### feat(client): 当事人编辑页新增「利冲检查」

- 当事人编辑页新增「🚨 利冲检查」按钮，一键发起金诚同达 OA「利益冲突信息预检」
- 复用 `JtnAuthService` 的统一登录凭证（cookie 持久化）：登录态有效时直接复用，失效才走 SSO 企业微信扫码，与归档「打开 OA」、盖章、立案等功能共享同一份登录凭证，不再各自重复登录
- 新增 `ConflictCheckAdapter` 适配器协议与 `open_conflict_check_page` 入口，未来更换律所只需实现协议并注册到 `oa_firm_registry`，核心调度逻辑无需改动
- 打开预检页后自动填入当事人名称并点击搜索，**保持浏览器打开**交由律师自行审查结果；未配置 OA 凭证时给出友好错误提示

#### feat(core): 文档解析平台增加排序迁移文件

- 补充 `DocumentParseProvider` 的 `Meta.ordering = ['priority', 'name']` 对应迁移文件，消除 `migrate` 时的模型变更告警，`makemigrations --check` 确认无剩余模型变更

### 修复

#### fix(oa_filing): 利冲预检关键词输入框为 readonly 联想组件，改用 JS 写入

- 修复利冲检查无法填入当事人名称的问题：预检页 `#strkeyword` 输入框为只读（`readonly` + `_ims_acprev` 联想组件），Playwright `fill()` 无法写入只读元素
- 改用 JS 移除 `readonly` 后写入 `value` 并派发 `input`/`change` 事件，再点击搜索按钮；关键词以参数传值规避注入，找不到输入框时主动报错
