# v27.15.1 · 非诉页卡片间距重排（去「三层套娃」）

## 前端

### 优化

#### 非诉详情页（专项 / 跨境 / 常法）卡片间距与边框层次

用户实测反馈：「非诉页面 UI 有点诡异，每个卡片之间很紧凑，没有合适的边距」。
拉开一量，问题不在**卡与卡之间**（那一直是 18px 栅格），而在**卡内部又套了两三层边框**：

| 层次 | 原状 | 症状 |
|---|---|---|
| 左栏卡片 | `Card` 自带边框 + 阴影，逐张通栏堆叠 | 卡间 18px 正常，但卡一变高，观感就是「一整块密排」 |
| 卡内列表 | 列表再画一整圈 `border` + 每行 `divide-y` | 与卡片边框形成同心矩形，行与行之间只剩一条 1px 线 |
| 卡内条目 | 条目再画一圈 `border`（校验项 / 风险行 / 执行块） | 三层边框相邻，中间白缝只剩 6px，被读成「挤」 |
| 模板行 / 执行卡 | 行内 `py-1.5`、卡中卡 `px-[18px] py-[15px]` | 行高过矮，与外围 15px 内边距不成比例 |

改法（只动视觉，不动任何交互与状态机）：

- **卡与卡**：统一 18px。`CrossBorderViews` 由 `mt-4`(16) 改为 `mt-[18px]`，与
  `DealDocLayout` 的 `space-y-[18px]` 同口径，不再出现 16/18 两种节奏。
- **卡内列表**：外框保留一圈，**行改成 `border-b` + `last:border-b-0`**，行高 `py-2 → py-2.5`。
  原来 `dark:divide-y` 与 `rounded + border` 叠加时，首尾行会被外框和内部分隔线夹出双线。
- **卡内条目**：`Inset`（专项共用内嵌层）默认**不画边框**，只留 `bg-secondary/35` 底色，
  需要真边框的场合显式 `framed`（如客户确认记录里的信息块）；
  `NonLitActionCard` 里的 `InsetBlock` 同步改为无边框 + `bg-secondary/35`。
- **三层套娃的直接拆除**：
  - 推进前置校验：条目不再各画一圈边框，改用**左侧 3px 色条**（绿=通过 / 黄=未通过）分档，
    底色只在未通过项上淡染；
  - 风险登记表：整表一层外框，高风险行改用**左侧红色条**标记，不再给行套红边；
  - 卡片内嵌的「执行卡」（`NonLitActionCard`）：`border-0 + border-l-[3px] + shadow-none`，
    待执行态 `bg-secondary/30`——
    它本身就是卡里的一块，再画一圈边框+阴影就成了「卡中卡」；
  - 跨境工作台的最外层是**容器卡**（内含 7 张子卡），改为 `border-0 bg-transparent shadow-none`。
- **行高与留白**：模板行 `py-1.5 → py-2`（去掉边框改底色块）；甘特阶段行 `py-[3px] → py-[5px]`；
  卡内「动作卡列表」与后续区块统一 `mt-3 → mt-3.5`；块标题 `mb-1.5 → mb-2`。
- 校验项里的说明文字（`r.detail`）加 `min-w-0 truncate` + `title`，窄栏换行不再把
  「未通过」胶囊挤扁。

改动文件（均在 `frontend/src/features/workbench/components/deal-detail/`）：

```
nonlit-action-card.tsx                    执行卡：卡中卡 → 左侧色条 + 浅底
nonlit-workbench.tsx                      专项 / 跨境 / 常法：区块间距、容器卡去边框、模板行
nonlit/special/special-bits.tsx           Inset 默认无边框（+framed 逃生口）
nonlit/special/special-phase-board.tsx    校验项 / 阶段清单 / 交付物清单
nonlit/special/special-risk-card.tsx      风险登记表 / 客户确认记录
nonlit/special/special-gantt-card.tsx     甘特行高与图例间距
nonlit/crossborder/CrossBorderViews.tsx   mt-4 → mt-[18px]
```

验证：`npx tsc -b --noEmit`、`npx eslint src/features/workbench/components/deal-detail` 均通过；
浏览器（1440×1150）逐屏核对专项工作台、前置校验、阶段清单、交付物清单、甘特、客户确认记录
六块，卡间距一致、无同心边框叠加。

### 修复

#### 非诉工作台里九张卡全部贴死（零间距）

上一节改的是卡**内部**的边框层次，但用户看的其实是**卡与卡之间根本没有缝**：

```
「推进到下一阶段」  bottom = 1022
「推进前置校验」    top    = 1022   ← 差 0px
```

根因在 `NonLitDetailPage` 的包装 div：三个工作台组件返回的都是**一串 `<Card>` 兄弟节点**
（Fragment 直接展开），而这层包装只写了 `mb-[18px]`（那是「与下一层之间」的外边距）：

```tsx
<div className="mb-[18px]">        {/* 只管自己与相邻层，不管自己内部的兄弟 */}
  <SpecialPhaseWorkbench />        {/* ← 展开成 9 个 <section> 兄弟，彼此 0 间距 */}
</div>
```

`DealDocLayout` 的 `space-y-[18px]` 作用在**这一层与相邻层**之间，管不到这一层内部。

修法：把这段抽成一个容器统一给栅格，四个分支（跨境 / 专项 / 常法 / 兜底）共用：

```tsx
const NONLIT_STACK = 'flex flex-col gap-[18px] mb-[18px]'
```

- 用 `flex flex-col gap-[18px]` 而非 `space-y-*`：工作台内可能有条件渲染的整段为空，
  `space-y` 依赖相邻兄弟选择器给「第一个非空子元素」打 margin-top，`gap` 只认实际参与布局的孩子；
- 四个重复的 `mb-[18px]` 分支收敛成一处，后续再加工作台不会再漏掉。

验证（浏览器实测，`document.children` 逐个量边界）：

```
before  gaps = [0, 0, 0, 0, 0, 0, 0, 0]     // 9 张卡全贴死
after   gaps = [18, 18, 18, 18, 18, 18, 18, 18]
```

改动文件：`frontend/src/features/workbench/components/deal-detail/NonLitDetailPage.tsx`

#### 阶段进度甘特里「提前 / 延期 N 天」胶囊溢出卡片右边界

用户截图：甘特卡右侧的统计胶囊跑到卡片外面去了。

实测（1280 视口，卡片宽 847、`clientWidth` 845、`scrollWidth` **859**）：

```
「提前 14 天」  right = 卡片 padding 右边界 + 13px   ← 溢出
「提前 15 天」  +12.7px
「延期 11 天」  +11px
「提前 3 天」   +7.2px
「提前 1 天」   +5.5px
```

根因是**右侧读数槽宽度写死**：槽 `w-[150px] flex-none`，但里面装的是
「计划天数 52 + 进度 34 + 状态胶囊（内容自适应 62~70）+ 箭头 12 + 两个 gap 12」
≈ **165~175px**，`flex-none` 不收缩 → 多出来的部分整体被推出卡片。

改法：

- 读数槽按真实需求放到 `w-[186px]`，计划天数 / 进度两列各收紧到 46 / 32；
- 状态胶囊包一层 `min-w-0`，极窄时允许压缩而不是撑破父级；
- 行加 `w-full min-w-0`，保证「轨道」是唯一让位的那一项；
- 表头改 `flex-wrap`：日期串过长时三个统计胶囊**整体换到第二行**，不再被挤出右边界；
  日期串本身 `min-w-0 truncate`；
- 窄栏（容器 < 520px）时阶段名列 132 → 92、读数槽 186 → 132，并隐藏「计划天数」列
  （两列读数里信息密度低的那列先让位）。

验证：

```
before  clientWidth 845 / scrollWidth 859   ← 溢出 14
after   clientWidth 845 / scrollWidth 845   ← 相等
```

全站扫描（`section.scrollWidth > clientWidth + 1`）：正常宽度下 0 张卡溢出；
把左栏强制压到 720px 时甘特卡也不再溢出。

改动文件：`frontend/src/features/workbench/components/deal-detail/nonlit/special/special-gantt-card.tsx`

#### 风险登记表的到期日折成两行（`2027-01-` / `20`）

用户截图：风险表每行的到期日都被折成两行，很难看。

实测该单元格：

```
槽宽 = 52px（w-[52px] flex-none）
「2027-01-20」在 10.5px tabular 下实际需要 = 87.7px
→ 差 35.7px，必然折行；单元格高度 31.5px（两行），把整行从 34px 撑到 52px
```

改法：

- 到期日槽 52 → **78px**（按实测 87.7px 的右对齐实际占位给），并加 `whitespace-nowrap`；
- 责任人列同样加 `whitespace-nowrap`（姓名三字时也会折）；
- 同类固定槽一并加固：阶段清单的「N 份 · 改 N」/「确认 N」、
  日期区间列全部加 `whitespace-nowrap`——它们都是写死宽度，
  一旦允许换行就会被折成「2 份 · 改」/「2」，把整行从 34px 撑到 48px。

验证：全站扫描「固定宽槽 + 内容高度 > 1.6 倍行高」的单元格：

```
before  到期日 6 处全部命中（h = 31.5，lineHeight = 15.8）
after   wrapped = 0
```

改动文件：
`nonlit/special/special-risk-card.tsx`、`nonlit/special/special-phase-board.tsx`
