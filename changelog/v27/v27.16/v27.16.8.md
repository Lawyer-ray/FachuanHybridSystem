# v27.16.8 · 预处理准确度：让律师知道「哪页我看不出内容、哪格我点不准」

> 分支 `feat/matprep-accuracy-upgrade`（3 个提交，46 文件 +4790/−45）。
>
> 前置：`v27.16.7` 之后大卷宗已经能跑完（两阶段任务链 + 分批解析），
> 本版转向**准确度**——按律所口径「预处理拿到精准 Markdown，支撑诉讼的部分准确即可，
> 不追求 100%」，把精力放在**让律师能发现并修正错误**，而不是「自动给出正确结论」。

## 背景：三个实测出来的盲区

拿到 164 页真实银行卷宗后，用数据量出三处「系统没说、律师也不知道」的地方：

| 盲区 | 实测证据 |
|:--|:--|
| **图形页静默丢失** | p147 宗地图只有 6 字、p148 平面图 27 字、p98 照片页 10 字——律师在 Markdown 里看到几行乱码，不知道那是图纸。而图纸恰是抵押案件的关键证据 |
| **跨页同名错字** | 同一枚经办人章在 164 页里识别 150+ 次，有 5 种写法：79 次正确、各 3 次错字。律师逐页读不可能发现 |
| **表格框太大** | 律师反馈「第 22 页框得很大」。查数据：该页只有 2 个块，其中一个 table 块占页面 40% 高度，罩住 17 行 × 4 列。想点「*房产证编号」那格根本点不中 |

外加一个深挖出来的存储 bug（见第四节）。

## 一、页面质量画像

新增 `page_quality.py`（纯 stdlib）。判据经过**三轮真实数据修正**：

| 判据 | 说明 |
|:--|:--|
| `blank` | 剔除印章套话后有效字符 == 0 且无块 |
| `graphic` | ① 有 table 块 且该块 < 50 字；② 无 table 块 + 有 image 块 + 有效字数 < 60 + 无业务字段标签 |
| `sparse` | 有效字数 < 200 |
| `text` | 其余 |

### 三轮误判，每轮都是真实数据打出来的

1. **「有 image 块就判 graphic」** → p8 银行欠款明细表（**617 字真表格**）被误判成图形页。
   MinerU 给页眉 logo、印章、表格截图都打 image 块，这不是充分条件。
2. **「字数 < 60 判 graphic」** → p23 身份证（45 字）中招。
3. **改用「table 块的字数」作主判据** —— 宗地图被当成 table 块但只抽出 6 字，
   而真表格是 587 / 10806 字。「有表格结构、无表格内容」区分度干净。
4. p148 平面图无 table 块 → 补 b2 判据；但 b2 会把 p23 身份证一起吞掉，
   再加「有效文本不含业务字段标签」区分（p23 有「居民身份证」、p41 有「面谈笔录表」，
   p148 只剩乱码）。

实测七页全部正确：p8/p52 → text，p23/p41/p116 → sparse，p98/p147/p148 → graphic。

### 印章套话必须先剔除

`已核对与原件相符`、`扫描件与留档资料相符`、`经办人：…` 这些跨页高频套话，
不剔除的话每页都「有成句中文」，把证件页和图纸页的数量抬到一样，判据全部失效。

## 二、跨页一致性校对

新增 `cross_page_consistency.py`。**1340 条噪声 → 2 条精准命中。**

### 第一版是噪声发生器

对每段连续中文做 3-6 字**全滑窗**，再找一字差配对。真实数据出 1340 条：

```
付宝支付(227) ← 应付通支付(675)   ← 「支付宝支付」和「财付通支付」都是真词
的利率(30)    ← 应款利率(34)      ← 句子碎片
抵押权利(17)  ← 应抵押物(39)      ← 两个都是真词
```

**滑窗 + 一字差 = 噪声发生器**，调 `min_count` 到 10 仍几百条。

### 改为只比对原子语义单元

- **字段值**：`经办人：X`、`签字：X`、`共有人：X` 等（白名单 16 个字段名）
- **表头单元格**：`| 交易卡号 |` 这类

### 修完还有第二层 bug

`经办人：张瑞琴 罗向文` 是**两个人**，代码 `_normalize` 去掉空格后粘成 6 字整体
`张瑞琴罗向文`，再 `[:6]` 截断——**「张瑞琴」永远不是候选**（候选池 2 次，实际 79 次）。
改为字段值先按空白切开各自成候选，粘连形态另存整体。

### 最终结果

```
张瑞孝(3) ← 应为 张瑞琴(79)   页=[90,146,148]
张瑞芳(3) ← 应为 张瑞琴(79)   页=[90,152]
```

阈值分两档：**业务术语 3 倍、人名 4 倍**。人名更严——共有人/保证人/配偶常是
「同姓差一字」的真实不同人，误报代价高（律师核对一次发现是两个人，以后就不信这功能）。

## 三、大表格拆格

### 根因

MinerU 对表格只给**整表 bbox**，不给逐格坐标。我们原样透传，于是前端只能画一个
覆盖整表的大框。全卷 152 个 table 块里 **114 个高度超过页面 25%**。

### 解法：按行列均分整表矩形

MinerU 虽不给逐格坐标，但 `table_body` 里给了完整 HTML 结构（行列齐全）。
等宽表格按行列数均分整表 bbox，落点误差在半格以内——律师要的是「点中这一格」而非像素级精确。

实测 p22：17 行 × 4 列全部对齐，每格约 149.5 × 23.5px。**2 块 → 69 块**。

### 两级粒度（块数不能爆）

第一版无差别拆格，全卷块数 **1147 → 6062（5.3 倍）**，前端渲染几千个绝对定位框会卡。

实测单元格数存在明显断层：

```
流水类长表  247 / 256 / 274 / 295 / 307×5 / 974 / 1341 / 1627 / 2046
表单类中等表  65 / 68 / 69 / 80 / 88 / 92
```

断层落在 92 与 247 之间，取 **120** 做分界：

- **≤120 格 → 拆到单元格**（表单类，要点具体某一格）
- **>120 格 → 只拆到行**（流水类，要看的是「哪一行」，单格无点击价值）
- **>80 行 → 整体保留**（237 行超长表拆了也点不中，靠原文检索）

最终全卷 1147 → 3718（3.2 倍），可接受。

拆出的格/行一律 `approx: true`——均分推算的不是量出来的，前端画**虚线**，
延续「不给假精度」的口径。

## 四、证件页关键字段提示

### 真实痛点

```
p23 身份证: 45 字 → 姓名/身份证号/住址全部丢失
   Markdown 只剩「中华人民共和国 / 居民身份证 / 已核对与原件相符 / 经办人：…」
```

律师看到的是「内容较少，可能是封面/证件/表单，建议核对」——太模糊。
他不知道自己最关心的身份证号根本没读出来。

### 做法

新增 `doc_type.py`：按标题行/关键词认出材料类型，再检查该类材料**应当有但没有**的字段。

| doc_hint | 预期字段 |
|:--|:--|
| id_card | 姓名 / 身份证号 / 住址 |
| household | 姓名 / 身份证号 |
| property_cert | 权利人 / 权证号 |
| marriage | 姓名 |

提示语从「内容较少」变成：

```
这页是身份证，但姓名 / 身份证号 / 住址 均未读出，请人工录入或核对原图
```

`summary["page_quality"]` 新增两个**结构化**键（不透传自然语言——前端从中文句子里
正则切字段名是脆的，后端改一个字前端就瞎）：

```jsonc
"doc_hints":   { "23": "id_card" },
"doc_missing": { "23": { "doc": "id_card", "missing": ["姓名","身份证号","住址"] } }
```

真实数据验证：p23 精确命中三项全缺；p30 结婚证 `missing` 为空（字段都在）。

## 五、OCR 缓存读写修复（真 bug）

### 现象

`default_storage.save` 遇到同名会**改名而非覆盖**，于是同页堆出多份副本：

```
accurate_mineru_text_v2: p1 积了 99 份副本，文字量 32 ~ 15217 字（差 475 倍）
read_ocr_cache 读固定名 page_0001.json —— 命中哪一份全看运气
```

实测固定名那份只有 805 字，最优 15217 字 → **丢 95% 内容**。

### 修法

- **写**：先 delete 固定名再写，并清理该页历史残档（失败只记 log，不影响主写入）
- **读**：扫该页所有副本，按 `(not ocr_failed, len(text), mtime)` 排序取最优 ——
  **内容多少是质量信号，时间不是**（一次偶然的失败识别不该盖住之前成功的结果）；
  选中残档后提升回固定名（自愈），后续读取不再扫目录
- **边界安全**：精确前缀 `page_{n:04d}` + 形状校验，`page_0001*` 不会匹到 `page_00010.json`

## 六、前端

- **左栏段行**：覆盖图形页加灰色 `FileImage` 图标、覆盖证件页换 `IdCard`，
  tooltip 指名类型。**不加彩色**——延续 `v27.16.7` 删彩色圆点的决策
- **右栏正文顶部**：按类型分行显示
  `⚠ P23 身份证，缺：姓名 / 身份证号 / 住址 · 建议核对原页`，可点击跳原页
- **待补录清单抽屉**：全卷证件页的缺失字段一览，按缺失数降序。
  `missing` 为空时显示「—（建议整页核对）」而非隐藏。
  **这是律师真正会用的**——打开就知道要翻哪几页、抄什么
- 所有字段可选，旧任务无这些键时不渲染任何东西

## 七、接入（不阻塞、不落库）

- `summary["page_quality"]`：graphic/sparse/blank 分桶 + `details` + `doc_hints` + `doc_missing`
- `summary["inconsistencies"]`：按 confidence→频次取**前 50 条** + `inconsistency_total`
  （1340 条全灌会撑爆 payload，这是输出体积边界不是业务过滤）
- `SegmentOut.quality_flags`：落 `segments_md.json`，不加 DB 迁移
- **两阶段链路打通**：page_quality 在取字阶段算、分段阶段才用，新增
  `page_quality_json_path` + `save/load_page_quality`，否则线上新字段永远是空的

## 已知边界

- **证件页识别失败是 OCR 引擎能力边界**——二代身份证文字压在底纹上，MinerU 读不出。
  本版只做到「诚实地告诉律师这几项没读出来，请人工录入」，不假装读到了
- 一致性校对只覆盖「字段值 + 表头」。正文里散落的人名变体（签字栏 vs 正文）抓不到——
  放宽到正文会回到 1340 条噪声，取舍明确选「宁可漏报」
- p148 这类「无 table 块 + 无字段标签」的图形页靠 b2 兜底，若图上恰好印了一行业务词
  会退回 `sparse`
