## 背景

`frontend/CLAUDE.md` 把三条列为「最高频红线」：文件 >450 行禁止、禁止 feature
互相 import、对接接口先查 OpenAPI。但 `eslint.config.js` 里**一条都没实现**——
`max-lines`、`no-restricted-imports` 全部为 `undefined`（用 `--print-config` 实测）。
今天这两条红线之所以基本没破，是 code review 的运气，不是门禁。

同一个病还有第二个病灶：`vite.config.ts` 设了覆盖率棘轮（statements 90 / lines 91
/ functions 85 / branches 82），但 CI 只跑 `pnpm test`，**从不跑 `test:coverage`**。
阈值写了 10 个月，从来没生效过一次。后果是 2026-10-23 之后落地的约 90 个文件带着
0% 覆盖进仓库，无人拦，真实水位一路滑到 statements 70.89%。

## 前端

### 修复

#### `ErrorBlock` 二次消毒吞掉后端文案

`useLoad`（`bank-litigation/hooks/use-cases.ts`）在 `.catch` 里已经调用过一次
`errMessage` 并把错误归一化成 **string** 往下传；`ErrorBlock` 拿到这个 string 后又跑
一遍 `errMessage` —— 而 `errMessage` 对非对象入参在函数第一行就
`return fallback`，于是已经取到的好文案被降级成笼统的「加载失败」，**后端原话被静默丢弃**。

改为已是非空 string 时直接透传（`AsyncState.tsx`）：

```tsx
{typeof error === 'string' && error ? error : errMessage(error, fallback)}
```

**刻意没有改 `errMessage` 自身**：它的 catch 路径契约是「裸 string 必须降级成 fallback」
（不向用户渲染原始服务端文案），这条被 `use-converter-job`、`court-sms` 等 3 个既有用例
正确锁着，且 court-sms 涉及安全口径。真正的问题是**二次处理**，就在二次处理的边界修。

#### 案件页把「加载失败」和「查无此案」混成一个分支

`BankLitigationPage.tsx` 原写法：

```tsx
if (c.error || !c.data) {
  <ErrorBlock error={c.error ?? '案件不存在'} fallback="案件加载失败" onRetry={c.reload} />
```

两个毛病：`c.error ?? '案件不存在'` 永不为 null，导致 `fallback="案件加载失败"`
**永不可达**（死配置）；且「查无此案」也挂着一个点了也没用的**重试**按钮——重试了
还是不存在。拆成两个分支：

- 有 `error` → 「加载失败」，保留「重新加载」（网络/5xx 值得重试）；
- 无 `data` → 「案件不存在或已归档」，按钮改成 **「返回案件列表」**走 `onBack`。

#### `DealDocLayout` 状态③ 整个省掉了事实卡

组件头部文档写着「③ 文档通栏，内容与事实卡在其下」，实现里 `focusDoc` 分支
只渲染了 `doc`，`rail` 整块丢失。宽屏（≥1280）且净宽不足 1100 时，右侧事实卡
（期限 / 当事人 / 收费 / 文件夹）**彻底不可达**。已补回。

#### `use-copilot-drop` 声称兼容旧 payload，实际丢弃

注释写「兼容三种 payload 形态：旧 `{contractId}` / 新 `{kind, ownerId}`」，但守卫
只认 `d.kind`，旧形态必然被静默丢弃。改为按 id 字段反推 kind：
显式 `kind` 优先 → `caseId` → `contractId` → 都没有才丢弃。

> 这 4 个 bug 都不是专门找的，是**补覆盖率的过程中照出来的**——写了测试才发现
> 「注释说一套、代码做另一套」。三个原先"记录 bug"的用例已同步改成断言正确行为
> （其中一个注释里本就写着「已作为待确认问题上报，不在测试里断言成正确」）。

### 优化

#### 把规范红线做成机器门禁

`eslint.config.js` 新增：

- **`max-lines: error @450`** —— 硬红线（ratchet 已归零）。
- **`no-restricted-imports`** —— 禁 `@/features/*/*` 深路径跨域引用，只允许走 barrel；
  `@/features/copilot/launch` 是架构决策放行的唯一例外（chunk 边界需要）。
- **`react-hooks/exhaustive-deps` 升 error**（基线 0 违规，可直接上）。
- **`max-depth: error @4`**（基线 0 违规）。

> **为什么只有 450 一档、没有 350 软红线**：eslint flat config 里后出现的 block 会
> **整体替换**同一规则的 severity + options，而不是合并。实测 eslint 10.11，两种
> 书写顺序的结果都是「后块赢」（warn@350 后接 error@450 → 生效 `[2,{max:450}]`；
> 反过来 → 生效 `[1,{max:350}]`，硬红线直接失效）。一个文件不可能同时挂两档阈值，
> 写两档只会留一条**永不触发的死规则**——比没有更误导人。350 保留为 review 期人工判据。

#### `lint` 加 `--max-warnings 0`，并新增独立 `typecheck` 脚本

warn 不能再蒙混过关；`typecheck` 让类型检查可单独调用（此前只能靠 `build` 间接触发）。
补测期间正是 `tsc -b` 抓出了 9 个 vitest/eslint 都放过的测试文件类型错误
（`vi.fn()` 未定型不匹配回调签名、props 既显式传又 spread 导致 TS2783 等）。

#### CI 改跑覆盖率，棘轮当场生效

`.github/workflows/frontend-ci.yml` 的测试步骤从 `pnpm test` 改为 `pnpm test:coverage`。
覆盖率阈值按实测重新校准（当前 `{statements:87, lines:89, functions:85, branches:81}`，
留约 1.5pp 抖动余量避免拆分/重构时误红）。**禁止下调**，补到 90 以上再抬。

#### 其余卫生项

- `frontend/.gitignore` 补 `tmpdbg/`、`.mp-smoke-shots/`——此前未跟踪也没忽略，
  一次 `git add -A` 就会进仓库。
- `e2e/bank-litigation.e2e.mjs` 去掉家目录硬编码
  （`/Users/<开发者>/node_modules/playwright/index.mjs` → `from 'playwright'`），
  并补前置条件说明：playwright 未声明为依赖、夹具在 gitignored 的 `prototype/` 下。
- `features/bank-litigation/DELIVERY.md`（发布说明躺在 `src/` 里）归档为
  `changelog/v27/v27.17/v27.17.0.md`，剔除已失效的提交哈希表与过时测试快照。

## 说明

### 踩过的坑：拆「文件 → 目录」后 vitest 假失败

拆分后有两个测试文件报 `Cannot find module '...demo-nonlit.ts'`，但路径和 barrel 都正确。
排查发现是 **vitest transform 缓存按旧文件路径 key**，只清 `node_modules/.vite` 不够，
**必须同时清 `node_modules/.vitest-cache`**。清完 18 个用例立刻全过。
后续任何人做同类拆分遇到这个报错，先清这两个目录再怀疑代码。

### 已知未修

  refetch（行为无害，但 effect 声明的意图是「每轮流结束后刷新」，实际范围更宽）。

  而同文件其他 client 已提到模块级——每次调用都新建一次性 client。

  该文件所在 `docs/` 被 gitignore，需本地维护，故未在仓库内修改。

### 关于 demo 数据进产线

两份 demo 数据（约 3800 行）被 64 个生产文件引用，**确实进了 bundle**。
本版只做了「按场景拆成可独立删除的模块」，**没有改变它是否进产线的决策**——
那属于产品口径，需要单独决策：要进就下沉到 `features/*/demo/` 并接受体积，
不进就按场景逐个清引用退场。拆分已经把这件事从「不可能」变成「可行」。
