# v27.16.6 · 材料预处理：Markdown 正文进右栏、可拖宽、识别错了能就地改

> 分支 `fix/matprep-md-to-sidebar`（3 个提交，全部只动前端 `features/material-prep`）。
>
> 前置：`v27.16.5` 之后、PR #634 修掉了**定位框偏移**（rect 按页面图像归一化，
> 却画在含页码栏的页卡上）并首次让分段 Markdown 可见。
> 本版接着处理那次落地后暴露的三个使用问题。

## 背景

#634 把 Markdown 面板放在**每段页面之上**。实际用起来是这样的：

- 展开后正文动辄数千字，把这个段各个页面之间的内容全推出屏幕；
- 「边看正文边对照原页」反而做不到——要来回滚；
- 识别明显的错（表格拍平、标题层级错、页眉混进正文）**没有修改入口**；
- 定位框画歪了，只能忍着。

外加一个纯粹的手感问题：右栏固定 256px，长文本折行严重，读不下去。

本版逐个处理。

## 一、Markdown 面板移到右侧栏

与「材料信息」同栏，放在字段卡**之前**——先看机器读到了什么，再决定填哪些字段。
右栏与页面流并排常驻，两边滚动互不干扰。

## 二、右栏支持拖拽改宽，宽度记 localStorage

| 决策 | 理由 |
|---|---|
| 手柄贴**右栏左缘** | 右栏靠屏幕右边，把手放右侧物理上不可达；放接缝处拖拽方向与直觉一致（往左拖变宽） |
| 夹在 **220–640** | 再窄读不了中文，再宽中栏没地方 |
| 键 `mp.meta.width` | 纯显示偏好：不进 store、不进草稿、不进 Undo 栈、不随后端同步。换个材料包打开，栏宽保持原样才符合直觉 |
| **拖拽期间不写盘** | localStorage 是**同步阻塞**的，pointermove 每帧写会产生几百次 IO，拖动肉眼可见地卡。改为拖完 pointerup 落一次 |
| 窄屏（抽屉）不渲染手柄 | 抽屉宽度由 CSS 固定，跟随拖拽值会漏出屏幕 |

## 三、识别错了怎么改——两个动作分开

关键判断：**框画歪 ≠ 文字读错**，两件事不该互相牵连。

| 动作 | 入口 | 行为 |
|---|---|---|
| 改正文 | 右键某一行 / 悬停「改正文」 | 就地编辑文字，保存进草稿（可撤销、随包保存） |
| 删错框 | 行尾悬停删除键 | **只删坐标，不动正文** |

### 改一行必须同步改 Markdown

`blocks[].text` 与 `seg.md` 是同一批文字的两种视图：前者带坐标给定位用，
后者是给下游 AI 消费的正文。只改一处会出现**「列表里改好了、Markdown 里还是错的」**
——比不改更糟，因为人以为已经修好了。

同步方式：**用原文匹配，不用行号**。后端拼 md 时做过格式化（表格转 GFM、标题加 `#`），
块文本与 md 的行不是一一对应，按行号改必然错位。
找不到原文时**只改块、不动正文**——宁可正文保留旧值，也不能乱替换别处的文字。

## 四、列表即正文，去掉底部重复渲染

一版是「上面带页码的定位块行 + 下面完整 `<pre>`」——同一段文字出现两次，
改的时候要来回比对“刚才改的是不是这一行”。

改为列表本身就是正文，改动直接落在行上：

- 每行 **双击**定位原页（单击是选字的自然动作，不该跳转）
- 每行 **右键**就地编辑
- 去掉面板顶部独立的「改正文」总开关——改哪行就在哪行改

没有定位块的段（本地 OCR / 旧任务）仍走整段编辑，入口收进悬停按钮。

## 五、单行编辑补显式「保存 / 取消」

一版只有「回车保存 + **失焦保存** + Esc 取消」，用户问了一句「要取消修改怎么办」
——这正是问题：**取消没有任何可见入口，而保存却在两个看不见的时机自动发生**。

失焦即保存的三个实际危害：

1. 界面上没有任何提示，用户不知道“切走”就等于提交；
2. 误点别处（想复制文字、想对照原页）就改了库；
3. 回车保存会让父级卸载输入框 → 触发 `blur` → **再提交一次**（重复写入）。

改为与「整段编辑」一致的显式按钮：

```
┌ P1 ┌────────────────────────────────┐
│    │ 债权人：某某金属材料公司…    │
└    └────────────────────────────────┘
  [✓ 保存]  [取消]        回车保存 · Esc 取消
```

判断依据：这一行是**法律文书正文**，改错了下游 AI 会拿错文本跑。
这种场景下“自动保存”是错的默认值，应该由人明确说“我要保存”。
回车 / Esc 保留给熟手，并在按钮旁写明——不让人猜。

三条新增测试均做**反向验证**：

- 把 `onBlur` 注入回去 → 「失焦不自动保存」立即失败；移除即通过
- 把页码栏移进图像区（v27.16.5 那个 bug）→ 结构断言失败

## 一次差点蒙混过关的记录

做「显式保存/取消」时，第一次跑完测试看到「4144 全绿」就以为成功了，
实际**改动根本没落盘**，被旧缓存骗过去。

发现方式：反向验证时把 `onBlur` 加回去，测试竟然全过——这不可能。
回头查 `git status` 才发现工作区与 HEAD 完全一致，补丁从未写入。

重做时改为**每步核验落盘**（`grep -c onBlur` 从 1 → 0），反向验证才真正成立。
教训：**测试通过不等于改动生效**，尤其在有缓存与批量替换的场合。
