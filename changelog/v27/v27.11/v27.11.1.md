# v27.11.1 — 全局检索两处“静默失败”修复：非诉命中跳回首页 + 单类别报错拖垮整包

两处症状不同、成因同源：**失败被静默吃掉**。前端拼出已不存在的路由，撞通配重定向跳回首页；后端一个类别查询抛异常，整个检索端点 500。用户侧都表现为“搜索坏了”，且都没有任何提示。

## 前端

#### 修复

- **非诉命中点进去到了首页**：`projectRoute` 仍按诉讼/非诉分流，非诉（`special` / `advisor`）拼出 `/projects/:id/nonlit`，而该路由已随详情页收敛为单条 `/projects/:id` 一并删除 → 命中 `App.tsx` 的 `*` 通配重定向、静默跳回首页。典型现场：搜某常法顾问客户（`case_type=advisor`）→ 点结果 → 回首页，用户以为“搜索没生效”。 // privacy-allow
  - 合同/案件一律返回 `/projects/:id`；诉讼与非诉的左栏差异由 `ProjectDetailPage` 按 `deal.lit` 在页内决定。
  - 案件命中保留 `#case-<id>` 锚点，非诉案件现在也带锚点（此前非诉分支提前 return，锚点丢失，跳过去后看不到是哪一案）。
  - 移除 `projectRoute` 对 `isLitigationType` 的依赖（前端不再需要知道分类语义）。

#### 测试

- `domain.test.ts`：非诉合同/非诉案件断言改为 `/projects/:id`；新增「生成的路由不带 `/nonlit` 后缀」用例，覆盖 advisor 合同、special 合同、advisor 案件三种来源。
- `GlobalSearch.dom.test.tsx`：测试路由表补上 `path="*"` 通配探针（与真实 `App.tsx` 一致）——以前跳错也看不出，因为“跳回首页”在测试里就是一片空白；现在断言非诉命中落在 `/projects/4` 且**不得**命中通配。

## 后端

#### 测试

- 新增 `tests/ci/unit/core/test_search_api_degradation.py`（4 例），为 `/api/v1/search` 已有的降级隔离补回归锁：
  - 单类别抛异常（模拟“模型有字段、库里没列”）时端点仍返回 200，坏类别退化为空列表，其余五类结果完整保留；
  - 坏类别必须记 ERROR 日志且日志带类别名（否则下次又只能靠翻 stacktrace 猜是哪类挂了）；
  - 正常路径不受 `return_exceptions=True` 影响，各类别结果原样合并；
  - 空关键词短路，不触碰任何查询。

#### 说明

- **背景事故（2026-10）**：`message_hub.InboxMessage` 加了 `upload_link` 字段但迁移没上库，`search_inbox` 报缺列；当时 `asyncio.gather` 未带 `return_exceptions=True`，一个类别炸掉把整个端点抛成 500——另外五类完全正常的结果一并丢失，前端只显示“啥都搜不出来”。
- 该降级隔离代码（`return_exceptions=True` + 逐类别 ERROR 日志）本版前已合入 `search_api.py`，本次只补测试，不改业务逻辑。
- 判断标准沿用仓库既有约定：**会让用户看到一个无法解释的结果的失败，一律 warning 以上**。
