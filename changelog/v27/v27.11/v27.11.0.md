#### 修复 · fetch_url SSRF 防护（2026-10-25 深夜审计）

- `fetch_url` 此前接受任意 http(s) 目标且 `follow_redirects=True`——模型可以让后端同机进程抓 `127.0.0.1:8002`（自家 Django/MCP）、律所内网网关、云元数据端点（169.254.169.254）,「公网 302 → 内网」重定向还会绕过任何首跳检查。标准 SSRF 面。

- 新增 12 个 SSRF 测试（9 类内网目标、域名解析内网 IP、DNS 失败 fail-closed、公网放行、302→内网中跳拦截）;既有测试补 autouse DNS mock（不再触网）。E2E 实测 `fetch_url('http://127.0.0.1:8002/api/v1/openapi.json')` → blocked_target。

#### 优化 · 对照官方规范——非销毁写显式 destructiveHint:false + 体量口径重测(2026-10-25 晨间审计三十四轮)

- 参考维度(goal 指定「看优秀 MCP 项目参考学习模仿」):抓取 MCP 官方规范 tools 页对照。达标项:isError 错误通道、参数描述/枚举进 schema、annotations 四 hint 覆盖、命名规范——均与官方 best practices 对齐。
- **真差异一处**:规范对未声明 hint 按「assume worst」缺省——`destructiveHint` 缺省=true。本工具面 117 个非销毁写工具(77 幂等+37 普通+3 开放世界写)此前不带任何标注,规范客户端会把 `create_case` 这类普通写当销毁型加确认拦截。照官方 reference server 全量显式的做法补 `destructiveHint:false`,实测仅 +2.8KB;`_tool_annotations` 不再返回 None,409 工具全部带标注(223 只读+69 销毁/高危+117 非销毁写)。openWorld 缺省 true 刻意不逐工具补 false——409×24B≈10KB 只防低危误读,pi 逐键解析不受影响,体量纪律优先(决策记录在 server.py 注释)。
- **连带发现:README 体量数过期**。「≈217KB」的测量方法已不可复现,按钉死口径(initialize→tools/list 原始 JSON-RPC 响应 UTF-8 字节)重测:**≈277KB ≈ 9 万 token**;成分分解:docstring 工具描述 103KB(最大头)、裸 schema 144KB、annotations 18.6KB、参数级 Field 描述 10.2KB、enum 列表 1.4KB——为灰度决策提供了第一杠杆排序(docstring 优先,schema 描述是买来的调用准确率不建议省)。
- 门禁同步:`test_tool_annotations.py` 三处断言随语义更新(普通写从「无标注」改「显式非销毁」),新增 `test_spec_default_alignment_non_destructive_writes` 钉死显式 false;线上 wire 实测 409 全带标注、`create_case→{destructiveHint:false}`、`update_case→{destructiveHint:false,idempotentHint:true}`。
