# v27.30.10 · 项目详情页顶部进度条按「程序线」分流：单案不画、一条线才画进度条、多条线改案件总览

> **版本判定**：§1.2 —— 本分支第 1 条提交，上一个号是 `v27.30.9` → 第三位 +1。

## 一句话

| 之前 | 现在 |
|:--|:--|
| 顶部永远铺一条「合同勾选阶段 ∪ 案件阶段」的线性进度条，同阶段多案压成 `×N` | 先判**这个委托下有几条程序线**，再决定画什么（判据 `chainShape`）|
| 单案也画，整条进度条 = 案件卡卡头抄一遍（`◎一审 在办 · 顺德法院`） | 单案**不画**；「下一步是什么」交给最下方的 NextStageRow（带按钮）|
| 合同勾了却永远不会发生的阶段（一审结案直接执行，中间那个二审）**永久空心** | 最后一个已启动阶段**之前**的空心节点不画，之后只留**紧邻的一个**（`trimPlan`）|
| 两条互不相干的程序线（261 两个被告各一条线、271 两个二审只有一个进执行）读成「都走到这一步，还差一个」 | 多条线降级成**一案一行的总览**（`CaseOverview`），每行左边是**该案所在程序线**的小链点 |
| 前端拿不到 `previous_case` | 后端 `CaseOut` / `CaseSlimOut` 下发 `previous_case_id`（裸 id）|

  - 271：`305 二审` + `361 执行(prev=305)` + `375 二审` → 两行小链点，执行只挂在它自己那条二审下面。

## 具体改动

### ① 后端：下发 `previous_case_id`（`apps/cases/schemas/{case_schemas,case_slim_schemas}.py`）

- `CaseOut.previous_case_id: int | None`，**裸 id、不嵌对象**（同 `contract_id` 的处理方式）；
  `CaseSlimOut` 同步声明——两份 schema 的标量列必须同口径，否则又是一次
  「完整版有、瘦身版没有」的静默缺口。
- 加 `resolve_previous_case_id`（dict 与 ORM 两条取数路径都走它，同 `resolve_contract_id`）。
- 无迁移：`Case.previous_case` 字段早就存在（`models/case.py:73`），一直没下发。
- 契约用例 `tests/ci/unit/cases/test_case_schema_previous_case.py`：钉住「两张 schema 都有、
  且不在 `CASE_SCALAR_FIELDS` 里」。**漏下发不会报错**——前端拿不到关系只会退化成"多条线"，
  页面照样渲染、只是把归属讲错，这种退化只能靠契约用例拦。

### ② 域逻辑（`detail/chain-domain.ts`，纯函数）

| 新增 | 作用 |
|:--|:--|
| `caseBranches(cases)` | 按 `prev` 取**无向连通分量**分出程序线，线内按程序序排。取分量而不是走单链：261 一个 `prev` 都没写，串过的（271）才归一组；`prev` 指向本委托外/指向自己 → 按无线处理，**案件一个都不能丢**；成环不死循环 |
| `chainShape(branches)` | `none` / `single` / `chain` / `multi` |
| `trimPlan(plan)` | 砍掉「最后一个已启动阶段之前的空心节点」，之后只留紧邻的一个；**一个都没启动时原样返回**（那时空心点=合同约定的代理范围，是有用信息）|

### ③ 组件

- 新增 `CaseOverview.tsx`（`multi` 形态）：`N 个案件 · x 在办 · y 已结` + 一案一行；
  默认分组**随数据变**——案由多样（系列案）按案由、案由只有一种（261）按程序；
  按程序分组时组序走**程序序**（一审 → 二审 → 执行），不是拼音序；行可点、滚到案件卡并高亮。
  **故意不按 `group_key` 分组**：那个字段只有归档/复制路径会拷，常规建案不写，现在基本是空的。
- `DealDetailPage`：`multi → CaseOverview`，`chain → ChainStepper`，`single → 不画`，
  `none → 只有勾了阶段才画`。
- `SegBtn`（视图切换小段按钮）从 `CaseSection` 提到 `ui.tsx` 共用，避免同页两种分段按钮。

## 已知边界

- 库里 `previous_case` **大面积为空**，所以「多条线」是常态而不是异常——总览如实呈现
  「这些案件的关系未知」，不替律师猜一条链。
- 单案隐藏进度条后，合同勾了哪些阶段只能从 NextStageRow 看到**紧邻的下一步**；要看全量约定
  需进「编辑」。这是有意的取舍：一个永远空心、且不可点的节点列表，读起来比不显示更像故障。
- 系列案仍是一个 `Contract`（用户已定），本版不引入分组层；`group_key` 留给将来。
