# v27.30.3 · 案件列表分页（服务端）：搜索与「待立案优先」一并下推，每页 50 行 20KB / 31ms

> **版本判定**：§1.2 同一条线（`v27.30.x` 的「列表接口响应瘦身 + 加载态」）→ 第三位 +1。

## 一句话

| 之前 | 现在 |
|:--|:--|
| 一次拉全部（115 件 = 724 KB），"待立案优先"与关键词过滤**在前端**做 | 服务端分页，**每页 50 行 ≈ 20 KB / p50 31 ms** |
| 排序只对已加载的那批生效 | `sort=filable_first` 在 SQL 里算，翻到第 2 页排序照样成立 |
| 关键词只过滤当前已加载的行 | `search` 下推（name / cause_of_action），`X-Total-Count` 与过滤同口径 |

## 为什么"直接加个分页条"是错的

`CaseListPage` 原来在**前端**做两件事：`keyword` 过滤（name / cause_of_action）、
"待立案优先"排序（无案号且在办 → 前，组内 id 倒序）。

这两件事和分页是**互斥**的：加服务端分页之后，前端 filter/sort 只作用于当前 50 行 ——
翻到第 2 页会冒出与关键词无关的行，"已立案"也会排到"待立案"前面。
**所以分页的前提是把过滤与排序先下推。**

## 后端（`apps/cases`）

`GET /cases/cases` 新增两个参数（不传时行为完全不变）：

| 参数 | 语义 |
|:--|:--|
| `search` | `name icontains OR cause_of_action icontains`，大小写不敏感 |
| `sort=filable_first` | 待立案优先：`status=active` 且案号为空（`IS NULL` **或** `=''`，防历史空串）排前，组内 `id DESC`；未知值按不传处理（不回 400） |

实现用 `annotate(Case(When(...)))` 出一个 0/1 排序键，而不是 `order_by(F(...))`：
谓词是「状态 + 案号为空」的**合取**，两个 `F()` 拼不出"同组内仍按 id DESC"，
且 `F("filing_number")` 还要额外拼 `nulls_first` 也覆盖不到空串。生成的 SQL：

```sql
SELECT ..., CASE WHEN (status = 'active'
                       AND (filing_number IS NULL OR filing_number = ''))
                 THEN 0 ELSE 1 END AS "_filable_rank"
FROM cases_case ORDER BY 21 ASC, id DESC
```

**`count_cases` 与 `list_cases` 走同一条过滤链**（`list_cases().count()`），否则
`X-Total-Count` 与分页对不上——这是这类改动最容易出的错，专门写了反向用例钉住。

## 前端（`features/bank-litigation`）

- `listCases({offset,limit,search,sort,withTotal})` → `{rows,total}`：为读
  `X-Total-Count` 把链式 `.json()` 改成先拿 `Response`；头缺失/非数字时 `total`
  退回本页行数（**不当 0**，否则单页数据会渲染成"没有案件"）。
- 页面：`PAGE_SIZE=50`，关键词 **300ms 防抖**且变化时**页码回 1**；两种空态
  （真没案件 / 有关键词没匹配 + 清除）。
- **翻页不闪白**：`useLoad` 重载时保留旧 `data`，所以 `data === null` 才是首次加载
  （走骨架）；有旧数据时保留列表 + `aria-busy` + `opacity-60`，翻页按钮禁用。
  理由：退回骨架 = 整块列表消失再长回来，视线和滚动条都跳；降透明度对"数据还是旧的"
  有正确暗示。
- **骨架与真列表同源**：抽出 `CASE_ROW_COLUMNS`（表头 / 真行 / 骨架三方共用，原先
  表头与行各写一遍列宽，是漂移点）与 `CASE_ROW_SHELL`；表头抽成 `CaseListHeader`，
  **骨架也渲染它**——不画的话数据到位时表头（~29px）突然出现会让整块下移。
- **页码越界回夹**：数据被别人删掉后 `page > totalPages` 时回夹到最后一页，而不是
  落到"还没有案件"空态（明明还有数据）。只在请求落定后判，避免 loading 中拿旧 total
  多打一次请求。

## ⚠️ 顺带发现一条护栏盲区（假绿）

`make openapi-refresh` 对本次改动报 **"一致"**，但新增的 `search` / `sort` 根本没进
`openapi.json`。原因：`scripts/check-openapi-fresh.sh` 的摘要只比 **paths** 与
**components.schemas 的属性**，**不比 query 参数** —— 参数级漂移无人拦。

本次手工补（`chore(openapi)` 提交）：从干净树导出，只把两个参数对象合进现有产物
（**不整份覆盖**：插件子模块在 worktree 里不生效，整份导出会丢掉插件注册的 15 条路径
—— 实测 637 → 622），再重生成 TS 类型。护栏本身未改，已写进提交说明作为待办。

## 已知取舍

- **无请求取消**：翻页时上一页在飞的请求不 abort，只靠 `alive` 丢弃结果（浪费带宽、
  不出错）。要做得干净得给 `useLoad` 加 `AbortController`，属独立改动。
- **翻页失败会丢旧行**：`useLoad` 失败时 `data: null` → 整表被 `ErrorBlock` 替换。
  共享 hook 的既有契约，本次未改。
- **页码不进 URL**：刷新后回到第 1 页（与 workbench 的分页同口径）。要做 URL 同步是
  另一次改动（`?page=` + 前进后退）。
