# v27.19.3 · 前端 AI 助手深度改造：可溯源、可审阅、可追责

> 分支 `feat/copilot-assistant-upgrade`（`main` 之后 **27 个 commit**）。
>
> 本分支由两段组成：**前 8 个 commit**（更早会话）把交互手感补齐（问答卡、停止不毁状态、
> 错误提示、草稿持久化…），**后 19 个 commit**（本轮）做四件更底层的事——
> 让 AI 说的话**能回溯到材料**、让它改的文书**能看出改了哪一句**、让失败**能说清原因**、
> 让四个 agent 的成本**能横向比较**。
>
> 前置：`v27.19.0~v27.19.2` 建成了多 agent 并答（pi / dsh / openai-agents，2~4 栏）。
> 本版把它们**从「能并排显示」推到「能被人真的用起来」**——两者之间的差距，几乎全是
> 「数据在链路上某处被丢掉了」。

## 后端

### 一、契约从「手抄模板」改成「反射生成」

原先契约有**三个源**：pydantic 模型、手抄的 TS 模板字符串、以及真正发事件的运行时。
实测三者**各自漂移且方向一致地落后于运行时**——模板与 pydantic 逐字段一致（差集 ∅），
但 `multi.py` 每条中间帧都在补 `agent` / `agents` / `reason`，契约里一个都没有。

所以「把生成器改成反射」单独做并不能治漂移，配套的是两层：

- `generate_ts()` 遍历 `model_fields` 渲染（含注解→TS 映射与可选性判定）——字段名与
  可选性只剩一个来源；
- `test_sse_contract_same_source.py`：生成物与仓库里的 `sse-events.ts` **逐字节一致**
  ＋ 每个事件类必须声明 `agent`/`run_id` ＋ `finish_reason` 可达集合。

`_RunScoped` 公共信封（`run_id` + `agent`）让 13 个事件类统一继承。这不是新增行为，
是把「三个后端每帧都在补这两个键」的既成事实写进类型——不写，前端就只能靠属性探测
绕过联合类型（`domain/dual.ts` 的 `agentOf`），而「这帧是谁发的」是多栏分流的唯一依据。

新增 `UnknownEvent`：dsh 会透传未识别的上游事件，不声明它就只能让一个未声明的
`type` 悄悄穿过 `parseSseEvent`（那里只做类型断言，不校验）。

### 二、`pi` 从不发 `done` → 水位永远是 null

`bridge.stream_events` 收到 pi 的 `agent_settled` 直接 `return`，而 `pi_backend` 取水位的
触发点是「收到 done」。那条分支**永不执行**：`result_for(run_id)` 恒 None →
`AgentRun` 记空模型 → `/stats` 的 `context_*` 恒 null → **前端水位条从来没亮过**。

改法：bridge 在 `agent_settled` 处发一个**内部标记** `settled`（不是 done），
`pi_backend` 收到后取一次 `get_session_stats`（此时 pi 进程还活着）、写好收尾事实、
**不转发**、结束。线上仍只有一条 done——由编排层发，那里才知道落库主键与会话级水位；
两个都发会把多栏「每栏各一条」的计数打乱。

### 三、具名错误码：typed error 投影，不是全局枚举表

参考 magpie 的做法（`internal/gui/api.go` 的 `fail()`）：它在每个 domain 定义 typed
error 结构体，HTTP 边缘用 `errors.As` 投影成 `code` + 一堆可执行参数，**没有**全局
code 表。这里照做——`apps/agent/errors.py` 定义 typed exception，发事件处投影。

`ErrorEvent` 加 `code` / `scope` / `detail`。纪律写进注释：`message` 可以改、`code`
一旦发出不能改语义。`test_error_code_registry.py` 守住「每个 code 都有 scope 与至少
一个可执行 detail 键（或显式声明无需）」，防止退化成又一句英文句子。

### 四、逐句溯源：`citations` 事件 + 落库

- `CitationRef` / `CitationsEvent`（`_RunScoped` 子类，每栏各带 `agent`/`run_id`）。
- `services/chat/citations.py`：把**检索类工具结果**投影成引用。只对确实带结构化定位
  信息（`name` + `page`/`chunk_id`/`clause`）的结果产出；纯文本结果一律不产出——
  渲染一个点开报错的角标，比没有角标更糟。
- 落库 `AgentMessage.metadata["citations"]`，历史回放靠它重建角标。
- `pi/AGENTS.md`（系统提示词）：答案里每条事实性陈述标注 `[K<编号>]`，无法标注来源的
  句子写成「未在材料中找到依据」。

### 五、分栏用量落库

`stream.py` 写 `metadata["usage_by_lane"]` + `metadata["ttft_ms"]`。此前
`turnStatsByLane` 只活在内存、每轮清空，所以「哪一栏更贵更慢」只在最后一轮成立——
多答的核心卖点在产品上是临时的。

### 六、`run_id` 真递增

`run_id = {session}:{kind}:{turn}` 原先恒 `:1`，跨轮不唯一 → 前端无法按 run 归集。
改用 Redis `INCR`（按会话），Redis 不可用时回落 `:1` 旧行为，不让对话失败。轮次在
编排层取一次再逐栏传下去——各栏各自 INCR 会让「同一轮」拿到不同 turn。

### 七、`core`：qcluster 收尾期死锁 + Redis 队列深度恒报 0

- 解释器已进 atexit（`p.join() -> os.waitpid` 持有 `_waitpid_lock`）时再来 SIGTERM：
  django-q 的 `sig_handler → Cluster.stop() → sentinel.join()` 在同一线程二次 acquire
  不可重入 SemLock → **永久死锁**。后果不是崩溃而是静默僵死：进程活着、心跳消失、
  worker 全死、队列只进不出，且对后续信号免疫（只能 SIGKILL）。
  修法：`sys.is_finalizing()` 为真时不碰 `Cluster.stop()`，恢复 `SIG_DFL` 并重发信号。
- `cluster_status().queue_depth` 无条件下 `OrmQ.objects.count()`，而 Redis broker 的
  排队任务不在那张表 → 现场堆了 296 条、状态卡片显示 0。改为按真实 broker 取。

## 前端

### 一、逐句溯源（`[Kn]` 角标 + 引用卡）

- **切片段放 domain**（`splitCiteSegments` 委托 `parseCiteMarkers`），渲染层只负责把
  片段画成节点。若渲染层自己再写一套 `\[K\d+\]` 正则，规则就会和数据层分叉——出现
  「同一句里有的 `[K1]` 是角标、有的还是纯文本」（渲染层拿到的是被 `**`、行内 `code`、
  表格单元拆开的**文本节点**）。
- 不写 remark 插件、不用 `dangerouslySetInnerHTML`：只接管正文容器，递归遍历 children。
  `code`/`pre`/`a` 明确跳过——代码里的 `arr[K1]` 是代码，不是引用。
- 流式半截（`[K`）整段降级为纯文本，闭合后再包角标；否则角标会闪现又消失。
- 只认后端分配过的编号：模型乱标 `[K9]` 时**不渲染角标**。
- 措辞诚实：`pageSpanNote` 区分「PDF 物理页」与「docx 解析分段」，后者写「第 N 段」——
  写错会让律师去翻纸质卷第 3 页而翻不到，那是合规风险。

### 二、修订可见（`domain/diff.ts` + `DiffBlock`）

`rewrite_folder_file` 的 `original` / `replacement` 全文**只在 `tool_call.arguments`
里完整到达**（`tool_result.result` 被 SSE 截到 2000 字）。所以 diff 只能从参数算，
纯前端还原、零新增请求。产出与 unified diff 同形的 hunk；超 250k 格不猜，退化成
「整篇替换」并置 `truncated` 让 UI 明说。

### 三、`@` 引用（一条管线服务四类对象）

识别是纯函数（词边界 + 邮箱/URL 豁免），候选由可插拔 `MentionSource` 提供，`@` 与 `/`
共用同一套菜单与键盘裁决。四条必须照抄的行为：异步竞态用 `AbortController` + generation
门控、单源失败只掉自己那组、**组还 pending 时 Enter 显式空转**、IME 期间全部 pass。

**出站协议只有一份**：`outgoing.ts` 用唯一构造器 `mentionRefBlock` 生成
`[已引用文件：…]`，`transcript.ts` 的 `SENT_REF_RE` 反向解析。所以历史 chip 与实时
chip 同形——新增 `@` 只是多了一条通往同一协议的输入路径。

### 四、错误可操作（code-first）

顺序：`code` 命中 → 动作按钮由 code 决定；`code` 缺失/认不出 → 回落**保留的**中文
文案表（旧后端唯一手段）；都不中 → `unknown` 且**绝不抛**（前端有缓存、后端先上线，
「前端比后端旧」是常态而不是异常）。

### 五、流式健壮性（四条）

1. 单栏 `pendingTool` 驱动「正在查 XX…」——**不写进 `tools`**（那是多栏渲染槽，写进去
   工具行会渲染两份）。工具返回后置「已完成」而不是清空，否则「工具都回来了、正文还没
   到」这一档判不出来，而那正是最需要交代的时刻。
2. 少一栏 `done` 时按栏记账，收尾只标**缺 done** 的那几栏（不能连跑完的栏一起标中断）。
3. EOF 尾帧再解析一轮 + 冲流式解码器（服务端常直接关流不补 `\n\n`，尾巴可能正是 done）。
4. 「是否已报过错」与「是否截断」拆成两个独立事实；更具体的错误优先显示，但不吃掉截断。
   idle **只提示、绝不 abort**——工具运行期间后端没有任何心跳，超时会杀掉长工具。

### 六、消息级动作与选中引用

复制/评分从 `Bubble` 抽出成 `MessageActions`，「不可用」统一成 `aria-disabled` +
**具体原因**（「这条还没落库，刷新后可评分」而不是「不可用」）。原生 `disabled` 收不到
hover/focus，tooltip 永远弹不出来——界面上就是「按钮在、点了没反应」。

选中正文一段 → 浮条 `[复制] [引用到输入框]`；定位扣掉祖先滚动容器与输入框占位。

### 七、分栏用量

新增统一形状 `LaneUsage`（实时账与历史落库都收窄成它）+ 9 个纯函数。徽标
`≈48 tok/s · 12k tok · 缓存 62%`，`title` 给四桶 + 首字 + 总耗时 + 模型名。
**不显示金额**（后端没有 cost 字段，前端拿单价乘 token 必错）；数字缺失**整段不显示**，
不显示 `0` 或 `—` 堆一串。

### 八、会话导航与位置

- `noMoreHistory` 判据错误：`refreshHistory` 替换消息时不重算 → 250 条的会话翻到底后
  一次轮询刷新，按钮**永久消失**，最早那 50 条再也翻不回来，且全程无报错。
- 滚动位置按会话记忆：`{anchorKey, anchorTop, scrollTop}` 语义锚点（不是 scrollTop），
  存 per-session 内存 Map（不落 localStorage/后端——窗口尺寸相关的值跨设备同步只会跳到
  莫名其妙的位置）。

### 九、拆分与护栏

- `MessageList.tsx` 394 → **172 行**，按职责拆出 `message/`（Bubble 174 / ThinkingBlock 47
  / ListChrome 71）。行为零变化的依据不是目测：脚本从 `git show HEAD` 抽原函数体与新文件
  逐行 diff，唯一差异是 `const X` → `export const X`。
- `detect-secrets` 钩子不再整份清空 `.secrets.baseline`（见下节）。

## 已知取舍与边界

1. **「继续生成 / 重生成」只有判据、没有按钮**。`canContinue` / `canRegenerate` 已实现
   并测过（含旧数据两路兼容：旧行只有 `truncated`、没有 `finish_reason`），但**故意不接
   UI**——`send()` 会二次注入业务锚点，直接复用出站正文会重复注入。要接需要后端提供
   「按 run 重跑」端点。
2. **dsh 审批仍未接线**（`_APPROVAL_WIRED = False`）。这是此前已确认的决定（等 dsh SDK
   自带审批能力）。本版只把能力声明绑到这个常量，保证 `/backends` 不再对前端撒谎。
3. **金额永远不显示**。`AgentRun` 没有 cost 列，`/stats/lanes` 也不存在；前端拿单价乘
   token 必错（缓存价、阶梯价、provider 差异）。金额是后端的事。
4. **不引入虚拟列表**。吸底 + `view-transition-name` + prepend 锚点三者会同时被打掉；
   门槛是「>400 条 且 单条 >8KB 且 滚动帧 P95 >24ms」三条件同时成立。
5. **`finish_reason` 的 `cancelled` 不上 SSE**。客户端断开时生成器已被关闭，没有通道发
   `done`；它只出现在落库 `metadata` 里，给历史回放与「继续生成」判定用。
6. **`MessageList.tsx` 仍在软红线附近**（172 行已达标）；但 `store/turn.ts` 与
   `turn-handlers.ts` 是持续热点，下次改它们优先拆纯函数而不是加分支。
