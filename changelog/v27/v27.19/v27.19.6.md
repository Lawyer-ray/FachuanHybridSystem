# v27.19.6 · 项目笔记：A 律师的判断，B 律师接手就能用

> 分支 `feat/agent-shared-context`。**39 个文件 / +2049 −73**（后端 26 / 前端 13），
> 其中新增 14 个（含 2 个迁移、4 个测试文件）。
>
> 起因是一句常识问题：同一个团队 2-3 人办同一个案子是常态，A 跟 AI 把争点、策略、
> 被否掉的方案都捋清楚了，B 接手时却完全看不到——pi session 是**按会话、按人**隔离的，
> B 只能把同样的问题再问一遍。而「把 A 的会话挂给 B」是错的：B 会继承 A 的试错与偏见，
> prompt cache 前缀也会每轮变。

---

## 一句话定位

| 能力 / 问题 | 之前 | 现在 |
|:--|:--|:--|
| A 在会话里捋出的判断 | 只活在那一次会话，换人就丢 | 点回答下方的书签存成**项目笔记**，挂在项目/案件上 |
| B 接手同一项目 | 零上下文，只能重问 | 会话一开始就注入「本项目同事的判断」，带作者与时间 |
| 模型写的结论 | 与人工结论无法区分 | **必须人点一下**才升为「项目事实」（`confirm_` 前缀 → HIGH 审批） |
| 结论被推翻 | 只能删掉，历史消失 | `supersedes` 指针：旧条保留、不再注入，能回答「当时怎么定的」 |
| 案件会话的归属 | 只有 `case_id`，项目维度是空的 | 建会话时从 `Case.contract` 反查补上，项目页才拉得到 |
| 项目页看本项目 AI 笔记 | 没有入口 | 页头「AI 上下文」抽屉，事实/判断分两组、事实在前 |

## 链路（改之前先读这段）

```
写入  回答下方书签 → POST /agent/memory/notes
        └ 前端只有 sessionId，锚点由服务端按会话反查（前端猜锚点必然写错项目）
      AI 也可直接写：save_project_note / save_case_note（MCP 工具，MEDIUM 留痕）
确认  confirm_project_fact → POST /agent/memory/{id}/confirm（HIGH，人工审批）
注入  pi session_start → GET /agent/memory/snapshot?session_id=
        └ build_snapshot 按会话锚点取同团队成员的笔记
        └ 本项目已确认的事实(1200) → 同事的判断(800) → 个人(1600) → 团队(900) → 律所(700)
读取  项目页 → GET /agent/memory?contract_id= → 「AI 上下文」抽屉
```

三条不可动摇的设计约束（写进 `backend/apps/agent/README.md`）：

1. **锚点与作用域正交**：`scope` 回答「谁能看」（个人/团队/律所），`contract_id` /
   `case_id` 回答「属于哪个项目、注入到哪」。不给 scope 再加 `project` 档——可见性
   真相只有一份（`org_access["lawyers"]` = 同律师团队），加第二套迟早漂移。
2. **快照缓存必须带锚点与版本号**：不带锚点会把 A 案的快照发给 B 案；不带版本号则
   失效只能按人删一个 key，而同一律师现在有 N 个锚点变体（locmem 没有
   `delete_pattern`）。版本号把失效降级成「自增一个整数」。
3. **三层记忆查询排除锚点条目**：否则一条挂 A 案的笔记会同时出现在 B 案会话的
   「个人记忆」里——项目隔离失效，而且同一条会被注入两遍。

## 已知取舍与边界

1. **共享的是判断，不是谈话记录**。把 A 的 pi session 挂给 B，B 会继承 A 的试错与
   措辞偏见，且前缀每轮变、prompt cache 全废。所以只传结论。
2. **谁都能写、谁都能确认**（同团队）。没有审核闸，风险靠 author / 时间 / `supersedes`
   链的可追溯性兜——`superseded` 的旧条不删，被推翻的结论仍可回查。
3. **撤权不可回收**。律师换团队后，快照立即失效、下一轮不再注入；但他已经读到的内容
   收不回来。这是接受的代价（要回收就得「失效重放」，成本高且挡不住截图）。
4. **`Case.contract` 允许为空**（历史/导入案件）。这类案件解不出项目，笔记只能挂
   `case_id`；回填命令会把「案件未关联项目」「案件已不存在」分别计数，不猜。
5. **同一句话不重复建行**（`content_hash` 去重）。代价：同一句结论想挂到第二个项目上
   时不会新增行，只会给原行补锚点。真实场景里极少见，暂不为此改唯一约束。
6. **PII 未加闸**。项目笔记天然含当事人/案号，且每轮进 system prompt；策展闸门
   （`scan_pii_risk`）只作用于团队/律所层提升。**同团队可见**是本期确立的边界，
   跨团队传播没有任何通道。
7. **工具面不带 `DIRECT_TOOLS`**。写工具按既有策略走 `tool_search`（`create_/update_`
   同理）；靠 `AGENTS.md` 的路由让模型知道「有这个工具」，而不是把 427 个工具全塞进
   每轮上下文。
8. **`confirm_project_fact` 用 `confirm_` 前缀**是为命中 `DANGER_PATTERNS` 判 HIGH。
   改名 `promote_to_fact` 会被判 LOW + `readOnly=true`（pi 免审批、前端显示只读徽标），
   等于模型替律师签字——这是本轮唯一一处「名字即安全策略」的地方。
