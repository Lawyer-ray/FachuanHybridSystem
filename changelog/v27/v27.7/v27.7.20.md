# v27.7.20

OA 立案表单必填项漏填修复（实测一份「执行异议之诉」案由的合同立案暴露）：业务种类与客户本案联系人均为带红 `*` 的必填项，但脚本提交后仍为空。

## 后端

#### 修复

- **业务种类（含业务子类）为空**：`_CIVIL_KINDTYPE_RULES` 只覆盖 10 类实体纠纷关键词，「执行异议之诉」「第三人撤销之诉」等**适用特殊程序**（`KindType03_10`）的案由不含任何已有关键词，`_map_kindtype` 直接返回空串。
  - 补齐 17 条特殊程序关键词（执行异议之诉 / 执行异议 / 第三人撤销之诉 / 选民资格 / 宣告失踪 / 宣告死亡 / 认定公民无民事行为能力 / 认定财产无主 / 监护权特别程序 / 督促程序 / 公示催告 / 申请保全 / 仲裁程序案件 / 海事诉讼特别程序 / 申请承认与执行 / 特别程序 / 特殊程序），并**排在最前**——这类案由自带「诉」字，若排在「合同/协议」等泛化词之后会被误吞
  - 民事案由仍未命中任何关键词时兜底 `KindType03_04`（合同、无因管理、不当得利纠纷）并记 warning，不再留空卡住必填项；兜底只影响一级分类，用户仍可在 OA 页手改
  - 业务子类由 `_resolve_kindtype_sed` 运行时拉取匹配，本次现产出 `KindType03_10 适用特殊程序案件案由` → `KindType03_1013 执行异议之诉`
- **客户本案联系人（姓名 / 手机）为空**：两条链路各有独立成因
  - **HTTP 链路**：`pro_pl_*` 在服务端 HTML 里只存在于 layui 模板（`id="tempLinker"`），仅当用户点「添加」才渲染成真实 input，`_fetch_form_state` 抓取的 payload 中**永远没有**这些键——旧代码 `for field_name in payload if "pro_pl_name" in field_name` 一条也匹配不上，静默漏填。改由 `_apply_client_payload` 按客户行同一 gid 主动生成 `pro_pl_name_<gid>` / `pro_pl_phone_<gid>`，再由 `_apply_case_info_payload` 统一回填
  - **Playwright 链路**：`_set_select` 只设 `.value` 并发 change，对 `chosenselect`（Chosen.js 接管）的下拉不会重绘选中项，服务端也可能取到空值。新增 `_set_select_chosen` 追加 `chosen:updated`，category / stage / which_side / kindtype 三级级联全部切换
  - 联系人填写抽为 `_fill_case_contact`：先 `wait_for_selector` 等 layui 渲染完成（超时则手动触发 `pageLoad.loadLinker()`），赋值后回读 `names/phones` 数量与首值写日志，避免再次静默漏填
  - 姓名 / 手机缺失时按必填约定填 `/`
