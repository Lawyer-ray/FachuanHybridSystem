## 后端

#### 修复

- **确认日期后 404「任务不存在」，提醒却已写入**：`POST court-document/task/{id}/dates/confirm` 在 `confirm_candidates`（带 user、事务内已写提醒并提交）之后重读任务拿刷新后的 `date_confirmation_status`，这次 `get_task(task_id)` 没带 user。#553（10-19）给 `get_task` 加的归属过滤对 `user=None` 走普通用户口径——`created_by_ownership_q(None)` 生成 `created_by IS NULL`，只放行存量无归属的旧任务——自己创建的任务必然取不到，响应阶段抛 NotFoundError。表现为提醒已落库、候选已 confirmed、前端却收到 404 弹「任务不存在」且界面不刷新，重试走幂等分支后再次 404。修复：重读与确认共用同一 `user`。全库仅此一处 `get_task` 漏传
- **仲裁委 / 行政机关字号被重拼成「（20XX）〕第N号」**：`_case_number_mixin` 两条正则都按法院案号「（年份）法院代字…号」设计（年份在前）。劳动仲裁文号「X劳人仲案字〔20XX〕第N号」（代字在前、括号 〔〕）落进无括号兜底模式，匹配出 year=20XX、代字=「〕第」、seq=N，再按法院格式重拼成残缺值；位置打分又选中文首的**文号**（X劳人仲**通**字，开庭通知书自己的编号）而非「案号」标签后的**案号**（X劳人仲**案**字）；LLM 给出正确值却被「以正则为准」压掉。修复：①新增机关字号模式「左界 + 代字(≤12 字) + 〔年份〕 + 第?N号」，原样重拼保留 〔〕 与是否带「第」（深圳式「深劳人仲案〔2024〕1234号」不擅自补第）——代字与标题之间常无任何分隔（VLM 原文「…开庭通知书X劳人仲通字〔2026〕…」），以「案号/文号」标签、标点或标题尾字「书」为左界防止把标题吞进代字；②兜底模式字符类排除 〔〕，机关字号的年份不可能再被按法院结构重拼；③打分加「案号」标签 +50、通字/函字/公告字等文号类代字 −20；④括号归一化补 [ ] / ［ ］ → 〔 〕（OCR 变体），`_normalize_case_number` 对机关字号把年份括号统一成 〔〕（LLM 常回 `()`，与正则对齐后交叉校验不再误报不一致）。法院案号三种写法、年份在前的「（20XX）京仲案字第XXXX号」、引用句式降权行为全部不变。对本次真实原文现产出「X劳人仲案字〔20XX〕第N号」形状的完整案号（与系统内该案件登记案号一致）——意味着下次同类文书自动匹配案件可直接命中，不必再转人工

## 前端

#### 修复

- **记一笔文书识别永停「正在上传文书…」**：v27.2.18（#527）把 `useRecognize` 的 `cancelled` ref 换成 `usePollSession`，旧实现的 effect setup 会把 `cancelled` 复位、cleanup 置位（可逆），新实现的 cleanup 直接 `session++`（不可逆）。开发态 StrictMode 对新挂载组件把 effect 跑成 setup→cleanup→setup；识别弹窗按需挂载（每次打开都是全新 mount），其提交 effect 用 `submittedFile` ref 防重，第二次 setup 不会再提交，于是唯一那次上传返回时 lease 已 stale，命中 `if (lease.isStale()) return` 后 phase 永停 `submitting`。现改为 `unmounted` 标志：setup 复位、cleanup 置位，`isStale = 会话号不符 || unmounted`——StrictMode 的假卸载可逆，真卸载仍让全部 lease 失效并唤醒挂着的 sleep。生产构建无双调用不受影响，但本机 5090 开发态自 10-04 起该路径一直不可用
- **`usePollSession` 返回对象引用稳定**：原来每次渲染都返回新对象，消费方 `useCallback(..., [pollSession])` 的 `submit` 跟着漂移，弹窗以 `submit` 为依赖的提交 effect 每次渲染都重跑（此前仅靠 ref 防重兜住）。现 `useMemo` 钉死，三个消费方（recognize / doc-parse / converter）同时受益
