#### 优化：诉讼地位行按判决书顺序分行展示

- 现状：地位行按后端返回的出现顺序单行流水排（386 上是「被告 … · 原告 … · 第三人 …」），和判决书的叙述顺序相反
- 修复：`legalStatusGroups` 分组后按 **STATUS_RANK** 排序——原告 / 上诉人 / 申请人 / 申请执行人 / 异议人等主动系在前，被告 / 被上诉人 / 被申请人 / 被执行人居中，第三人 / 原审第三人靠后，未知地位殿后保持出现顺序（`Array.sort` 稳定）
- 布局：地位行从「·」串联的单行改为**一行一个地位**（列布局），和判决书「原告：…／被告：…／第三人：…」的读法一致
- 测试：新增乱序输入的排序用例（被告 / 第三人 / 原告 → 原告 / 被告 / 第三人，未知地位殿后保序）；workbench 88 例 / tsc / ESLint 全绿；真实 Chromium 复核 386 案件卡三行按序
