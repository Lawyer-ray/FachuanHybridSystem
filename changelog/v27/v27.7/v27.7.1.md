# v27.7.1

pre-commit 新增**大模型隐私复审**：正则看不见的孤立人名、无后缀机构名、门牌级地址、执业证号，交给已配置的 kimi 复审；分片并发吃满多 key 配额，模型不可达一律放行。

## 工程化（backend/devtools/security_guard.py）

#### 新功能：`--check llm-privacy` 大模型隐私复审

- **补正则盲区**：正则闸门（v27.6.9）靠模式匹配，孤立出现的人名、无标准后缀的机构名、不带省市链的门牌地址都看不见——这些正是截图实测最容易带进 changelog / 夹具的东西。现在把含中文的新增行送 LLMProvider 表配置的模型（当前 kimi-2.6）做人工级判读，命中按同一口径拦截，输出「文件:行: 大模型判定疑似姓名「…」——理由」
- **只送该送的**：候选 = staged 新增行中**含中文**且未带 `privacy-allow` 标记的行；纯代码 / URL / 数字行不送（不含人名机构名，省 token）；复用隐私正则的跳过规则（锁文件、生成物、案由词库）；上限 400 行 / 24k 字符，超出只审前段并提示
- **分片并发**：按 60 行一片切分，线程池槽位 = Σ 启用平台的（每 key 并发 × key 数）（kimi 单 key 限 3 并发，多配 key 槽位自动叠加，上限 12），走后端进程级 `KeyPool` 轮转 key、不额外记账；实测 150 行 → 3 片 × 3 并发 4 秒跑完（含 Django 启动 2 秒）
- **确定性兜底**：模型偶尔一边写「含甲方虚构名应放行」一边照样输出条目——证据符合脱敏规则（某 / 甲方 / 张三 / 测试…）或理由里自己说「放行 / 虚构 / 示例」的条目一律丢弃；`privacy-allow` 标记对两道闸门同时生效
- **永不挡住离线提交**：Django 初始化失败、模型异常、JSON 解析失败、单片失败、整体超 60 秒，全部**放行并打一行提示**（hook 以 `verbose` 注册，提示始终可见）；`FACHUAN_LLM_PRIVACY=off` 可临时关闭
- 实测：8 行正例命中虚构人名 / 门牌地址 / 无后缀机构 / 执业证号 4 项，张三 / 李四测试 / UI 文案 / 甲方公司放行；三条放行路径（开关、初始化失败、无暂存）各自给出明确提示

#### 配套

- `backend/devtools/llm_privacy_hook.sh`：pre-commit `language: script` 入口，用 `backend/.venv` 的 Python（要读 LLMProvider 表）；没有 venv 的机器（CI、新同事）直接放行——隐私正则闸门仍然生效
- CI 不跑这一步（kimi 网关在飞连内网，GitHub Runner 不可达），本地 pre-commit 是它的唯一执行位
- 新增 CLI 输出改用 `sys.stdout.write`，不触发「禁止新增 print」hook
