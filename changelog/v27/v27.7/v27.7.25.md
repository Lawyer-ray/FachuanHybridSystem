# v27.7.25

## 后端

#### 修复

- `apps/agent` 安全与稳健整改（复审清单第一批）：
  - **pi 内置工具不再向模型声明**：启动参数加 `--tools "mcp__fachuan__*"`，内置 read/bash/edit/write 全部剔除（此前它们不在审批清单内，工具输出中的提示注入可免审批在服务器执行命令；参数已真机握手验证）。
  - **审批 extension 缺失改为 fail-closed**：此前仅告警后继续，等于高危工具裸奔；现在拒绝启动 pi 进程。
  - **stderr 持续消费并记日志**：此前 `stderr=PIPE` 无人读，pi 写满管道缓冲（约 64KB）会整体卡死；现在逐行记入 `pi stderr` 日志，extension 加载失败一类问题有迹可循。
  - **临时工作目录用完即删**：每请求工作目录含 models.json（真实 API key），此前只在 Django 重启时批量清理，磁盘与密钥材料无限堆积。
  - **send_message 会话归属过滤**：补上与其他端点一致的 user 过滤，堵横向越权（任何登录用户可向他人会话发消息并接收其 SSE 流）。
  - **审批决定归属校验**：`/approval/{id}/decide` 仅会话所有者或超级用户可操作；`/approvals` 非超级用户仅见自己会话的记录。
  - **`FACHUAN_INTERNAL_TOKEN` 未配置时仅 DEBUG 放行**（非 DEBUG 一律拒绝），已配置时改常数时间比对（`hmac.compare_digest`）。
  - **审批等待者先登记后广播**：根除「用户决定先于 register 到达 → 超时分支把已 approved 记录覆盖成 timeout」的竞态。
  - mypy 修复：`shared_mcp.py` 补 `Any` 导入（此前 CI changed-files 门必红）。
- `apps/agent` 事件翻译两处修正：
  - `DeltaTracker` 水位在每条 assistant 消息边界（`message_start`）复位——工具循环中第二段文本比第一段短时不再被旧水位整段吞掉；
  - assistant 消息同时带文本与工具调用时两者都发（此前 `tool_call` 事件被文本增量吞掉，前端看不到工具在执行）。

#### 新功能

- `apps/agent` 多轮对话与系统提示词：
  - 历史回放：pi 每请求新进程无记忆，新增 `services/history.py` 把 `AgentMessage` 历史渲染成 transcript 附在 prompt 前（30 条窗口 / 单条 4000 字截断 / 总预算 24000 字超限丢最旧）；本轮助手文本与工具结果在流结束时回写消息表，多轮上下文与审计闭环成立。
  - 系统提示词：新增内置 `pi/AGENTS.md` 模板（法穿法律助手人格、只认工具返回事实、高风险操作需审批等规范），写入每个会话的工作目录（pi 无条件读取该文件）；可用 `FACHUAN_PI_AGENTS_PATH` 覆盖。
  - 模型按请求解析：`--model` 与 models.json 同源取自 LLMProvider 当前值，Admin 修改默认模型即时生效，不再有池级缓存失配。

#### 优化

- 进程池重写为「每请求进程 + 并发闸门」语义：删除 `_take`/`_give_back`/空闲队列等不再使用的复用路径（复用会串审批路由与跨用户上下文），文档同步重写。
- `event_bus.redis_cache_enabled()` 成为 Redis 可用性的唯一判定（approval 侧去重复制）；共享 MCP 自动拉起的 stderr 落 `/tmp/fachuan-shared-mcp-<port>.log`（此前 DEVNULL，启动失败无从诊断）。

#### 测试

- `tests/ci/unit/agent/` 25→39 例：新增工具限制红线、extension fail-closed、多事件翻译、水位复位、transcript 渲染（包壳/截断/丢最旧）、AGENTS.md 写入与覆盖、审批归属判定。
