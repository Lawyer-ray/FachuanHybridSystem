# v27.7.7

新建合同页「律所ID」旁新增「同步」按钮（2026-10-19）：填好律所ID（OA 案件 GUID）点一下，用当前登录人自己的律所 OA 凭证读取该案件详情，自动回填合同名称、合同类型、开始日期、代理阶段、收费模式与律师费金额、律所OA链接、当事人（委托人 + 对方）与承办律师。纯 HTTP 后台抓取、不弹浏览器——OA 详情页 `projectView.aspx` 的客户信息 / 案件信息 / 利冲三个 tab 是服务端一次性渲染在同一份 HTML 里的，一次 GET 即全量，无需「打开页面再切标签」。真机实测含完整会话自愈 4～5 秒出结果。

## 后端

#### 新功能

- `JtnCaseGuidScript.fetch_project_detail(keyid)`：按 GUID 直达详情页并复用 `case_import.html_parser.parse_case_detail_html` 解析三 tab；会话复用「查询ID」同一套三层自愈链（磁盘 cookie → 飞连本机客户端一键登录 → 网关回调 → OA 账密登录），中途失效整体重试一次；keyid 经 `uuid.UUID` 规范化（非法直接返回 None，一个请求都不发，防任意字符串拼进 URL）；lxml 对任何页面都能解析出空壳数据，故至少含案件名/编号或客户才判定为真拿到详情
- `CaseGuidLookupAdapter` Protocol 新增 `fetch_project_detail`，`JTNAdapter` 薄委托；`ScriptExecutorService.fetch_oa_project_detail(keyid, user)` 按请求者本人凭证装配、`run_coro_sync(timeout=60)`、异常统一转友好文案，拿不到详情抛「律所ID 无效或当前 OA 账号无权查看」业务错误
- `contracts/services/.../oa_project_sync_service.build_sync_payload`：OACaseData → 表单回填 JSON 纯函数——合同类型沿用案件导入口径（案件类别优先、业务种类兜底，复用 `map_oa_case_type_from_text`，收敛为纯字符串 value）、收案日期多格式归一 ISO、名单按名去重保序、详情 URL 拼装；不落任何 Client / Lawyer 数据（新建页合同尚未保存）
- **收费回填**（真机用真实案号验证后补全）：解析「委托合同信息管理」tab（`tab_con_5`）的「收费方式 / 合同总额 / 币种 / 是否免费或减免代理」，`OACaseInfoData` 新增 4 个可选字段；「定额 / 固定 / 包干」→ 固定收费、「半风险」→ 半风险、「风险」→ 全风险、有值无命中 → 自定义并把原文写进自定义收费条款；合同总额归一两位小数，OA 未填的 0.00 不填
- **代理阶段回填**：OA「案件阶段」按 `CaseStage` label 精确优先、最长 label 包含兜底映射（「行政复议」→ `administrative_review`，「重审一审」不被「一审」抢先），对不上则不填
- `ContractAdmin.sync_oa_project_view`（路由 `sync-oa-project/`，仅新建页）：405/403/400（非 JSON / 空 / 非 UUID）门槛与 `ok/error` 约定同「查询ID」，成功返回 `{ok, data}`
- `contracts/js/oa_project_sync.js`（新建页注入，变更页不出现）：成功静默内联汇总、失败红字不弹窗；普通字段 / 收费模式 select / 代理阶段多选（追加选中不清已有）赋值后派发 change 让既有联动照常；当事人（委托人 ← 客户信息，对方 ← 利冲，随行展示法律地位）与承办律师（← 案件负责人）经 admin autocomplete **精确同名**匹配本地库后填 inline 行（先注入 option 再赋值再派发 change，跳过 `__prefix__` / `.empty-form` 模板行，无空行自动增行，已选同一客户不重复），库中无同名记录只提示不新建；承办律师自动勾选主办

#### 修复

- `case_import/html_parser.extract_conflicts_from_html`：真实 OA 利冲 tab 是**列式表格**（分组标题「▼类别：对方当事人　法律地位：被告」+ 表头「序号|客户类型|中文名称|英文名称|…」+ 数据行），旧实现按「标签-值」两两配对读单元格，把表头里「中文名称」后面的「英文名称」四个字当成了对方名称——案件导入会因此建出一个叫「英文名称」的客户。现按表头定位列、取分组法律地位为 `conflict_type`（缺失退回「客户类型」列），旧键值对结构（单测夹具 / 其他形态）保持原行为

#### 已知边界（真机核实）

- OA 详情页（PROJECT002 视图，含全部 10 个 tab）**不展示案件编号**，案号只在列表页有，且该案按案名 / 客户名反查列表页均无结果行——同步不回填案号，结果框明确提示手动填写「律所OA案件编号」；主流程「先填案号 → 查询ID → 同步」案号本就在手、同步不覆盖
- 每次同步都会走一遍会话自愈（`case_guid` 链路不写回磁盘 cookie 缓存，与「查询ID」一致），约 3～5 秒
- 对方当事人沿用 `case_import` 口径：利冲 tab 的全部分组（含「相关利益的潜在第三方」）都作为对方候选，法律地位随行展示供判断；承办律师只取「案件负责人」（真机核实「承办律师信息」tab 分配表与之同一人）
- 列表页搜索范围固定为「我的案件」，案号 / 案名 / 客户名只能查到当前 OA 账号名下的案件——换用主办律师本人的凭证即可查到
