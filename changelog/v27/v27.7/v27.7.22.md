# v27.7.22

图片自动旋转工具的角度处理修复：预览弹窗图片被裁掉一半；同根因波及工具页导出（被裁）与历史记录页导出（-90° 不转、90°/270° 反转）。

## 后端

#### 修复

- **预览弹窗图片被裁掉一半**（`image_rotation_utils.js` `renderModalPreview`）：ONNX 方向检测返回的是 `-90` / `-270`（`onnx_service.ORIENTATION_TO_ROTATION`），而「横竖互换」判定写的是 `rotation === 90 || rotation === 270`，负角度一律落到「未旋转」分支——canvas 按原图宽高比开尺寸，内容转 90° 塞进去，上下各裁掉一截只剩中间一条。缩略图侥幸没事：180×180 正方形 canvas 内「先适配再旋转」的矩形转置后仍在框内。新增 `normalizeRotation()`（任意角度 → 0 / 90 / 180 / 270，顺时针为正），缩略图 / 弹窗 / `getRotatedBase64` 三处渲染统一先归一再判定
- **工具页导出 ZIP / PDF 同样被裁**（`image_rotation_export.js` `getRotatedImageData`）：同一判定写法，-90° 图片导出到文件里的就是弹窗那条被裁的中段。改用 `U.normalizeRotation`
- **历史记录页导出：-90° 不转、90°/270° 反转**（`transform/image_transform.py` `rotate_image_for_output`、`transform/pdf_transform.py` `apply_rotation_for_pdf`、`facade._process_page_for_pdf`）：三处都是 `if rotation not in (0, 90, 180, 270): rotation = 0` 再 `img.rotate(rotation)`，两层问题叠加
  - ① 数据库 `onnx_rotation` 存的就是 ONNX 原值 -90，被当非法值**静默归零**，导出的图根本没转
  - ② 界面 canvas / CSS `rotate()` **顺时针为正**，PIL `Image.rotate()` **逆时针为正**，数值直接递给 PIL 就是反向（实测 200×100 左上角红块：rotation=90 后端转到左下，界面转到右上）
  - 新增 `transform/angles.py` 作为角度语义唯一归一点：`normalize_rotation()` 收口负角度 / 越过 360 / 非直角 / 字符串，`to_pil_angle()` 做顺时针 → 逆时针换算，三处消费点改用。MCP 工具 `export_rotated_pdf` / `export_rotated_images` 透传同一接口，顺带修好
  - 历史记录页两处 `rotation_N` 表单值也改为归一后的 0 / 90 / 180 / 270；后端对存量 -90 数据与归一后的新值均正确处理

#### 测试

- 新增 `test_rotation_angle_semantics.py`（32 例）：`normalize_rotation` / `to_pil_angle` 边界（负角度、越过 360、非直角、字符串、None）；用「左上角红块落到哪个角」钉死 **UI 顺时针**契约——`rotate_image_for_output` 七组、`apply_rotation_for_pdf` 四组角度的尺寸与方向；facade `_process_page_for_pdf` 对 -90 返回 270 不再归零。既有测试只断言 `isinstance(result, bytes)`，发现不了方向反转
- 验证：Playwright 真机探针（带红 / 蓝角标的 640×400 测试图）六个角度（0 / 90 / 180 / 270 / -90 / -270）弹窗 canvas 像素覆盖率 100%、红块方向全对；`getRotatedBase64(-90)` 导出 400×640 红块左下，与后端新行为一致。接口全拦截零落库，临时账号测完即删
