# v27.7.8

合同归档「从合同文件夹同步」全链路强化（以真实合同的一审+执行双阶段文件夹真机调试定型）：全局扫描、裁判文书案件信息提取、案卷封面占位符全阶段共存、执行结果提炼、委托材料去重与「清空结果」，外加三个真机暴露的缺陷修复。

## 后端

#### 新功能

- **全局扫描**：不选子文件夹＝扫描全部内容；「客户资料」目录默认跳过（当事人身份材料不属归档清单，需要时显式选中单扫）；子文件夹选择保留可选。扫描弹窗同步展示扫描范围卡片与当前目录
- **案件信息提取**：扫描完成后自动从裁判文书候选提取审级/案号/法院名称/主文——两层提取：判决书/调解书/仲裁裁决书/执行证书/执行裁定书/终本裁定全量提取主文；告知书/通知书/传票/决定书等程序性文书只补案号（执行等阶段的案号常只在告知书里出现），同案号优先保留带主文版本。确认导入时追加式回填关联案件：案号按 (案件, 案号) upsert 且只回填空字段（人工维护内容永不覆盖）、法院全称/简称后缀去重、合同无案件时自动创建——一审+执行多阶段共存。财保/执保/民保/行保等保全类程序编号不纳入提取；案号被 PDF 排版切开（段间空格）时整体去空白兜底再匹配
- **执行结果提炼**：执行阶段的程序性文书（执行告知书等）没有裁判主文，但正文常含实质执行结果——自动提炼摘要充当该案号的结果内容：含金额的扣划/发放句（须带已支付/发放/余款等发放语义，保全段落裸「扣划 N 元」不误选）＋终结执行/终本（优先）/尚未到位状态句，最多三句按文书原句顺序、超长句逗号边界截断
- **案卷封面占位符全阶段共存**：`案件案号`/`案件审理结果`不再只取 is_active 案号——全部审级共存，多条主文按【文书名】标注后换行分隔；`案件当前阶段`从全部案号类型字推断审级并与当前阶段合并去重、按程序序排列（如「一审、执行」）
- **AI 分类改「重新分类」**：按钮改为「重新分类（N）」，将全部材料视为未正确分类重新判定类别与归档清单项（scope=all）——误分类场景下旧「AI 分类未匹配项」恒为 0 永远禁用无法自救
- **「清空结果」**：同步弹窗一键清空合同全部扫描会话（只删扫描工作区，不动已导入材料与已回填案号；扫描进行中拒绝清空），确认后弹窗回到空白状态
- **工作日志补全完善**：反馈/费通知类事项自动补「收到」前缀（不再误用「提交」）；反馈类事项从告知书正文提取带金额的关键句附加（如扣划金额与余款去向）
- **委托材料族去重**：授权委托书（解除授权委托申请书除外）/法定代表人身份证明书/所函三族文书跨审级、跨格式（docx 草稿与签章 PDF）只保留最新一份，其余标「重复文书，已取最新一份」跳过——误放进来的他案同名旧文书也随「最新者胜」淘汰
- **对方当事人身份材料排除**：文件名含对方当事人名称且命中身份类关键词（身份/营业执照/证照/工商/报告）即标「对方当事人身份材料，无需归档」跳过；匹配前先剥离文件名内嵌的案件标题（所本命名惯例把含对方名称的完整标题写进几乎每个文件名，不剥离会误杀我方文书）

#### 修复

- **扫一审全判「合同正本」**：合同发票文件夹判定从整路径子串匹配改为分段匹配——末段视为文件名不参与、组合词（合同发票/合同及发票）包含式、单词（合同/合同正本/发票/补充协议/监督卡）剥离数字前缀后须整名相等；绑定根目录名含案由「…买卖合同纠纷一案」不再把全部材料误判为合同正本
- **扫描完成弹窗空、重开才见数据**：文件遍历结束时底层扫描服务发 progress("completed")，任务侧映射把它提前写成会话 COMPLETED，但后处理/工作日志/案件信息提取还要数秒才原子落库完整结果——前端轮询见 COMPLETED 即停并渲染空结果误报「未找到可导入的文件」。现 contracts 与 cases 两侧扫描任务的进度映射均不再提前置 COMPLETED（保持 RUNNING、进度封顶 99%），COMPLETED 只由最终带完整 payload 的原子落库写入
- **folder_scan.js 缓存版本号**（20260422a→20261020b）：4 月起版本号未随 JS 改动 bump，浏览器长期吃旧缓存导致新功能「时有时无」，普通刷新不救
- finance LPR 同步按钮权限修复（并行工作随车合入）：改用模型权限校验，不再撞只读策略恒 403
