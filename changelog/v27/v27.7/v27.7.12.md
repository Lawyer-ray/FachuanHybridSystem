# v27.7.12

## 前端

### 新功能

- 办案详情页案件卡新增「日志 / 文件夹」视图切换：案件绑定了文件夹时默认展示文件夹视图（逐层下钻 + 面包屑），手工整理的目录结构（如「2-邮件往来/2026.09.29-收到法院裁定书」）原样透出，与只含 AI / 系统写入记录的日志视图互补；未绑定的案件保持日志视图且不渲染切换。
- 文件夹视图内文件点击即新标签预览（经一次性下载票据，PDF / 图片 / 文本浏览器直开）。
- 案件日志附件从「📎 N」数字徽章升级为可点文件 chip，点击新标签预览。

### 修复

- 案件日志时间轴相同内容自动合并：合并组以最新一次的时间与位置叙事、附件按 id 去重取并集、标注 ×N——测试灌入的重复日志与法院短信重放不再刷屏。

## 后端

### 新功能

- 新增案件绑定文件夹只读浏览 API（`GET /cases/{id}/folder-entries`、`GET /cases/{id}/folder-file`）：逐层列子文件夹与文件（含大小 / 修改时间）、单文件内联预览；子路径规范化后收敛在绑定根内（拒 `../`、绝对路径、盘符、越界符号链接），案件行级 ACL 与文件夹绑定端点同款，危险扩展名（html/svg/js 等）强制附件下载。

### 修复

- 下载票据认证不再让行级 ACL 误拒：`?ticket=` 兑现成功后认证结果未同步回 `request.user`（ninja_jwt 的 Bearer 路径会同步），下游 `get_request_access_context` 读到 AnonymousUser 导致 ticket 打任何 ninja 业务端点都 403——此前 ticket 只用于 `/media/`（独立视图读认证返回值）故未暴露；现与 Bearer 同口径同步，并补回归测试。

### 测试

- 新增 `CaseFolderBrowseService` 单测 21 例（子路径规范化安全 / 目录枚举契约 / 绑定与 ACL 分支 / fail-closed）、下载票据认证同步回归 1 例、前端时间轴合并与文件夹视图 DOM 用例。
