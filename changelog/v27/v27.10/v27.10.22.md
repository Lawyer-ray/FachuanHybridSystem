# v27.10.22 — docx 直接在预览卡里编辑并保存（不再跳整页）

## 前端

#### 功能

- **docx 直接进编辑态**：右栏文档卡从 `mode="view"` 改为 `mode="edit"`，律师点开就能改，不用再点「打开编辑器」跳走。理由：看合同几乎总要先对照左栏的服务事项与右栏的期限/当事人，跳页就断了对照；4K 屏上右栏拉宽后编辑体验与整页无差别，省掉的是一次路由往返与上下文重建。
- **原地保存**：顶栏「保存」或 `⌘S` 触发文档服务器 forcesave，内容经 `callbackUrl` 回到后端 `adopt_edited` 覆写原文件。
- pdf / 图片等不可编辑格式仍走只读，且不给保存按钮（改完也存不回去，不做假按钮）。

#### 修复

- **保存点了没反应（文件纹丝不动）**：`OfficeView` 原来用 `editorRef.current.downloadAs('docx')` 取字节再上传，但社区的编辑器实例没有 `downloadAs`（实测 `Asc.editor` 上只有私有的 `forceSave*` 系列），外层也拿不到实例方法——返回 `null` 后静默失败。改为调用 DS 官方外部 API `serviceCommand({c:'forcesave'})`。
- **保存回调被拒（`{"error":1}`、DS 报「未知 document key」）**：`editor-config` 只在 `contract_review` 路径时建 `EditorSession`，合同文件夹的文件从不建会话 → 回调按 key 查不到 → DS 放弃保存。改为**凡注册过的业务域都建会话**；folder 没有业务 task_id，用 `uuid5(source_path)` 派生稳定 id（同一路径永远同一 id，否则每次签配置都算新 id）。
- **`_doc_saved_version` 跨业务域串号**：加 `task_type` 参数。folder 与审查任务的 id 可能撞（后者是路径派生的 UUID），不带域会把两边的保存轮次混在一起。
- **回写时多余的告警**：`_current_output_file` 只在 `contract_review` 有「旧产物」概念（另存新文件名），folder 是原地覆写，直接跳过。

#### 测试

- Playwright 真实保存验证（1920px，改内容 → 点保存 → 比对磁盘 md5）：
  - 修前：`md5 未变`，后端日志 `未知 document key` + `{"error":1}`
  - 修后：`md5 发生变化`，后端日志 `保存回写完成: task=... v1 -> 264:3-办案/.../<某合同>[修订版]V1_20261017.docx`
- 测试完成后已从备份恢复原文件。
- 单测：`FilePreview` / `FilePreviewCard` 更新为「保存走 forcesave」；`OfficeView` 句柄接口由 `getDocxBlob` 改为 `requestSave`。

#### 说明

- 保存**没有即时成功反馈**：落盘发生在 DS 回调里（通常 1–3 秒），所以提示语是「已提交保存」，并在 2.5s 后刷新列表读新 mtime。
- 另存为暂时移除：它需要拿到当前内容的字节喂给新文件，而社区版拿不到字节。等 DS 提供可用的导出 API 再加回。
