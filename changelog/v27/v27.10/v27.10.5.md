# v27.10.5 — 项目详情统一路由、文件夹视觉重做与页内预览

## 前端

#### 新功能

- **项目详情单一路由**（`ProjectDetailPage`）：`/projects/:id` 一条 URL，按 `deal.lit` 分流左栏——有法院程序走案件程序链、无走合同文件夹。此前非诉挂在 `/projects/:id/nonlit`，且 `DealDetailPage` 会把直达 `/projects/:id` 的非诉委托**悄悄重定向**过去，用户在地址栏看到 URL 自己变了却不知道为什么。`nonlit` 是 non-litigation 缩写，属实现分类而非用户概念，律师只知道「这是个顾问项目」。
- **页内预览卡**（`FilePreviewCard`）：点文件夹里的文件在右栏就地展开只读预览，**不离开当前页**。律师看合同时常要对照右栏的期限、当事人、收费——整页跳走或弹窗遮住都会让对照失效；关闭成本为零。真要改才点「打开编辑器」升级到整页（那里有分页、修订标记、批注栏的宽度需求）。
- **文件类型视觉标识**（`FileKindBadge` / `file-kind.ts`）：色块 + 扩展名文字（PDF 红 / DOC 蓝 / XLS 绿 / IMG 紫）替代统一的灰色 `FileText` 图标。合同文件夹里 80% 是 pdf/docx，同一种灰图标只能靠读文件名分辨，扫读负担全压给用户。用色块而非彩色图标是因为彩色 lucide 图标在 15px 下细节糊成一团，且 `FileText` 与 `FileSpreadsheet` 缩到 15px 轮廓几乎一样。
- **文件行选中态**：当前预览的那份用左侧竖条 + 浅底标示（`aria-current`），与 hover 区分——律师常要「看着预览、在列表里点下一份」，光靠 hover 无法表达「正在看的就是这份」。

#### 修复

- **非诉页同屏两份文件夹树**：左栏 Card 渲染一棵、`DetailRail` 里又渲染一棵（320px 高几乎没法用）。`DetailRail` 新增 `showFolder`，非诉传 `false`——文件夹是左栏主角，右栏不再画第二棵。
- **文件夹卡高度**：非诉左栏 `max-h` 520px → 620px，配合独占整栏的实际可用空间。

#### 测试

- `ProjectDetailPage.dom.test.tsx`（3 例）：lit=true 走诉讼页、lit=false 走非诉页、数据未就绪不崩。
- `FilePreviewCard.dom.test.tsx`（7 例）：只读画布、元信息、升级整页、docx 才有 AI 审查、收起、票据现换。
- `DealDetailPage.dom.test.tsx` 更新：断言不再重定向（分流已上移）。
- `App.dom.test.tsx` mock 对齐新导出（`ProjectDetailPageLazy`）。

#### 说明

- 页内预览**不写 URL**：它是高频「看一眼」，不该在浏览历史里堆记录；只有升级到整页编辑器才带 `?file=`。
- 页内预览**只读**：改动一律走整页编辑器或 AI 审查，避免同一个文件出现「页内改一半、整页改一半」的两套落盘路径。
- 诉讼页保持右栏小树（`showFolder` 默认 true）：那里左栏是案件程序链，文件夹作次要信息放右栏合适。
