# v27.25.4 · 多引擎分歧的判别式裁定（Jev）：能判的自动判，不能判的一次都不发

> **版本判定**：本 PR 内按功能分段记账的第三段，沿用 `v27.25` 的第三位顺延。
> 能力轴：**多引擎分歧裁定**（与 `v27.25.2` 的取字可靠性相邻但不同：那一版让取字更少出错，
> 这一版处理「两个引擎已经读出两个不同答案」怎么落）。

## 一句话

| 之前 | 现在 |
|:--|:-|
| 双引擎对照只能**报出**分歧，交律师逐页核对 | 分歧先过一次判别式打分器：能判的自动裁定并留痕，判不了的才进人工抽屉 |
| 所有字段一律送判 | **禁判域一次 HTTP 都不发**：证件号 / USCC / 银行卡 / 账号 |
| — | 判定**不删除任何分歧**：`accept` 也只加「已自动裁定 + 分数」标记 |
| — | 判定默认关闭；`ENABLED=1` 但没填 key 按未启用处理并 warning（否则每次去请求注定 401 的接口、白占全局并发位） |

## 为什么是判别式打分器，而不是「再识别一次」

`MiniCPM-OCR-Jev` 给「一张裁块图 + 一段候选文本」，返回这段文本是该图正确转写的概率。
输出空间被压成一个概率，没有生成模型的串行、错号、幻觉空间。

提交里记录的实测依据：

- **错配图对照**：prob_yes ≈ 1e-6（5/5 通过），排除了「它没看图、只给文本打常识分」这一替代解释；
- **合成样本** 36 组裁定 36/36；
- **真实扫描件裁块**：A-p18 案号 0.9461 vs 0.0005；A-p32 金额 0.9961 vs 0.0000。

## 四道「不许判」闸门（每条都有实测依据）

1. **`no_usable_box`**：无框 / 近似推出来的框 / 越界 / 反向 / 零面积；
2. **两侧框竖直不重叠**（并集会横跨两行）；
3. **两侧框高度比 > 2.5**（一行 vs 两行，粒度对不上）；
4. **`multiline_block` / `length_mismatch`**：多行块与长度悬殊的「分歧」判不出结论
   （实测多行块 3/3 落到 `prob_low`，白花两次调用）。

## 其他关键决定

- **只认相对比较**：`p(胜)/p(负) ≥ 10` 且 `p(胜) ≥ 0.05`。实测真值可以是 0.158、错值可以是
  0.58（形近字），**任何绝对阈值都会两头误判**。
- **并发上限 2**：实测并发 >2 立即 429 → 进程内全局信号量限 2 + 指数退避（0.5/1/2s 带抖动）；
  `content_policy_violation` 不重试，401/403 不重试。
- **禁判域不送判**：证件图像在可读分辨率下必被 `content_policy_violation` 拒，缩到能通过的
  分辨率 p 又低到不可判；这类字段的正确性靠 L1 校验位（Mod-11 / Mod-31 / Luhn），不靠模型打分。
- **案号必须判**：实测判定器能把它判对（误判成证件就等于让最该判的一类失效）。
- **旋转换算**：PaddleOCR-VL 会为识别把页转正，它报的框在转正后的坐标系里；按「用哪个引擎的框
  就把渲染图转同样角度」对齐，两侧角度不同则放弃判定。
- **fail-open**：任何异常都落到 `human` / `call_failed`，绝不让打分把上传主链拖挂。
- **留痕脱敏**：日志与 `snapshot()` 只留掩码（长度 + 前 8 字符）；卷宗里的姓名/证件号/金额不落日志。
- **key 走 `SystemConfig.OCR_JUDGE_API_KEY`**，禁止进代码。

## 说明与遗留

- 判定**默认关闭**（`OCR_JUDGE_ENABLED=0`）：关着时与引入本模块前逐位一致，分歧只进人工抽屉。
  任务级开关见 `v27.25.6`。
- 判定器只处理**单行字段级**分歧；多行块、长度悬殊的分歧按闸门 4 直接不判，这是它的能力边界，
  不是 bug。
- 千分比裁块层只收千分比四点（MinerU / DeepSeek rich / PaddleOCR-VL 同量纲）；越出千分比量级
  直接 `bad_bbox`——量纲混用在仓库里出过事故，本层不猜单位。
