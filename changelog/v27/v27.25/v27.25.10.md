# v27.25.10 · 审批注解表不再静默退化成空：插件自报的风险等级终于生效

> **版本判定**：本 PR 内按功能分段记账的第九段，沿用 `v27.25` 的第三位顺延。
> 能力轴：**审批分级的安全面**。这是本 PR 里唯一一个「改完之前一直在悄悄降级」的缺陷。

## 一句话

| 之前 | 现在 |
|:--|:-|
| 插件 `weike_advanced_search` 自报 `MCP_TOOL_RISK = {"...": "write"}`，却一直判 **LOW**——无审批、无留痕、`readOnlyHint=True`，而它实际发 `POST /legal-research/capability/search/mcp` | 判 **MEDIUM**（静默放行 + 审计留痕），与插件声明一致 |
| 注解表在启动早期建成**空表并落缓存**，之后整个进程生命周期内 `classify_risk` 只剩名字黑名单 | 空表**绝不落缓存**，下次调用重试；`list_tools()` 给空时退回同步读注册表 |
| 表建在插件注册之前，插件随后注册，缓存非空所以永不重建 → 该工具永远查不到，回退名字判定 | 缓存里没有 **且** 注册表里确实有这个工具 → 重建一次 |
| 护栏单跑必红、全量跑却绿（跑在谁之后决定表是空还是陈旧） | 隔离连跑两次全绿 |

## 两个根因

都在 `apps/agent/services/approval/annotations.py`：

1. **空表被缓存**。本模块当年为了同一个理由拒用 `lru_cache`——注释里写着「会把加载中/失败的
   空表一起记下来」——但空表自己照样被缓存了。空表意味着 `load_tool_annotations` 恒返回
   `None`，`classify_risk` 退回纯名字判定，**注解这一整层形同不存在**。
2. **缓存不会自愈**。表可能在「内置工具已注册、插件还没注册」的那一刻建好并缓存；插件随后
   注册，注解随之进来，缓存却是非空的（441 个内置工具），于是永远查不到那个插件工具。

这也解释了那条护栏为什么「单跑红、全量绿」——**绿灯取决于跑在哪个用例之后**。

## 改法

- `_sync_tool_snapshot()`：`list_tools()` 给空时退回同步读 `ToolManager._tools`
  （进程内活的注册表，无上下文依赖）。
- 空表**绝不落缓存** + 一条 warning；下次调用重试。
- `load_tool_annotations()`：缓存未命中 **且** 注册表里确实有该工具 → 重建一次。
  正常路径只多一次 dict 查找，重建是纯内存操作。

实测（本机）：表 **0 → 441** 条；`weike_advanced_search` 注解 `destructive_hint=False`
→ `classify_risk` = **MEDIUM**；`server._tool_annotations()` 与 `classify_risk()` 口径一致。

## 同一提交里修的第二条假绿

`tests/ci/unit/organization/test_registration_approval.py` 的 4 条「首位用户」用例：
**全量跑全红、单跑本文件全绿**——判据是「系统里没有已激活账号」，而上游用例会留下活跃账号。

第三条语义要守的场景）。

## 说明与遗留

- `_registered_now()` 只接 `ImportError`。其余异常照常抛——吞掉 `AttributeError` 会把
  「注册表结构变了」伪装成「工具不在」，而那个方向只会让审批更松。
- 这层修好后，**所有 441 个工具的注解第一次真正参与分级**。本轮全量单测没有因此出现新红，
  但「生产上分级结果与改造前不同」这件事本身需要在下次真机验收时再看一眼——
  尤其那些名字看不出来、靠注解才升到 MEDIUM 的工具，审计日志量会上升。
- 插件工具的风险声明现在真的生效了，反过来说：**插件作者声明错等级就会直接体现到审批上**。
  `plugin_tools` 的「不声明 = 高危」规则因此更值得遵守。
