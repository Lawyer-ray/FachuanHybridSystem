## 四块改动

### 一、凭据池 → 配额感知调度器（`services/credential_pool.py`）

这是「多账号免费额度」的地基。原实现的失败语义只有一个，导致额度耗尽的 key 被反复启用。

- **失败分档冷却**：transient 30s / auth（401·403）长冷却 / quota（429）冷却到下一个
  本地零点重置点；冷却取 `max`，不被后续瞬时失败缩短。
- **日配额记账**：`OCR_CREDENTIAL_DAILY_PAGES`，`acquire` 跳过已耗尽凭据，按
  `settings.TIME_ZONE` 的本地日期翻页。
- **跨进程共享**：状态经 Django cache（有 Redis 时多 worker 共享，LocMem 时降级为进程内），
  与进程内账本取**较坏值**；cache 失败一律降级、不打断主流程。
- **可诊断**：`snapshot()` 给每凭据 `cooldown_remaining / used_pages / exhausted`；
  额度跳过与全不可用各打一条 WARNING。
- **凭据不落日志**：cache key 用 sha256 摘要，日志只留脱敏尾号。

### 二、切批增加字节上限（`services/split/*`）

`PDF_SPLIT_CLOUD_BATCH_MAX_MIB`（默认 32）。超限批二分到合法大小；单页本身超限时
独占一段并告警——**宁可多一次请求，也不静默丢页**。

### 三、残余页接力下一个候选（`pipeline.py::_parse_cloud`）

原逻辑「任一候选返回非空即锁定」，但「空页 / 退化页」是拿到结果**之后**才判的，
所以第二候选永远接不到这些页。改为按候选轮次推进，每轮只处理上一轮未拿到可用结果的页。

保住六条既有不变量：退化页不写缓存、每批落盘、心跳、取消检查、`stats` 不重复计数、
候选不重复调用。

### 四、DeepSeek 修补页三修（`document_parsing`）

- 已修补页不进 `unrepaired` 复判：首跑遗留的 `finish_reason=length` 会把修好的勾选
  表单正文当成循环清空。
- rich 主模式对**所有页**解析版面块，不再只保留修补页的坐标。
- 单页重试先按主 purpose 原样重试；空返回不再一律切到更脆的 rich。

顺带一处：`pix.tobytes` 的返回类型显式标注，收口 mypy 的 `no-any-return`。

## 说明与遗留

- 分档冷却是**进程内账本 + 可选 cache 共享**；没有 Redis 的部署下，多 worker 的日配额
  仍各记各的（取较坏值只会更保守，不会超发）。
- 字节上限解决的是「整批 413」，不解决单页超限被拒——那种页只能落本地 OCR 兜底，
  目前没有更细的降采样策略。
- 本地 OCR 兜底本身仍只有「有没有字」一个判据；它自己开始复读时这一层抓不到
  （`page_degeneracy` 只用在云端结果与页缓存两处，见 `v27.25.1`）。
