# v27.0.1

## 后端

### 新功能

- **前端材料预处理上传进收件箱**：收件箱新增 `manual_upload` 来源，前端预处理上传入口 POST 多文件后统一收进收件箱，作为材料预处理的统一受理池。
  - 新增 `manual_upload_service.py`：手动上传文件落盘到 `message_hub/manual/` 暂存路径（相对 `local_path`，与 IMAP 附件同一套存储协议）；`ManualUploadFetcher` 支持按需读取已落盘附件，下载/预览复用既有链路。
  - `MessageSource.credential` 改为可空，手动上传无外部账号。
  - 新增 API：`POST /inbox/messages/upload`（multipart 多文件上传进收件箱）；`PUT /inbox/messages/{id}/draft`（保存拆分草稿，纯 UI 状态存储，语义归前端）；`GET /inbox/messages` 增加 `source_type` 过滤，详情返回附件信息。
  - `InboxMessage` 新增 `draft_state` JSONField 承载拆分草稿，支持碎片化时间多次续接拆分进度。
- **手动上传记录上传人**：`InboxMessage` 新增 `uploaded_by`（外键 `organization.Lawyer`，`SET_NULL`），上传接口从 `request.user` 写入当前登录律师；列表/详情输出 `uploaded_by_id`、`uploaded_by_name`（优先 `real_name`，回退 `username`）；列表查询 `select_related("uploaded_by")` 避免 N+1。

### 修复

- 修复手动上传 `message_id` 唯一性冲突：原来用秒级时间戳 + source_pk 生成，同一秒两次上传会撞 `(source_id, message_id)` 唯一约束导致 500，改用 uuid 片段修复。

### 测试

- 新增端到端测试 `test_inbox_manual_upload_e2e.py`：覆盖上传进收件箱、来源/上传人断言、列表筛选、详情、草稿存取续接、附件下载/预览、手动来源去重、未认证拦截。
- 新增单元测试 `test_manual_upload.py`：覆盖落盘、草稿往返、下载复用、来源去重。

### 结构变更
