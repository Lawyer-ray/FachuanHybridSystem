# v27.0.8

修复 django-q qcluster 退出阶段打印 `AttributeError: 'NoneType' object has no attribute 'set'` atexit 噪音、以及由此衍生的 worker 未干净拆机问题。仅后端，无前端改动。

## 前端

本次无前端改动。

## 后端

### 修复（qcluster 退出时 atexit AttributeError）

- core：`tasking/qcluster_shutdown.py`（新增）monkeypatch `django_q.cluster.Cluster.stop()`，修复其既不幂等也不可重入的缺陷。原实现无条件执行 `self.stop_event.set()`，而首次 `stop()` 末尾会把 `stop_event` / `start_event` 置 `None`；qcluster 主进程靠 `atexit → _exit_function → join → os.waitpid(sentinel)` 阻塞驻留，若此时再次投递退出信号（watchfiles 自动重启、双击 Ctrl-C、终端广播 SIGINT/SIGTERM），会再次进入 `sig_handler → stop()` 并命中已置 `None` 的 `stop_event` 报错。异常发生在解释器退出阶段，仅打印 `Exception ignored in atexit callback`，不崩溃但 cluster 未干净拆机
- core：补丁用 `threading.RLock` + `_fachuan_stopping` 标志实现重入短路（`stop()` 卡在 `sentinel.join()` 期间到达的后续信号在同一线程重入时立即返回，避免重复 join / 重复清尾），并以 None 检查做前置短路（未启动或已拆机状态安全返回），从根上杜绝 `NoneType.set()`
- core：`apps/core/apps.py` 的 `ready()` 中调用新补丁，复用 `tasking/qcluster_spawn.py` 既有的 macOS qcluster 补丁族模式——不落 venv、集中可测试；若上游未来修复此问题，补丁的短路分支自动降级为 no-op

### 说明（影响面）

- 该缺陷是 macOS 开发环境下 `qcluster` 每次通过 Ctrl-C / watchfiles 重启时的常见路径，连续两个退出信号叠加即触发
- 故障表象仅为退出阶段的一行 `Exception ignored` 噪音，但底层意味着 spawn 出的 worker 池可能未被级联回收，残留为 PPID=1 孤儿进程、以旧模型代码抢占任务队列，表现为间歇性且与代码/迁移/DB 均无关的诡异报错
