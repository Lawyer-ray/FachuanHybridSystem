# v27.23.5

关键日期候选加「出处」与五道闸门：修掉通用送达文书编造假日期的事故（告知书 85% 假期限），并把「默认勾选」的策略从裸置信度搬到后端。

---

## 事故

法院短信（一条送达、8 份文书）里，《诉讼权利义务告知书》《诉讼费退费缴费须知》两份**不含本案期限**的通用文书各冒出一条「待确认日期」，带「规则 85%」且**默认勾选**，律师一键即可写进案件日历：

| 文书 | 编出来的日期 | 真实情况 |
|:--|:--|:--|
| 告知书（诉讼权利义务告知书） | 2026-11-27（收到短信 + 3 天） | 原文是「申请不予公布的，至迟应在**裁判文书**送达之日起三日内」——那份裁判文书还没产生 |
| 诉讼费退费缴费须知 | 2026-12-01（收到短信 + 7 天） | 原文是「应自收到**《缴费通知书》**之日起七日内」——锚点在同批另一份文书上，且这句是通用通则 |

同批 7 份文书里 LLM（kimi-2.6）对这 6 份**一条日期都没报**，两条假日期全部由确定性正则层产出：`_RELATIVE_ANCHOR_RE` 用 `[^，。；;\n]{0,14}?` 把「本通知 / 裁判文书 / 《缴费通知书》」一律当通配符吞掉，锚点永远取短信 `received_at`。

## 后端

#### 新模块 · `services/date_candidate_policy.py`（纯函数，不依赖 Django）

一条候选必须能回答「谁对谁、何时、依据哪份文书、锚点是什么」：

- `classify_document_role`：**内容判据**（有无具体落款日期/案号 + 文首 80 字标题），不靠文件名——法院把归档名写成「告知书（…）.pdf」时，`document_template_filter` 的「诉讼权利义务告知书」条目压根匹配不到。
- `parse_anchor_clause`：把「收到/送达 **X** 之日起」的 X 抽出来分类——自指（含省略主语）/ 生效起算 / 同批另一份文书 / 尚未产生的文书 / 他案函件。两种语序都认（「裁判文书送达之日起」与「收到《缴费通知书》之日起」）。
- `is_optional_motion`：选择性申请类条款（申请不予公布/延期/证人出庭/鉴定/调查取证/回避）**不进日历**；但保留词（复议/上诉/答辩/管辖/举证期限）一律不误伤。
- `decide_candidate`：`default_checked = keep and not flags`——默认勾选只认 flags，彻底消灭「置信度压到恰好 0.5 仍默认勾」的边界 bug。

#### 五道闸门接线（`date_candidate_service.build_date_candidates`）

1. 文书角色闸 → 通用告知类文书**不产规则推算候选**（LLM 读到的明文绝对日期仍保留，打 `generic_boilerplate`、不默认勾）；
2. 锚点归属闸 → `anchor_document != self` 一律丢弃（期限归属那份文书，由它自己的识别产出）；
3. 选择性申请闸 → 直接丢弃（业务口径 2026-11-24）；
4. 批内收敛 → 同一条短信内 `(案件, 日期, 类型)` 完全相同才折叠，保留权威那条（LLM 明文 > 正则明文 > 相对期限）；**同日不同类型、同类型不同日期一律都留**，不做冲突裁决；
5. 默认勾选 → 后端算好下发，前端删掉按分数判断的 `shouldDefaultCheck`。

#### 数据模型（迁移 `document_recognition/0010`）

- `DocumentRecognitionDateCandidate` 新增 `anchor_kind` / `anchor_at` / `anchor_document` / `derivation` / `review_flags` / `default_checked` / `duplicate_of`；
- `DocumentRecognitionTask` 新增 `suppressed_candidates`（JSON）：**被丢弃也要留一行**，律师问「这份文书为什么没提醒我」时，确认弹窗能展开看到「锚点在同批另一份文书上」这类人话原因。

#### 顺带修掉的历史缺陷

- `anchor_note`（「起算点为判决生效之日，请与书记员确认」）在 `tasks.py` 重建 draft 时被丢掉，从未到达前端——现在随行落库并透出；
- 「起算点不确定 → 降一档、默认不勾」把置信度压到**恰好 0.5**，而前端阈值是 `>= 0.5` → 意图反向失效（改成 0.45 + flag）；
- LLM 提示词让模型按**落款日**做相对期限算术，与确定性层按**送达日**推算冲突，同一句期限能生成两条矛盾候选——提示词改为「只输出原文明文绝对日期 + 标注 `anchor_hint`，不做任何推算」，算术独占归确定性层，并注入送达日作为背景（仅用于判断，禁止用于计算）。

#### 运维命令

- `manage.py date_candidates_audit [--sms N] [--task N] [--apply]`：按新口径复核存量候选（默认 dry-run）。已确认（律师已确认写入日历）的行一律不动，只列「人工回看」。

## 追加：当事人地位闸（业务纠正 2026-11-24）

业务口径纠正：**举证期限/答辩期只在我方是被告、被申请人、被上诉人、第三人时才需要律师跟进**。我方是原告/申请人/上诉人时，举证已随起诉状/申请书提交，逾期举证主要是对方的证据失权风险，与我方日历无关。

实测印证：2026-11-24 那条送达短信所属案件（`cases_case#374`）我方是**原告**，法院照样送达了《举证通知书》——文书长得一模一样，只有"我方在该案是什么地位"能区分要不要跟。

- `date_candidate_policy` 新增 `DEFENSIVE_PARTY_ROLES`（defendant/respondent/appellee/third/criminal_defendant/orig_defendant/orig_third）、`is_defensive_only_clause`、`party_role_verdict`；
- 只约束「举证 / 提交证据 / 证据材料 / 答辩」这类防守型条款；**上诉期、缴费期、开庭、保全到期不受影响**（对所有诉讼地位都成立）；
- 我方地位取自 `CaseParty.legal_status`（只取 `Client.is_our_client=True` 的当事人），经 `ICaseService.get_case_parties_internal` 读取；
- **拿不到地位时不硬丢**：保留候选 + `party_role_unknown` flag + 不默认勾（与 `anchor_unknown` 同一哲学——漏报真期限比多报更贵）；
- 顺带修：相对期限事件类型词表补 `提交证据 / 证据材料 / 证据目录`，「向本院提交证据材料」不再被归成 `other`（`other` 一过期就会被"纯历史过滤"删掉，律师连"举证期已过"都看不到）。

## 追加：举证期限的两种缺失写法（2026-11-24 第二批）

真实样本只有 1 份（`apiSystem/media/case_logs/425/...举证通知书...pdf`，正好是"我方是原告"那个案子里的三档模板），历史短信引用的举证通知书 PDF 已全部从磁盘清理（DB 里只剩文件名）。按这一份真实样本 + 法条口径补了两个抽取能力：

| 能力 | 之前 | 现在 |
|:--|:--|:--|
| **期间长度**「举证期限为十五日」 | 只认同一句「…之日起 N **日内**」，「期限为N日」完全不抓（JSON 里只有 `_PERIOD_YEARS_RE` 抓「期间为一年」） | 新增 `extract_period_length_verdict`：能算的算出日期（`rule_period`）；**三档程序 / 法定下限 / 无起算点一律不算**，改为留痕提示 |
| **纯日期（无时刻）**「举证期限至 2027-01-10 止」 | `DATETIME_PATTERNS` 7 条模式全部要求时刻，只有 LLM 能抓；LLM 熔断窗口内全空 | 新增 `extract_date_only_candidates`：纯日期 + **上下文 40 字内必须命中期限词**才采纳（否则判决书的开庭日/立案日会被成片抓进来） |

期间长度的三条拒绝理由（都写进 `suppressed_candidates`，律师可展开看到）：

1. **多档程序**：一份文书里普通 15 日 / 简易 5 日 / 小额 3 日三档并存且没指定本案适用哪档 → 三个互斥日期，系统无权替法院选；
2. **法定下限/上限**：「不得少于十五日」「不得超过十五日」是《民诉法解释》第 99 条口径，不是本案指定期限，当死线用会让律师提前放弃举证；
3. **无起算点**：只有长度没有「自收到 X 之日起计算」，不拿送达日硬凑。

另：当事人地位集合改为引用唯一权威 `apps.cases.domain.party_status`（`DEFENDANT_SIDE_STATUSES | THIRD_SIDE_STATUSES` / `PLAINTIFF_SIDE_STATUSES`）——生产库 `cases_caseparty.legal_status` 是**中英文混存**的，自建英文集合会漏掉中文那批（结构护栏 `test_party_status_single_source` 也会拦）。

真机验证（真 PDF + kimi-2.6）：真实《举证通知书》→ 0 条候选 + 留痕「文书含多档期限（普通程序15日/简易程序5日/小额诉讼3日）且未指定本案适用哪种程序」；`举证期限为十五日 + 明写起算点` + 我方=被告 → 2026-12-09 举证到期日。

## 口径（业务拍板 2026-11-24）

1. 选择性权利期限（申请不予公布等）**不进日历**；
2. 通用须知类文书里的**明文绝对日期**保留（不默认勾）；
3. 批内同日同类型但日期不一致 → **两条都留**，不做冲突裁决。
