| 之前 | 现在 |
|:--|:-|
| 五个后端：pi / dsh / openai-agents / antigravity / claude-agent。其中 openai-agents 是「我们的循环 + OpenAI 的螺丝刀」，不构成对外部 agent 设计的对照 | **七个**：新增 opencode（ACP 协议）、codex（OpenAI 官方 app-server）、cline（Cline SDK）；移除 openai-agents，空缺由 codex 顶上 |

## 后端

#### 新增：`opencode`（第六栏，ACP over stdio）

- `backends/opencode_backend.py` + 自实现 ACP 客户端（JSON-RPC over stdio，无新依赖）
- `session/new` 直挂共享 MCP（律师 token + `x-fachuan-session` + tool-tier 头）；实测 430 个 `fachuan_*` 工具进工具面（`inputTokens≈80810`）
- 审批：`session/request_permission` → `services/approval` 四级判定；工具名 `fachuan_x` 归一化成 `mcp__fachuan__x` 后再判级（**不归一会静默降级成低风险**）
- 内置 14 个工具用**自定义 agent** 关掉（顶层 `tools` 字段对它无效，实测）
- 每会话独立配置目录（0700/0600）+ 共享 `node_modules` 软链；剔代理
- 实测坑与并发画像：`docs/harness/backend/opencode-probe.md`

#### 新增：`codex`（第七栏，`codex app-server`）

- `backends/codex_backend.py` + `codex_gateway.py`（loopback 反向代理）
- **为什么必须反代**：codex 的 reqwest `system_proxy_fallback: true` 会读 macOS 系统代理，内网网关被 Clash 劫持即 502；`NO_PROXY` / 删环境变量都无效，只能从 `base_url` 绕。同一份请求体经本地反代转发就正常
- 只认 `responses` 协议（`wire_api = "chat"` 在 0.161 已移除）；律所网关支持 `/v1/responses`（实测 200 + SSE）
- 审批：`item/commandExecution|fileChange|permissions/requestApproval` 反向发来 → `services/approval`。codex 自己的 shell / 打补丁能力不经过 MCP，故命名为 `codex_execute_command` / `codex_rewrite_file`——这两个名字命中 `DANGER_PATTERNS`（`execute_` / `rewrite_`），**必然判 HIGH、必然弹卡**
- 用量：`thread/tokenUsage/updated` 是**累计值**，按差值记账（同 dsh 的教训）

#### 新增：`cline`（第八栏，Node 桥 + `@cline/core`）

- `devtools/cline_bridge.mjs`（stdio 行分隔 JSON）+ `backends/cline_backend.py`
- cline 只发 npm SDK、**没有可执行文件**；桥负责三件事：写 cline 的 MCP 设置文件（`streamableHttp` + 三个头）、建 `ClineCore`、翻事件
- 隔离：`CLINE_DIR` 直接决定 `cline_mcp_settings.json` 路径（实测 `resolveDefaultMcpSettingsPath()`），每会话一份 = 数据/设置/sqlite 全隔离
- 实测形状：正文增量在 `content_start(contentType:"text").text`；工具在 `contentType:"tool"` 的 `content_start` / `content_end`（`toolName` 形如 `fachuan__<tool>`）

#### 移除：`openai-agents`

- 删 `backends/openai_agents_backend.py` 与单测、`_register_openai_agents` 两处调用
- key 覆盖口径仍由 dsh / pi / claude-agent 三组测试守着，未降低覆盖

#### 修复：多栏并答撞车

- `opencode` 不再登记单槽 `live_sessions`：三栏共用同一会话时 pi 先登记，opencode 直接 `SessionBusyError` 整栏挂掉（实测）。它声明 `concurrent_in_session=True`，中止走编排层取消生成器 → `session/cancel`

| 后端 | 耗时 | 工具调用 | cache_read | 回答 |
|:--|--:|:-|--:|:--|
| pi | 4.8s | 2/2 | ≈16k | 12 |
| opencode | 11.2s | 1/1 | ≈76k | 12 个 |
| codex（app-server） | 23.3s | 1/1 | ≈168k | 12 |
| cline | ~3s | 1/1 | ≈76k | 12 个。 |

多栏并答（`stream_multi`）：

| 栏数 | 后端 | 耗时 | 断言 |
|--:|:--|--:|:--|
| 2 | pi + opencode | 9.8s | `meta.agents` / 每栏 done=1 / 无串栏 / 落库 1+2 ✅ |
| 3 | pi + opencode + codex | 18.2s | 同上 ✅ |
| 4 | pi + opencode + codex + cline | **10.6s** | 同上 ✅ |

codex 审批双向闭环：

```
拒绝 → asked=['codex_execute_command'], file_exists=false   ← 命令真没执行
批准 → asked=['codex_execute_command'], file_exists=true
```

## 已知限制（如实记录，不是待办）

- **cline 没有人工审批**：`ToolApprovalRequest` 走它自己的 capabilities 通道，本桥未接线 → `capabilities.approval=False`。高危 MCP 工具仍由 MCP 服务端闸门拦；cline 内置工具当前无闸门，启用前需合规确认
- **codex / opencode 不能替换 system prompt**：ACP 未广告该能力、codex 侧未接 → 综合结论 lane 不用它们（与 dsh 同待遇）
- **codex 每轮约 17 万 token**（工具面 + 它自己的系统提示词）；`FACHUAN_CODEX_TOOL_TIER=lite` 可压到约 3 万，但冷门工具就调不到（实测 lite 下模型答「没有这个工具」）
- **codex 拒绝值是 `decline`**（写 `denied` 会解析失败、整个 turn 挂住——实测踩过）
