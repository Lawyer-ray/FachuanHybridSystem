# v27.14.1 · 生成案件文件夹 500（特殊渲染器签名不一致）

## 需求

点「生成案件文件夹」报 500，案件 487（买卖合同纠纷）必现：

```
TypeError: FolderGenerationService._render_legal_rep_certificate()
           missing 1 required positional argument: 'failed_templates'
```

## 后端

### 修复 · 特殊渲染器签名与 dispatch 调用点不一致

`generate_case_folder_with_documents` 的 dispatch 按**固定五参数**调用特殊渲染器：

```python
handler(case=…, template=…, file_location=…, folder_path=…, documents=…)
```

而 `_render_legal_rep_certificate`（法定代表人身份证明书）的签名多声明了一个
**必填**的 `failed_templates`，于是只要该模板绑定命中就走不到渲染、直接 TypeError，
整个接口 500。

病灶是一个**死参数**：该函数体内从未引用过 `failed_templates`（异常只
`logger.warning`，不追加失败项），所以正确修法是**删掉它让签名与另外两个渲染器
（授权委托书 / 所函）对齐**，而不是给 dispatch 补参数——后者会让「有的 handler
记失败、有的不记」的语义漂移固化下来。

> 顺带说明：`_render_default_document` 的 `failed_templates` 是**真在用**的
> （渲染异常时 append），它不走 dispatch，签名不同是合理的，未改动。

### 测试 · 把 dispatch 调用形状固化成契约

这类 bug 编译器与 mypy 都拦不住（handler 是 `getattr` 出来的 `Any`），所以在
`test_folder_generation.py` 新增 `TestSpecialRendererDispatchContract` 三条守卫：

| 用例 | 拦什么 |
| --- | --- |
| `test_every_special_renderer_accepts_dispatch_kwargs` | 每个特殊渲染器必须接受 dispatch 传的五个参数名 |
| `test_no_special_renderer_requires_extra_positional_args` | 不允许出现 dispatch 未提供的**必填**参数（本次 bug 的直接形态） |
| `test_handler_callable_with_dispatch_args`（参数化） | 运行时把五参数真打到 handler 上，缺参数即 TypeError |

**已验证测试抓得住原 bug**：临时回滚修复后，后两条用例变红，断言消息与线上
500 完全一致（`missing 1 required positional argument: 'failed_templates'`）；
恢复修复后全绿。
