# v27.14.3 · Admin 日期筛选统一为自然期间（31 处）

## 需求

Django 对日期字段**裸用** `list_filter = ("created_at",)` 时只给四档：
今天 / 过去 7 天 / 本月 / 今年。但律师真实要问的是「**上个**月收了多少款」
「**上个季度**立了多少案」——正好是原生四档缺的那两档。于是只能翻页找或导出 Excel 筛。

承接 v27.14.2 的 admin 字段守卫，把全站日期筛选一并收敛。

## 后端

### 新功能 · `apps/core/admin/filters.py`：`NaturalPeriodFilter`

一个筛选器覆盖 10 个自然期间：今天 / 昨天 / 最近 7 天 / 最近 30 天 /
**本月 / 上月 / 本季度 / 上季度** / 今年 / 去年。

用法：

```python
from apps.core.admin.filters import date_filter

list_filter = ["status", date_filter("created_at", title="创建时间")]
```

**时区口径是本模块的核心难点**（项目 `USE_TZ=True` + `TIME_ZONE=Asia/Shanghai`）：

| 字段类型 | 存储 | 边界处理 |
| --- | --- | --- |
| `DateTimeField` | UTC | 本地日 → `make_aware()` 转 aware datetime，用**半开区间** `[start, end)` |
| `DateField` | 纯日期 | 直接用 `date` 比较。**绝不能传** aware datetime（会被隐式转换，结果随 DB 时区漂移） |

上一版若用 `__year=...__month=...` 做月度筛选，跨年与时区下都有坑且无法走索引，
故统一改为 `__gte / __lt` 半开区间。

`parameter_name` 由字段名派生（`period_created_at`），同页多个期间筛选器不会互相覆盖 URL 参数。

### 优化 · 31 处 admin 日期筛选全部替换

覆盖 26 个文件、31 处裸日期 `list_filter`（`contracts` / `cases` / `automation` /
`legal_research` / `document_parsing` / `document_recognition` / `pdf_splitting` /
`reminders` / `finance` / `labor_arbitration` / `organization` / `agent` /
`batch_printing` / `express_query` / `contract_review` / `client` / `legal_solution` 等）。

排除项（有意不动）：
- `django_q.admin.ScheduleAdmin`：第三方 app，不应改动；
- 已有 `date_hierarchy` 指向同一字段的 10 处：顶栏时间轴已能按天钻取，重复加筛选器只是噪声。
