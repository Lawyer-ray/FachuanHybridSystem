# v27.14.2 · 文书模板 admin 搜索 500（search_fields 引用已删字段）

## 需求

文书模板列表页一搜索就 500：

```
GET /admin/documents/documenttemplate/?q=清单
FieldError: Cannot resolve keyword 'description' into field.
```

列表面板本身正常，**只有输入关键词才炸**——所以日常使用看不出来。

## 后端

### 修复 · `DocumentTemplateAdmin.search_fields` 引用了已删除的字段

`DocumentTemplate.description` 早在迁移 `0006_remove_documenttemplate_description`
里就被从模型删掉了，但 admin 的 `search_fields` 一直留着它。Django 会把
`search_fields` 直接拼进 ORM `filter()`，字段不存在即 `FieldError`。

修法：`search_fields` 收敛为 `("name",)`（模型上确实没有等价的描述性长文本字段可替代）。

### 修复 · `StoryAnimationAdmin.search_fields` 的 `id__icontains` 是非法写法

全站守卫扫出来的**第二个同类隐患**（`story_viz`）。admin 的 `search_fields`
只接受字段路径，**不支持 ORM lookup 后缀**：`id__icontains` 会被当成
「关联穿透到名为 `icontains` 的字段」，一搜索同样 `FieldError` 500。
已改为 `id`（整型主键走精确匹配）。

> 这是潜伏 bug，尚未被线上触发——但如果没人搜过 story_viz 后台，它随时会炸。

## 测试

### 新功能 · 全站 admin 字段引用守卫

`tests/ci/unit/test_admin_field_references.py`：反射遍历**全部 103 个已注册
ModelAdmin**，校验 `search_fields` / `list_filter` / `list_display` 引用的列
能在模型上解析（支持 `fk__sub_field` 关联穿透）。

| 用例 | 拦什么 |
| --- | --- |
| `test_search_fields_exist_on_model` | 搜不存在的字段 → 搜索即 500 |
| `test_list_filter_exist_on_model` | 筛不存在的字段 → 点筛选即 500 |
| `test_list_display_entries_are_resolvable` | 列表页有无解项 |
| `test_document_template_search_does_not_reference_removed_field` | 本次 500 的直接防复发哨兵 |
| `test_document_template_search_actually_works` | 端到端走一次 `get_changelist_instance`，确认真能拼进 ORM |

守卫同时把「ORM lookup 误用进 search_fields」识别为错误，而不是当成字段名放过
——否则 `id__icontains` 这类写法会被漏掉。

### 修复 · 单测自己把 bug 固化成了「预期」

`test_documents_admin_coverage.py` 原来断言：

```python
assert "description" in admin.search_fields   # ← bug 被写成测试预期
```

所以 CI 一直全绿、线上一直 500。已改为断言该字段**不在**搜索项里，并在注释里
写明来历。

### 已验证守卫抓得住原 bug

临时回滚 admin 修复后，三条用例同时变红，其中端到端用例抛出的正是线上那条
`FieldError: Cannot resolve keyword 'description'`。恢复修复后全绿。
