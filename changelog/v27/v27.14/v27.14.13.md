# v27.14.13 · 任务失败日志降噪（外部环境故障不再刷整段堆栈）

`qcluster` 终端里每隔半小时就刷出一大段红色报错，看起来像系统全线崩溃：

```
ERROR - 'apps.core.tasking.entries.run_task' (finch-asparagus-indigo-montana) 失败 - IMAP 连接失败（已尝试: …）: [Errno 8] nodename nor servname provided, or not known : Traceback (most recent call last):
  File ".../imaplib.py", line 1315, in __init__
  ...
socket.gaierror: [Errno 8] nodename nor servname provided, or not known
```

本分支（`feat/quiet-task-failure-logs`）不改变任何业务行为，只把**日志观感**修对：
让「外部依赖当前不可用」和「代码真的有 bug」在终端里长得完全不一样。

---

## 后端

### 优化

#### 一、同一份堆栈为什么会在终端里出现两遍

根因不在 IMAP，而在**两层日志各打了一份**：

1. `apps/core/tasking/entries.py` 的 `run_task` 捕获异常后调用 `logger.exception` —— 第一份完整栈；
2. django-q 的 monitor 进程（`django_q/monitor.py:66`）把 `task["result"]`（**就是那段完整的
   traceback 字符串**）原样拼进日志消息 —— 第二份完整栈。

再叠上 django-q 随机生成的任务名（`finch-asparagus-indigo-montana`），一条「域名填错」的
配置问题就被包装成了 80 行的系统级事故。而这类任务（IMAP 收件箱、法院一张网抓取）按
`poll_interval_minutes` **周期性重跑**，失败一次就重刷一遍。

#### 二、区分「外部环境不可用」与「代码缺陷」

`run_task` 现在按异常类别分流（`_is_expected_task_error`）：

| 类型 | 判定依据 | 终端输出 |
|---|---|---|
| 外部环境故障 | `socket.gaierror` / `TimeoutError` / `ConnectionError` 族，或消息命中 `name or service not known`、`connection refused`、`timed out`、`target closed`（Playwright）等白名单 | **一行 WARNING** 摘要，堆栈降级到 DEBUG |
| 真代码缺陷 | `AttributeError` / `KeyError` / `TypeError` 等 | **带完整堆栈的 ERROR**（不变） |

异常消息同时被压成单行并截断到 300 字符（`_shorten`），超长时附上原始长度，方便判断是否需要看全文。

#### 三、新增 `TaskResultLogFilter`，剥掉 django-q 那份重复堆栈

`apps/core/infrastructure/task_result_logging.py`（新增），挂到 `console` / `console_error` 上：

- 把 `失败 - <result>` 里以 `Traceback (most recent call last):` 开头的那一整段剥掉，只保留
  `异常类型: 异常摘要` 末行；
- 命中可预期故障白名单时，把这条日志从 ERROR **降级为 WARNING**；
- 把随机任务名换成**业务任务名**（取自 `request_context` 的 `task_name`，如
  `message_hub.sync_source_by_id`），拿不到时回落到函数路径。

解析上有两个坑（已用测试锁定）：
- 日志可能已被外层格式化器加上 `[2026-11-09 13:44:46] ERROR - ` 前缀，所以锚定到 `失败 - `
  向前找 `(任务名)`，不能直接从头匹配；
- 消息体里满是括号（`（已尝试: a, b）`）和引号（`type object 'X' has no attribute 'Y'`），
  按引号切会被带偏。

**`file_error` 故意不过滤**：终端要清爽，落盘仍保留完整堆栈，事后排查照旧。

#### 四、IMAP 主机名全解析失败时给出可执行提示

`imap_fetcher._connect` 在所有候选主机都 `gaierror` 时，错误消息补一句
「请检查该消息来源的 IMAP 主机名/域名是否正确」——这类失败 99% 是配置里域名填错，不是网络问题。

### 测试

新增 `tests/ci/unit/core/test_task_failure_logging.py`（16 个用例），覆盖：

- 预期故障（DNS / 超时 / 内置 `ConnectionError` / Playwright 已关闭）降级为 WARNING 且不带栈；
- 代码缺陷仍为 ERROR 且保留 `exc_info`；
- 超长异常消息被截断；
- django-q 失败日志的 traceback 剥离、随机任务名替换、带时间戳前缀的解析、
  非任务日志原样透传。

### 说明

本次改动只影响日志表现，不改变任务的成功/失败判定与重试逻辑。那条 `mail.jtn.com`
来源仍会同步失败——那是**数据配置问题**，需在消息来源管理页把 IMAP 主机名改对。
