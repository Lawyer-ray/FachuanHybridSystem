# v27.14.0 · 记收款支持粘贴银行回单截图（图片识别）

## 需求

记收款弹窗原先只有「粘贴到账短信」一个入口——**只支持文字**。但律师手上的到账凭据
一半是短信，另一半是**网银 App 里的电子回单截图**：金额、大写金额、付款人/收款人、
完整交易时间全在图上。只支持文字，等于把后一半逼回手抄，而抄错一位就是财务事故。

现在：**回单截图直接 ⌘V 粘进第一个输入框**（也可拖入 / 点「选图片」），金额、日期、
付款人、用途自动填好，律师核对后保存。图片不进 media、不入库——它只是取字段的中间产物。

## 前端

### 新功能 · 记收款支持粘贴 / 拖入 / 选择图片

- 新增 `PaymentPasteZone.tsx`：文字与图片**同一个入口**。粘到文本框里是最顺手的动作，
  所以不另开一个「图片上传框」——`onPaste` 里若剪贴板带文件就拦下来走图片识别，
  纯文字则放行给 Textarea 默认行为（复用 home 域既有的 `fileFromClipboard`，
  泛名 `image.png` 会按 MIME 补全扩展名与时间戳）。
- `PaymentDialog` 增加 `doParseImage`：识别结果回填表单，**读到的原文同时贴回输入框**
  ——律师要手改某个字段时，原文就在上面可对照。
- 「没认出字」与「链路失败」分开提示：后者 `toast.error`（调不通），前者落到表单提示
  （这张图没读出东西，去手填/重拍）。混在一起会把「服务没通」误报成「这张图糊了」。
- `InvoiceDropZone` 增加可选 `onPasteFiles`，记收款/发票两处上传区都能直接粘贴截图。

### 新功能 · 大写 / 小写金额冲突醒目提示

回单上的**中文大写金额**是财务上更可信的一方，与小写互为校验。两者对不上时（常见于
OCR 把小写读错一位）表单顶部弹出黄色警示条，**不拦保存但必须让人看见**——否则就是
一个静默错账。

### 优化 · 备注按回单口径拼装

回单版式的备注取「用途；付款人：XX」（`ContractPayment` 没有付款人字段，备注是唯一
能存自由文本的地方）；短信版式沿用原口径。

## 后端

### 新功能 · `POST /finance/payments/parse-image`

粘一张图（回单截图 / PDF）→ 收款草稿，与 `parse-text` 同口径：**只解析不落库**，
金额必须由人在表单里核对后才保存。

识别引擎**不另起炉灶**：直接复用 `document_recognition.TextExtractionService` 的既有
阶梯（文本层 → VLM 视觉转写 → macOS Vision / RapidOCR 本地 OCR），所以换供给只改
「AI 平台」一行，代码零模型名硬编码。实测在真实回单截图上走 `vlm` 档，金额/日期/双方
户名/用途全部正确。

新增两个模块：

| 文件 | 职责 |
| --- | --- |
| `services/payment/payment_image_reader.py` | 图片/PDF → 文本。大小与 MIME 校验、**临时文件不落 media**、引擎认不出时返回空而非抛错 |
| `services/payment/receipt_fields.py` | 回单文本 → 字段（纯函数，零 IO、零 DB、零模型），含中文大写金额换算 |

### 修复 · 回单两栏都叫「户名」时会把自家律所当付款人

回单表格里「付款人」与「收款人」两栏**都叫「户名」**，OCR 出来是
「付款人 户名:甲 转出账号… 收款人 户名:乙 转入账号…」。按标签顺序取第一个「户名」，
取到的很可能是**自己律所**——这正是回单识别最容易出的事故，且错了还看着像对的。

`receipt_fields` 按**付款人标签出现的下标切一刀**分两段，再各自取户名；切段失败
（OCR 顺序乱）时用「律所即自己」的常识纠正取反。真实回单截图验证：付款人取到
**客户公司**、收款人取到**本所**，不再取反。

### 修复 · 模板告示粘进「用途」导致备注变长噪声

回单底部那段「提示1、已在银行柜台领用业务回单的客户，请注意核对，请勿重复记账使用。」
是模板告示，OCR 会直接粘在用途值后面，修复前备注成了
`往来款提示1、已在银行柜台领用业务回单的客户…`，对账时毫无用处。现在用途值与
「提示N / 电子印章 / 打印时间 / 币种 / 手续费」等后栏位词之间截断。

### 安全 · 新路由必须排在 `{payment_id}` 通配之前

`parse-image` 与 `finance/payments/{payment_id}` 同层，晚注册会被通配先吃掉（405）。
已与 `parse-text` 一并放在 enhance router 首位，并在 `api/__init__.py` 的注册顺序注释
里补上说明。
