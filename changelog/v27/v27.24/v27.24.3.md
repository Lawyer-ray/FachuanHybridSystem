## 后端

#### 新功能：输出侧页旋转

- `apps/pdf_splitting/services/split/output_rotation.py`（新）
  - `parse_page_rotations`：`"页码:角度,页码:角度"` 编码（页码=源 PDF 绝对页号）；脏 token / 非直角 / 越界页一律**忽略 + 告警**，绝不 400——不该因为一个脏角度让律师丢掉一份切好的卷宗
  - `merge_page_rotations`：跨段合并；同一绝对页被两段给了不同角度 → **后者生效 + `logger.warning`**（正常拆分不会出现，出现就是调用方页区间算错了，静默取值会让这个 bug 永远查不到）
  - `apply_page_rotations`：`page.set_rotation((page.rotation + deg) % 360)` —— **叠加**在页自身 `/Rotate` 之上。歪着扫的法院件本来带 `/Rotate 90`，再转 90 必须读回 180；写成覆盖会把一页正常纸转倒，而且肉眼极难发现
- 四个出口接线（参数名统一 `rotations`）：`POST /extract-pages`（归案切页，Form）、`POST /archive-to-case-folder`（段字段）、`GET /segments/{id}/pdf` 与 `GET /download`（zip，query）
- 归档路径**先合并再 apply 一次**：一份 `source_doc` 复用给所有段，页指纹也在同一份文档上算（`page_signature` 走 `get_pixmap`，会吃 `/Rotate`）；逐段 apply 会让先切出的段与后算的指纹方向不一致，副本判定随之出错
- `page_rotation.py`（PaddleOCR 转正帧回写，逆时针为正、纯数学）与本模块是**两套约定**，两个 docstring 互相指路并禁止互传角度：两个 90 恰好互相抵消符号错误

#### 未新增迁移

旋转不落库：下载/归档都是无状态请求，草稿侧存前端 `draft_state`（JSON），服务端只在生成 PDF 时用一次。`summary_payload` 等字段未改动。

## 前端

#### 新功能：页级旋转状态

- `DraftState.pageRot: Record<"partIndex:page", 0|90|180|270>`（相对页自身 `/Rotate` 的顺时针增量）
  - 键用 **partIndex** 而不是素材下标：追加附件会让下标漂移；与切段解耦，切/并/删段都不会让旋转错位
  - 转四次 90° 回正时**删键**，所以「已转正 N 页」永远不会虚高
- `draft/page-rotation.ts`（新，纯函数）：角度收敛、批量叠加/设绝对值/重置、计数、`rotationsForRange`（给后端的编码）、`rotateNormRect`（归一化坐标换算）、`firstRotationOf` / `joinRotationEncodings`
- `lib/pdf/page-render.ts`：`renderPdfPage` / `renderPdfPageRegion` / `imageRegionBlob` 支持旋转增量。**pdf.js 的 `rotation` 是覆盖 `page.rotate` 而非叠加**，内部相加；90/270 按旋转后的宽反算缩放（否则横过来的页会渲染成窄带、被 CSS 拉回后字糊）

#### 新功能：三个转正入口

- **单页**：页卡悬停右上角 `↺ / ↻ / 0°`，页脚挂 `90°` 徽标（长列表里能扫出哪几页转过）
- **右键菜单**：顺时针 90° / 逆时针 90° / 旋转 180° / 重置方向，标题带「当前 90°」；多选时文案变「旋转所选 7 页」，多页角度不一致时不谎报具体角度
- **批量**：选中多页 → 底部浮条多出 `↺90 ↻90 180° 0°` 与「已转 N」；另有左下角常驻「已转正 N 页 · 全部重置」
- **键盘**：`R` 顺时针 / `Shift+R` 逆时针，只作用于已选中的页（盲转当前页会让你找不到转错的那页）
- **照片素材**：没有页对象可烧 `/Rotate`，就地渲染成旋转后的图；归案上传时用**同一个函数**（`rotateImageBlob`）重编码，屏幕所见与客户所得是同一路径
- **识别框跟着转**：引擎双框、正文定位框、来源绿框全部经 `rotateNormRect` 换算；不转的话框会指到隔壁——比没有框更糟
- **框选取字**：`renderPdfPageRegion` 按同一角度抓图（框画在屏幕上，图必须按屏幕方向裁），否则「圈的金额、识别出隔壁日期」

#### 外发接线

- 归案：`extract-pages` 带 `rotations`；覆盖整份素材时**不再省掉切页往返**（有旋转就必须过服务端才能落地）
- 归档：每段带 `rotations`
- 下载：单段/多选/整包 URL 追加 `rotations`（`ids=` 之后用 `&` 续接，不拼出第二个 `?`；空旋转不加参数，URL 与改动前逐字相同）
- 素材下标 → `partIndex` 的换算收敛到一处（`pageRotRefsOf` / `archiveGroupsOf` / `Rail` 各一次显式换算）：换算错的表现是「转了这一页、歪的是另一页」

## 说明与遗留

- **旋转不写回源附件**：这就是设计。改源文件要重写几十 MB，还会让 OCR/拆分缓存整体失效（转一下等几十秒），且不可撤销
- 照片素材的显示是「读字节 → 旋转重编码 → 显示」，比 PDF 多一次编解码（图片素材通常几百 KB～几 MB）；换来的是尺寸精确，不做 CSS 旋转那种「留白或裁切」
- 归档端点只在单测层面覆盖到「合并 + apply」（真实归档需要案件已绑定文件夹）；端到端归档用的是 v27.23.9 那套真实回放，本次未重跑
- 重跑/自动拆解重建草稿时 `pageRot` 天然保留（所有重建函数都是 `{...d, segs}` 的不可变展开），`store.test.ts` 有回归断言
- 未做（原 P3，已按用户要求取消）：用 ONNX 方向识别自动标注「疑似倒了」的页并一键修正
