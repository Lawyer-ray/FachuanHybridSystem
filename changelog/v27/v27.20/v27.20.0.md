## 一句话定位

| 问题 | 之前 | 现在 |
|:--|:--|:--|
| 引用核验的第④步（条文是否支持主张） | 返回「待判定」，**没有任何调用方接手**（死路） | 插件内多判定器合议：要件分解 → 严格多数 → 弃权转人工 |
| 上游挂了 / 切不出条款 / 名称只是近似 | 一律报「**不存在该引用**」（假死） | 无结论 + `needs_human`；只有「检索成功且确实没有」才判死 |
| 越南语法律名 | `Luật Dân sự`（民法典）与 `Luật Dân số`（人口法）归一化后**相等**，直接锁错法 | 变音折叠成基字母，两者可区分 |
| 条号写法 | `Section 4` 永不命中（docstring 却说支持）、`5.1`→`51`、`มาตรา ๔`→空 | 统一归一化，全部命中且不串号 |
| 条文内引用落在行首 | 造出**编号正确、正文是残片**的诱饵条，判定器据此给自信的错误结论 | 检测重复序号并按「是否像段首」排除 |
| 合议结果 | 插件算完就被工具层丢掉，律师只看得到一句散文 | 全链路透出：逐要件清单 + 一致度 + 需人工复核理由 |

## 后端

#### 新功能

- **多判定器审查（`plugins/barlc_asean_law/jury.py`，新增）**：主张拆成可独立证伪的原子要件
  （≤5）→ 3 个判定器（中立×2 + 对抗×1）并发判定 → **代码**聚合回四档 → 严格多数
  （`winner*2 > valid` 且 `valid ≥ 2`）否则弃权。三道闸：选项集（自造选项记协议偏离，
  不折算）、弃权（不用「票数最多」凑答案）、证据（判定器引的原文片段必须能在条文里找到，
  否则记 `fabricated_quote` 并转人工）。失败票不进分母。
- **合议结论面全链路透出**：`asean_law_verify` 返回 `adjudicated / unconfirmed / needs_human /
  review_reasons / agreement / matched_by / elements / votes / jury_tokens`；
  `ForeignLawVerifyOut` 同步声明（Ninja 按 schema 过滤，未声明会被静默丢掉）。
- 结果缓存 1 小时（同一「法律 + 条号 + 主张」只付一次判定成本）、详情/正文缓存、HTTP 客户端复用。

#### 修复

- **「上游失败」被当成「法不存在」**：`resolve_law` 全候选都因上游错误失败时改抛
  `BarlcUpstreamError`（工具层落 `verify_failed`），不再返回「不存在该引用」。
- **「切不出条款」被当成「没这一条」**：切分为 0 条时返回无结论 + `needs_human`。
- **跨国家同名法被乱挑**：检索结果 `SortA` 才是国别码（`Civil Code` 实测在 4 个国家都有），
  无国别信息时判歧义并列出候选，而不是随便挑一条。
- **名称近似直接当命中**：模糊档不再产生 `sys_id`，只作为「疑似候选」要求人工核对。
- **`files[0]` 与语言回退**：日志原先写「回退本地语」但代码没回退；现在切不出条款时真的改取本地语。
- **`/api/Detail` 权限信号**：成功响应**没有** `IsOk`（top-level 是 `HasRight`），按 `IsOk` 判会把
  每次正常调用判成失败；改为 `HasRight` 明确为假时才抛错。
- **凭据串号**：token 缓存在进程内且不绑定账号，律师 B 的请求会以律师 A 的身份执行
  （额度/权限/审计全串）。改按 `credential_id + account` 分槽。
- **`needs_model_judgement` 语义漂移**：它等于 `not result`，于是「合议弃权」被冒充成
  「请外部判定层来判」。新增 `adjudicated` 区分「跑过但弃权」与「未开启」。
- 账号（手机号/邮箱）不再明文进 INFO 日志；正文 PDF 页数与切分条数加安全阀。

#### 优化

- 条款切分支持 `Article N` / `Art. N` 体例（越南、菲律宾英译本用这个，原先切出 0 条）。
- 条号归一化支持 `Section 4` / `第4条` / `第四条` / `มาตรา ๔` / `4 bis` / `12/1`。
- 推理模型预算：`max_tokens` 700→2000（实测 9 次判定 6 次 `parse_failed` 归零）、
  单次超时 12→20 秒；超时/报错不再重试（预算有限，重试会吃掉其他判定器额度）。

#### 测试

- `backend/tests/ci/unit/plugins/test_barlc_asean_law.py`（51 条，纯函数，不联网不连库）
- `backend/tests/ci/unit/mcp_server/test_foreign_law_verify_payload.py`（6 条，钉住工具返回键集
  与「弃权 ≠ 待判断」语义）
- 子模块缺失时 `importorskip`，不拖累不拉子模块的 CI。

## 前端

#### 新功能

- **外国法条核验卡**（`ForeignLawVerifyCard`）：渲染合议结论（支持/矛盾/原文未提及三种颜色不同，
  不再混为「已判定」）、逐要件判定清单 + 一致度、需人工复核理由块。
  `adjudicated` 但无结论时显示「判定器未形成多数」，不再显示「待判断层比对」（会让人白等）。

#### 修复

- 「原文未提及」与「支持」此前共用同一个占位标签，律师容易读反；现在各自有独立文案与颜色。

## 说明

- `backend/openapi.json` 与 `frontend/src/types/api-schema.d.ts` **未刷新**：导出后发现仓库里这两个
  产物已落后代码 20+ 个端点（含已合并的裁决/审批接口），刷一次是 4000 行无关 diff。
  本批只更新了手写的 `foreign-law-api.ts` 类型；建议单独开一个「刷新 openapi 产物」的 PR。
- 默认三个判定器是**同一个模型**（只换角色与起点），`agreement` 会虚高（实测 4 例均 1.0）。
  要真独立性需配 `FACHUAN_BARLC_JURY_MODELS`；本条不涉及模型选型。
