# v27.20.8 — 搜索侧补齐：URL 去重 / 发布日期 / 按站限速 / 熔断加重

> 承 `v27.20.7`。涉及 `backend/mcp_server/tools/web_search`。

## 一、结果 URL 规范化去重（SearXNG / ddgs 同族做法）

实测兜底引擎 148 条结果里同文多站转载很常见，同一篇带 `utm_*` 与不带被算两篇，
18KB 预算被重复内容吃掉。新增 `_url_key()`：忽略 scheme、`www.`、fragment、参数顺序
与跟踪参数（`utm_* / spm / from / _fr / share_token / scene / src`），但**保留业务参数**
（不同 `entityid` 是不同判决书），且**不做整串 unquote**（中文路径两种编码不能被误合并）。

桌面通道、手机通道、兜底通道统一走 `_dedupe_results()`：重复时保留**摘要更长**的那条。

## 二、`fetch_url` 返回发布日期（`published`）

法律场景里「这条法规/解释是不是现行、最新」几乎全靠日期，而**兜底引擎完全没有日期字段**
（只有 title/url/hostname/snippet）。页面自己能给的就必须拿到：按可信度依次读
`<meta property="article:published_time|publishdate|pubdate|date|og:release_date">` →
JSON-LD `datePublished` → `<time datetime>`，归一成 `YYYY-MM-DD`，随结果返回并存进抓取缓存。

## 三、按站点礼貌抓取（学 Scrapy AutoThrottle / SearXNG 多尺度节流）

此前 `fetch_url` 对「同一 host 连击」毫无防护，实测抓同一站连续多篇直接换回
**521（hefei.gov.cn）/ 403（law-lib.com）**。现在：

- **最小间隔 0.5s**（`FACHUAN_FETCH_HOST_INTERVAL`，上限 2s）：太快就**短暂等待**而不是拒绝
  （读同一站多个链接是正常用法）；
- **429/503**：读 `Retry-After`（夹 5–300s）冷却该 host，返回新 reason `host_throttled`，
  消息里写明「约 N 秒后再试」——继续打只会再吃一次同样的错；
- **401/403**：该 host 冷却 600s（要登录/被封，短时间重试没有意义）；
- 熔断状态按 host 记账、LRU 上限 64，且**单测里关掉等待**（礼貌等待不该拖慢用例）。

## 四、通道熔断「连续失败加剧」（学 SearXNG 的连续错误计数）

搜狗封禁实测 **≥10 分钟**，而首次冷却只有 600s——到点立刻再撞等于白送一次请求并
重新计时。`ChannelBreaker` 现在记 `strikes`：同一通道连续失败时冷却 ×1 → ×2 → ×4
（封顶 4×），并在 reason 里写明「第 N 次，冷却 ×M」；一次成功（`clear`）即清零。
