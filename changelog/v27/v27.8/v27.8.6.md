# v27.8.6

开发体验修复：消除 pip-audit 豁免清单的双份维护，本地 `pre-push` 不再因过期副本误拦。

## 后端

#### 修复

- **`scripts/ci-local.sh` 的 pip-audit 豁免清单改为单一来源读取**（`backend/devtools/pip-audit-ignores.txt`，与 `.github/workflows/backend-ci.yml` 同一份）：此前脚本内**硬编码了 37 条 `--ignore-vuln` 副本**，与 `devtools/` 清单各自维护，导致后者新增豁免后脚本副本必然落后。后果是已登记豁免的 advisory 仍会拦下本地 push，只能靠 `git push --no-verify` 绕过。
  - 解析方式与 CI 逐字一致：`grep -Ev '^[[:space:]]*(#|$)'` 跳过注释/空行后取第 1 列，避免两处逻辑再次漂移。
  - 保留本地专属豁免 `LOCAL_ONLY_AUDIT_IGNORES`（`PYSEC-2026-3721` / `PYSEC-2026-3447`）：本地 TRAE 污染 python 底盘的构建工具漏洞，CI 干净环境扫不到，故只在脚本追加、不进 `devtools/` 清单。
  - 清单文件缺失时降级为「仅用本地专属豁免」并打印告警，不静默跳过审计。
  - 修正变量插值写法：`"$ignore_file，..."` 在全角逗号前会被 bash 并入变量名，`set -u` 下报 `unbound variable`，改为 `"${ignore_file}，..."`。

#### 说明

- 触发本修复的现场：v27.8.5 的 Pillow 12.3.0 → 13.0.0 批次改了 `uv.lock`，pip-audit 步骤被唤醒，随即被 PR #563 当日登记在 `devtools/` 的 certifi（`PYSEC-2026-4320`）与 virtualenv（`CVE-2026-113722` / `113725` / `113726` / `113732` / `113776`）共 6 条豁免拦下——脚本副本里没有这 6 条。该问题在 `main` 上同样存在（`git show main:scripts/ci-local.sh | grep -c 'PYSEC-2026-4320\|CVE-2026-1137'` 返回 0），属存量缺陷。
- 修复后实测：用脚本本体抽出的 `_pip_audit_invoke` 直跑，`No known vulnerabilities found, 6 ignored`，退出码 0（改前同环境为失败）。豁免参数由 37 条增至 43 条（devtools 41 + 本地专属 2）。
- 另有 `backend/CLAUDE.md` 层面的一致性收益：`pip-audit-ignores.txt` 头部约定「修改豁免只改本文件，不改 workflow」，本次把脚本也纳入该约定，三处（清单 / CI / 本地 hook）真正归一。
