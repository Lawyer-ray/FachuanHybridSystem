# v27.8.0

新建合同页「律所ID → 同步」两处修正：利冲表里的同案其他当事人被误标为「我方共同当事人」，以及 OA 有、本地没有的当事人需要手工先建客户才能回填。

## 后端

#### 修复

- **我方当事人口径纠正**：原先按「法律地位 == 代理何方」判定我方阵营，导致我方被告案件里的**共同被告**（以及我方原告案件里的共同原告、刑事同案嫌疑人）被报成「我方共同当事人」。事实上 OA 利冲表列的是全部相关方（利冲检查本来就要求列全同案方），法律地位相同只说明处在同一诉讼位置，**不代表律所代理他们**。
  - 现在只有 OA「客户信息」tab 里的委托人才算我方当事人；利冲表里同法律地位的条目改归 `co_parties`（同案其他当事人，非我方，只提示不填），含「第三人 / 利害关系 / 第三方」仍归 `third_parties`，其余才是回填为对方当事人的 `opponents`
  - `_split_conflicts` / `_classify_conflict` 同步改名并补注释，避免后续再把「同位」当「我方」
- **当事人自动建库**：新增 `ClientPartyResolveService`（`apps/client/services/client_party_resolve_service.py`）与 `OaPartyResolutionService`（contracts integrations），同步时把四组名单解析成本地 Client id：
  - 证件号优先、名称忽略大小写精确匹配；命中即复用，不再要求用户先手工建客户
  - 本地缺失时自动建库：委托人 `is_our_client=True`，对方 / 同案其他 / 第三人 `is_our_client=False`；法人 / 自然人按 OA 客户类型优先、名称关键词兜底
  - 委托人分组命中既有「非我方」记录时提升为「我方」——否则 `ContractParty.save()` 会把委托人身份自动纠正成对方当事人；非我方分组**不会**把既有「我方」记录改回非我方（同一当事人可能在别的案件是我方委托人，全局标记不能被一次同步抹掉）
  - 建库带上 OA 客户信息里已有的证件号 / 电话 / 地址 / 法定代表人；OA 用「/」「-」「无」占位的字段按空处理，自然人客户不写法定代表人（提取器会把「姓名」也当法定代表人）
  - 单个当事人建库失败只降级为「未匹配」，不影响其余字段与当事人回填
- **权限门槛**：自动建库要求 `client.add_client`；没有该权限时同步照常返回名单但不落库，响应带 `auto_create_allowed=false`，前端提示手动新建

#### 优化

- `build_sync_payload` 继续纯函数无 ORM（解析建库拆到独立服务），客户名单额外透出证件号 / 电话 / 地址 / 法定代表人字段

## 前端

Django admin（`contracts/js/oa_project_sync.js`）

#### 修复

- 结果汇总分组文案：`我方共同当事人（未回填，按需手动添加）` → `同案其他当事人（非我方当事人，未回填，按需手动添加）`；第三人分组补「非我方当事人」
- 当事人回填优先使用后端返回的 `client_id`（缺失才回退 autocomplete），并在成功行标注「其中 X 已在当事人库自动新建」；同案其他 / 第三人条目后标「已建库」，用户按需手动添加时无需再离开页面建客户
- 无当事人新增权限且存在未匹配当事人时给出明确提示
