# v27.8.7

Agent 运行时为前端侧边栏接入做准备：工具调用改为以**当前律师本人身份**执行（修复共享 MCP 的超管服务账号 confused deputy），补齐会话详情/历史端点，中断对话不再丢失已生成文本；前端新增 **AI 助手侧边栏**（features/copilot），可与 pi 流式对话。

## 前端

#### 新功能

- **AI 助手侧边栏（`features/copilot`，首个 pi 对话入口）**：导航栏「AI 助手」按钮唤起右侧常驻面板（404px，窄屏全宽），跨路由不卸载（挂 AppShell 壳层懒加载），展开状态记 localStorage。
  - 流式对话：POST + fetch 读 SSE 流（EventSource 发不了 POST/带不了 JWT），delta 逐字上墙、光标脉动，「停止生成」= AbortController 断开后自动重拉历史对齐（服务端已落库部分回答，标「已中断」）；
  - 会话管理：无会话时自动创建、标题由后端首条消息自动生成；面板内**会话侧边栏**（左滑入）支持切换回放、行内**重命名**（hover 显形）与**删除**（确认弹窗，删除当前会话自动切新对话），头部常驻「新对话」按钮；
  - 工具执行可视化：tool_call/tool_result 折叠行；**审批卡**带 300 秒倒计时（超时服务端按拒绝处理）与同意/拒绝；
  - 登出清空转录与会话指向（换账号不残留）。
- 面板开/收改为 200ms **滑入/滑出动画**（AppShell 在 animate-out 播完前保持挂载再卸载），此前生硬闪现。
- 纯逻辑覆盖：SSE 帧解析器（跨 chunk 半截缓冲、CR 容忍、坏 JSON 跳过）与 store 流式状态机（发送/停止/错误/审批）共 15 例单测。

## 后端

#### 安全

- **Agent 工具调用按用户身份执行（confused deputy 修复）**：共享 MCP 是一份进程服务所有律师，而 `mcp_server` 一律用服务账号（库里为 superuser）调 REST API——任何律师都能借 agent 读到全所数据，写操作审计也记在服务账号名下，且审批只拦删除/外发类写操作，读操作零门槛。现改为：
  - `apps/agent/pi/user_token.py`：每轮对话开始前为发起会话的律师铸一个无状态 access token（寿命同全局 `ACCESS_TOKEN_LIFETIME`，不发 refresh），**铸不出（用户被删/停用）即整轮拒绝**，不退回服务账号；
  - token 经 pi 子进程 env `FACHUAN_USER_TOKEN` 注入，`mcp.json` 以 `"Authorization": "Bearer ${FACHUAN_USER_TOKEN}"` 引用（pi 1.3.0 支持 header 的环境变量展开，本地 `docs/mcp.md:55`），不落盘明文；
  - `mcp_server/identity.py`：streamable-http 入口包上纯 ASGI 中间件，把请求头 Authorization 存入 ContextVar（anyio `to_thread` 会拷贝 context，同步工具同样读得到）；`client.py` 发上游请求时优先透传，无有效 Bearer 才回退服务账号（stdio/手工场景行为不变）。
  - 378 个工具零改动：归属过滤、权限、审计与律师直接登录完全一致。

#### 新功能

- `GET /api/v1/agent/sessions/{id}`（会话详情）与 `GET /api/v1/agent/sessions/{id}/messages`（消息历史，旧→新，含 tool 消息与 `metadata`）：此前 docstring 写了「详情」但端点不存在，历史只在服务端回放进 prompt，前端重开会话必然空白。不归属当前用户的会话与不存在的会话同样 404，不泄露存在性。
- `PATCH /api/v1/agent/sessions/{id}`（重命名会话，标题去空格、空标题 400）：侧边栏改名入口。

#### 修复

- **中途停止/断连丢失已生成文本**：助手消息落库原在 `finally` 之后，客户端断开触发的 `GeneratorExit` 路径跑不到——用户看着几段回答按停止，重开会话全没了、下一轮上下文也缺。现把落库挪进 `finally`，取消/出错路径同样保住已流出的部分回答并标 `metadata.truncated=true`；取消路径里 `await` 可能被再次打断，改派独立任务兜底。

#### 优化

- **删掉 `llm_model` 死字段**：`SessionIn` / `MessageIn` 接受并存储 `llm_model`，但 `stream_chat` 根本没这个参数，模型只由 `FACHUAN_PI_MODEL` 与 LLMProvider 默认决定——前端若做模型选择器就是在骗用户。入参契约移除；`SessionOut.llm_model` 改为回报服务端解析出的**实际使用模型**（每轮对话回写）。
- **会话标题自动生成**：`title` 为空时取首条用户消息前 30 字，侧边栏会话列表不再是一排 UUID。

#### 测试

- 新增 `tests/ci/unit/agent/test_agent_identity.py`（凭证铸造/停用拒绝、env 与 mcp.json 配线、取消路径落库、标题与模型回写、铸造失败 fail-closed）与 `tests/ci/unit/mcp_server/test_identity.py`（Bearer 判定、中间件→ContextVar→工作线程传播、client 透传优先且不触发服务账号登录）；集成测试补会话详情/历史端点的归属与 payload 断言、标题自动生成断言。

- 生产部署仍需按 `apps/agent/README.md` §7–8 配齐 `FACHUAN_INTERNAL_TOKEN` / `FACHUAN_APPROVAL_URL`（默认指 dev 的 8002 端口，公网栈 gunicorn 在 8003）/ `FACHUAN_PI_BIN`，当前 `deploy/env/prod.env` 一项都没有；nginx `proxy_read_timeout` 需 ≥300s 以覆盖审批等待。本版不含这些配置变更。
