# v27.8.4

## 后端

#### 安全（审批策略改为注册表校准）

- 高危工具判定从固定名单改为**子串模式**（`DANGER_PATTERNS`）：对照 mcp_server 实际注册表发现旧名单 6 个名字中 3 个（send_document / file_lawsuit / submit_court_document）在 378 个工具里根本不存在，而 39 个 `delete_*` 只拦住 8 个。新策略覆盖一切删除、对外发出/递交/上传、归档确认、批量清空重置；刻意不拦 `create_`/`update_`（业务写由服务层归属兜底）与 `sync_`/`export_`（无破坏性）。pi 侧 `approval-gate.ts` 同步为同一模式清单。
- 新增注册表对账测试 `test_danger_patterns_cover_mcp_registry`：加载 mcp_server 全部工具，断言每个删除类/外发类工具都被审批模式拦住——新增工具忘进审批从此是红灯而非静默免审。

#### 修复

- `send_message` 会话不存在分支把 bytes 直接当 `StreamingHttpResponse` 内容，被 Django 逐字节迭代成 int 再 `str()`，前端收到一串十进制数字而非 SSE 事件；改为传单元素迭代器。

#### 测试

- 新增端点级集成测试 `tests/ci/integration/test_agent_api.py`（6 例）：会话 CRUD 与归属隔离（他人看不到/发不进/删不掉）、pi 缺失时 SSE 返回 error 事件且用户消息已落库、未知会话、审批回调 token 鉴权与无订阅者 fail-closed、审批决定归属（他人不可批且状态不变）、审批列表可见性。测试内关闭 Redis 跨 worker 判定——否则继承 `.env` 的 REDIS_URL 会让无订阅者的审批硬等 300 秒。

#### 验证

- 延迟按「每请求进程」新架构实测（真实 LLM kimi-2.6，含工具限制 / AGENTS.md / 共享 MCP）：串行单轮 0.8–1.5s，4 路并发总 1.93s，进程 spawn <0.05s——per-request 进程模型的代价可忽略，README 旧的池化口径数据已标注。

#### 依赖变更

- pip-audit 豁免清单登记 2026-10-21 上游新发 advisory（pillow 12.3.0 × 8、certifi 2026.7.22 × 1，当日打挂全仓 CI 的依赖审计步骤；main 同样命中，非本分支引入）。修复版本分别为 pillow 13.0.0（major，需回归 image_rotation/OCR 管线）与 certifi 2026.10.19（patch），升级放独立依赖批次处理，复评日期 2026-11-30。
