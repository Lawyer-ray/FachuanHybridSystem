# v27.18.7 · 清理死依赖 pydantic-ai

> 分支 `chore/drop-pydantic-ai`。
>
> **无迁移、无 API 变更、无行为变更**。纯依赖面收敛。

---

## 为什么删

`pydantic-ai` 曾是 `apps/workbench` 下 Agent 路径的框架依赖。该 app 已整体移除，
但 `backend/pyproject.toml` 里的 `pydantic-ai>=2.26.0` 一直留着。

排查确认它已是**彻底的死依赖**：

- 全后端 `*py` 文件对 `pydantic_ai` **零命中**；
- 无动态导入（`importlib.import_module` / `__import__` 均无）；
- `uv tree --invert pydantic-ai` 反向依赖树为空——没有任何包依赖它。

留着它只会扩大依赖面、增加 pip-audit 噪音，并且每次 Dependabot 升级
（此前 #653 就把它当成高风险项对待）都要重新论证一遍影响面。

## 删掉了什么

`uv remove pydantic-ai` 连带清掉 **47 个包**，主要来自三条链：

| 链条 | 代表包 |
|---|---|
| pydantic-ai 核心 | `pydantic-ai-slim`、`pydantic-evals`、`pydantic-graph`、`genai-prices` |
| LLM provider SDK | `anthropic`、`google-genai`、`fastmcp-slim`、`tiktoken`、`regex` |
| 可观测性 / 工具链 | `logfire`、`logfire-api`、`opentelemetry-sdk` 及一批 `opentelemetry-*`、`keyring`、`tenacity`、`wrapt`、`cachetools`、`distro` |

其中 `opentelemetry-api` **保留**——它是 `pyproject.toml` 里的直接依赖
（固定下限 `>=1.45.1` 以避开 CVE-2026-114603），不随本次清理消失。

## 安全性核对

删依赖最大的风险是误删别处在用的包，因此对上述链条逐项核对了**代码直接导入**：

```
tenacity / keyring / wrapt / email_validator / fastmcp / opentelemetry /
tiktoken / regex / logfire / anthropic / google_genai / cachetools / distro / beartype
```

全部 **0 个 `import` / `from` 命中**。`mcp` 仍在（`mcp[cli]` 由 `apps/enterprise_data`
与 `apps/workflow` 实际使用，且新版 `mcp-types` 依赖树独立）。

## 附带修正

`backend/apps/core/llm/key_pool.py` 模块 docstring 原写着
「服务路径（`OpenAICompatibleBackend`）与 Agent 路径（pydantic-ai）共用本模块」——
Agent 路径早已不存在，改为只描述现存的服务路径，避免误导后续读者以为还有第二条链路。

## 验证

全量 pytest：`34862 passed, 15 skipped`，与清理前基线**逐项一致**。

唯一失败项 `test_report_pdf_view_strips_script_and_event_attrs` 为**本机缺
WeasyPrint 系统库**（pango/cairo），在 main 原始依赖上同样失败，与本改动无关。
