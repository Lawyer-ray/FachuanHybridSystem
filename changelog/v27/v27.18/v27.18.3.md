#### 修复

- **document-parsing 表格内容不再从 parsed.text 丢失 + 三处连带静默误判**（`122fa068`）
  - 主问题：MinerU 表格块 `text` 恒为空、内容全在 `table_body` HTML，原 `_extract_text_from_content_list` 只取 text 块 → 表格 100% 丢失（实测 164 页卷宗 94 个表格块修复后正文涨到 132891 字符）。新增 `_content_block_text()` 让 text/layout 两条路径同源；Textin 侧同缺陷（Table 整类被排除）同批修掉。
  - 连带一：正文与页眉同文时正文被吞 → 改「出现 2 次以上才算真页眉」。
  - 连带二：双引擎比对把每张表判成 high 分歧 → runner/normalize/VL 三处入口显式剔表格。
  - 连带三：图形页判据把 text+table_body 叠加算两遍 → 改「去标签 table_body 或 text，不叠加」。
  - 顺带清掉注释里的真实当事人姓名（换占位名）。

- **document-parsing PDF 一律 OCR + 云端回调 + 解析参数静默失效**（`6309dedd`）
  - MinerU `is_ocr` 放错层（批量接口应在 `files[]` 元素而非顶层）→ 按后缀显式 `files[].is_ocr=true`，补齐 language/enable_table/enable_formula。
  - Textin `parse_mode` 被 pydantic `extra="ignore"` 静默丢弃 → 改走 `EngineConfig.engine_params`，PDF 显式 `scan`。
  - 新增云端回调支持，取代自写轮询。

- **document-parsing 注释按实测修正 + pytest 冷启动超时 + 回调环境变量**（`260285b1`）
  - 实测纠正：vlm 下 `is_ocr` 开关逐字节无差异，注释从「质量优先」改为真实理由（切回 pipeline 时防扫描件静默空白）；`enable_formula` 收敛为常量并写明真实理由。
  - pytest 冷启动超时：`timeout_func_only=True` 只给用例主体计时（建库不再被 30s 一刀切误杀）；移除默认 `-n 2`（xdist 派生多测试库互抢是超时放大器）。
  - `.env.example` 补 DOCUMENT_PARSE_WEBHOOK_BASE_URL / MINERU_CALLBACK_UID / TEXTIN_CALLBACK_SECRET 三项并写清留空即轮询。
