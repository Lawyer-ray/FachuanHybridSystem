# v27.1.9

本版本补齐法院短信处理弹窗的**故障可见性**与**退出通道**：下载失败/卡住时把具体报错亮给用户（不再永远卡在「下载文书」转圈），并新增「停止并删除」按钮一键彻底终止任务——连同 Django-Q 里的重试调度与排队任务一起清理。无数据库迁移。

## 前端

#### 新功能

- **「停止并删除」按钮**（处理中 / 等待超时 / 失败三种基调可用）：两段确认（首击武装 4 秒、再击执行），删除成功 toast 提示并回到初始态、刷新收件箱；红色危险样式复用新增的 `BTN_DANGER` 常量

#### 修复

- **下载失败不再卡死在「下载文书」**：`download_failed` 从前端终态改为非终态——后端 retry_count<3 时本来就会建 +60s 一次性调度自动重试，此前前端把它当终态停轮询，用户停在错误页错过自动恢复；现在弹窗跟随轮询走完（恢复→继续跑，重试用尽→真终态失败）
- **处理中弹窗展示具体报错**（此前 running 态只有步进器）：`download_failed` 显示错误信息与重试进度（第 N/3 次）；`downloading` 期间爬虫层出错（指数退避重试中）透出具体错误；等待超时态也把后台已知错误亮出来，不再只给一句「继续等待」

#### 优化

- **轮询会话化**：每次开启轮询分配会话号，重试 / 中止删除 / 重开弹窗后旧轮询自动退出——修复记录被删除后旧轮询 404 计数、把 UI 拖回「幽灵超时」态的竞态

## 后端

#### 新功能

- **`POST /automation/court-sms/{id}/abort-and-delete`**：彻底终止一条短信处理任务（`CourtSmsAbortService`）——删除该短信的 Django-Q 重试调度（SMS 级 `court_sms_retry_download_{id}` + 爬虫级指数退避 `retry_task_{task_id}_n`）、按签名 payload 精确匹配清理 broker 队列中的排队任务（Redis 与 ORM 双 broker）、删除短信记录与归属的下载任务（级联删 CourtDocument，下载原件随 post_delete 信号清理；已归档到案件日志的复制件不受影响）。正在执行中的 worker 无法强杀，但各入口对记录不存在均安全返回
- **详情接口透出下载子任务状态**：`CourtSMSDetailOut` 新增 `download_task_status` / `download_task_error`——downloading 卡住时爬虫层（ScraperTask）的报错比 SMS 状态先知道，前端据此展示具体错误而非干等

#### 测试

- 新增 `CourtSmsAbortService` 单测 11 例：签名队列条目匹配（含数字子串误配防护）、SMS 级/爬虫级重试调度清理（无关调度不误删）、记录删除与外来任务保护、Redis/ORM 双队列清理路径；前端 `stages.test.ts` 同步更新 download_failed 非终态断言
