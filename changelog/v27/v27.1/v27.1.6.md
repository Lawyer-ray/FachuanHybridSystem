# v27.1.6

本版本重设计法院文书智能识别的交互：识别出的日期不再自动写提醒，改为**律师逐条人工确认后才写入重要日期提醒**；案件绑定对齐法院短信纪律（严格匹配才自动绑，否则转推荐卡片人工选）；前端「记一笔」支持上传文书走同一套识别管线。另含 cases 模块一轮代码审查修复。**后端含一次加列迁移（0004：日期候选表 + 任务新列；本地开发库已应用，合并部署到其他环境时需 migrate）。**

## 前端

#### 新功能

- **记一笔升级：📎 上传/拖入法院文书**（新 feature `document-recognition`）：QuickAdd 上传 → RecognizeDialog 识别轮询（404 宽限）→ 推荐卡片 + 搜索绑定案件（可跳过）→ 日期候选勾选/改时间/改类型 → 批量写入提醒；未绑定任务创建独立提醒
- 纯文字路径的日期解析升级：全部候选进同一确认弹窗（不再只取第一个）
- 首页 SideCards 联动文书识别入口

## 后端

#### 新功能

- **日期候选人工确认**：新模型 `DocumentRecognitionDateCandidate`（行级状态机 pending/confirmed/skipped，reminder 回链 + `select_for_update` 幂等防双击）；任务新增 `date_confirmation_status` / `party_names` / `source_court_sms` 列（迁移 0004）；confirm-dates / revoke / pending 新端点；确认写入 `include_in_important_time=True`，按 `(case_log_id, due_at)` 复用存量旧提醒
- **绑定期彻底不写提醒**：提醒唯一入口改为日期确认接口；案件绑定改严格匹配（规范化精确 + 在办 + 唯一）才自动绑，否则 `PENDING_MANUAL_BINDING` 转推荐卡片（法院短信零行为变化）；所有文书类型均可绑定
- LLM 单次结构化分析新增 `key_events` 多日期事件（类型/原文/置信度）+ `party_names`；正则路径透出全部候选并按上下文关键词推断类型（修降级模式全标开庭的误判）；两路按 (日期, 类型) 合并去重
- 管线预留缝：recognize 支持 `source_court_sms_id` 预绑定（法院短信管线复用已建日志，跳过建日志/附件/通知）
- admin 工作台改两步式（绑定 → 日期确认），支持 `?task=` 装载历史任务、待确认侧栏、DateCandidateInline、确认进度列与筛选

#### 修复（cases 代码审查，b5640067）

- P0：`parse_document_view` 补路径约束（防任意文件读取）+ POST 方法守卫；导入服务附件路径 MEDIA_ROOT confinement（防 `../` 逃逸）；删除 `constraint_checks_disabled` 强删兜底（IntegrityError 改报错引导，不再绕过外键留孤儿）
- P1：caselog 列表 API 逐条预热提醒改批量（消灭 N+1）；`_latest_reminder` 收敛单一缓存派生；云存储账号解析下沉 service；建档服务内部错误不再随 API 外泄；`save_formset` 事务包裹 + 指派批量预查重；吞异常处补日志
