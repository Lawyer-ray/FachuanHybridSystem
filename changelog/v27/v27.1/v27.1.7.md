# v27.1.7

本版本为法院文书智能识别补上**视觉管线与确定性提取层**：扫描件改用多模态模型视觉转写（kimi-2.6 实测读图质量远超本地 OCR，能读手写签名与表格），本地档引入 macOS Vision；案号/日期新增不依赖 LLM 的规则层，从根上修复「案号选成引用案号」「期间起止日双报」两类误报。工作台补齐预览、默认案件列表、联系人/地址展示、上传前选模型等体验。**后端含一次加列迁移（core 0027：LLMProvider.vision_model；本地开发库已应用，合并部署到其他环境时需 migrate），并新增 darwin 平台标记依赖 pyobjc-framework-Vision（Linux/CI 自动跳过）。**

## 前端

无变更。

## 后端

#### 新功能

- **视觉转写管线（供给配置化）**：`LLMProvider` 新增 `vision_model` 字段（admin「AI 平台」表单可改，**换供给只改这一行**），LLM 层消息类型放宽支持多模态（`image_url` 分段 content）。文本提取阶梯：文本 PDF 直接提取 → VLM 视觉转写（逐页 150dpi 渲染、页数上限 5、单页超时 120s）→ macOS Vision（darwin 自动优先，`accurate=0/fast=1` 反直觉坑已写入 docstring）→ RapidOCR 跨平台兜底；每档失败自动降级，任务不失败
- **案号确定性层**：括号全半角归一化（OCR 混宽是漏配根因）→ 全量枚举 → 位置/引用句式加权（「根据…（案号）裁定书」中的引用案号重降权，文首自身案号优先），正则命中优先于 LLM 并记交叉校验日志
- **日期候选期间规则**：「从X起至Y止」的起始日不再作为提醒候选；中文数字期间（壹年）+ 起始日算术推算到期日，可校正 OCR 乱码年份（如 20254→2025）；同上下文候选去重
- **联系人/地址提取**：标签锚定正则（联系人/承办法官/书记员 + 联系电话/地址），读时从 raw_text 现算、不落库不加迁移（存量任务即时生效）；展示于工作台结果卡、admin 任务详情，并写入绑定案件日志正文
- **工作台文书预览**：任务状态接口新增 `file_url`（MEDIA_ROOT 相对路径转 `/media/` URL），结果卡头部「预览文书」弹层（PDF=iframe / 图片=img / 可新窗口打开）
- **案件下拉默认加载全部在办案件**：空输入/聚焦即展示（按创建时间倒序、上限 200，预加载秒开），不再要求先输入 ≥2 字符；统一切到轻量接口 `/court-document/search-cases`（不再走重量级 CaseOut 全量序列化）
- **上传前可选识别模型**：recognize 接口可选 `llm_model`（校验在可用模型列表内，非法 400）；工作台上传区上方模型下拉（来自 `/api/v1/llm/models`，默认模型排首位）；「提取方式」新增 `vlm=AI视觉转写` 标签

#### 修复

- **任务列表页 500**：`date_confirmation_display` 的 `format_html` 无参数调用——Django 6 起直接抛 TypeError，任一行日期候选为 0 即整页崩（AST 扫全后端仅此一处）
- **案件列表接口 500**：存量证件表 `file_path` 列实际可空（历史遗留），46 行 NULL 老数据打挂严格 schema `ClientIdentityDocLiteOut` 序列化；`from_model` 空值归一为 `""`，对外契约不变
- 识别任务异步执行期 TypeError：`CourtDocumentRecognitionServiceAdapter` 转发签名补齐 `llm_model`（改协议/内部服务签名必须同步 adapter）；模型下拉在 admin 全局 select 样式下文字被裁（定高 40px + 自适应宽度）
- 案件搜索接口 `created_at` 字段误返回收案日期，改回真实创建时间

#### 优化

- 日历案号读取走 prefetch 缓存消除 N+1 查询（reminders）；EMS 协议轮次补 deadline 守卫使 timeout 真正生效（express_query）
- 新增 `apps/document_recognition/README.md`（架构、提取阶梯、供给配置 Runbook、确定性层、API、迁移清单）

#### 依赖变更
