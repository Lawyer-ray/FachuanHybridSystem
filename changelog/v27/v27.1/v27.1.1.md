# v27.1.1

本版本的主线是**新一代前端（`frontend/`）正式接入社交登录**：登录页从「只有账号密码」扩展为「账号密码 + 社交身份」的多方式登录，并补齐了**绑定 / 解绑闭环**与**只放行已绑定身份**的安全策略。后端把 Provider 抽象重做了一轮——授权上下文收进单一对象、支持 `redirect` 与 `embedded_qr` 两种登录形态，配置源从环境变量迁到 SystemConfig（密钥加密存储、改完即生效、无需重启），并新增飞书与 Google 两个 Provider。前端登录页同期做了一次**编辑 / 时装杂志风**的视觉改版，首页快捷工具里用**文档解析**替换了 LPR 计息。

## 前端

#### 新增

- auth：**登录页接入多方式登录**。新增 `login-methods.ts` 登录方式注册表，把 `/social/providers` 下发的 Provider 与「账号密码」合并为统一的 `LoginMethod` 列表，按 `kind`（`password` / `embedded_qr` / `redirect`）派发渲染器；以后新增 redirect 型 Provider 只需后端加配置，登录页不动
- auth：**飞书内嵌二维码登录**（`SocialQrPanel`）。注入飞书二维码 SDK，`postMessage` 同时校验 `matchOrigin` 与 `matchData`（只校验其一均可被伪造登录），通过后拼接 `tmp_code` 整页导航；含 SDK 懒加载、二维码刷新与错误重试
- auth：**Google 网页登录**（`SocialRedirectPanel` + `GoogleIcon`）。按钮改用白底配官方四色 G 标，符合 Google 品牌规范
- auth：**账号绑定页**（`BindingsPage` + `/settings/bindings` 路由）与**绑定弹窗**（`BindProviderDialog`）。一个平台只能绑一个账号，换绑需先解绑；弹窗按 `login_mode` 复用二维码面板或跳转面板
- auth：**社交登录回调页**（`SocialCallbackPage` + `/social-callback` 路由）。解析回调用一次性码换取 JWT 后跳转目标页，`ref` 防严格模式重复兑换（临时码仅可用一次），`redirect` 参数做开放重定向校验
- auth：`social-api.ts` 统一封装 `/social/providers`、`/social/{provider}/session`、`token-exchange` 与绑定 / 解绑接口；token 交换成功后写入 localStorage，与账密登录保持同一约定
- auth：`social-callback-domain.ts` / `social-format.ts` 抽出回调域名解析与展示格式化纯函数，配套单测
- navbar：账号菜单的「个人中心」占位改为「账号绑定」，直达 `/settings/bindings`
- home：**快捷工具用文档解析替换 LPR 计息**（`DocParseCard`）。接的是后台「文档解析工作台」同一套能力（MinerU / TextinParse / 本地），把原本只能进 admin 的上传解析搬到首页；按所选后端限制可选格式与文件大小，提交前拦截必然失败的请求

#### 优化

- auth：**登录页整体视觉改版为编辑 / 时装杂志风**，替换原先的渐变 + 玻璃拟态。近黑画布配暖白文字、全页只保留单一黄铜强调色；层级不靠阴影和卡片，改用极端字号对比、极细分割线与编号索引条；表单改为下划线输入框 + 直角按钮 + 下划线标签页；补印刷颗粒质感与底部能力走马灯
- auth：窄屏改单列布局，隐藏品牌栏并在表单区补精简标识；二维码落在浅色底板上以保证可扫描性
- auth：整页跳转型登录的文案与键盘交互打磨
- auth：**登录页配色提亮**。原画布 `#0b0b0c` 接近纯黑，表单栏仅比它亮 5%，双栏看不出层次、整页发闷；次要文字又靠压低不透明度表达层级（30% 白，对比度约 2:1，低于 WCAG AA 的 4.5:1），小标签与说明文字灰得看不清。现改为深灰画布 + 明显提亮的表单栏，层级改由明度承担；分割线与黄铜色随之微调

#### 修复

- auth：**修复扫码成功后闪回登录页**——换取 JWT 后未写入 token，补上 `setTokens`
- auth：**修复社交回调页 404**——Vite 字符串形式的代理 key 是前缀匹配，`'/social'` 会把前端路由 `/social-callback` 一并转发给 Django；代理 key 改为正则 `'^/social/'` 精确匹配后端路径
- auth：**修复账号绑定页接口 404**——社交 API 路径缺前导斜杠，被按相对路径解析

#### 测试

- 新增 `login-methods.test.ts`、`social-api.test.ts`（校验 token 落盘）、`social-callback-domain.test.ts`、`social-format.test.ts`、`doc-parse-formats.test.ts`

## 后端

#### 新增

- social_auth：**Provider 抽象重做**。`providers/base.py` 引入 `LoginMode`（`redirect` / `embedded_qr`）与 `AuthorizationRequest`，把授权上下文收进单一对象并支持 session 序列化往返，为 PKCE 预留 `code_verifier` 字段；`exchange_code` 签名改为接收 request；`ENDPOINTS` 支持多 Host
- social_auth：**`FeishuProvider` 内嵌二维码扫码登录**。二维码 SDK 只支持旧流程，故授权页走 `passport.feishu.cn`、令牌走 `accounts.feishu.cn/oauth/v3/token`、用户信息走 `open.feishu.cn`；scope 取最小集 `contact:user.base:readonly`；账号唯一键用 `union_id`（跨应用稳定）
- social_auth：**`GoogleProvider` 网页登录**（redirect 型），默认 scope `openid email profile`
- social_auth：**Provider 配置源从 settings 环境变量迁移到 SystemConfig**（新增 `social_auth` 分类，密钥加密存储）。admin 修改即失效缓存、无需重启进程；上线换域名只需改回调地址
- social_auth：**飞书凭证复用 IM 群聊的飞书应用**。`fallback_credentials` 留空即自动借 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`，无需在社交登录分类里重复填写
- social_auth：**绑定 / 解绑闭环**。`SocialAccount` 新增 `(user, provider)` 唯一约束；新增绑定 / 解绑 service 与 API 端点；登录策略改为**只放行已绑定身份**——首次使用需账密登录后到 `/settings/bindings` 完成绑定
- social_auth：新增 `SocialAccountAdmin`；律师 admin 增加社交账号内联视图、列与筛选
- social_auth：新增 `signals.py`，SystemConfig 变更时失效 Provider 缓存（含被借用的共用凭证），修掉运行中新启用 Provider 后列表长期不刷新的问题
- social_auth：新增 `POST /api/v1/social/{provider}/session` 供前端获取授权 URL；`GET /social/providers` 增加 `login_mode` 字段
- core：SystemConfig 新增 `social_auth` 分类与默认配置项（飞书 / 微信 / Google 的 App ID、Secret、回调地址、scope、开关）
- 后台：`social_auth` 从 admin 侧边栏隐藏，收纳到「其他工具」聚合页

#### 修复

- social_auth：**修复扫码登录回调 500**——`TempAuth.token` 缺默认值，补 `uuid.uuid4`
- social_auth：**修复本分类 App Secret 未解密**导致 Provider 认证失败
- social_auth：**修复扫码登录 422**——session 端点不再强制要求 body
- social_auth：session 端点限流改用 EXPORT 档，不再误伤正常扫码
- social_auth：Google 回调默认地址改用 `localhost`，与前端访问 host 对齐
- social_auth：回调视图统一 state 校验、`next_url` 开放重定向防护、多平台错误参数归一化
- core：修复默认配置描述超长（272 字符 > `SystemConfig.description` 的 `varchar(255)`）导致「初始化默认配置」抛 `DataError`；该问题会伪装成 organization 的注册用例失败（`FirstUserSetupService` 会顺带初始化默认配置），已补默认配置数据的完整性单测

- settings：移除 `SOCIAL_AUTH_PROVIDERS` 环境变量配置块；`FRONTEND_BASE_URL` 默认值与 CORS 白名单由 `5173` 改为 `5090`，与新一代前端 dev 端口对齐

## 说明

- 本版本含 **3 个数据库迁移**，部署时需执行：
  - `core.0025` — SystemConfig 新增 `social_auth` 分类
  - `social_auth.0002` — `SocialAccount` 新增 `(user, provider)` 唯一约束
  - `social_auth.0003` — `TempAuth.token` 补默认值
- **部署前须清理存量数据**：同一律师在同一平台存在多条社交账号记录时会触发唯一约束冲突，需先清理
- 登录策略变为只放行已绑定身份，存量用户需先账密登录后到 `/settings/bindings` 完成绑定
- 上线前须在飞书开发者后台「开发配置 → 安全设置 → 重定向 URL」精确登记回调地址（不支持动态路由，`?` / `#` 后缀会被忽略，不匹配返回 `redirect_uri unmatch`）；Google 需在 GCP 配置对应的 redirect URI
- 微信 Provider 代码保留但**当前不可用**：微信开放平台不接受个人主体，且业务域名必须完成 ICP 备案。详见 `backend/apps/social_auth/README.md`
