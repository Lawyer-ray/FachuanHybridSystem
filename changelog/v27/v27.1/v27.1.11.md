# v27.1.11

四张快捷工具卡补齐「历史」能力：文档解析、要素式转换、DOC 转 DOCX 三张卡像法院短信一样加入「历史」按钮，可浏览过往记录、重新查看/下载结果。**后端含一次加表迁移（doc_convert 0003：DocConvertRecord，合并部署到其他环境时需 migrate）。**

## 前端

#### 新功能

- **三张工具卡新增「历史」入口**（卡片头部，与法院短信同款按钮）：文档解析 / 要素式转换 / DOC 转 DOCX
- **文档解析历史弹窗**：同一弹窗内「列表 ⇄ 详情」切换（不叠第二层弹窗）——列表分页（状态徽章 + 文件名 + 正文预览 + 引擎 + 时间，按全部/已完成/失败筛选）；点某条在弹窗内切到详情视图看解析全文（头部「← 返回」回列表），复制 / 下载 .md / .txt 与结果弹窗同款（复用提取出的 `doc-parse-outcome.ts`）
- **要素式转换历史弹窗**：列出每次转换（原文件名 + 文书类型 + 时间）；成功记录行内直接重下 docx，失败记录显示具体原因；支持两段确认删除单条记录
- **DOC 转 DOCX 历史弹窗**：列出过往任务（状态 + 件数 + 时间）；点开任务在同一弹窗内切换到详情视图，逐件下载或打包下载 ZIP，「← 返回」回列表
- 历史弹窗共用零件抽到 `tools/history/`（HistoryButton / HistoryHeader / HistoryPager / 徽章配色），三个新弹窗与法院短信弹窗同布局同交互

## 后端

#### 新功能

- **要素式转换历史落库**（此前 convert 是纯转发，产物即焚）：新增 `DocConvertRecord` 模型（迁移 0003，产物 docx 经 `DatedUUIDPath(doc_convert/output)` 落盘，post_delete 信号清理）；convert 端点每次转换成败都落一条记录；新增 `GET /doc-convert/records`（分页 + 状态筛选）、`GET /doc-convert/records/{id}/download`（重新下载产物）、`DELETE /doc-convert/records/{id}`
- **文档解析历史 API**：`GET /document-parsing/records`（分页列表，含 100 字预览与状态筛选）与 `GET /document-parsing/records/{id}`（text/markdown/metadata 全文）；数据源为既有 `DocumentParsingTask`（v27.1.10 起前台异步解析已落库），本地同步引擎不建记录，历史覆盖云端解析
- **DOC 转 DOCX 任务列表**：`GET /doc-converter/jobs`（分页，最新在前，复用既有 job payload；详情/下载沿用既有端点）

#### 测试

- 新增 `DocConvertRecordService` 单测 5 例（落库 + 文件清理 + 列表筛选 + 未知 mbid 兜底）；convert 端点既有测试适配落库 mock
- 浏览器实测三个历史弹窗全链路：解析历史点开 92 页白皮书全文正常渲染、要素式成功/失败记录与删除清理、doc-converter 历史 job 逐件/打包下载入口
