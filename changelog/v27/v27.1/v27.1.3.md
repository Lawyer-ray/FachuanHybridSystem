# v27.1.3

本版本修复**立案流程在 CloakBrowser 拟人化模式下必然失败**的问题：客户弹窗 iframe 用 `page.frame_locator()` 定位，其生成的链式选择器被 humanize 层的隔离世界解析器直接拒绝，立案中断。改为取真正的 `Frame` 对象后，既绕开链式选择器，又保留拟人化点击/输入。**仅后端改动，无数据库迁移。**

## 后端

#### 修复

- oa_filing：**修复立案报 `UnsupportedHumanizeSelectorError`**。客户弹窗 iframe 原先用 `page.frame_locator(xpath=...)` 定位，FrameLocator 的 locator 会拼成 `xpath=... >> internal:control=enter-frame >> xpath=...` 链式选择器；CloakBrowser 的 humanize 层在隔离世界里只用原生 DOM API 解析选择器，**不支持 `>>` 链式定位、`frame_locator`、`get_by_role`、`:visible` 等**，遇到即抛错，导致合同详情页立案标签下点「添加委托方」后流程中断
- oa_filing：新增 `_resolve_client_frame`，改用 `page.query_selector()` 定位 iframe 元素后取 `content_frame()` 得到**真正的 `Frame` 对象**。选择器随后在子 frame 自己的 `document` 里解析，humanize 走 frame 级补丁——实测该 frame `_human_patched=True`，**拟人化点击/输入仍然生效**，并非退化为 `humanize=False`
- oa_filing：`_try_select_client` / `_create_new_client` 的参数类型由 `FrameLocator` 改为 `Frame`，与调用方保持一致
- oa_filing：委托方按钮的文案回退选择器去掉 `#wrap >> a:has-text("委托")` 的 `>>` 链式写法，改为 `#wrap a:has-text("委托")`，消除同类隐患

#### 测试

- 离线复现脚本验证机制（不随代码入库）：`page.frame_locator().locator().fill()` 精确复现该报错；`query_selector().content_frame()` 后 `frame.locator().fill()` 成功写入并确认 frame 级拟人化补丁已生效

## 说明

- 本版本**不含数据库迁移**，部署无需执行 `migrate`
- 本版本**无前端改动**
- 真实 OA 立案链路需线上会话，未做端到端验证；已通过离线复现确认报错成因与修复机制，`tests/ci/unit/oa_filing/` 全量通过
- **已知同类隐患（本次未处理）**：`jtn/case_import/playwright_browser.py` 有一处 `page.get_by_role("button", name="确定")`，`get_by_role` 同样不被隔离世界解析器支持。该调用包在 `except Exception: pass` 中，异常被静默吞掉、不影响主链路，仅导致「关闭模态框」这一步降级失效，留待后续单独处理
