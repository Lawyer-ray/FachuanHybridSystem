# v27.1.0

本版本的主线是**新一代前端界面（`frontend/`）正式落地「首页 · 今日工作台」与材料预处理工作台**，并在后端把**日程日历的合并 / 归一化 / 统计收敛为单一事实来源**，前端与 Django admin 共用同一套口径，消除两边各算一套导致的漂移。前端在大功能落地后又做了一轮**反巨石重构**——拆分全部超过规模红线的巨石文件、清理死代码、收敛 feature 边界，并据此做了 **React 最佳实践整改**（修掉重构引入的回归 bug、收敛重渲染、补齐可访问性）。全程 `tsc` / `eslint` / `vitest` / `vite build` 全绿，无数据库迁移。

## 前端

### 新增

- **首页 · 今日工作台**（`features/home`）：接入真实数据的综合工作台，含日历面板、今日安排、待处理流入（收件箱）、快捷工具四大块。按 feature-first 组织为 `api/`、`domain.ts`（纯函数 + 单测）、`constants`、`ui`、`errors`、`types`，responsibility 清晰
- 首页快捷工具三个卡片：**要素式转换**（`/doc-convert`）、**DOC 转 DOCX**（`/doc-converter`，带轮询进度与 zip 下载）、**LPR 计息**（央行报价分档计算）
- **全局检索**（⌘K，`components/shared/GlobalSearch`）：跨域命令面板检索，支持分类筛选标签与命中计数、方向键高亮选择，接入 navbar
- 首页 **新增安排弹窗支持关联对象**（合同 / 案件 / 案件日志三选一，关键字联想 + 分类 tab）；对应后端 `reminders/target-options` 由 admin 组合标签拆成 `title`/`hint` 两字段
- 端到端验证脚本 `scripts/e2e_home.py`：用真实数据跑首页 → 各快捷工具 → 日历的完整链路

### 优化

- **navbar 收敛为全站唯一组件**（`components/shared/AppNavbar`）：首页与材料预处理共用同一套；退出登录加确认弹窗、头像改下拉菜单
- **日历按庭审合并展示**，对齐 admin 口径；点日历空白格直接新增安排（去掉独立的「新增安排」按钮）；事件点开有详情弹窗、日格加高并显示律师、事件行时间独立成行以用满宽度
- 日历行数按当月实际需要渲染，不再固定 6 行，切月高度不抖动
- 路由切换加入场过渡（`PageFade`），并修掉两处整页刷新式跳转

### 修复

- 修日历上/下月切换按钮图标消失（图标被 2px 内容区压成 0 宽），并固化「图标被容器压扁」的检查防止同类复现
- 修材料包最后几页只转骨架屏不渲染（PDF 文档单槽缓存互相杀）；修阅读器追加材料按钮显示两个加号；修云端内容识别 400（PDF 缓冲被 pdf.js 抢占致上传空文件）
- 修全球检索输入闪烁、删空关键词后残留旧结果、小屏弹窗横向溢出

### 重构

- **反巨石重构**：拆分全部越过规模红线的文件——`draft.ts`(447 行) → `draft/` 目录 6 模块 + barrel、`home/api.ts`(417 行，混 6 个后端资源) → `api/` 目录、`DeskPage.tsx`(468 行，超 450 硬红线) → 4 个子组件 + 3 个 hook、`reader/Reader.tsx`(439 行) → ops/keys/widths/dialogs。拆分全部用 barrel 保住 import 路径，调用方零改动；整改后无任何源文件超过 350 软红线
- 修依赖倒挂：新建 `reader/layout.ts` 收编列宽常量与计算，`Reader` 不再反向 import 子组件 `Flow` 的常量
- 清理死代码：删零引用的 `lib/date.ts` / `format.ts` / `file-utils.ts`、`use-attachment.ts`，修剪 `lib/api.ts` 与 draft barrel 的死导出，修 `PdfSplitSegmentSuggestion` 双定义、`store` 与 `draft` 的 `renameMat` 重复实现；补 `material-prep` / `auth` 的 `index.ts` feature barrel
- **React 最佳实践整改**：`Reader` 整树订阅改 selector、`flowOps`/`metaOps`/OCR 回调固化让 `PageCell`/`PackCard` 的 `memo` 真正生效、`marksOf` 由每格 O(N×M) 改预算成 `Map` 与 `Set`、`ring`/键盘订阅从「每次按键拆装」改为只挂一次、两处轮询补卸载取消；补齐一批可访问性（段名改 `button`、全局检索补 `DialogTitle`、`PackCard` 修嵌套交互、弹窗补 `DialogDescription`）

## 后端

### 重构

- reminders：**日历的合并 / 归一化 / 统计收敛到后端单一事实来源**。新增 `calendar_month_service.py`、`calendar_view_service.py`，把「同一庭审多条 reminder 的合并、当日事件排序、今日/7 日/当月开庭统计」统一到 service；前端首页与 Django admin 日历现在共用同一口径，避免两边各算一套导致展示不一致
- reminders：`reminder_api.py` 日历视图接口改为消费上述 service；`schemas.py` 补充日历合并/统计的响应结构

### 修复

- reminders：日程案号改从关联案件的 `CaseNumber` 取（原先来源不稳定）

### 测试

- 新增 `tests/ci/unit/reminders/test_calendar_view_service.py`（481 行）覆盖日历合并 / 排序 / 统计逻辑；同步更新 `test_reminders_admin_coverage.py`
