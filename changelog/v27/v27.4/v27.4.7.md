# v27.4.7

「查ID」断供修复（2026-10-12）：SSO 会话过期恢复通道 + 搜索通道回退。本版本全部为后端修复，均为 oa_filing 案号查 GUID 链路。

## 后端

#### 修复：案号查 GUID 断供——缓存飞连 SSO 会话过期后自愈链死循环

- **现象**：合同编辑页「查询ID」报「OA 会话无法建立（网关/登录页循环）」。**根因**：v27.3.4 自愈链依赖磁盘缓存里 `access.jtn.com` 的飞连 SSO 会话（authorize 据此免交互发 code）；该会话数天后过期，纯 HTTP 链路每轮被弹到 SSO 门户登录页（飞连 SPA，JTN 租户仅一键/扫码/短信，无账密表单）死循环
- **修复**：自愈链新增第三层——**本机飞连客户端一键登录的纯 HTTP 复刻**。本机客户端在 `127.0.0.1:31080/v1/quick-login` 签发一次性 token（CORS 仅放行 access.jtn.com 来源），POST 门户 `/api/quick-login?os=web`（携带门户 csrf-token 头）兑换即恢复 SSO 会话，后续网关回调 → 应用层登录照旧。实测端到端打通（恢复后宽词检索正常命中）
- 细节：**`?os=web` 查询参数必须携带**（缺省时门户按非 web 客户端返回 194008「当前登录方式未开启」）；恢复前清缓存里过期的扁平 `session`/`csrf-token`（与门户新下发的域 scoped 值同名共存会 CookieConflict/旧值压新值）；一键登录身份=本机飞连客户端当前登录用户（单机部署即机主），OA 应用层仍按各律师自己的凭证登录，案件可见性按凭证账号过滤，两层身份不混用；客户端不可用时报「飞连客户端不可用」友好错误

- **修复**：搜索机制回退方法一（案件管理列表页 VIEWSTATE postback，v27.3.4 实证对表单登录会话可靠），三字段保留（project_no 案号 / project_name 案名 / **project_cust_name** 客户名——注意与对话框的 project_customer_name 不同名，字段名从列表页 HTML 实测提取）
