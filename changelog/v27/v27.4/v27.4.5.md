## 后端

### 修复：合同保存不再抹掉案件级手动添加的承办律师

**事故背景（2026-10-12，案件 389）**：案件 admin 手动添加的承办律师保存成功后，再次保存合同（哪怕零字段改动）时被静默删除。根因是 `sync_assignments_from_contract` 旧实现「先删光案件全部指派、再按合同指派重建」，合同上没有的律师直接蒸发，且成功路径零日志零提示。

**修复方案：引入来源标记 + diff 同步**

- `CaseAssignment` 新增 `source` 字段（迁移 `cases.0041`，存量行默认 `manual` 即受保护）：
  - `contract`=由合同指派同步生成，跟随合同（合同移除则删、新增则补）；
  - `manual`=手动添加/改派，任何合同同步不删除、不覆盖。
- `sync_assignments_from_contract` 重写为 diff 语义：只清理「合同上已移除的 contract 行」、只补建「合同上新增的律师」，manual 行原样保留；有实际变更时记 INFO 日志（`created_count`/`deleted_count`——注意 `created` 是 LogRecord 保留属性，extra 不能直接用）。
- 手动来源的标记点全覆盖：
  - 案件 admin inline 新增行 / 换律师改派行 → `manual`（`CaseAdminSaveMixin.save_formset`，标记逻辑抽 `_mark_assignment_source` 纯函数）；
  - API `create_assignment` 显式 `manual`；`update_assignment` 换律师 → `manual`；
  - OA 案件导入 `get_or_create` / 建案工作流走模型默认 `manual`；
  - 「从合同生成案件」流程 `create_assignment_internal` 显式 `contract`（该来源本就来自合同）；
  - 复制案件 `duplicate_case` 保留原行的 `source`。
- 合同侧每次保存仍会触发同步（`ContractSaveMixin.save_related`），但现在对无 diff 的合同是空操作，不再有删光重建。
