# v27.4.8

新建合同页两个「先保存才能用」门槛的放开。本版本全部为后端改动（Django admin 模板 + JS），无迁移。

## 后端

#### 新功能：新建合同页「查询ID」可用——无需先保存合同

- **原限制**：查询端点路由挂在 `/{contract_id}/lookup-oa-guid/` 下，新建页合同无主键拼不出 URL，前端直接拦截提示「请先保存合同后再查询」
- **放开**：新增无 id 路由 `/admin/contracts/contract/lookup-oa-guid/`（`lookup_oa_guid_view` 的 `contract_id` 参数改为可选——查询逻辑本就不依赖已保存合同：case_no 来自请求体、权限是模块级检查）；变更页旧路由原样保留；模板 else 分支注入新 URL
- OA 会话三层自愈（v27.4.7：缓存 → 飞连客户端一键登录 → 应用层账密）对新路由同样生效

#### 新功能：新建合同页「文件夹绑定」可用——保存后自动绑定，免二次操作

- **原限制**：文件夹组件只在变更页渲染（绑定接口 `/api/v1/contracts/{id}/folder-binding` 需要已保存的合同），新建页选不了文件夹，只能建完合同再进来绑定
- **放开（deferred 模式）**：新建页同样渲染文件夹组件，浏览/选择文件夹照常（浏览接口本就与合同无关），但**不发绑定请求**——选择写入表单隐藏字段（`_add_folder_path` / `_add_storage_type` / `_add_storage_account_id`）随表单提交；`ContractAdmin.response_add` 在合同落库后调 `FolderBindingService.create_binding` 补建绑定（复用既有 wiring 装配；云存储账号沿用 API 层同一解析服务 `resolve_active_storage_account`）
- **失败不阻断**：绑定失败（路径无效/云账号失效）只弹警告消息，合同创建不受影响（合同已落库，不能因绑定失败丢表单）
- 变更页组件行为不变（即时绑定/解绑）；组件徽章在新建页显示「已选择/未绑定」并提示「保存合同后自动绑定」

#### 测试（22 例全绿）

- 无 id 路由：URL 解析（新旧双路由）/ 405/403/400（含 JSON payload 断言，structure-tests 棘轮口径）/ 无合同成功返回 GUIDs
- 延迟绑定：未选择跳过 / 本地路径落库 / 云存储账号解析透传（AsyncMock）/ 账号失效仅警告 / 绑定失败仅警告不抛 / 非表单请求体健壮性
- 渲染断言：新建页注入无 id 路由 + `folderBrowser(0, true)` deferred 组件 + 提示文案；变更页保持带 id 路由与非 deferred 组件
