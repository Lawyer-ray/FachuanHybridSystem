# v27.4.1

分支 `feat/contract-archive-sync-improve`：合同详情页立案标签新增「合同附件自动上传至金诚同达 OA」。原「开始立案」只填表单不上传文件，OA「委托合同信息」的合同附件（必填项）需要人工在 OA 页面手动传；现在支持拖拽上传与绑定文件夹自动识别两条来源，立案时自动完成上传。

## 后端

### 新功能：立案合同附件三级来源解析（filing_attachment_service）

- 新增 `apps/oa_filing/services/filing_attachment_service.py`：立案附件按优先级解析——① 合同最新「合同正本」归档材料（拖拽上传的文件即落成它）→ ② 绑定文件夹自动查找合同文件（本地/云存储；pdf 优先于 docx、同名多版本取最新 mtime）→ ③ 都无则不上传（维持现状）
- 合同正本判定采用**父文件夹段前缀**规则（去编号前缀后以「合同」开头的段，如 `1-合同`/`合同发票`）：案由目录名含「合同」（如「…借款合同纠纷一案」）不再把委托材料下的执业证等误判进合同区（实测 373 逮到并修复）；区域外须命中强文件名关键词（委托合同/服务合同/合同正本等）且排除案由描述，宁缺勿滥
- 拖拽暂存 `stage_filing_attachment`：文件保存为 `FinalizedMaterial(category=contract_original)`（Material-first，content_hash 幂等去重），同时满足归档清单「委托合同」材料需求
- 新增 `POST /api/v1/oa-filing/attachment`（multipart，合同访问校验 + TASK 限流）；adapter `execute_filing` 构建 `ContractInfo` 时接入解析，解析失败不阻断立案

### 新功能：JTN 立案双链路自动上传合同附件

- OA 侧上传契约经逆向立案页 JS 实测摸清：上传端点 `js/legalup/code/LegalUp.ashx`（查询参数 `action=uploadfile&path=projectfiles&size=50&suffix=&encode=utf-8`，参数名以 attachment.js 的 serializeParam 为准），multipart 字段名 `upfile`，响应 `{state:"SUCCESS",url,original}`，成功后以 `filenamecontract_{guid}`/`fileurlcontract_{guid}` 隐藏域随表单提交（guid 为客户端随机串）
- HTTP 主链路：提交表单前逐文件 multipart 上传 LegalUp.ashx，把返回的 original/url 注入表单 payload；任一失败抛错整体回退 Playwright（避免"表单已提交但附件缺失"的半成品草稿）
- Playwright 兜底链路：「委托合同信息」Tab 填写后点 `upFile_contract` 上传弹窗（legalup iframe + webuploader，与盖章上传同族模式）`set_input_files` 多文件一次性上传，页面 JS 自动回填隐藏域，上传后校验附件行数
- `ContractInfo` 数据类新增 `attachment_paths` 字段

### 新功能：立案标签拖拽上传交互

- 立案标签新增虚线拖拽区（拖拽/点击选择 pdf/doc/docx），落地即保存为合同正本材料并显示状态；附说明文案「未拖拽时自动使用最新合同正本材料或绑定文件夹合同文件」
