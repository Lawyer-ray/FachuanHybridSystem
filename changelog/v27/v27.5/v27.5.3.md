## 后端（事故一：短信卡 pending）

#### 修复：法院短信任务入口错误兜底落库

- qcluster 未随代码更新重启，worker 内存残留旧模块，短信处理任务在服务装配阶段抛 ImportError 静默死亡，短信永远卡在「待处理」且无任何错误信息——admin 页面看不到异常、无法判断可否重试
- `automation/workers/court_sms_tasks.py` 四个任务入口（process_sms / process_sms_from_matching / process_sms_from_renaming / retry_download_task）补 try/except 兜底：进入处理服务**之前**的失败（import、服务装配等）也把短信落库为「处理失败」+ 带入口标识的 error_message，异常继续上抛给 Django-Q 记录
- Service 层 process_sms 自带的 FAILED 落库不受影响：已是 FAILED/COMPLETED 的记录跳过兜底，避免覆盖更精确的业务错误信息（`_process_from_matching` 原先连 service 层兜底都没有，静默 raise 一并补齐）
- 回归测试 5 例：ImportError 事故场景复现、usecase 执行失败、既有 FAILED 信息不被覆盖、COMPLETED 不回退、短信不存在时无副作用

- 触发链：dev qcluster 07:43 启动 → 12:49 PR #545 代码（`CaseAssignmentSource`）落到工作区 → 20:47 SMS #276 的处理任务被陈旧 worker 领取，import 新枚举失败 → 任务失败但短信状态停留 pending
- 处置：按 CLAUDE.md「Django-Q 队列与僵尸集群防范」清剿陈旧集群树、重启 qcluster、`recover_court_sms_tasks` 恢复积压短信

## 后端（事故二：群聊通知 app secret invalid）

#### 修复：SystemConfig 分类配置读侧解密

- 根因：`SystemConfigService.get_value` 读侧有 `_maybe_decrypt`，但 `get_category_configs` 直接返回库内原值；2026-10-04 安全审计把存量明文 secret 全量重加密（`enc:v1:` 前缀）后，飞书/企微/钉钉/Telegram 四个群聊 provider 经分类 loader 拿到的 APP_SECRET 是密文，原样发给平台 → 飞书回 `10014 app secret invalid`，建群/发消息全挂（10-09 起法院短信群聊通知三连失败，SMS #274/#275/#277）
- webhook 推送走另一条读取路径不受影响——「飞书推送正常」的体感与群聊失败并存的原因
- 修复：`get_category_configs` 与 `get_value` 同口径，值过 `_maybe_decrypt`（明文原样、密文解密、解不开降级返回原值）；消费面只有四个群聊平台 loader，无 API 回显路径，不引入明文泄露
- 实测：修复后用库内 secret 换 `tenant_access_token` 一次通过（code=0），SMS #277 补发群聊通知成功（案件 390 群已创建），secret 本身从未失效，无需去飞书后台轮换
- 回归测试 5 例（密文解密/明文透传/降级/provider 端到端/四平台参数化）
- 遗留（独立问题，非本次修复范围）：企微建群报「至少需要 2 人」，需在系统配置补充 `WECHAT_WORK_DEFAULT_MEMBER_IDS`

## 后端（事故三：列表页多行列换行失效）

#### 修复：Django 6.1 `format_html_join` 分隔符转义致 `<br>` 显示为字面文本

- 根因：Django 6.1 起 `format_html_join` 的 sep 也过 `conditional_escape`（旧版不转义），字面 `"<br>"` 分隔符被转义成 `&lt;br&gt;`——法院短信列表页「提取的案号 / 提取的当事人」两列多值全挤成一行带字面 br 文本
- 修复：`court_sms_admin_base.py` 模块级 `_BR = mark_safe("<br>")` 作分隔符；回归测试 2 例（真 `<br>` 渲染 + 当事人名仍转义防 XSS）
- 同病未修（文件被并行改动占用）：`documents/admin/document_template_admin.py` 落位预览列的 `format_html_join("<br>", ...)` 同样受影响，待该文件改动合入后跟进
