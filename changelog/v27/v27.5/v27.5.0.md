# v27.5.0

文书落位体系槽位化重构（第一步落地）：文书模板从「逐文件夹手工绑定」升级为「一次槽位声明」，新增文件夹模板后零绑定操作；路径改为生成期派生，结构改名不再腐烂。含 1 组加法迁移。

## 后端

#### 新功能：文件夹槽位（FolderSlot）受控词表

- 新模型 `documents.FolderSlot`（槽位键/名称/说明/启用），键一经引用不可修改、名称可随时改（身份是键不是名）
- admin 新增「文件夹槽位」管理页（列表含占位文书数，编辑页防止误改已引用的键）

#### 新功能：文书模板「落位槽位」声明（folder_slot）

- `DocumentTemplate` 新增可空外键 `folder_slot`（`SET_NULL`，存量行为不变）
- 文书模板编辑页新增「落位声明」区块：槽位下拉 + 「落位预览（实时派生）」只读字段（列出各骨架的派生路径与未提供槽位的骨架数）
- 声明一次即适用于所有提供该槽位的文件夹模板（含未来新增）；原「文件模板文件夹绑定」inline 保留为兼容通道

#### 新功能：槽位解析服务（SlotResolutionService）与生成入口切换

- 新解析器：文件夹模板 structure 节点支持 `kind` 标记槽位；生成时刻按 kind 派生落位路径，**不落库**——结构改名/调序自动跟随，根治存量 `folder_node_path` 保存时刻算死、改名后静默失效的缺陷
- 合同 ZIP 与案件 ZIP 两个生成入口切换为「生效绑定」迭代：存量绑定 + 槽位声明的虚拟绑定（已声明槽位但与该骨架无任何绑定行）——**新增文件夹模板后无需补建任何绑定**
- 解析优先级：槽位命中 → 派生路径；槽位未命中且为存量绑定 → 回退旧路径（记日志）；槽位未命中且为虚拟绑定 → 显式跳过（拒绝「塞进其他材料」式静默吞位）
- 模板与骨架已有任何绑定行（含停用）时不生成虚拟绑定——停用行代表显式意图

#### 新功能：回填命令 backfill_folder_slots（幂等，支持 --dry-run）

- 种子槽位词表（31 键，按开发库「去序号名称」归组推导，命名可在 admin 随时调整）
- 按「去序号名称 → 槽位名」前缀匹配回填全部文件夹模板节点的 kind（不覆盖已有 kind）
- 按绑定节点 kind 汇总回填文书模板的 folder_slot，名称子串决胜（修正病理样本：佛山送达地址确认书曾被绑进「其他答辩材料」，回填选 service_address 而非多数派）
- `complete_defaults.json` 数据源闭环：新增 `slots` 顶层键 + 文书模板 `folder_slot_key`，`initialize_default_templates` / `export_template_defaults.py` 同步支持

#### 优化：复制文件夹模板连带复制绑定

- admin「复制选中的模板」此前只复制结构——复制完还要手工补绑定；现在按 `folder_node_id` 平移全部启用绑定（副本结构节点 id 与源一致）

#### 优化：落位槽位选择器交互迭代（v27.5.1–v27.5.5）

- 槽位下拉从平铺 select 迭代为全站统一的 **select2 搜索式下拉**（`autocomplete_fields`，单框可搜可选），替代外挂过滤框与 optgroup 分组方案
- 槽位显示文本带**分类短标签**：`委托材料 (power_of_attorney) · 通用`、`送达地址确认书 (service_address) · 立案`——搜索、候选、选中态全链路可见类型；`FolderSlot` 新增 `category` 字段（迁移 0022）供词表管理
- 候选/选中态的分类渲染为**右侧胶囊徽标**（`slot_select_enhance.js` 重初始化 select2 注入 templateResult），无词候选按分类枚举序聚类（通用→立案→答辩→…→合同），接近分组标题的浏览效果
- 落位槽位控件尺寸加大（560×40，候选行加高），样式限定于落位声明控件不外溢

#### 优化：文件夹模板侧接入槽位体系（v27.5.6）

- 结构编辑器每个节点新增「槽位」下拉（词表经 json_script 注入），可为节点标记落位槽位；**修复编辑器序列化丢 kind 的缺陷**（extractStructure 此前只序列化 id/name/children，二次保存会抹掉全部回填的 kind）
- 列表页新增「提供槽位」列：N 类 + 分类聚合计数（通用×3 立案材料×7 …），悬停显示全量
- 解析预览树节点名后渲染 ⌘ 槽位徽标；保存时校验 kind 必须在词表内（防手写 JSON 打错字静默失效），校验逻辑下沉 `FolderTemplateAdminService.validate_slot_kinds`
- 词表按分类枚举序注入（通用→立案→…），下拉内分组自然聚类

#### 修复：OA 半自动页面浏览器窗口溢出屏幕——底部永远滑不到底（v27.5.7）

- **根因**：`jtn` 手动会话固定视口 1920×1080，有头模式窗口内容区被拉到视口等大，超出本机物理屏幕（逻辑 1800×1169），视口底部不可见且页面按 1080 高计算滚动——「打开OA」等四个半自动功能（利冲/盖章/归档/发票）无论如何滑动都到不了页面底部
- **修复**：`create_browser_async_manual` 调用方未显式指定 viewport 时按物理屏幕适配（AppKit 读真实屏幕，`--window-size` = 屏幕可用区域 + `no_viewport` 视口跟随窗口）；显式传 viewport 保持原固定视口语义
- macOS 指纹补丁的 screen 伪装参数化：屏幕适配会话报真实屏幕尺寸（与窗口自洽），其余会话维持 1920×1080 伪装不变；附带 DPR 回归真实值（Retina 下渲染更清晰）
- **修复关窗后 Chromium 僵尸进程在 Dock 常驻堆积**：macOS 点红色关闭按钮只关窗口不退进程，Playwright `disconnected`（进程退出）永远不触发，回收链路挂死。`wait_user_closed` 增加页面级结束信号（最后一个页面关闭 / context 关闭，多 tab 关一个继续等）；adapter 兜底清理 `_cleanup_stale_sessions` 改 async，对「窗口已关尽但进程还在」的会话补回收
- 测试 +5：屏幕适配/显式视口两分支、screen 几何回退、指纹 JS 默认与覆盖；测试 +4：页面级关闭信号（关窗触发/多 tab 保留/关尽即返）、兜底清理回收关窗会话

#### 优化：旧绑定通道退役（v27.5.7）

- 数据清理：删除佛山送达地址确认书在二审答辩/上诉的 2 条病理绑定（塞「其他答辩材料」）；东莞两份送达确认书补声明 service_address——存量 39 条绑定 100% 走槽位解析，兜底命中率归零
