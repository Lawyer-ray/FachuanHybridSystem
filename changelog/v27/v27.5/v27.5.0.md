# v27.5.0

文书落位体系槽位化重构（第一步落地）：文书模板从「逐文件夹手工绑定」升级为「一次槽位声明」，新增文件夹模板后零绑定操作；路径改为生成期派生，结构改名不再腐烂。含 1 组加法迁移。

## 后端

#### 新功能：文件夹槽位（FolderSlot）受控词表

- 新模型 `documents.FolderSlot`（槽位键/名称/说明/启用），键一经引用不可修改、名称可随时改（身份是键不是名）
- admin 新增「文件夹槽位」管理页（列表含占位文书数，编辑页防止误改已引用的键）

#### 新功能：文书模板「落位槽位」声明（folder_slot）

- `DocumentTemplate` 新增可空外键 `folder_slot`（`SET_NULL`，存量行为不变）
- 文书模板编辑页新增「落位声明」区块：槽位下拉 + 「落位预览（实时派生）」只读字段（列出各骨架的派生路径与未提供槽位的骨架数）
- 声明一次即适用于所有提供该槽位的文件夹模板（含未来新增）；原「文件模板文件夹绑定」inline 保留为兼容通道

#### 新功能：槽位解析服务（SlotResolutionService）与生成入口切换

- 新解析器：文件夹模板 structure 节点支持 `kind` 标记槽位；生成时刻按 kind 派生落位路径，**不落库**——结构改名/调序自动跟随，根治存量 `folder_node_path` 保存时刻算死、改名后静默失效的缺陷
- 合同 ZIP 与案件 ZIP 两个生成入口切换为「生效绑定」迭代：存量绑定 + 槽位声明的虚拟绑定（已声明槽位但与该骨架无任何绑定行）——**新增文件夹模板后无需补建任何绑定**
- 解析优先级：槽位命中 → 派生路径；槽位未命中且为存量绑定 → 回退旧路径（记日志）；槽位未命中且为虚拟绑定 → 显式跳过（拒绝「塞进其他材料」式静默吞位）
- 模板与骨架已有任何绑定行（含停用）时不生成虚拟绑定——停用行代表显式意图

#### 新功能：回填命令 backfill_folder_slots（幂等，支持 --dry-run）

- 种子槽位词表（31 键，按开发库「去序号名称」归组推导，命名可在 admin 随时调整）
- 按「去序号名称 → 槽位名」前缀匹配回填全部文件夹模板节点的 kind（不覆盖已有 kind）
- 按绑定节点 kind 汇总回填文书模板的 folder_slot，名称子串决胜（修正病理样本：佛山送达地址确认书曾被绑进「其他答辩材料」，回填选 service_address 而非多数派）
- `complete_defaults.json` 数据源闭环：新增 `slots` 顶层键 + 文书模板 `folder_slot_key`，`initialize_default_templates` / `export_template_defaults.py` 同步支持

#### 优化：复制文件夹模板连带复制绑定

- admin「复制选中的模板」此前只复制结构——复制完还要手工补绑定；现在按 `folder_node_id` 平移全部启用绑定（副本结构节点 id 与源一致）

#### 兼容与迁移说明

- 迁移 `documents.0021`（新建 FolderSlot + DocumentTemplate.folder_slot，纯加法）
- 部署后需执行：`python apiSystem/manage.py migrate` → `python apiSystem/manage.py backfill_folder_slots`（建议先 `--dry-run` 核对）
- 未声明槽位 / 未回填 kind 的存量数据走旧绑定路径，行为与升级前完全一致
