# v27.5.10

前端日历增加删除功能，权限口径「谁创建谁删」：A 律师不能删 B 律师建的日程，即使两人同在一个案件；管理员豁免。后端新增批量删除接口与日历事件 `can_delete` 标记，前端按标记显隐入口并走二次确认。同批重做窄屏（手机）日历交互：点格子不再误触新增、格内直接显示事项标题、整月一屏，抽屉 / 今日卡点事项可进详情。

## 后端

#### 新功能：提醒删除权限收敛为「谁创建谁删」+ 批量删除接口

- `reminder_access` 新增 `can_delete_reminder` / `ensure_can_delete_reminder`：仅创建人本人与管理员可删，**不论是否关联案件 / 合同**。创建人优先取 `created_by` FK，回退 `metadata.created_by_user_id`（案件日志等内部路径至今只写 metadata 不填 FK，与日历可见性 `_scope_for_context` 同口径，否则会「看得见却删不掉」）；无创建人记录（同步 / 导入产生、存量未回填、创建人已删）fail-closed，只有管理员能删。错误码 `REMINDER_NOT_CREATOR`
- 既有写判定 `can_write_reminder` 不动：改时间 / 勾完成对关联了案件的提醒仍放行给有访问权的同事（同案同事要能勾完成），只有删除另走更严的一档——否则 B 连 A 建的开庭提醒都没法标完成
- `DELETE /reminders/{id}` 改走删除判定；新增 `POST /reminders/delete`（`ReminderDeleteIn {reminder_ids}` → `{deleted}`）：合并事件（同一庭审多条同步）全部 member_ids 一次原子删除，任一条无权整批 403、一条不删。`ReminderService.delete_reminders` 逐条 `instance.delete()`，与单条路径同一套信号 / simple_history 记录
- `GET /reminders/calendar` 事件新增 `can_delete`：`CalendarMonthService.build_month` 按 AccessContext 用户标记，合并事件须全部成员可删才为 true；admin 内部调用不标记保持 False
- `backend/openapi.json` 重新导出（10-04 以来的存量漂移一并带上：passkey / download-ticket / 归档 ai-classify / 立案附件等，全部为新增路径与 schema、无删除）

## 前端

#### 新功能：日历事件详情弹窗增加「删除此安排」

- `EventDetailDialog`：仅 `event.can_delete` 时渲染删除入口（低调文字按钮，悬停才见红），点击弹 `AlertDialog` 二次确认（合并事件提示「同一庭审的 N 条同步记录会一起删除」），取消不下发、确认才回调；别人建的日程连按钮都没有，而不是点了才 403
- `api/reminders.ts` 新增 `deleteReminders(ids)` → `POST /reminders/delete`；`hooks/use-delete-reminder.ts` 乐观删除：onMutate 先从各月缓存里移除命中的事件（格子立即少一条），失败回滚快照并把后端 `message` 弹出来，onSettled invalidate 兜底；合并事件用 `eventReminderIds` 全量下发，与勾完成同口径
- `CalendarPanel` 新 prop `onDeleteEvent`，确认后先关详情弹窗再下发；`HomePage` 挂 `useDeleteReminder`
- `pnpm gen:api` 重生成 `api-schema.d.ts`（`CalendarEventItemOut.can_delete`、`ReminderDeleteIn / Out`、`delete_reminders` operation）

#### 优化：窄屏（≤760px）日历重做——点格子开抽屉、格内直接显示标题、整月一屏

- 根因（手机实测）：手机端事件只渲染成不可交互的圆点，日历格的点击把「非事件行」一律当成「点空白新增」——点圆点穿透成新增弹窗，详情永远开不了；格子沿用桌面 132px 起步高度，一屏只见两三周且全是空白
- `CalendarPanel` 手机断点（`useMediaQuery('(max-width: 760px)')`，与 `max-[760px]:` 类同口径）：点格子任意位置 = 选中该日开当日抽屉，绝不触发新增（新增走抽屉里的「＋新增」）；键盘 Enter 同理；格子 `aria-label` 改「点按查看该日安排」，不再挂桌面的 `title` 提示
- 格内标题列表：最多 2 条「紧要色圆点 + 标题截断」、余下 `+N`（格子仅 ~50px 宽，只够看开头几个字和颜色，全文进抽屉）；格高压到 72px、内边距 4px，整月在 390px 宽一屏内
- 详情弹窗从 `CalendarPanel` 上移到 `HomePage`：日历格（桌面）/ 手机当日抽屉 / 今日卡三个入口共用一个——以前抽屉与今日卡点事项只是 toast，窄屏上详情 / 勾完成 / 删除全都够不着；原「打开案件」toast 移到弹窗内的 `onOpenCase`；快照保鲜 effect 随之上移
- `DaySheet` 行尾提示「→ 打开案件 / 材料」改「→ 查看详情」
