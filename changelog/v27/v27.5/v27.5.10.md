# v27.5.10

前端日历增加删除功能，权限口径「谁创建谁删」：A 律师不能删 B 律师建的日程，即使两人同在一个案件；管理员豁免。后端新增批量删除接口与日历事件 `can_delete` 标记，前端按标记显隐入口并走二次确认。同批重做两处窄屏（手机）体验：日历点格子不再误触新增、格内直接显示事项标题、整月一屏，抽屉 / 今日卡点事项可进详情；材料预处理阅读器工具条不再被裁、取字 / 选页提示条有真退出按钮。阅读器随后做了第一批减负：删掉两个无后端效果的仪式性按钮（「完成拆分与归类」「拆分为文件」）与 `done` 字段，底栏整条移除，顶栏 / 工具条 / 段头各只留必要项；另修复列表页键盘高亮框拉伸窗口后错位。

## 后端

#### 新功能：提醒删除权限收敛为「谁创建谁删」+ 批量删除接口

- `reminder_access` 新增 `can_delete_reminder` / `ensure_can_delete_reminder`：仅创建人本人与管理员可删，**不论是否关联案件 / 合同**。创建人优先取 `created_by` FK，回退 `metadata.created_by_user_id`（案件日志等内部路径至今只写 metadata 不填 FK，与日历可见性 `_scope_for_context` 同口径，否则会「看得见却删不掉」）；无创建人记录（同步 / 导入产生、存量未回填、创建人已删）fail-closed，只有管理员能删。错误码 `REMINDER_NOT_CREATOR`
- 既有写判定 `can_write_reminder` 不动：改时间 / 勾完成对关联了案件的提醒仍放行给有访问权的同事（同案同事要能勾完成），只有删除另走更严的一档——否则 B 连 A 建的开庭提醒都没法标完成
- `DELETE /reminders/{id}` 改走删除判定；新增 `POST /reminders/delete`（`ReminderDeleteIn {reminder_ids}` → `{deleted}`）：合并事件（同一庭审多条同步）全部 member_ids 一次原子删除，任一条无权整批 403、一条不删。`ReminderService.delete_reminders` 逐条 `instance.delete()`，与单条路径同一套信号 / simple_history 记录
- `GET /reminders/calendar` 事件新增 `can_delete`：`CalendarMonthService.build_month` 按 AccessContext 用户标记，合并事件须全部成员可删才为 true；admin 内部调用不标记保持 False
- `backend/openapi.json` 重新导出（10-04 以来的存量漂移一并带上：passkey / download-ticket / 归档 ai-classify / 立案附件等，全部为新增路径与 schema、无删除）

## 前端

#### 新功能：日历事件详情弹窗增加「删除此安排」

- `EventDetailDialog`：仅 `event.can_delete` 时渲染删除入口（低调文字按钮，悬停才见红），点击弹 `AlertDialog` 二次确认（合并事件提示「同一庭审的 N 条同步记录会一起删除」），取消不下发、确认才回调；别人建的日程连按钮都没有，而不是点了才 403
- `api/reminders.ts` 新增 `deleteReminders(ids)` → `POST /reminders/delete`；`hooks/use-delete-reminder.ts` 乐观删除：onMutate 先从各月缓存里移除命中的事件（格子立即少一条），失败回滚快照并把后端 `message` 弹出来，onSettled invalidate 兜底；合并事件用 `eventReminderIds` 全量下发，与勾完成同口径
- `CalendarPanel` 新 prop `onDeleteEvent`，确认后先关详情弹窗再下发；`HomePage` 挂 `useDeleteReminder`
- `pnpm gen:api` 重生成 `api-schema.d.ts`（`CalendarEventItemOut.can_delete`、`ReminderDeleteIn / Out`、`delete_reminders` operation）

#### 优化：窄屏（≤760px）日历重做——点格子开抽屉、格内直接显示标题、整月一屏

- 根因（手机实测）：手机端事件只渲染成不可交互的圆点，日历格的点击把「非事件行」一律当成「点空白新增」——点圆点穿透成新增弹窗，详情永远开不了；格子沿用桌面 132px 起步高度，一屏只见两三周且全是空白
- `CalendarPanel` 手机断点（`useMediaQuery('(max-width: 760px)')`，与 `max-[760px]:` 类同口径）：点格子任意位置 = 选中该日开当日抽屉，绝不触发新增（新增走抽屉里的「＋新增」）；键盘 Enter 同理；格子 `aria-label` 改「点按查看该日安排」，不再挂桌面的 `title` 提示
- 格内标题列表：最多 2 条「紧要色圆点 + 标题截断」、余下 `+N`（格子仅 ~50px 宽，只够看开头几个字和颜色，全文进抽屉）；格高压到 72px、内边距 4px，整月在 390px 宽一屏内
- 详情弹窗从 `CalendarPanel` 上移到 `HomePage`：日历格（桌面）/ 手机当日抽屉 / 今日卡三个入口共用一个——以前抽屉与今日卡点事项只是 toast，窄屏上详情 / 勾完成 / 删除全都够不着；原「打开案件」toast 移到弹窗内的 `onOpenCase`；快照保鲜 effect 随之上移
- `DaySheet` 行尾提示「→ 打开案件 / 材料」改「→ 查看详情」

#### 优化：材料预处理阅读器（/material-prep/:id）窄屏重做——工具条不再被裁、完成按钮进底栏、提示条有真退出按钮

- 根因（手机实测）：`ReaderToolbar` 写死 `h-[56px]` 却又 `flex-wrap`，窄屏折出来的第 2–4 行被下方画布盖住——缩放 / 列数 / 云端识别只露半截，**「恢复初始分段」「完成拆分与归类」整行不可见**；底栏三段键盘提示各自折行；段头「并入上一份 / 拆分为文件」两个文字按钮把段名挤成「赖景浩-…」
- `ReaderToolbar`：桌面改 `min-h-[56px]` 允许换行可见（平板宽度也不再裁）；手机（≤760px）单行横向滚动 + 右缘渐变提示还有更多，隐去无信息量的「进度」徽章与恒禁用的「列数」，「完成」从工具条移走
- `ReaderToolbar` 手机再减三个按钮：缩放 `− / 100% / +` 只在桌面显示——触屏靠系统双指捏合（`index.html` viewport 未禁缩放，本来就能捏），按钮只是占横向空间；手机工具条最终只剩 材料 / 信息 / 选页 / 追加材料 / 云端内容识别 / 恢复初始分段 六项。布局规则改为 `material-prep.css` 手写 `.mp-rd-toolbar` 媒体查询：用户手机实测同一断点下 `max-[760px]:hidden` 生效、`max-[760px]:flex-nowrap` 却没压过 `flex-wrap`（工具条折成两行），手写规则不依赖工具类的生成顺序与层叠
- `KeyHintsBar`：手机藏掉全部键位提示（`Esc 逐级退出` / `⌘ 点页` / `在此切开`），只留归类状态，并承载「完成拆分与归类」主按钮（底部拇指区，不用横滚去找）
- `HintBar`：取字 / 选页提示条的「Esc 取消」从文字改成真按钮（手机没有 Esc 键，此前进了选页态就退不出来），退出口径与 `use-reader-keys` 的 Esc 一致（取字态清待确认 OCR + 取字目标；选页态清选区 + 退模式）；手机短文案不再提 ⇧ / S 键
- `ReaderTopBar` 返回键手机只留箭头（标题更要紧）；`SegmentHeader` 两个动作按钮手机图标化（`aria-label` 承担名称，`aria-pressed` 始终声明）；`SelectionBar` 浮条手机收进屏宽并允许换行、抬高到底栏之上；`Rail` 重命名铅笔在无 hover 设备常显（`@media(hover:none)`）
- `PageCell` 根节点补 `w-full`：页卡此前不定宽，骨架屏阶段在 `items-center` 容器里被内容宽收缩成中间一条窄卡（手机上尤其明显），PDF 渲染完才跳成整宽

#### 修复：材料包列表的键盘高亮框在拉伸窗口后与卡片错位

- 现象：拖动窗口宽度后，卡片外那圈黑色高亮框（`.mp-ring`）停在旧尺寸——拉宽后框比卡窄、拉窄后框比卡宽，1400→640 宽实测差 280px
- 根因：`useDeskRing` 的 resize / scroll / ResizeObserver 订阅只在首次挂载时建立，而 `DeskPage` 在 `isLoading` 期间渲染骨架、不渲染 `PackGrid`，首次挂载拿不到 grid / ring 节点，effect 提前返回后**再也不会跑**——窗口事件全没挂上，ring 只在 sel / 列表 / 页签变化时画一次
- 修复：以 `visible.length > 0` 作为「节点已就绪」的信号建立订阅；ResizeObserver 回调改为直接重绘（原先再包一层 rAF，拖拽时框慢一帧）；补听 grid 上冒泡的 `transitionend` / `animationend`，卡片自身动画结束再对一次；jsdom 无 ResizeObserver 时退化为只靠 window resize
- `PackCard` 根节点 `transition-all` → 只过渡 `transform / border-color / box-shadow`：网格重排时卡片宽度不该做 150ms 过渡（高亮框量到中间帧）
- `use-desk-ring.dom.test.tsx` +2：首屏无卡片不订阅、卡片出现后订阅且 resize 重绘；transitionend 后按终态尺寸重绘。真实 Chromium 验证 1400 / 760 / 640 / 1200 / 1000 六个尺寸框与卡片零偏差

- **删「完成拆分与归类」「拆分为文件」及 `Segment.done` 字段**：追查三条证据链——前端 `done` 只被这两个按钮写、只被段头自己读；后端 `draft_state` 虽整包存储但 7 个 resolver 只读 `status / segs[].t / mats[].pages / mats[].k`，无一读 `done`；归案启用条件是「每段选了类型」与 `done` 无关。它是原型遗留的仪式性状态，无处落地。旧草稿里残留的 `done` 键由后端当不透明 JSON 原样存着，前端不再声明即自然失效，无需迁移

- 底栏（KeyHintsBar）**整条删除**，桌面 / 手机都不再有：键位提示进 ⋯ 菜单，取字 / 选页模式本就有各自的琥珀提示条；归案留在顶栏单一入口。阅读区多 42 / 54px
