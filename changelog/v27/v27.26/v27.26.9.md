# v27.26.9 · Qoder 选模型 / 用自家网关：按官方文档重做，并撤回一个跑不通的入口

> **版本判定**：§1.2 同一条线（`v27.26.x` qoder）→ 第三位 +1（原号 `v27.28.4`）。

## 一句话

| 之前 | 现在 |
|:--|:--|
| 我按 wheel 源码猜「`resolve_model` 里塞 `{url, api_key}` 就能接自家网关」 | 读了官方文档 + 逐项实测：**必须先用 BYOK 注册 provider**（CLI 是 `/model → Custom`，SDK 是 `Daemon.create_byok_config`），否则 Qoder 回 `BYOK is disabled by your enterprise admin`（不是组织开关，是「没注册」） |
| — | 注册后 **CLI 直跑通了**：`qodercli -p … --model fachuan-gw/kimi-2.6` → 「收到」 |
| 但 SDK 通道（`--input-format stream-json`）选中 BYOK 模型报 `You do not have access to this model service` / `Sorry, something went wrong` | 这个入口**先藏起来**：模型下拉只列 Qoder 自己的 17 个（`FACHUAN_QODER_SHOW_BYOK=1` 可再打开做联调），并把这句错误译成「改回 Qoder 自己的模型 / 等打通」 |
| 内网网关带代理 → 502 空 body（`2026-11-27` 实测） | `build_env(direct=True)` 在「本轮会打到内网网关」时清空全部代理变量 + `NO_PROXY` |

## 实测记录（决定性）

```
# 1) 未注册 provider，直接 resolve_model 塞自定义模型
RESULT errors: ['BYOK is disabled by your enterprise admin. Please contact them for details.']

# 2) 注册 provider（Daemon.create_byok_config，baseUrl=律所网关）
check  -> {"success": true}
create -> {"providerId": "fachuan-gw"}
qodercli --list-models  → …  kimi-2.6 (fachuan-gw/kimi-2.6)

# 3) CLI 直跑（清代理；另外 --setting-sources "" 必须配 --settings 内联，否则回落 auto）
qodercli -p "回复两个字：收到" --model fachuan-gw/kimi-2.6 \
  --setting-sources "" --settings '{"providers":{…}}' --tools "" --permission-mode default
→ 收到

# 4) SDK（stream-json）同配置
errors: ['You do not have access to this model service. Please check your account permissions.']
```

结论：**能力在，但 SDK 通道还没打通**。下一步要么找 Qoder 支持确认 stream-json 下自定义 provider
的选择方式（`set_model` / initialize 顺序），要么这一栏改走 CLI 子进程（codex/opencode 那样的做法）。

## 改了哪些文件

- `backends/qoder_byok.py`（新）：`register_platform` / `list_saved` / `unregister` / `settings_payload` / `is_byok_model`
- `backends/qoder_models.py`：解析 `显示名 (provider/model)` 只取 id；`FACHUAN_QODER_SHOW_BYOK` 默认不列 BYOK 模型
- `backends/qoder_backend.py`：`build_env(direct=…)` 清代理；BYOK 轮次带 `settings=` 内联（只含 providers）；两句 SDK 报错译成人话
- 账号 `default` 上我注册的 `fachuan-gw` **已删除**（不留明文 Key 在跑不通的路径里）
