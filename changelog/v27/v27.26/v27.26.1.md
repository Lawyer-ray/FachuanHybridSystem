# v27.26.1 · 锁定平台不许静默降级 + 两类识别风险终于上了界面（列数突变 / 退化页）

> **版本判定**：`v27.26.0` 的延续（同一条「取字可靠性对人可见」主题线），只加第三位。
> 具体判据：两件事都在回答同一个问题——**机器算出来的结论，律师到底能不能看到**。

## 一句话

| 之前 | 现在 |
|:--|:-|
| 律师在「解析平台」里锁定 DeepSeek（或 Textin），而那台环境没配 Key → **静默回落本地 OCR**。任务成功、分段成功、进度条正常结束，界面一个字都不说明——他以为这就是 DeepSeek 的水平 | 任务**明确失败**，错误原文点名平台 + 明说「未降级」+ 给两条修复路径（去「解析平台」管理页启用 / 填 `DEEPSEEK_OCR_API_KEY` / 改为「自动」） |
| 同一份 PDF 先跑过一次（云端失败→本地兜底）之后，本地结果被写进「无平台」那份页缓存；改锁定 MinerU 重跑 → 命中该缓存 → pending 清空 → 守卫根本走不到 → **又一次静默降级** | 锁定不可用时**不采信页缓存**（那份档案里只可能存着本地结果），页留在 pending，守卫按设计抛错 |
| `degenerate_pages`（该页云端取字判为退化、正文被清空重取）只落磁盘侧车，**前端永远读不到**；三份真实卷宗实测退化率 10.8% / 5.4% / 22.6%，这些页和正常页长得一模一样 | 搬进 `summary_payload`，按页挂提示：`P147 云端取字判为退化，已换识别路径重取 · 建议核对原页` |
| `table_geometry.column_anomaly_pages`（列数突变 → 数字可能挂到错误表头下，即「余额被当成发生额」）同样只在日志里 | 按页挂提示：`P66 表格 7 列，上一页 P65 为 4 列 · 列可能被并/拆或换了模板，请核对数字表头`；左栏另有卷级计数徽标 |
| — | 多份 PDF 的包：信号**按源（`mi`）存**，A 份的 P5 退化不会显示到 B 份的 P5 段上 |

## 后端

| 文件 | 改动 |
|:--|:--|
| `services/split/pipeline.py` | 新增 `LockedCloudBackendUnavailable(RuntimeError)` + `locked_cloud_backend_message()`；`extract` 在候选覆盖前保存 `cloud_backend_requested` 并写进 `stats`；`_parse_cloud` 的「无候选」早退分支按「请求值 ∈ `CLOUD_BACKEND_CHOICES`」抛错；`_extract_from_text_layer_or_cache` 对该情形**跳过页缓存** |
| `services/split/service.py` | `segment_stage` 把 `degenerate_pages` 并进 DB summary（来源 `two_stage.load_extract_summary`），只收 `int` |
| `apps/pdf_splitting/README.md` | 复用示例补新异常与该契约 |

**为什么失败点落在 `_parse_cloud` 而不是入口**：纯电子件 + `fast_text` 在文本层定稿后就返回，甚至命中整本 OCR 缓存时也根本不调云端；入口 fail-fast 会误伤一批本来能跑的任务。只有在「确实要云端取字且一个平台都解析不出来」时失败，才既准确又不打扰。

**为什么不用 `ValidationException`**：pipeline 刻意不依赖 `apps.core`（`parser_factory` 会把它拉进来），且 `ValidationException` 的 `__str__` 带 `VALIDATION_ERROR: ` 前缀，会原样展示给律师。

**取舍（写在 docstring 里）**：`layout_mode=layout` + 纯电子件 + 锁定不可用 → **失败**。`layout` 故意不把「文本层可用」当成完事（那会连坐标都没有），所以这里不能回落文本层：锁定了就不许换路。

## 已知取舍与边界

- **不做卷级抽屉**：两类信号页数不多，按页提示 + 卷级计数已够，第三个入口是噪音。徽标因此是**不可点的说明性元素**（`cursor-default` + `aria-label`），不是「看着能点、点了没反应」的按钮。
- **`pageQuality` 仍有同样的「多 PDF 整键覆盖」老问题**（`ocr_failed_pages` 也是按最后一份存活）。本次只把新引入的形状做对，没有顺手动它——那是既有行为，改了要单独验一轮 `ocr_failed` 的所有提示与警告口径。
- **「平台已启用但调用失败 → 回落本地并成功」与「平台未启用 → 硬失败」不对称**，刻意保留：前者是瞬时故障（既有容灾语义），后者是配置错（必须让人知道）。
- **`OCRHandler.resolve_cloud_backend()`**（单值旧版，全仓零调用方）仍是「空候选 → None」的旧语义；本轮按范围不动，已在 changelog 记账。
- `types.ts` 446/450 行，两处单行改动；新类型全部落在 `quality-types.ts`。`SegmentMarkdown.tsx`(358) / `Rail.tsx`(375) / `RailSegRow.tsx`(369) 在 350–450 软红区间，拆分点都要新建文件，留给下一轮。
