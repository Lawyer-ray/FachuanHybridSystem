## 为什么这么接（四个不能省的判断）

### 1. 依赖冲突是真的，覆盖的**依据是实测**而不是「大概能跑」

`qoder-agent-sdk==1.0.17` 声明 `mcp>=1.0.0,<2.0.0`，而本仓库自己的 MCP 服务要求
`mcp[cli]>=2.2.0` —— 不加覆盖 `uv lock` 直接无解。加覆盖之前先核了两件事：

1. qoder 在**模块级**只 import 四个 `mcp.types` 符号（`ToolAnnotations` /
   `CallToolRequest` / `CallToolRequestParams` / `ListToolsRequest`），mcp 2.3.0 上全在；
2. `mcp.server.Server` 只在它建**进程内 SDK MCP server** 时才 import，而法穿只用外部
   HTTP MCP（:8011），那条路径永不触达。

两条都由 `test_sdk_import_surface` 钉住——mcp 升到删名的版本时当场红，而不是等真机跑对话。
覆盖写的是 `mcp[cli]>=2.2.0`（**带 extra**）：写成 `mcp>=2.2.0` 会把 `[cli]` 一起吃掉，
`typer` / `shellingham` / `annotated-doc` 从锁里消失（实测踩到，第一版就是这么写的）。

### 2. 未登录必须**秒级报错**，不能等 SDK 的 60 秒

`qodercli` 未登录时立刻退出并打印 `Not logged in · Please run /login`，但 SDK 的
`initialize` 控制请求会一直等到 `control_request_timeout_ms`（默认 60s）才抛
`Control request timeout: initialize`。律师看到的是「转圈一分钟 + 未知错误」，而真因是
一个 5 分钟能修好的「没登录」。

所以 `stream()` 在拉起真会话前先跑一次 `qodercli --list-models`（**仅在没配显式凭据时**），
看到未登录特征就抛 `BackendError(AUTH)` 并给出「去 `qodercli login` / 配
`QODER_PERSONAL_ACCESS_TOKEN`」的具体动作。**探测失败（超时/网络）一律不拦**——把
「探测不到」当成「没登录」会让离线部署被一句错误的提示卡死。同时收 CLI 的 stderr 尾巴，
把超时那一档也翻成人话。

实测（本机未登录）：`AUTH, retryable=False`，文案带原文 `Not logged in. Run 'qodercli login' to authenticate.`，
耗时从 60s 级降到 1s 级。

### 3. 工具面的安全边界要**重建**，而且要证明它真的发出去了

qoder 是代码 agent，内置 21 个工具（`Bash` / `Read` / `Write` / `Edit` / `WebFetch` /
子 agent …）。`tools=[]` 经 SDK 变成 `--tools ""`（CLI 文档：`""` to disable all）；
**写成「不传 `--tools`」等于全量内置工具**，提示注入只需要一次工具结果就能直通 RCE。

三道闸：

| 层 | 作用 | 位置 |
|:--|:--|:--|
| `disallowed_tools` | 不可逆删除类**连审批卡都不弹** | MCP 全名 `mcp__fachuan__delete_case` |
| `PreToolUse` hook | 把高危工具**强制置 `ask`** | qoder 的 `can_use_tool` 只在「CLI 觉得要问」时才被调用，它自己的分类器不能替律师放行 |
| `can_use_tool` | 真正的审批（落库 + 离线挂起） | 复用现有 `services/approval`，零改动 |

`test_hardening_flags_are_emitted` 不看我们的选项 dict，而是调 SDK 的
`build_session_args()` 把参数拼出来看：`--tools ""`、`--permission-mode default`、
`--permission-prompt-tool stdio`、`--setting-sources ""`、`--disallowed-tools mcp__fachuan__delete_case`、
`--allowed-mcp-server-names fachuan`、`--strict-mcp-config`、`--include-partial-messages`
逐条断言。**选项写对了但 SDK 不翻译成 flag** 的情况，只有这条能抓到。

### 4. 不用原生 session（与 pi 相反，与 claude-agent 一致）

每轮一条子进程，**不传** `resume` / `continue_conversation`。两个理由：

- 律师对话不能在多个会话、多个律师之间共用配置目录。配置目录只在**配了显式凭据**时
  才临时化（`finally` 删除）；否则必须复用本机 `~/.qoder` 登录态——**指到临时目录就等于
  「未登录」**，这是本后端最容易「看着配好、一跑就报未登录」的一处。
- 编排层在「无 pi session 但有历史」时会把历史渲染成 transcript 附在 prompt 前。再叠一层
  原生历史，同一句话会出现两次。

代价要认：跨轮没有原生上下文（上限由编排层的 transcript 回退负责），且**放弃了调研里
指出的「确定性压缩接管」**——qoder 的 `PreCompact` 只能观察、不能接管。

## 还没做的（上线前必须做，都需要一个已登录的 Qoder 账号）

1. **一次真实对话**：`qodercli login` 或配 `QODER_PERSONAL_ACCESS_TOKEN` 后跑一轮，
   确认正文 / 工具卡片 / usage 三段都正常（`test_qoder_backend.py` 只覆盖离线翻译）。
2. **高危工具必定弹审批卡**：让模型调 `submit_court_filing` 一类工具，确认审批卡出现、
   拒绝后工具未执行。若 qoder 的分类器在 `PreToolUse` 之前就放行，说明 `ask` 语义与
   claude 不同，需要改走 `McpServerToolPolicy(permission_policy="always_ask")`。
3. **MCP 工具全名确认为 `mcp__fachuan__<raw>`**：审批链按**全名**匹配（`DANGER_PATTERNS`
   子串）。若 qoder 用了别的前缀，审批会**静默失效**（工具照旧可调、没人被问）。
4. **`allow_byok >= 2`**：只有确认这个开关对我们开放，`MODEL_SOURCE=gateway` 才有意义
   （需要 Qoder 销售给书面口径）。
