# v27.13.2 · 收件箱并入预处理页 + navbar 简化为「预处理」

收件箱与材料预处理原本是 navbar 上两个并排的一级入口，但它们是同一条单向漏斗
的前后两段（`收件箱 → 拆包 → 归案`），并排摆放看不出先后关系。本次把两者合并成
一个页面、一套阶段页签，navbar 收敛为「首页 / 预处理 / 办案」三项。

## 前端

#### 优化

- **navbar 简化**：删除「收件箱」一级入口，`材料预处理` 改名为 `预处理`。
  导航从 4 项降到 3 项。`navPath` 判定同时覆盖 `/material-prep` 与 `/inbox` 前缀，
  前转期间高亮不会丢失。

- **收件箱并入预处理页**：新增一级「阶段」页签，顺序即漏斗顺序——
  `收件箱 · 待处理 · 已归案 · 不接归档`。层级变为「一级页签 = 流水线阶段，
  二级筛选 = 当前阶段内的切分维度」（收件箱视图内的来源档位 / 材料包视图内的三态），
  两套原先互相竞争的筛选条不再并排。

- **阶段入 URL**（`?stage=todo`）：可刷新、可分享、支持前进后退。缺省即收件箱阶段，
  因此 `/material-prep` 不带冗余参数。非法值一律回落收件箱，脏 URL 不会白屏。

- **动作区收拢到页面头部**：`客户链接` / `新建材料包` 移到阶段页签之上，
  四个阶段下都可见。上传后自动切到「待处理」（新包落在那里），
  从收件箱页直接把文件拖进来同样生效。

- **收件箱角标与列表同源**：一级页签上的收件箱计数复用收件箱列表的同一份
  react-query 缓存（同一 queryKey），不会出现「角标 12、列表 9」。

- **`/inbox` 保留为前转**，避免旧书签、控制台旧链接、首页收件箱卡的「查看全部」断链。
  `inboxPath()` 直接返回预处理页地址，调用点不需要知道重定向存在。

#### 结构调整

- `features/inbox/*` → `features/material-prep/inbox/`（子域）。收件箱现在是
  material-prep 域内的一个**视图**，不再是独立 feature——它与其共享页面外壳、
  上传动作与拖放层。这样避免了 feature 之间横切 import（`frontend/CLAUDE.md` 硬规则）。
- `InboxPage` → `InboxView`：去掉自身页面外壳（`<main>` / `<h1>`），只保留列表主体
  与详情抽屉。页面标题与阶段页签由 `DeskPage` 提供。
- 新增 `features/material-prep/stages.ts`：阶段模型的单一权威（页签顺序、
  `isPackStage` 窄化、`parseStage` 容错解析）。
- `app/preload.ts`：删除独立的 inbox chunk，`/inbox` 与 `/material-prep` 共用
  material-prep chunk（两者现在就是同一个页面）。

#### 测试

- 新增 `stages.test.ts`（10 例）：锁定页签顺序即漏斗顺序、`isPackStage` 窄化、
  `parseStage` 对缺省/非法/大小写错值的回落。
- `DeskPage.dom.test.tsx` 新增 4 例阶段编排：缺省落收件箱、`?stage=todo` 进材料包、
  非法 stage 回落、上传后自动切「待处理」。
- 同步更新 navbar / App / HomePage / InboxView 里涉及旧导航文案与 `/inbox` 跳转的断言。

全量：212 个测试文件 / 2528 例通过，`eslint` 与 `tsc -b && vite build` 均通过。
