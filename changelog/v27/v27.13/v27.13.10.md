## 前端

### 双视图结果区

`DocParseCard` 的结果弹窗拆成两个页签：

- **逐块复核**：按页分组的块列表，每块带分数徽标与复核原因；
- **全文**：原来的 Markdown/纯文本预览。

**默认落在哪个视图取决于数据**：有低分块时默认进「逐块复核」（此时用户最需要看的是
"哪里可能错了"，而不是"整体读起来很顺"——顺的文本恰恰掩盖了错字）；无低分块时仍默认「全文」，
不无谓改变既有习惯。页签上带红色计数徽标。

### 三态徽标（这是整个界面最要紧的一条）

| 状态 | 显示 | 含义 |
| --- | --- | --- |
| `unscored` | 灰色「未评估」+ 问号 | 引擎没提供可信度，**没人看过这块** |
| `risky` | 红色分数 | 低于阈值，建议人工核对 |
| `confident` | 绿色分数 | 阈值以上 |

刻意用三态而不是「有分/没分」的二分：

1. **未评估不能用绿色**。绿色等于替沉默背书，而实际上没有任何判断发生过——
   这比不给结论危险得多。未评估用中性灰 + 问号，视觉上明确"未知"。
2. **`confidence === null` 绝不等于 `0`**。null 是未评估，0 是评估过且几乎肯定错。
   全链路（后端协议 → API 归一化 → 领域逻辑 → UI）都保持这个区分，
   `formatConfidence(null)` 返回 `—` 而不是 `0.00`。
3. **未评估不自动进「需复核」清单**。否则引擎一不支持打分整页全红，
   用户会训练出"红色可以无视"的习惯，这个功能就废了。

### 其他交互

- **筛选**：全部 / 待复核 / 已评估 / 未评估，各带计数。
- **只看正文**（默认开）：页眉页脚页码常整段重复，混进来会稀释有限注意力。
- **按页折叠**：多页时默认展开有风险的页，其余收起；**单页时默认展开**——
  折起来等于把唯一的内容藏起来。
- **摘要行**：`reviewHeadline()` 根据统计生成，全部未评估时明说「均未评估（当前引擎不提供可信度）」，
  绝不会说成「全部在阈值以上」。
- 历史详情弹窗同样接入双视图（`HistoryResultTabs`），历史记录也能复核。

### 能力位只读不猜

`canAttachConfidence(coverage)` 要求后端明确 `has_blocks && has_bbox` 才认为可以裁图送判定。
**`coverage` 为 null（旧记录没存）时不显示"无可裁切坐标"**——这是真机验证时抓到的显示 bug：
历史记录没有 coverage，原实现会误报成"缺少坐标"，属于凭空报能力缺失。
