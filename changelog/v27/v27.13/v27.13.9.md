# v27.13.9 · 文档解析：补齐块级结构与可信度字段（为 OCR 质检层铺路）

## 需求

调研 MiniCPM-OCR + Jev（OCR 结果判定模型）能否用于法律文书识别质检时，卡在一个前置问题上：
**现有解析链路没有任何"最小可信度单元"**。

`ParsedDocument` 只有 `text / markdown / tables / metadata / images / layout` 六个字段，
`ParseOutcome`（前端）同样只有 `ok / markdown / text / method / error / metadata`。其中 `ok`
的语义是 **HTTP 请求成功**，但系统上下游一律把它当作 **内容识别正确** 来用 —— 所有 OCR
错字都是静默的，一路传到「案件信息提取」「合同审查」才以"AI 提取错了"的形式暴露。

Jev 这类判定模型的输入是「**块裁切原图 + 候选文本**」，因此必须先有块结构与坐标才谈得上接入。
本次只做基础设施：**把块级结构、能力位、可信度字段补进协议和数据模型，不接任何新引擎、不改选型逻辑。**

## 后端

### 协议层（`protocols/document_parser_protocol.py`）

- 新增 `ParsedBlock`：`type / text / bbox / page_no / confidence / needs_review / review_reason`。
  - **`confidence=None` 有确切语义：未评估**（后端无此能力或判定模型未运行/失败）。
    决不能把 None 当成 0 —— 0 表示"评估过，很可能是错的"，两者在复核界面上处置完全不同
    （前者「无法判断」，后者「优先复核」）。代码与前端都按此约定，序列化时原样透出 None。
  - `is_body()` 排除页眉页脚页码：这些块常整段重复且无信息量，送检/评分会把
    「页码 3」这种块的分数拉进统计，污染免检率指标。
- 新增 `ParseCoverage` 能力位：`has_blocks / has_bbox / has_confidence / has_page_geometry`。
  存在理由：选型与门禁判断必须看**能力**而非看失败。Textin 不返回原位可信度属于能力缺失
  而非解析失败，混为一谈会导致"无置信度就当低置信度"的误处置。
  `can_attach_confidence()` 表达 Jev 类外挂的前置条件（块 + 坐标）。
- 新增 `normalize_block_type()`：把各后端方言（Textin 的 `NarrativeText`、
  MinerU 的 `interline_equation`）归一到架构层词汇（`text/title/table/image/formula/header/footer/unknown`）。
  未知类型归为 `unknown` **保留而不丢弃** —— 宁可看到一个 unknown 块，也不要它凭空消失。
- `ParsedDocument` 新增 `blocks` 与 `coverage`（默认 `ParseCoverage()` 全 False：
  不声明即视为无能力，避免静默假设有）。

### 服务层（新增 `services/block_builder.py`）

独立一层，理由：后端解析（像素→文本）和块结构（文本→可定位单元）是两件事。

| 函数 | 作用 |
| --- | --- |
| `build_blocks_from_layout` | 从 `layout.pages[].blocks` 提取（Textin / MinerU 共用形状） |
| `build_blocks_from_lines` | 本地后端无 layout 时按文本行兜底 |
| `detect_coverage` | 能力位探测，**以数据为准而非以后端名为准** |
| `attach_blocks` | 宿主唯一入口，返回同一对象（PEP 695 泛型保类型链） |

几个刻意的判断：

- **能力位按实际数据判定**。Textin 理论上应给 bbox，但若某次坐标全为 None，能力位就该是
  False —— 否则下游裁图会拿到空区域并静默失败。
- **1 个块不算"块结构可用"**（下限 2）。单个块可能是巧合（整页只有一行标题），
  2 个起才说明分块确实在跑。
- **整幅插图页没有文本是正常的**（`image` 类块不参与文本块计数），不能据此判定分块失效。
- **文本行兜底只给本地后端**（`allow_line_fallback=True`）。云端后端拿不到 layout 说明
  本次返回异常，用文本行冒充块会掩盖问题。
- **坐标原值保留，不做换算**。Textin 的 element coordinates 与 MinerU 的千分比 bbox
  坐标系不统一，构建阶段换算错就再也对不上原图，由调用方按来源解释。

### 三个后端接入

`textin_backend` / `mineru_backend` / `local_backend` 的 `ParsedDocument(...)` 构造统一包一层
`attach_blocks(...)`；本地后端（PyMuPDF 与 RapidOCR 两条路径）额外开启行兜底。

### 数据模型与 API

- `DocumentParsingTask` 新增 `blocks = JSONField(default=list)`（迁移
  `0004_documentparsingtask_blocks`）。存空列表而非 None，前端统一单态。
- `mark_completed()` 增加 `blocks` 形参（缺省 `[]`）。
- `document_parsing_hook` 回写 `blocks`；**异步路径的块结构从此不再丢失**
  （此前 Q 任务结果里只有 text/markdown/metadata，块结构无处可存）。
- `ParseDocumentResponse` 新增 `blocks: list[ParseMemoryBlockOut]` 与 `coverage: ParseCoverageOut`；
  `DocumentParsingRecordDetailOut` 新增 `blocks`（历史记录为 None，可区分"没存"和"存了空"）。
- `tasks.py` 的 `_serialize_block` / `_coverage_dict` 用 `getattr` 防御：块结构是增强信息，
  后端未实现新版 Protocol 时缺字段不应让整次解析失败（这条是被测试逼出来的 —— 两个用
  `SimpleNamespace` 桩的既有测试当场炸出 `AttributeError`）。
