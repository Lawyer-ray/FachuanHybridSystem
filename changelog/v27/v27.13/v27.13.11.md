# v27.13.11 · 非诉专项详情页：阶段树 + 交付物表格

## 需求

非诉专项（合同 `case_type=special`）的工作推进方式和常法顾问完全不同：

- **常法**按「哪天做了什么」推进，事项天然散落成流水；
- **专项**按合同约定的**阶段**交付——尽调 → 方案 → 起草 → 登记 → 交割，每个阶段验收几份定稿文书，再按节点收款。

用流水（`ServiceItemStream`）表达专项，会把「现在卡在第几阶段」冲淡成 30 行日期。所以专项页的脊椎必须是**阶段树 + 交付物**，并且：

1. 阶段由律师自己设计（模板库 / AI 建议 / 手写三种起点混用）；
2. 阶段名可改、有层级递进（最多 3 级）、顺序可调；
3. 阶段就是文件夹——这些阶段最终都要建成目录交付给客户；
4. 点交付物在当前页展开 OnlyOffice，不跳页；
5. 从 0 起草：说清需求 → AI 起草 → 落到对应阶段。

设计过程见 `frontend/prototype/2026.10.03-办案详情原型/`（54 号，共 18 轮迭代记录）。

## 后端

### `Contract.stages`（结构化 JSONField）

此前只有 `representation_stages`——一个中文标签数组（`["一审","二审"]`），只够表达「代理了哪些程序」，表达不了「阶段顺序 + 每阶段验收标准 + 交付物 + 模板绑定」。

节点结构：

```json
{
  "key": "ph_dd",              // 稳定标识，改名不丢交付物
  "name": "尽职调查",
  "acceptance": "《尽职调查报告》定稿",
  "templates": ["尽职调查清单模板"],
  "date": "2026-10-26",
  "children": [],
  "deliverables": [
    { "date": "2026-10-27", "doc": "《...》", "ver": "v1", "state": "ok", "planned": false }
  ]
}
```

**主键是 `key` 而不是 `name`**：原型早期用名字匹配交付物，换模板再换回来时丢过一次数据（README 第十节），这是后端必须用稳定 key 的原型级证据。

迁移：`0049_contract_stages` + `0050_historicalcontract_stages`（含历史表）。

### 端点

```
GET  /api/v1/contracts/contracts/{id}/stages  → { stages: [...] }
PUT  /api/v1/contracts/contracts/{id}/stages  → body { stages: [...] }
```

整树覆盖而不是逐节点 patch：律师在弹窗里可能一次改名 + 升降级 + 删子阶段，逐条提交会产生中间态（「先删父阶段、再加子阶段」的顺序一旦颠倒就丢节点）。

校验（`STAGES_TOO_DEEP` / `DUPLICATE_STAGE_KEY` / `EMPTY_STAGE_NAME`）拒绝后不污染库里数据。

### `derive_phase_states`

状态**不存盘**，由交付物事实推导：有实际文件=已完成、第一个无文件的叶子=进行中、父节点由子节点聚合。

推导必须 **DFS 先序**。最初写成按层展开，顶层空阶段会抢走「当前阶段」，和原型 `phase-tree.js` 不一致。

顺带发现原型自身一个 bug：`every()` 短路会让父节点第二个及以后的子节点拿不到状态。Python 侧用列表推导避开了，行为与原型**测试的预期**一致而非与它**有 bug 的实现**一致。

## 前端

### 阶段与交付物 = 真正的 `<table>`

四列 `日期 / 交付物 / 版本 / 状态`，**不渲染表头**，层级只在「交付物」列内部用缩进表达。

**为什么必须是 table 而不是 flex/grid**——这是本轮最硬的技术结论。试了 6 种 flex/grid 方案全部失败，只要阶段行与文件行的内容不同，列就会错开 11px：

| 尝试 | 失败原因 |
| --- | --- |
| flex + `flex:1` | 阶段行多一个「＋起草」，该列宽度不同 |
| flex + 固定列宽 | 交付物列起点仍受前置元素影响 |
| grid + `1fr` | `1fr` 按内容最小宽度参与计算 |
| grid + `calc(100% - …)` | `100%` 依赖每行容器宽度 |
| 统一 padding/margin | 盒模型累积误差 |

`table-layout: fixed` + 四列固定宽度一次解决：列宽由浏览器统一分配，与单元格内容完全无关。实测四列的 `left` 各自只有一个值。

### 阶段树（`special-phase-tree.ts`，纯函数 + 19 例单测）

`flatten` / `indent` / `outdent` / `moveBy` / `moveBefore` / `rename` / `remove`，全部返回新树。

`indent` 有两个硬约束：前面没有同级节点不能降级（第一个节点下面挂不了东西），超过 3 级拒绝并给出原因。`outdent` 时原位置的后续兄弟跟着变成它的子节点——否则升级一个父节点会把自己的孩子留在原处，变成「孩子挂在叔叔下面」。

### 设计阶段（960px 两栏弹窗）

左：阶段主线（缩进 + 编号 `3.1`）；右：选中阶段细节（名称 / 验收标准 / 交付物清单 / 绑定模板 / 子阶段 / 让 AI 补全）。

两页签：**手工设计** 与 **✦ AI 设计（对话）**。

AI 设计是**多轮对话**而不是「给一版建议」：左栏草稿随对话实时变，每条 AI 回复列出「改了哪几处」，未命中时明确说没找到（不假装改），对话历史保留（关弹窗再开能接着聊）。

本轮不接 LLM：`special-design-assistant.ts` 是可注入的建议器接口，默认实现为确定性规则（照抄原型 `design-chat.js` 的规则语义），注释写清了将来接 copilot 的位置。

### 就地编辑三态（`DealDocLayout.tsx`）

| 形态 | 条件 | 布局 |
| --- | --- | --- |
| 未展开 | `picked == null` | 左内容 + 右事实卡 |
| 文档在右 | 展开 + 净宽 ≥1100 | 左内容（事实卡退左栏底部）+ 右文档 |
| 文档通栏 | 展开 + 净宽 <1100 | 文档置顶通栏，内容与事实卡在其下 |

净宽口径是「`100vw` − 助手宽度」而不是容器查询：助手是 `position: fixed` 抽屉，容器测不到它。

### 合同文件夹 = 阶段树派生

目录名 = `<编号>-<阶段名>`（如 `3.1-职工安置文书`）。不另存一份——原型里独立写死的目录名在阶段改名后立刻与左栏对不上。

## 过程中修掉的 6 个真实 bug

前 3 个由子 agent 实现带出、我在集成时发现；后 3 个由用户截图指出。

1. **阶段名完全看不见**：`min-w-0 truncate` 在兄弟全 `shrink-0` 时被压成 **0 宽**——文字在 DOM 里存在却完全不可见。加 `flex-1`。
2. **表格被挤扁**：AI 助手占 600px 后 main 只剩 840，`grid-cols-[1fr_360px]` 让左栏只剩 402px、交付物列 70px。改成净宽 <820 单列叠底。
3. **子阶段静默消失**：后端字段叫 `children`、前端内部叫 `folders`，直接透传导致被丢弃。`api/stages.ts` 加了双向适配层（同时对齐 `doc`↔`name`、`ver`↔`version`）。
4. **状态列「定稿」跑出卡片**：`.c-state` 缺 `overflow:hidden`，`text-align:right` + `nowrap` 下内容超宽会溢出到容器外。加宽状态列 168→196 并加裁切保护。
5. **全页 31 处字号 <11px（最小 8px）**：折叠箭头用 8px 的 `▾` 字符。改 CSS 三角伪元素，尺寸与字号脱钩；其余 `10/10.5px` 统一提到 `11px`。
6. **文件点不开**（三层原因叠加）：
   - `onToggle` 走 `saveStages` → PUT → 后端不存 `open` → 返回时洗掉，重绘后全收起；
   - 单击阶段名被 `closest('[data-rename]')` 直接 return（为双击改名让路）；
   - 每次点行都发一次 PUT。

   修法：展开/折叠只改本地（`setTreeLocal`），改名才落库；`open` 随写回往返并按 key 以本地为准合并；单击/双击用 220ms 延时区分。

## 说明

- **AI 设计是确定性规则替身**，不是 LLM。同一句话永远得到同一处改动，便于测试。正式落地时这一层换成 copilot 域的流式对话 + 一个能编辑阶段草稿的工具（类似现有 `rewrite_folder_file`，但作用对象是结构化草稿而不是文件）。交互形态、草稿与对话的双向联动、改动说明的展示方式与实现无关，可直接复用。
- **`open`（展开态）存进了后端 JSON**。它是纯 UI 状态，本不该入库，但往返丢它会导致「点开就缩回」。现按自由 JSON 存着、不参与任何校验；将来若要清理，在保存时剥掉即可，前端用 `keepOpenState` 兜底。
- 原型 `frontend/prototype/2026.10.03-办案详情原型/`（54 号 + `_audit54*.py` 自审脚本）保留作为设计记录，不入库（`.gitignore` 已排除 prototype）。
