# v27.2.14

两轮代码审计（并发正确性 / React 与 Django 最佳实践 / 安全 lint）+ 测试债治理的集中清偿批次，含分页契约收敛、四层架构下沉、openapi 类型生成基建；另并入 GitHub 登录（并行工作）。

## 后端

#### 修复

- **合同建档编号并发安全**：`select_for_update().count()+1` 的行锁在 Django 聚合查询中被静默丢弃（并发建档撞 `filing_number` 唯一约束；删除中间序号后 count+1 与存量冲突致该年度建档永久卡死）——改用 `pg_advisory_xact_lock` 串行化 + 解析存量最大序号 +1，无需 schema 变更
- **重试计数原子化**：法院短信 `_process_matching` 与爬虫 `ScraperTask` 的 `retry_count += 1` 读改写在 Django-Q 重投递/恢复服务并发时丢计数，致 OCR-OOM 熔断（≥3 次转人工）失效——改 `F()` 表达式原子更新；保险询价任务失败后不再 `raise`（django-q2 按 max_attempts=3 自动重跑会把外呼重复提交 3 次），改落库 FAILED 终态后返回
- **批处理资源与幂等**：`batch_runner` 主/重试路径的 `ThreadPoolExecutor` 补 try/finally `shutdown(cancel_futures=True)`（任务取消时不再泄漏最多 50 线程）；主路径重跑排除已完成 item（Q2 kill 重跑不再重复调用 LLM 烧 token）；`create_job` 的 job+items 写入补事务、submit 失败标记 FAILED 不留孤儿
- **async-unsafe 作用域化**：15 处进程级 `DJANGO_ALLOW_ASYNC_UNSAFE` 永久放行（其中 oa_filing 4 处在 web 进程内、labor_arbitration 模块 import 即污染）全部收敛到新工具 `allow_async_unsafe()` contextmanager（执行期间放行、退出恢复），并附迁移指引注释
- **静默降级可观测**：云存储目录列表 / 归档分类 / 聊天平台探测 / redis 预热四处 `except: return` 补 `logger.warning`（可用性故障不再伪装成"没有数据"）；cloud_storage 四端点 `str(e)` 收敛为通用文案 + `logger.exception`
- **无超时阻塞收口**：合同 OA 同步 submit 补 timeout=3600（原吃 600s 默认被 kill）、`future.result()` 补超时；legal_research ORM fallback 单 worker 与凭据校验的 `.result()` 补 60s
- **消息中心调度治理**：`sync_all_sources` 补 `cache.add` 抢锁防 30 分钟调度重叠；Playwright 收件箱同步任务补 timeout=1800
- **客户删除数据保护**：四处 `client` 外键 CASCADE→PROTECT（合同/案件/补充协议当事人、企查报告任务，迁移 0043/0038/0025 已应用）——删除客户不再静默清空业务当事人数据；`delete_client` 补前置守卫，有业务关联时抛业务异常并给出可操作引导（防裸 ProtectedError 500）
- **安全 lint 清零**：bandit `-ll` 39 条全部处置——7 处 XML 解析改 defusedxml（WebDAV 响应与用户上传 docx 的 XXE/billion-laughs 防御）、6 处 `mark_safe` join 改 `format_html_join` 官方等价替换、`/tmp` 硬编码改 tempfile；21 条带理由 nosec 豁免（沙箱 exec、SSR 名单误报、纯静态 HTML 等）

#### 优化

- **分页契约收敛**：9 类列表端点统一到 `paginate_queryset` 标准信封 `{items,total,page,page_size,total_pages}`（litigation/mock-trial 的 limit/offset、image_rotation 手解析 query、invoice 双信封、workbench sessions、workflow 硬编码 [:20]）；contracts 下线"不传 page 返回全量裸数组"旧口径；cases 未传 limit 一律默认 200（堵住宽过滤全表序列化）；admin 静态 JS 消费方一并适配
- **四层架构下沉**：5 处 API 层 ORM/try-except 清偿到 service 层（contract_review 格式化任务 156→43 行、contracts 补充协议、reminders 日历 feed、document_parsing、法院短信文档重命名——后者入参从裸 `dict[str,Any]` 补 Schema 校验）
- **查询效率批**：全局搜索补确定性排序（DISTINCT+LIMIT 无排序时结果不确定）；合同列表补 `prefetch("cases")` 消 N+1；法院短信推荐最贵的多表 COUNT 不再跑两遍；scraper 监控 2N 条 COUNT 改单次聚合；仲裁图片抓取/模板映射拷贝改 bulk_create；证据 RAG 免物化数十 KB 向量列；案件材料批量删除合并 queryset；42 处 naive `datetime.now()` 统一 `timezone.now()`

## 前端

#### 修复

- **阅读器分段状态错绑**：分段列表 `key={index}` + 段头组件本地 state，切分/合并/删除后索引位移导致类型选择器与改名草稿写到"位移过来的另一个段"——Segment 增加稳定 id（存量草稿自动兜底补齐），Flow/Rail 全部换用

- **登出残留**：登出补 material-prep reader store 重置与 PDF 文档缓存清理（动态 import 引入避免 pdfjs 打进 entry chunk）——换账号不再能读到上一账号驻留内存的案件材料
