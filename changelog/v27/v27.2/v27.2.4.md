# v27.2.4

材料预处理（material-prep）交互专项：修复阅读器内改名「卡死」与材料改回原名失效、列表 ↔ 详情切换闪烁；材料包打开 1.6s → 0.3s（前端免整包下载 + 后端维护 PDF 页数）。全部为交互修复与性能优化，**无数据库迁移**。

## 前端

#### 修复

- **阅读器内弹窗被盖住导致改名「卡死」**：radix AlertDialog / Dialog 经 portal 挂在 body 下（原 z-50），与全屏阅读器 `.mp-reader`（z-[80]）同处根层叠上下文——弹窗在 DOM 里已打开却被整屏盖住不可见，模态又锁死整页 pointer-events，点「重命名材料包 / 改源文件名字 / 删除所选页确认」后表现为整页卡死（Esc 可解锁，列表页因无 z-[80] 层不受影响）。`components/ui/alert-dialog` 与 `dialog` 的 Overlay + Content 统一提到 **z-[130]**（高于阅读器 80 及其内部自绘弹窗 120），阅读器内按 ⌘K 唤起全局检索被盖住同治
- **材料改回源文件名永远不生效**：`draft.renameMat` 的早退守卫 `mats[mi].n === name` 把「改回原文件名」当成无变化直接短路，customName 永远清不掉；段名跟随判断也由「等于源文件名」改为「等于改名前显示名」，使二次改名 / 还原对称生效（新增 `draft/auto-split.test.ts` 4 组用例）
- **列表 ↔ 详情切换闪烁**：PageFade 以完整 pathname 判定换页，`/material-prep` ↔ `/material-prep/:id` 会重播列表入场动画，与阅读器的半透明淡入（opacity 0→1）叠加即闪烁，关闭阅读器返回列表同理。改为按**首段路径**判定页面身份，进出详情、切换材料包 id 不重播，真正的跨页导航动画照常——与组件注释「打开 material-prep/:id 不重放动画」的既有意图一致

#### 优化

- **材料包秒开**：`resolveMats` 优先采用附件元信息里后端算好的 `page_count`（零下载），缺失（老数据回填失败）才下载整包用 pdf.js 数页数兜底；多附件由串行 `await` 改 `Promise.all` 并行。实测 92 页 / 26MB 扫描件：列表点击 → 阅读器就绪 **1.6s → 0.3s**，打开阶段仅剩 ~24ms 详情请求，大文件下载转入页面渲染的渐进加载（新增 `draft/resolve.test.ts` 5 用例）

## 后端

#### 新功能

- **附件页数维护（`attachment_page_service`）**：
  - 上传 / 追加附件时用 PyMuPDF 算好 `page_count` 写入 `attachments_meta`（JSON 字段内新增键，**无需数据库迁移**）
  - 详情接口读取时给老数据回填（一次写库，后续直读），存量材料包首开即生效
  - `AttachmentMeta` schema 与 `get_public_attachments_meta` 透出 `page_count`（本地路径仍不外泄）；`manual_upload_service` 上传 / 追加路径接入（新增 9 用例）

- 前端：vitest 101 用例（含新增 9）、ESLint、tsc + Vite build 全绿
- 后端：message_hub 全量单测、ruff、mypy、bandit（唯一告警为存量 OCR 归一化代码，非本次改动）全过
- 浏览器实测（真实数据）：标题 / 材料改名（改名 + 改回原名）、阅读器内 ⌘K、打开耗时、三个方向的切换动画均逐一验证
