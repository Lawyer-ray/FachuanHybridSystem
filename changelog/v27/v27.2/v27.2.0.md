# v27.2.0

MCP Python SDK 升级到 2.2.0（协议级大版本迁移），解除 v27.1.13 的 `<2` 锁定并完成配套代码改造。

## 后端

#### 依赖变更

- **mcp 1.30.0 → 2.2.0**：连带 fastmcp-slim 3.4.7 → 4.0.10、新增 mcp-types 2.2.0（types 拆分为独立包）、移除 httpx-sse（SSE 传输改用 httpx2 实现）

#### 迁移改造（Breaking Changes）

- **`mcp_server/server.py`**：`FastMCP` 重命名为 `MCPServer`（`from mcp.server.mcpserver import MCPServer`），旧 import 路径在 mcp 2.x 中是抛 `ModuleNotFoundError` 的迁移指引存根。`MCPServer("法穿AI Copilot")` 构造与 `mcp.tool()()` 注册模式、`__main__.py` 的 `mcp.run()`（默认 stdio）均确认兼容，无需其他改动
- **`enterprise_data/mcp_tool_client.py`**：
  - types 字段 camelCase → snake_case：`result.isError` → `is_error`、`result.structuredContent` → `structured_content`、`Tool.inputSchema` → `input_schema`（原 v1 双 fallback 收敛为单一 `input_schema`）
  - `streamable_http_client` 返回值从三元组变二元组（`get_session_id` 回调已移除）
  - HTTP 客户端与异常类从 httpx 切换到 httpx2（mcp 2.x 内部统一用 httpx2，异常类型跨包 `isinstance` 不互通）：`httpx2.Timeout` / `httpx2.AsyncClient` 与重试/熔断分派中的异常判断全部同步
  - `sse_client` 签名、`ClientSession` + `initialize()` 调用方式确认兼容，未改动
- **测试同步**：5 个 enterprise_data 测试文件的结果模拟字段名改 snake_case、异常构造改用 `httpx2 as httpx` 别名；2 个专测 v1 `inputSchema` fallback 分支的用例改写为 v2 语义（缺 schema 时收敛为空 dict）
- **零改动确认**：`workbench/agents/definitions.py` 的 fastmcp `Client(transport, timeout=)` + pydantic-ai `MCPToolset(client, process_tool_call=)` / `StdioTransport(command, args, cwd=)` 签名在 fastmcp-slim 4.0.10 + pydantic-ai 2.51 下完全兼容

- enterprise_data / mcp_server / workbench 测试子集全绿；ruff / mypy 通过
