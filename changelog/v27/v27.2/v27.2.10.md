## 前端

#### 修复

- **401 刷新单飞**：`lib/api.ts` afterResponse 的 401 路径改走 `refreshAccessTokenSingleFlight`——并发请求同时 401 时只发一次 `/token/refresh`，不再互相消费 refresh token 造成有效会话误登出
- **上传超时**：新增 `UPLOAD_TIMEOUT_MS`（300s）显式覆盖六个 multipart 上传端点（材料包整包上传/追加、文书识别、OCR 取字、PDF 拆分、DOC 转 DOCX），ky 默认 10s 此前会误杀大文件（92 页扫描包必超）
- **登出清缓存**：`AppNavbar` 登出时 `queryClient.clear()`，换账号登录不再在 staleTime 窗口内串显上一账号的日历/收件箱/合同数据
- **法院短信错误出口**：`retry()` / `assignCase()` 失败补 toast 提示（原 promise 逃逸成 unhandled rejection，用户无任何感知）
- **DOC 转换单件复制降级 bug**：系统剪贴板不可用时降级复制文件名，`copyNames(items)` 参数化——原实现固定复制全部成功件文件名，与单件复制按钮语义不符

#### 优化

- 四个分页历史弹窗（DOC 转换/要素式/解析/法院短信）补 `placeholderData: keepPreviousData`，翻页不再整块闪「正在加载…」
- `BindingsPage` 改用 `auth/constants.ts` 导出的 query key，删除本地重复定义

## 后端

#### 修复

- **jtn OA 脚本 Playwright driver 泄漏（P0）**：半自动 `open_*` 返回后 `asyncio.run` 退出关闭事件循环，`disconnected` 事件永远无法触发；旧断连回调里 `asyncio.run(playwright.stop())` 在运行中循环内必抛 RuntimeError 被吞——用户每关一次 OA 浏览器泄漏一个 node 进程。修复：适配器协议新增 `wait_open_browsers_closed()`（默认 no-op），调度器把 `open_*` 流迁到专用 daemon 线程压住循环，等浏览器关闭并回收 driver 后线程才退出；四个脚本删除必败回调
- **OA 调度容量死锁（P0）**：立案/盖章/归档共享 2-worker 池原为无限静默排队（进程重启即丢且无反馈）→ 加排队上限（4 个名额、开始执行即释放），满载时会话立即置 FAILED 并抛 `ScriptExecutionError`，把「卡死」变成「可见的失败」
- **爬虫任务终态**：重试耗尽补落 `failed` + 错误信息（原停在 running，只能等 qcluster 重启 `reset_running_tasks` 兜底空转）
- **方向检测伪装成功（P0）**：`image_rotation` detect-page-orientation 失败不再返回 `{rotation: 0}`（等于谎报「确认无需旋转」，错误静默固化进导出产物），改抛 `ValidationException` / `ExternalServiceError` 走全局异常体系；批量端点逐图失败补显式 `error` 标记
- **归档学习丢计数**：`hit_count += 1` 读-改-写在并行学习任务下互相覆盖 → `F()` 原子自增
- **客户导入丢失语义**：`resolve_with_attachments` 整体包 `transaction.atomic()`（client admin JSON 导入无外层事务，中途失败曾留半成品客户）；`PropertyClue` 查重键补 `content`——旧写法按 `(client, clue_type)` 查重，重导入会静默吞掉同类型其余银行账户
- **文件夹打包 N+1**：身份证明收集改一次性 `prefetch_related`（原每个 identity_path 外层循环重复执行 parties 查询且逐当事人查证件），律师执业证/案号裁判文书循环同款提升
- **`GET /cases/logs` 无界**：新增 `limit/offset`（默认 200、上限 1000），不传 case_id 也不再全表物化日志（含正文与附件 prefetch）

#### 错误契约归一

- HTTP API 层业务失败统一抛域异常（`ValidationException` 400 / `NotFoundError` 404 / `PermissionDenied` 403 / `ExternalServiceError` 502），经全局异常处理器返回 `{code, message, error, errors}`——`message` 与 `error` 同值，前端 ky 的 HTTPError 与 admin JS 的 `data.error` 新旧消费方天然兼容
- 覆盖：oa_filing 案件/客户导入（裸 error 与 14 处 JsonResponse 全部归一，顺带删除路由级鉴权下的死代码未登录检查）、court_sms 文书重命名六处、legal_research 法规核查（凭证/权限/登录/核查失败）、contract_review format（任务不存在/无权与同文件 download 端点的 404 语义对齐）、documents generation 四处缺参、client parse-text 与 casenumber 上传的 error 键归一为 message（两个 admin JS 消费点改 message 优先读取）
