# v27.2.1

开发工具链与 CI 升级：Node.js 22 → 24 LTS、pnpm 10 → 12、setup-uv v5 → v10。无业务代码变更。

## 前端

#### 依赖变更

- **Node.js 22.12 → 24.21（LTS）**：本地 nvm 默认版本与 CI `node-version` 同步升至 24；`engines: >=20` 保持不变；`@types/node` 随之 22.20.4 → 24.19.0（与运行时对齐）
- **pnpm 10.28.2 → 12.6.0**：`packageManager` 字段升级，lockfile 在 pnpm 12 供应链策略下完全重解析（lockfileVersion 仍为 9.0）
- **pnpm 12 新安全默认的适配**：
  - `minimumReleaseAge` 发布冷却期策略生效，lockfile 重解析后 `@swc/core` 从 1.16.12 回落到 1.16.2（不足冷却期）；昨日已人工验证的 typescript-eslint 8.71.0 全家经 `minimumReleaseAgeExclude` 显式豁免
  - 新增 `pnpm-workspace.yaml`：`allowBuilds` 显式批准 `@swc/core` 的 postinstall（pnpm 12 将忽略构建脚本从 warning 升级为 error）
  - 副作用收益：本地 `pnpm-workspace.yaml` 使 frontend 自成 workspace root，家目录 workspace 吞 install 的问题天然解除，安装不再需要 `--ignore-workspace`（且带该 flag 会跳过本地安全配置导致安装失败，后续一律不用）

## 后端

#### 优化

- **CI：astral-sh/setup-uv v5 → v10**（backend-ci.yml 5 处）：跨 5 个大版本，本项目均为无参数裸用，v6–v10 的 breaking（immutable releases、缓存修剪默认、安全收紧）不涉及现有用法

- Node 24.21 + pnpm 12.6.0 下：eslint 通过、vitest 92 用例全过、`tsc -b && vite build` 成功
