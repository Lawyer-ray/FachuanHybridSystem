# v27.2.15

技术债第四批清偿：生产配置健康 / 数据修复 / mypy 全仓清零 / 安全暂缓项落地 / 四层架构收官 / **零断言测试全仓清零**（571→0）/ 前端测试基建补齐。

## 后端

#### 修复

- **生产配置健康**：
  - `django` logger `propagate: True→False`——与 root handler 同组导致 `django.server` 等子 logger 每条日志双写
  - `DATA_UPLOAD_MAX_MEMORY_SIZE` 100MB→70MB 并修正错误注释（multipart 实际由 `FILE_UPLOAD_MAX_MEMORY_SIZE` 管控；70MB 为 50MB PDF Base64 膨胀 4/3 的最小满足值）
  - `idle_in_transaction_session_timeout` 移出 DEBUG 分支生产全局生效（300s，env 可覆盖；长任务的 atomic 只包短 SQL 已逐一核查不误杀）；`statement_timeout` 保持 DEBUG-only 并注明后续方案（请求级 SET LOCAL，避免杀 7200s 批量任务）
  - finance 月度调度 `next_run` 归一（20 日后注册不再落到过去时刻立即执行一次外呼）
  - RequestIdMiddleware 挪到限流之前（429 响应可关联请求 ID）
- **客户文本解析两个数据缺陷**：`_extract_parties` 依赖甲方/乙方标签分块，无标签多行文本只返回 1 个客户（丢数据，前批测试暴露的 xfail 转正）——新增按行独立解析兜底；含手机号行的 name 整行吞入——剥离 7 位以上电话形态数字串。带标签分组语义不变（5 个回归用例）
- **admin 显示**：reminder_admin 的 `str(mark_safe(...))` 丢 SafeString 标记（列表显示原始 HTML 标签）——改 `format_html_join` + `format_html`
- **mypy `apps/` 23→0，其中三类真实运行时风险**：
  - 13 处非空 CharField 灌 None（PG NOT NULL 违约，统一边界收敛）
  - `generation_service.create_task` 的 `update_fields` 引用两个非 DB 字段（调用即 FieldError）——死方法删除
  - evidence「双域」实为两套 pdf_merge_service 并存（documents 版生产零调用）——删除收敛到 evidence 唯一链路
- **审计安全暂缓项落地**：
  - 模板 XSS：contract_review 报告页 `{{ report_html|safe }}` 是 LLM 分析用户合同的输出（markdown 不转义原始 HTML，存储型 XSS）——提取 bleach 白名单消毒为 `core/services/report_html_sanitizer.py`（legal_solution 原路径复用），渲染前消毒；upload.html 模型名补 `<` 转义；删除死模板
  - 改密 token 失效（E-07/C-14，零迁移方案）：refresh token 绑定 `pwd_ver` claim（密码哈希短指纹），签发注入/刷新校验（含扫码登录直铸路径）——改密后旧 refresh 即拒。**上线后存量 refresh 首次刷新即失效（一次性全员重登），属预期收紧**
  - 媒体路径（C-12 代码侧）：`client/utils/media.py` 补 `..` 路径段拒绝（生产鉴权仍需 nginx 配合）
  - LLM 默认网关明文 http（E-16）：保留回退值但补使用时告警（TLS 化为服务器侧工作）
  - admin search_fields 移除 `api_keys`（搜索词进查询日志泄密钥片段）
