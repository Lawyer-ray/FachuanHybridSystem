# v27.2.5

办案主页实装（38 号原型落地）：合同大行流 + 服务端分页 + 详情抽屉。分支 `feat/material-prep-menu-ia`，6 个提交，22 个文件（前端 +1868 / 后端 +172）。

## 前端

#### 新功能

- **办案主页**（新 feature `features/workbench`，路由 `/cases`，导航「办案」从 toast 占位改为真实链接）：
  - 合同全宽大行流：名称主视觉 + 「我方 vs 对方」副行 + 金额/到期右对齐（今日到期红点脉冲），按类型分组（诉讼组在前非诉在后），sticky 组头
  - **服务端分页**：每页 50 条，底部分页条（上一页/页码/下一页），筛选变化自动回第 1 页，翻页 keepPreviousData 不闪白；首屏请求从初版全量 1.27MB 降至 **15KB**
  - 筛选/搜索下推后端：状态/类目/收费 chips 计数来自 facets（全库口径）、搜索防抖 300ms、`/` 聚焦搜索、激活筛选为可单独移除的黑底 chips
  - **详情抽屉**（右侧滑入，办案页唯一浮层）：九节全字段——律师费四格（律师费/已收款/已开票/未收款）/ 当事人（我方在前 + 留白分组）/ 主办律师（含执业证号、律所）/ 合同要素 / 收款记录 / 提醒事项 / 补充协议 / 案件程序节点条；当事人、律师行内一键复制；OA 编号可跳转
  - 案件明细**按需加载**：打开抽屉才按合同 ID 拉取（60s 缓存），列表期不再全量拉案件
  - 交互语义与原型终态一致：左键行/「详情 →」=「详情页正在开发中」提示；**右键行或 👁 = 直接弹抽屉**；Esc/遮罩关闭
  - 域逻辑全部下沉 `domain.ts` 纯函数（合并/分组/格式化/复制文本），24 例单测
- 新增 `components/ui/sheet.tsx`（radix Dialog 封装的右侧滑入面板，z-[130] 对齐弹窗基线）；`/workbench` 路由后更名 `/cases`（对齐后端 cases app，预留 /cases/:id）

#### 优化

- 导航栏删除无用的「台账」占位按钮（首页 / 材料预处理 / 办案 三项）
- 办案页懒加载独立 chunk（feature lazy 出口，29KB），不影响首屏

## 后端

#### 新功能

- **`GET /contracts/contracts` 服务端分页**（`?page=N&page_size=50`，钳制 1..200）：返回 `{items, total, status_counts, cat_counts[{value,label,n}], fee_counts}`；不传 page 保持全量裸数组兼容存量消费方
  - 排序固定「离今天最近」：`ABS(end_date - CURRENT_DATE)` 升序、无到期沉底、id 倒序
  - facets 三组 group by 全库计数（状态代码 / 类目与收费 value+label+数），供筛选 chips
- **`GET /cases/cases` 新增 `contract_id` 过滤**（API → CaseService → search service 三层透传），供抽屉按需加载

#### 优化

- 合同列表序列化瘦身：去掉 cases 整表内嵌改 `case_count` 计数（相关子查询聚合，避免与 payments Sum 同链 annotate 笛卡尔积）；`?slim=true` 剔除 `finalized_materials`（占响应约 60% 体积，仅归档场景需要，默认关）
- 实测（144 合同）：全量接口 1.27MB/0.9s → slim 394KB/0.74s → 分页 15KB/0.32s
