# v27.6.8

争议解决详情页首版落地（`/cases/:id`）：以 52 号「工作现场」原型为底本，一页一委托——合同是页头身份、案件程序链是页面脊椎、右栏放期限/联系人/律师/钱、档案沉底。用户只见「一个案子」，不感知后端合同与案件两张表。非诉详情页另轮设计。

## 前端

#### 新功能：争议解决详情页（`features/workbench/components/deal-detail/` 子域）

- 路由 `/cases/:id`（`:id` = 委托合同 id）。列表左键行 / → / 抽屉「详情 →」对争议解决委托直达详情页，非诉委托保持开发中提示；列表挂载后空闲预载详情 chunk（独立 24 KB）
- 页头：面包屑 + **合同名主标题** + meta 单行（类型 · 状态 · 我方 → 对方 · 建档 · 主办，空值不渲染）+ 两个创建动作
- 程序链 stepper：已结 ● / 在办 ◎ / 未启动 ◌，按收案日期升序（后端尚未把 `previous_case` 透出 API，时间序即程序序），点击滚到对应案件节并短暂高亮；民商事等有执行程序的类型在无执行案时追加「执行 未启动」虚节点与「＋ 立执行案」
- 案件节：阶段名 + 已结/在办 + 案号 chips + meta（审理机构 · 收案 · 案由 · 标的 · 保全）+ 诉讼地位行（按地位分组，随案变化）+ 日志时间轴升序叙事（经办人 / 附件数）；同阶段多案自动带案名消歧；无日志给空态文案
- 右栏 sticky：期限（合同直挂 + 日志级 + 案件直挂三源合流，只取今天起、已完成剔除、今日唯一红）· 法院联系人（按机构分组、电话可复制）· 律师（主办徽章 / 电话 / 证号 / 律所）· 涉案与收费（标的/保全取链上首个有值案件，费用取合同；无金额只有方式时标「收费方式」）
- 档案沉底：当事人（我方在前、头像块 + 角色标签 + 复制）· 合同要素（复用抽屉 `dealFacts`）· 收款表 · 补充协议
- 非诉委托直达 `/cases/:id` 给「设计中」提示 + 返回；非法 id 重定向回 `/cases`；合同加载失败给错误 + 重试 + 返回
- 创建类动作（记办案日志 / 新增期限 / 立执行案 / 记收款）本轮占位 toast，样式定稿后接 `POST /cases/logs`、`/reminders/create` 等真实端点
- 数据层：`getContract`（`GET /contracts/contracts/{id}`）、`listRemindersByCase`（`GET /reminders/list?case_id`，该接口 contract_id / case_id 都是直挂口径且互斥，案件级只能逐案取）；`DealCase` 增 `parties` / `logReminders`，`DealContact` 增 `authority` / `address`，`WorkbenchDeal` 增 `caseType`；案件缓存与抽屉共用
- 测试：`detail-domain.test` 16 例（排序 / 虚节点判定 / 三源合流 / 分组 / 金额行 / 页头 meta）、`DealDetailPage.dom.test` 10 例（加载 / 错误 / 非诉 / 非法 id / stepper / 案件节 / 右栏 / 档案）；全量 668 例绿
- 真实数据验证（无头 Chromium，1440 与 390 双断点零横向溢出、零 pageerror、零 4xx）：两个一审已结 + 两个执行在办的委托正确消歧排链；劳动仲裁已结 → 一审在办 → 执行虚节点；日志含法院短信长 URL 的时间轴行加 `break-words` 不再撑破窄屏
