# v27.6.2

材料预处理「云端内容识别」链路终态整理：内容分析流水线从任务执行中解耦为可复用模块（`split/pipeline.py`），前端透出分段后端可观测性；92 页真实移交材料端到端验证（MinerU 真调用 + LLM 降级路径）。

## 后端

#### 重构：内容分析流水线解耦为无任务耦合模块（pdf_splitting）

- 目标链路（/material-prep/:id 阅读器「云端内容识别」）梳理定形：**MinerU/TextIn 整本解析取字（带版面块）→ 律所 LLM 语义分段 + 命名（失败降级关键词规则引擎）→ 每段 Markdown 重建 → API 透出 → 前端写入草稿（t/fn/md）**。此前取字编排内嵌在 `PdfSplitService.analyze_job` 的 200 行单体里，与他处复用（归案识别、文书处理等未来场景）不可行
- 新增 `services/split/pipeline.py`：`analyze_pdf()` 无状态门面（PDF 路径 → pages / drafts / segments_md / summary 四件套，进度与取消经回调透出，零任务 / 零 DB 耦合）+ `PageTextExtractor` 取字编排（PDF 文本层 → OCR 页级缓存 → 云端整本解析 → 本地并行 OCR 兜底）+ `detect_segments_with_fallback` / `build_page_descriptor` 模块函数
- `PdfSplitService.analyze_job` 瘦身为任务态适配层：进度 / 取消回调 + `_persist_analysis(outcome)`；取消语义统一为 `PipelineCancelled` 异常（原先三处重复的取消分支收敛为一处）
- `extract_layout_title` 由 service 下沉 `split_models`（pipeline / service 共用），service 保留旧名再导出与 `_build_descriptor` / `_detect_segments_with_fallback` 委托方法（既有调用方与测试零改动）
- README 补「复用（其他域直接调）」章节：`analyze_pdf()` 用法与组件级复用清单

#### 修复：LLM 分段调用加硬时限墙（供给离线不再拖死任务）

- 实测根因：律所网关离线时，LLM 调用链的 key 池轮换（5 key）× OpenAI SDK 内建重试 × 连接超时层层相乘，92 页材料的分段调用挂了 25 分钟以上（采样确认卡在裸 socket connect）——Q 任务与前端 14 分钟轮询窗口都会被拖穿
- `LLMSegmentDetector` 新增守护线程硬时限墙（默认 300s，可注入）：到点抛 `LLMSegmentationError` 立即降级规则引擎；单次 HTTP 请求同时显式传 `timeout_seconds=180`（backend 支持的 kwarg，防网关半开挂流）。健康网关下 92 页分段约 1-2 分钟，墙余量充足

#### 修复：规则引擎空版面标题命名成 file.pdf

- 92 页真实材料端到端暴露：`_suggest_filename` 直接对 `layout_title` 做 `sanitize_upload_filename`，空标题时清洗函数的兜底名 "file" 被当成有效标题，大量分段命名成 `file.pdf`（连 Markdown 的 H1 也变成 `# file`）。改为先判原始标题非空、清洗后非空才用标题，否则回退类型默认名；修复后同一份材料 46 段 file.pdf 残留 0，全部拿到「放款凭证 / 借款合同 / 温馨提示」式命名

#### 真实端到端验证（92 页移交诉讼材料，本地直跑任务函数）

- 全链路走通：**540s 完成**——MinerU 真实云端解析（77 页缓存命中 + 15 页 miss 全部由 MinerU 补齐、零本地 OCR 兜底）→ LLM 撞 300s 墙（飞连隧道离线）自动降级规则引擎 → 46 段、42 段识别（此前同域数据 2/3 未识别）→ `analysis/segments_md.json` 产出（合同号 / 借款凭证标题 / 日期结构化正确）→ 状态 review_required → API content_md 可透出。隧道恢复后同一路径将由律所 AI 出分段与命名（前端 toast 会标注「律所 AI 分段」）
