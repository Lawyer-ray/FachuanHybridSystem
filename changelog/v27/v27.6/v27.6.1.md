# v27.6.1

材料预处理「云端内容识别」两处补强：LLM 分段的逐页摘要改开头+结尾双窗口（材料边界的关键证据在页尾落款），并新增每段 Markdown 产出（`content_md`）供下游 AI 直接消费。

## 后端

#### 优化：LLM 分段摘要改「开头 + 结尾」双窗口

- 用户反馈成立：一份 PDF 是多份材料扫描合并时，判断两页是否同一份材料要看「上一页的末几句 + 下一页的头几句」——落款、日期、签名、「此致」「具状人」等结束信号都在页尾，只给开头 200 字会漏掉
- `build_page_digests`：每页摘要改为开头 150 字 + `……（中略）……` + 结尾 110 字（总长 ≤ 320 字的短页整段直出，不重复）；SYSTEM_PROMPT 同步补「边界两侧信号」判断规则（上页收尾信号 + 下页新标题 = 大概率两份材料；上页未完句 / 表格行 + 下页无标题 = 同一份续页）

#### 新功能：每段产出 Markdown（analysis/segments_md.json + API content_md）

- 新增 `services/split/markdown_builder.py`：云端解析（MinerU / TextIn）的版面块重建为结构化 Markdown——标题类 block（type / text_level）映射标题层级、`table_body` / `table_structure` 的 HTML 表格转 GFM 表格（容忍残缺标记、解析失败退回块文本、单元格 `|` 转义、短行补空列）、页眉页脚等噪音块剔除；本地 OCR / PDF 文本层无版面时退回页原文，页间空行
- `_persist_analysis` 为每个分段生成 md（标题取材料名），落 job 目录 `analysis/segments_md.json`（零迁移，不进 DB）；`page_split` 模式无内容分析、不产出
- `job_service` 新增 `load_segments_md`（文件缺失 / 损坏 / 非列表一律回空表，旧任务 `content_md` 退化为空串不阻断接口），`build_job_payload` 按 order 关联注入
- `SegmentOut` 新增 `content_md` 字段，`backend/openapi.json` 重导出
- 真实数据冒烟（既有任务的 pages.json + segments.json 直跑）：正文、当事人、判决主文完整进入 md

## 前端

- `PdfSplitSegmentSuggestion` 投影加 `content_md`；`Segment` 新增可选 `md` 字段，`applyAutoSplit` 把每段 Markdown 一并写入草稿——后续 AI 流程（要素提取 / 归案识别）可直接取用
- `pnpm gen:api` 重生成 `api-schema.d.ts`

- `test_llm_segment_detector.py` 摘要用例改双窗口断言（长页头尾都在且中段未混入、短页不重复）；pdf_splitting 单测 + 集成测试全绿，mypy / ruff / tsc 通过
