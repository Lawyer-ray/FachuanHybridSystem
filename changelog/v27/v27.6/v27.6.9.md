# v27.6.9

pre-commit 隐私闸门全面加固：扫描范围从后端源码目录扩到**全部入库文件**，新增案名 / 公司名 / 座机 / 统一社会信用代码 / 法院案号 / 内部案号 / 地址七类模式，身份证与信用代码带校验位验证。

## 工程化（backend/devtools/security_guard.py）

#### 修复：隐私扫描只盯后端源码目录，changelog / docs / 前端 / 测试不设防

- 根因：`_check_sensitive` 以 `SOURCE_DIR_PREFIXES`（`backend/apps`、`backend/apiSystem`、`backend/scripts`、`scripts`）做门禁，其余路径直接跳过——PR #550 泄过真名、本轮 changelog 与测试夹具又差点写进真实公司名与座机号，hook 全程无感
- 修复：**隐私类模式扫全部入库文件**（只跳锁文件、`openapi.json` / `api-schema.d.ts` 生成物、最高法案由种子词库）；**凭证类**（Bearer / 密钥字面量）维持只盯运行时源码目录（全库凭证由 detect-secrets 兜底，测试里的 `password="…"` 夹具不再误伤）

#### 新功能：七类隐私模式 + 校验位闸门 + 脱敏感知

- 新增：座机（`0XXX-XXXXXXX`）、统一社会信用代码（GB 32100，**校验位合法才拦**）、法院案号（`（20XX）粤01民初NNN号`）、内部案号 / OA 合同号（`20XX + 字母 + 数字`）、案名（`X诉Y…一案/纠纷`、`X与Y…纠纷`）、公司 / 机构名（有限公司 / 律师事务所 / 经营部…）、完整地址链（省…市…区/路/村）
- 身份证改为 **GB 11643 校验位验证**：真证号校验位必然合法，乱造的测试假数据天然放行，不再误伤既有夹具
- **脱敏感知**：案名两侧任一含「某」/ 张三李四 / 甲乙方即放行（`张某诉李某 借贷纠纷` 不拦）；公司名含「某」/ 甲方 / 测试 / 示例放行；解析代码里裸写的 `"股份有限公司"` 后缀字面量不算公司名
- 公开第三方允许名单（爬取目标 / SDK 厂商 / 自家律所）：小米科技、腾讯科技、阳光财产保险、上海道律、金诚同达
- 行级豁免标记 `privacy-allow`（与既有 `pragma: allowlist secret` / `# nosec` 同机制）：确属虚构的假数据在行尾注明即放行，`git grep privacy-allow` 可审计全部豁免
- 新增 `--mode all`：读整文件做全量审计（`git ls-files -z | xargs -0 python backend/devtools/security_guard.py --check sensitive --mode all`）；pre-commit 与 CI 仍是 `staged` / `range` 模式只拦新增行
- 自身免疫：报错文案里的示例全部用 `20XX` / `138****1234` 形式，脚本不会命中自己
