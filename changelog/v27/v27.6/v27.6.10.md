# v27.6.10

争议解决详情页程序链改为**合同勾选的代理阶段驱动**：删掉硬推「执行」虚节点的启发式。用户以 322 号委托指出——合同只勾了劳动仲裁、一审、二审，页面却凭空长出执行；且程序链以后会像树枝一样分叉，不是一条直线。

## 前端

#### 修复：程序计划 = 合同勾选阶段 ∪ 案件实际阶段，按程序序排

- 新 `buildStagePlan(selectedStages, cases)` 取代「按收案日期排链 + 判要不要补执行」：合同 `representation_stages` 里勾了的阶段全部进 stepper（没立案 = 未启动 ◌），案件实际所在阶段也进（没勾但立了 = 数据漂移，照样展示）；合同一个阶段都没勾（库里 45 个争议合同如此）退化为只看案件
- **程序序表 `STAGE_ORDER`**：后端 CaseStage 枚举的 choices 顺序（一审/二审/执行/劳动仲裁…）不是程序顺序，合同存的勾选数组也按 choices 序（322 号存成「一审、二审、劳动仲裁」），所以排序只能靠前端这张表——前置程序（侦查/审查起诉/劳动仲裁/行政复议/自诉）→ 一审/二审 → 再审重审分支 → 申诉抗诉 → 执行；未知标签排最后
- **分叉结构**：每个阶段节点挂 0~N 个案件，N>1（两个一审分案、按被执行人分立的多个执行）stepper 标 ×N、主列各节带案名消歧；`StagePlan` 预留 children 位置，保全挂一审下 / 执行再分被执行人这类嵌套下一步往这棵结构长
- **「下一步」行**只给最后一个已启动阶段之后的第一个未启动阶段（322：二审；全未启动取第一个），文案「＋ 新建{阶段}案件」；夹在中间被跳过的勾选阶段（261 的二审：一审直接到执行）只在 stepper 留空心点，不冒充下一步
- 主列案件顺序 = 计划顺序（stepper 即目录），同阶段内按收案日期——合同 9 的执行案收案早于两个一审，页面仍按 一审 → 执行 排
- 删除 `needsVirtualExec` 及其民商事/刑事特判；空态文案改「合同没有勾选代理阶段，也还没有立案的程序」
- 测试：detail-domain 换成 322 / 261 / 合同 9 三种真实形态 + 空勾选 / 漂移 / 全未启动 / 未知标签；DealDetailPage.dom 加 322 形态（无执行、下一步二审）、空勾选（无下一步行）、同阶段两案（×2 + 案名消歧）；全量 673 例绿
- 真机复测四个真实委托：322 劳动仲裁已结 → 一审在办 → 二审未启动、全文无执行；261 一审×2 → 二审未启动 → 执行×2；9 一审×2 → 二审未启动 → 执行；271 一审未启动 → 二审×2 → 执行；零 pageerror、零 4xx、零横向溢出
