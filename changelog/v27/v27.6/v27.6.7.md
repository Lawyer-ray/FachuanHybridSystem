# v27.6.7

全局检索「客户」改「当事人」并带我方/对方徽章；撤除电话与证件号的 API 出参打码（本机部署、办案要看得到联系方式与证件号）。

## 前端

#### 优化：全局检索（⌘K）客户 → 当事人，命中带「我方 / 对方」徽章

- 类别文案、筛选标签、分组头、输入框占位统一改「当事人」：后端 Client 表装的是所有当事人（我方 + 对方），叫「客户」会让人以为只有我方委托人
- 当事人命中行加徽章：**我方实底、对方描边**——复用本面板筛选标签「实底=选中 / 描边=未选」的既有视觉词汇，不引入新颜色；非当事人类命中不渲染
- `runSearch` 透传后端新字段 `side`（旧后端缺字段时兜空串）；`api-schema.d.ts` 随 OpenAPI 重新生成
- 测试：`api.test` +1（side 透传 / 座机原样）、`GlobalSearch.dom.test` +2（当事人文案与徽章 / 非当事人无徽章）
- 真实 Chromium 验证：搜某我方当事人 → 标签「当事人 1」、行「名称 · 我方（实底）· 座机号原样」；搜某对方当事人 →「对方」描边徽章 + 手机号原样

## 后端

#### 修复：全局检索电话出参打码撤除（座机此前整串变星号）

- 现象：当事人命中的副标题是电话，此前按「手机号前 3 后 4、非手机号形态数字全打码」处理，座机（如 `0757-xxxxxxxx`）显示成 `****-********`，用户完全看不到
- 修复：`search_service._mask_phone` 删除，电话原样出参——与证件号同一产品决策（2026-10：本机部署、办案要能直接看到联系方式）
- `SearchResultItem` 新增 `side`（`ours` / `opposing` / 空串），当事人类取 `Client.is_our_client`，其他类别恒为空串
- 测试：`test_search_service_acl` 打码用例改为原样出参 + side 断言，补座机回归、我方用例、HTTP 层 side 透出；`core/client` 相关单测与 integration 全绿

#### 修复：客户证件号出参打码撤除（ClientOut / ClientLiteOut）

- `ClientOut` 删掉 `resolve_id_number` / `resolve_legal_representative_id_number` 打码解析器，证件号字段直出；`ClientLiteOut.from_model` 同步直出（cases / contracts 域当事人出参 import 的就是它，口径自动统一）
- `IdCardUtils.mask_id_number` 工具保留（日志脱敏等场景），API 出参不再调用；工具单测保留，出参测试改为原样透传（含 dict re-validation 路径）
- `openapi.json` 重新导出：除上述字段外，一批 Decimal 字段的 `pattern` 消失是 #548 升 pydantic 后生成器行为变化（库漂移，不影响 TS 类型）
