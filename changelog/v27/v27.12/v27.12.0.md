#### 新增 · core 迁移 `0038_remove_docspace_cloud_docs`

应用删除后 Django 不再管理其表，残留需显式清理，一条迁移处理三件事：

- **清数据**：删除 `category='docspace'` 或 `key__in=(DOCSPACE_*)` 的 `SystemConfig` 行——尤其是那条加密的云端 API token，避免变成无人读取的孤儿凭据。
- **收敛枚举**：`AlterField` 更新 `SystemConfig.category` 的 choices（先清数据再改枚举，避免存量行违反新 choices）。
- **DROP 孤儿表**：`DROP TABLE IF EXISTS docspace_docspacedocument`（幂等）。正向不可逆，反向仅恢复枚举值不恢复数据。

顺带修正一处历史漂移：`0036` 迁移的 choices 里含 `onlyoffice`，但模型 `Category` 中从未定义该值，本次 `0038` 按模型实际值收敛，`makemigrations core --check` 已无待生成迁移。

#### 修复 · 同步 OpenAPI 与前端类型生成物

- 重新导出 `backend/openapi.json`：移除 7 个 `/api/v1/docspace/*` 路径与 `DocSpaceConfigOut`/`DocSpaceUploadOut`/`DocSpaceDocumentOut` 三个 schema（−418 行）。
