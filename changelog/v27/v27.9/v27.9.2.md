## 后端

#### 新功能 · Agent 技能包化（P1-6）

- **系统提示词拆技能包，按需加载**（`apps/agent/pi/skills/` 新增 4 个 SKILL.md + `pi/AGENTS.md` 瘦身）
  - 原 76 行单块 AGENTS.md 拆为：核心底线（定位 / 身份与时间纪律 / 行为规范）+ 4 个场景技能包——`deadline-queries`（期限与进度）、`list-projection`（列表投影与分页纪律）、`materials-parsing`（材料正文解析）、`web-research`（联网检索）。核心每轮常驻，技能全文按需读取，降低每轮上下文成本并聚焦。
  - **为什么不是 pi 原生 Skills 机制**：pi 的技能发现靠模型用 read/bash 工具读 SKILL.md 文件，而本系统出于安全不向模型声明任何文件读取工具（防提示注入直通服务器文件面）。故技能内容经由 MCP 工具面供给，与「工具面只在 `mcp__fachuan__`」原则一致。
  - SKILL.md 保持 Agent Skills 规范格式（frontmatter name/description），未来若开放受控读取通道可直接复用。

- **新 MCP 工具 `get_agent_skill(name)`**（`mcp_server/tools/core/agent_skills.py`，工具注册表 395→396）
  - 按名读取技能包全文（Markdown 含 frontmatter）；未知技能报错并列出可用名。
  - 安全：只读随代码发布的静态文件，不调 REST 不碰用户数据；名称白名单 = 技能目录实存子目录（正则 + 实存双校验），路径穿越（`../`、斜杠、绝对路径、symlink 逃逸）一律拒绝。读类风险等级（免审批）。
  - 环境变量 `FACHUAN_AGENT_SKILLS_DIR` 可覆盖技能目录位置（容器部署异位时用）。
  - ⚠️ **部署注意：改了 mcp_server 工具面，必须重启共享 MCP**（`python -m mcp_server`，:8011），否则 pi 拿到的还是旧工具面（表现为模型说没有 `get_agent_skill` 这个工具，且无任何报错）。

## 前端

#### 新功能 · 案件/委托页内嵌 AI 入口（P1-1）

- **委托详情页页头「AI 助手」按钮**（`workbench/deal-detail/DetailHeader.tsx`）：围绕本委托打开 AI 助手面板，面板进入「本委托」范围模式。
- **copilot 业务上下文模式**（`store.context` + `launch.ts` 启动入口）：
  - 会话列表只显示该委托的会话（`GET /agent/sessions?origin=contract&contract_id=`），新会话 / 后台任务自动带 `origin=contract + contract_id` 归属——后端多入口（origin）能力首次在前端落地。
  - 面板头部显示「AI 助手 · {委托名}」+「本委托 ✕」chip，一键退出回到全部会话；空态文案区分「「{委托名}」还没有 AI 会话」。
  - 启动链路 `features/copilot/launch.ts`（零依赖独立入口，经 window 事件 + pending 兜底解决面板 chunk 未加载的竞态）：AppShell 只负责开面板，业务上下文由 copilot 域自己消费。刻意不从 index.ts re-export，避免把面板拖进使用方 chunk 破坏懒加载边界（跨 feature 引用经此文档化的架构豁免入口）。
- `case` 入口同构支持（store/api 均按 origin 分派 case_id/contract_id），后续案件页接入零成本。

#### 新功能 · 个人用量视图（P1-2）
