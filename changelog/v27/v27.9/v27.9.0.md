### 修复 · 数据展示

- **P0 · 时间轴同名附件重复计入**（`deal-detail/detail-domain.ts`）
  合并同内容日志时 `seenNames` 建好后从未 `.add()`，单条待合并日志自带两个同名附件时第二个绕过去重被重复 push，附件数虚高、同一附件在时间轴重复出现。对照同函数新建路径（已有 `.add()`）属笔误。
  - 回归测试：单批内同名去重、跨轮次同名不重复。

- **脏日期渲染「剩 NaN 个月」/「已到期 46000 天」**（`workbench/domain.ts`）
  `daysFromToday` 只判空不校验格式，`"abc-def-ghi"` 得到 `NaN`、`"0-0-0"` 被规范化成 1899 年，一路渲染到列表行与到期预警。
  - 改为只接受 `4-2-2` 数字段并校验月/日范围；带时间的 ISO 串仍按日期段计算。

- **根目录只有文件时一个文件都不显示**（`deal-detail/FolderTree.tsx`）
  根目录无子文件夹时无条件 `return` 一个空 div，直接跳过后面的 `files.map`。有文件时改为继续往下渲染。
  - 同源缺陷：根目录点「新建文件夹」被空态提前 `return` 挡住，点了没反应。空态条件补 `creatingIn !== subpath`（与子目录分支口径一致）。

### 修复 · 安全

- **`DocumentPreview` 缺 scheme 白名单**（`document-recognition/components/DocumentPreview.tsx`）
  后端可写的 `file_url` 直通 `<a href>` 与 `<iframe src>`，未过 `safeHttpUrl`——同目录 `RecognizeDialog` / `RecognitionSummary` 两个兄弟组件都已加守卫，唯独此文件遗漏。
  - 补 `safeHttpUrl`，`javascript:` / `data:` 均被挡（React 因空串不渲染该属性）。
  - 回归测试 4 条：合法 https 正常渲染、`javascript:` / `data:` 被挡、图片分支同样受保护。

- **会话过期与主动退出清理范围不一致**（`lib/reset-client-state.ts` 新增、`lib/api.ts`、`AppNavbar.tsx`）
  401 刷新失败只 `clearTokens()` 就跳 `/login`，而主动退出会额外清 query 缓存、材料预处理阅读器、PDF 缓存、AI 助手转录。同一浏览器换人登录时，上一账号的材料草稿/阅读器恢复点（localStorage）会残留给下一个人。
  - 新增 `resetAllClientState` 作为唯一清理入口，两条路径共用；`QueryClient` 由 `main.tsx` 通过 `setQueryCacheCleaner` 注入（lib 层拿不到实例）。
  - 三条 feature 清理链（material-prep / copilot / pdf）走动态 import，避免把 ~1MB 的 pdfjs 拖进首屏。
  - 顺手修掉注入清理器抛错时中断整个登出（token 已清但 feature 未清，表现为「点了退出没退出去」）。
  - 新增 `SessionExpiredError` 类型，`main.tsx` 的 retry 判断改用 `instanceof`，不再依赖 `'Session expired'` 文案字符串。

### 修复 · 交互与状态机

- **Copilot `send()` 未校验会话归属**（`copilot/store.ts`）
  `createSession()` 在途期间用户切走，迟到结果会覆盖用户刚选中的会话并把消息推进去。
  - 记录本次发送的起始 `sessionId`，回来后比对不一致即丢弃。

- **社交绑定失败落到死端页**（`auth/SocialCallbackPage.tsx`）
  绑定失败（`not_bound` / `already_bound` / `provider_occupied`）时后端仍带回 `redirect`，但前端错误分支只给「返回登录页」，用户在绑定页的上下文丢失。
  - 按 `redirect` 决定落点：绑定流程显示「返回账号绑定」，同时保留回登录页的次要出口。

- **飞书二维码错误态点「重新加载」无效**（`auth/components/SocialQrPanel.tsx`）
  `boot()` 用 `containerRef.current` 同时承担「组件是否挂载」与「找到挂载点」两个职责，而容器只在非 error 态渲染——错误态 `ref` 为 `null` 被误判成已卸载而直接 `return`，重试永远无效，用户只能刷整页。
  - 新增 `mountedRef` 表挂载状态，容器为 null 不再中断流程。

- **通行密钥 Esc 取消改名可能被当成提交**（`auth/components/PasskeySection.tsx`）
  Esc 置 `renamingId=null` 会卸载输入框，部分浏览器卸载时补发 `blur`，`onBlur` 里的 `rename.mutate` 把「取消」变成「保存」。
  - 加 `cancelRenameRef` 标记取消意图，`blur` 时跳过提交。（jsdom + React 19 实测不派发 blur，故为防御式修复。）

- **文字提醒部分成功会重复创建**（`home/components/SideCards.tsx`）
  逐条创建时中途失败，前面已建成功的提醒不记入结果、也未从待处理行移除，用户重试会把它们再建一遍。
  - 改逐条 `try/catch`，已成功的行从 `textRows` 移除，只留失败行供重试，并提示「N 条已加入，M 条未写入可重试」。

- **文件夹上传被 ky 默认 10s 超时误杀**（`workbench/api.ts`）
  `folder-upload` 漏传 `UPLOAD_TIMEOUT_MS`，而 material-prep / document-recognition / home 三个模块的上传端点都已传。案件工作台成批上传扫描件必然超时。
  - 补 `timeout: UPLOAD_TIMEOUT_MS`（300s）。

- **文件夹重命名后已展开目录莫名收起**（`deal-detail/FolderTree.tsx`）
  重命名成功后不清 `open` 集合里的旧 subpath，新名字的行 `isOpen` 为 false，用户的展开状态丢失。
  - 把展开集合里的旧 subpath（含子树）改写为新名。

### MCP 工具

#### 修复 · 契约漂移（378 个工具全量清偿）

首次真正启用 MCP 前做全量审查，发现「注册成功但永远不可用」的批量化契约漂移：MCP 框架按返回类型注解生成 `output_schema` 并强制校验，声明与后端实际返回不符即每次调用都 `ValidationError`。原有测试只做正则匹配（检查函数名是否在 `__all__` 与 `server.py` 里），不导入工具、不比对后端，因此全绿但工具全废。

**输出契约（24 个必定失败 → 0）**

- 声明 `list` 但后端返回 `dict`：`browse_case_folders` / `list_scan_subfolders` / `list_contract_scan_subfolders` / `list_template_bindings` / `list_system_configs` / `list_available_models` / `enterprise_search` / `match_templates` / `get_custom_fields` / `get_fill_history` / `get_review_models`
- 声明 `dict` 但后端返回 `list`：`list_case_logs` / `list_case_parties` / `list_clients_with_docs` / `get_contract_all_parties` / `update_contract_lawyers` / `extract_template_placeholders` / `get_undefined_placeholders`
- `delete_*` 声明 `None` 却丢弃后端返回：统一改为返回后端结果
- `download_sms_documents` 用 `client.get` 请求 ZIP 二进制（`resp.json()` 必崩）：改用 `client.download` + base64

**补齐 22 个能力缺口**（身份 / 期限 / 正文等字段此前未暴露）

#### 修复 · 静默兜底

- **`as_items` 不再静默伪造空列表**：旧实现把无法识别的返回结构变成 `{items: [], total: 0, data: {...}}`。后端结构一旦变化（如改成 `{data: [...], count: n}`），模型看到 `items=[]` 就如实回答「没有数据」——数据明明存在，用户无从察觉。这比直接报错更危险。改为抛 `TypeError` 并说明期望结构。

#### 修复 · 限流

- 限流改为**快速失败**，不再静默等待后返回不确定结果。

#### 新功能 · `fetch_url`

把「点不开的搜索链接」变成可读正文。`web_search` 只返回标题 + 链接 + 摘要，且链接是搜索引擎跳转形式（`/link?url=hedJjaC...`），模型据此无法回答需要看原文的问题（法条全文、判决书、政策文件）。

**设计：诚实报错优先**

这个工具最大的风险不是抓不到，而是**假装抓到了**——返回 `{ok: true, text: ""}` 会让模型以为「页面没内容」而不是「我们被拦了」，与刚修掉的 `as_items` 静默兜底是同一类错误。因此：

1. 抓不到一律返回 `{ok: false, reason, message}`，`reason` 区分 `antispider` / `javascript_required` / `blocked` / `timeout` / `network_error` / `http_error` / `empty_content` / `invalid_url`，专门给模型做决策用；
2. 核心契约由测试守护：`ok=True` 时 `text` 必然非空。
