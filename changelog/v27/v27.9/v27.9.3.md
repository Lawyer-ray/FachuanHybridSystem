## 后端

#### 新功能 · 共享 MCP 运维命令（make mcp 系列）

- **`make mcp`**：一键「杀旧（TERM→5s→KILL）→ 拉新（同 `spawn_shared_server` 的 env/端口/日志约定）→ 等端口就绪 → **工具面核对**」，核对不过非零退出——忘重启再也不会静默漂移。
  - 实现于 `scripts/shared_mcp.sh`（bash 3.2 兼容，端口/主机解析顺序与 `shared_mcp.py` 一致：环境变量 > `backend/.env` > 默认 8011/127.0.0.1）。
- **`make mcp-verify`**：MCP **真握手**（streamable-http initialize + list_tools）取「线上工具面」，与「代码注册表」（进程内 `mcp_server.server.mcp.list_tools()`，复刻 `__main__` 的 Django 引导与 stdout 改道）**逐名对比**：
  - 线上缺失 → 直接点名（旧进程没换新代码）；
  - 线上多出 → 代码回退后未重启；
  - 握手失败 → 端口未就绪**或被非 MCP 进程占用**（给出 lsof 排障提示）；
  - 成功路径输出干净（bootstrap 的 60 行 Django INFO 走 stderr 暂存，仅失败时附异常栈尾部，且过滤 INFO 噪音）。
- **`make mcp-status`** / **`make mcp-logs`**：进程 PID/运行时长/命令行、endpoint、日志路径（`$TMPDIR/fachuan-shared-mcp-<port>.log`）；跟随日志。
- 实测：restart 全流程（停止 10h+ 旧进程 → 4s 就绪 → 397/397 工具一致 ✅）；端口被 `http.server` 占用时 verify 明确报「可能被非 MCP 进程占用」并非零退出。

#### 说明 · 已知边界（本次记录，未改 Django 代码）

- `ensure_shared_server` 的复用判定只探端口不握手：若 8011 被**非 MCP** 进程占用，Django 自动拉起路径会静默「复用」占用者，pi 连工具时报错难懂。`make mcp-verify` 能发现该状态（握手失败 + lsof 提示）；如需彻底修复（拉起路径也做握手探活），列入后续批次。
- 文档中写死的工具数（378/395）已随注册表增长漂移（当前 397）——以 `make mcp-verify` 的「注册表 vs 线上」对比为准，不再维护文档口径数字。
