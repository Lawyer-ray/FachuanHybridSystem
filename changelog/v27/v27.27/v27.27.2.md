## 一句话

| 之前 | 现在 |
|:--|:--|
| 一张网送达的文书只能「转材料包」再手工拆段；**案件匹配 / 自动重命名 / 案件文件夹归档 / 群通知**这四件事，只有在首页「法院短信」卡里手工粘贴正文或拖本地文件才走得到 | 收件箱里一条一张网消息，点一次就能进同一条短信处理链路 |

| `CourtSMS.delivery_event_id` 是死字段（无写入方） | 复活为「一张网送达编号 `sdbh`」的跨来源去重键：同一送达被多个律师来源各拉一份时只处理一次 |

## 自动通道：起始时间节点

- 新字段 `MessageSource.auto_sms_since`（留空 = 不自动）。
- 数据迁移把**现存** `source_type='court_inbox'` 的来源设为迁移当时的 `now()` ——
  即「从现在起自动，之前的不管」；现有 139 条历史一张网消息（`received_at` 均早于此刻）
  一条都不会被回溯处理。反向迁移置回 `NULL`。
- 判据是 `InboxMessage.received_at >= auto_sms_since`（**恰好等于**也算，有边界测试）。
- 挂载点：`tasks.py::sync_source_by_id` 尾部。**不能挂 `post_save` 信号** ——
  `CourtInboxFetcher` 用 `bulk_create` 建消息，信号根本不会触发；而手动同步与定时同步
  都汇聚到这一个函数，挂这里一处覆盖两条入口。
- 单轮上限 50 条（`AUTO_SUBMIT_BATCH_LIMIT`），单条失败只 warning 跳过，不中断、不回滚已提交的。

## 手动通道：收件箱按钮

- 新端点 `POST /api/v1/inbox/messages/{id}/submit-to-sms` → `{success, sms_id, created, attachment_count, skipped[]}`；
  权限与 `/convert` 同口径（`_get_message_or_404`）。`created=false` 也是 200 + 既有 `sms_id`。
- 前端：收件箱抽屉/首页就地展开的动作区新增「提交短信流程」按钮（仅 `court_inbox` + 有附件）；
  `created` 决定 toast 是「已提交短信处理（SMS #N）」还是「该消息已提交过（SMS #N）」。
- 原先只存在于 Django admin 的 `submit-to-sms` 视图改为**薄壳**，复用同一个服务，
  admin 的成功/重复/无附件三种文案与跳转逐字保持不变。

## 三个必须钉死的细节

1. **复制字节，不引用路径**。`DocumentRenamer` 是 `original_path.rename()`（原地改名），
   把 `attachments_meta[].local_path` 直接交出去，收件箱里那条消息的附件会当场失效
   （预览/下载/转材料包全 404）。所以每个附件先 `download_attachment` 取字节 →
   `save_uploaded_file` 落到 `automation/uploads/`（白名单 + 50MB + 魔数校验，与「客户转交」
   通道同口径）→ 只保存副本的 media 绝对路径。有回归测试断言**原文件仍在且字节不变**。
2. **案号必须抽出来写进 `case_numbers`**。`CaseMatcher` 只在 `sms.case_numbers` 非空时才做
   案号精确匹配，否则退化成当事人匹配 —— 一张网消息正文里往往只有法院与文书名，命中率差得多。
   实测：139 条历史一张网消息**主题 100% 带案号**，其中 91 条（65%）库内已有对应案件。
3. **幂等三级**：`inbox_message_id`（本消息）→ `delivery_event_id=sdbh`（跨来源同送达）→
   内容去重键（**同时按新口径与升级前 Admin 按钮的旧正文口径**各查一遍，否则升级前在 admin
   点过的消息会再归档一次）。`inbox_message_id` 上加了条件唯一约束兜并发。
