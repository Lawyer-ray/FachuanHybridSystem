# v27.27.7 · qoder 不选模型时改跑律所的 model（原来落到 Qoder 云侧的 Auto）

> **版本判定**：§1.2 同一条线（`v27.27.x` 的 AI 选择器）→ 第三位 +1。
> 判号按 PIT-026 规则 1：`origin/main` 最新 = `v27.27.1`，本分支第 6 条 → `v27.27.7`。

## 一句话

| 之前 | 现在 |
|:--|:--|
| 勾了 Qoder、不选模型 → 交给 CLI 默认 = Qoder 云侧的 **`Auto`**，用哪个由它的账号套餐决定；本所账号实测报 `You do not have access to this model service. Please check your account permissions.` | 不选 → **`fachuan-gw/kimi-2.6`**（律所网关，走 BYOK，已跑通）；一个律所模型都没有时才回落 `Auto` |
| 菜单里「默认」只是显示上的 `Auto`，与实际下发的不一定一致 | 三处同一口径：`/agent/backends` 的 `default_model`、模型下拉的显示值、真正下发给 CLI 的 `model` |

## 为什么默认 ``Auto`` 是错的

`Auto` 是 **Qoder 云侧**的型号，具体用哪个由它的账号套餐决定，本所账号对它
**没有权限**（错误日志里那条英文话术就是它）。而 `fachuan-gw/*` 这一批是律所
自己的网关模型（`QODER_SDK_CUSTOM_BASE_URL_BYOK=1` 已接好，实测能回答且
`model_usage` 报的是它自己）。律师不选模型时的意图很明确：**和别处一样用律所
自己的模型**。

## 改了什么

- `qoder_models.py`：`default_model()` 改为「律所网关模型优先 → `Auto` → 第一项」，
  并抽出 `_pick_default()`；`for_display()` 用同一个口径（两处不一致等于骗人）
- `qoder_backend.py`：抽出 `_effective_model(ctx_model, target)`，优先级
  **gateway target → 律师手选 → 律所默认 → 交回 CLI**；`_stream` 与 `_stream_once`
  共用它；`direct` / `--settings` 也按**实际要跑的模型**算（默认值就是 BYOK 模型时
  不带 settings 会丢掉 provider 配置，那一轮必然失败）
- 顺带把两个会让「选律所模型」失败的东西修了：
  1. **磁盘缓存**：模型清单落到 `<FACHUAN_AGENT_HOME>/qoder/models.json`，
     跨 reload / 跨 worker 复用；`CACHE_FORMAT` 版本号让旧缓存自动失效
     （解析规则改了，旧文件里存的是「已解析的坏 id」，必须重跑）
  2. **带括号的 id**：`kimi-2.6(Anthropic) (fachuan-gw/kimi-2.6(Anthropic))` 原来被
     非贪婪正则从中间切开、拼出不存在的模型名；改成「从行尾往前配对括号」
- 发言路径用 `cached_default_model()`（**绝不跑子进程**）：拿不到就用 CLI 默认，
  不让一条消息为了一份模型清单等 5 秒

## 实测

| 请求 `GET /api/v1/agent/backends` | 结果 |
|:--|:--|
| 缓存格式升级后第 1 次 | 200 / **3.73 s**（重跑一次 `--list-models`） |
| 第 2 次 | 200 / **0.024 s**（磁盘缓存） |
| qoder `default_model` | **`fachuan-gw/kimi-2.6`** |
| qoder 模型数 / 末三项 | 20 / `fachuan-gw/kimi-2.6`、`fachuan-gw/glm53`、`fachuan-gw/kimi-2.6(Anthropic)` |

## 已知取舍

- **冷机器第一次仍要 ~5 秒**（子进程），之后磁盘命中。落盘解决的是 reload / 多 worker 的重复付费。
- **没接 BYOK / `FACHUAN_QODER_SHOW_BYOK=0` 时回落 `Auto`**：那时律所模型本来就不在清单里，
  硬塞一个进请求等于必失败。
- **`gateway` 模式不受影响**：那条路由 `target.model` 决定，优先级最高。
