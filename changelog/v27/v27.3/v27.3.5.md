# v27.3.5

律所ID（OA 案件 GUID）直通三连 + 案号查 GUID 换更简通道。本版本全部为后端改动（含 Django admin 模板），3 commits。授权依据：JCWD-GZ-2026-033（V3）5.8 读取复制条款，全部为只读查询。

## 后端

#### 新功能：合同详情页「申请开票」支持律所ID直开

- **有律所ID（law_firm_oa_guid）**：浏览器新标签直接打开 OA 开票申请页（`FapiaoRequestReg.aspx?ProjectID=<GUID>&FirstModel=FINANCE&...`）——用户本机浏览器自带飞连同博会话，零服务端中转（服务器部署形态可用的关键设计）
- **无律所ID**：回退原服务端 Playwright 备用链路（查案号 → 搜索案件 → 打开开票页），行为不变

#### 新功能：「打开OA」支持律所ID直达归档申请页

- **有律所ID**：Playwright（headed）登录后直达 `projcloseapp.aspx?&FirstModel=PROJECT&SecondModel=PROJECT008&keyid=<GUID>`——案件随 keyid 直接定位，跳过「弹窗搜案号 → 选案件 → 回填」；案件小结、删默认附件行、卷宗上传、保存等填充逻辑一行未动
- **无律所ID**：回退弹窗搜案方案，行为不变；调度链从 executor 到 `ArchiveAdapter.open_oa_page(project_id=)` 协议加参透传（恒字符串语义：空串=备用方案）

#### 优化：案号查 GUID 改走案件选择对话框 GET 直搜（免 VIEWSTATE）

- 依据《案号查GUID方法文档.md》1.4 更简变体（2026-10-06 实测取证）：全站共享的案件选择对话框 `searchdlg/searchProject.aspx` 接受 GET 查询参数直接搜索，**单次 GET 完成**（原先「GET 列表页取 ~13KB VIEWSTATE + POST postback」两步，VIEWSTATE 过期/不匹配故障类整个消失）；结果 radio value 即 GUID，lxml 提取 + 文档同款正则兜底
- **三字段同一入口**：`project_no`（案号）/ `project_name`（案名）/ `project_customer_name`（客户名），protocol（CaseGuidLookupAdapter）+ JTNAdapter + ScriptExecutorService 同步透出 `lookup_oa_case_guid_by_name` / `lookup_oa_case_guid_by_customer_name`（admin UI 暂未接入，供后续按案名/客户名查 ID 复用）
- **归档弹窗搜案的纯 HTTP 预解析**：归档 Playwright 链路（半自动 open-oa 与全自动提交）在无律所ID 时先用案号查 GUID 预解析，**唯一命中即直达 keyid 归档申请页**（跳过 iframe+radio+重试的弹窗交互）；查询失败/0 命中/多命中一律回退原弹窗链路（弹窗按行精确匹配案号，多候选仍能选对），行为只增不改
- **会话自愈链原样保留**：网关回调 Set-Cookie 恢复 + 单 client 表单账密登录 + 残留网关 token 清理（v27.3.4 修复的核心资产，与具体页面无关，仅落点判定从「有 VIEWSTATE」换为「对话框表单特征 + 非登录页」）
- 不适用三处维持原状：盖章（无 keyid 直达页，弹窗本身是回填手段）、开票 Playwright 备用链路（搜开票页自身）、案件导入（要案件详情非 GUID）
