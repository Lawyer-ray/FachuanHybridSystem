# v27.3.6

安全审计整改批（多 agent 全栈审计 + `.workbuddy-ai/security-audit-2026-10/SECURITY-AUDIT-REPORT.md` 逐项复核）。2 commits。全部为后端改动；每一处均经「读实际代码 + 追调用链 + 单测验证」确认，未采信报告字面结论。

## 后端

### 安全加固（第一批）

- **收件箱 IDOR 收敛（新增 `services/inbox_access.py`）**：原 `inbox_api` / `message_source_api` 全部端点只按 pk/source_id 取对象，任意登录用户可读改删全所他人的材料包与消息来源。新增集中可见性策略：手动上传的消息收敛到 `uploaded_by`，外部拉取的消息收敛到 `source__credential__lawyer_id`，无凭证来源仅管理员可见（fail-closed）；列表层 QuerySet 过滤 + 单对象层 `can_view` 双层防护，无权限时返回 404 不泄露存在性。注意 `is_staff` 不等于管理员——只有 `is_superuser` / `is_admin` 走全量
- **auto_register 超管硬编码口令移除**：`AUTO_REGISTER_BOOTSTRAP_PASSWORD = "1234qwer"` 从源码中删除，改由 settings 注入；同时要求显式开启 `ALLOW_FIRST_USER_SUPERUSER`，未配置口令即 fail-fast RuntimeError。DEBUG 实例不再可零凭证抢超管
- **workflow MCP code 步骤旁路封堵**：`create_workflow_template` / `update_workflow_template` 补 `validate_steps_for_user`（user 缺省按非 superuser fail-closed），封堵「经 MCP 落库绕过 API 白名单 → 调度已下线的 `generic_code_exec`」这条链路
- **Temporal code 步骤物理拒绝**：`workflows.py` 的 code 步骤分发体改为硬拒绝（`ApplicationError`），不再有可执行分支
- **前端 sourcemap 下线**：`sourcemap: 'hidden'` 仍会随包发布 `.map` 文件（等于把未压缩源码和注释公开），改为 `false`；需要时走显式 `pnpm build:sourcemap` 产物不出 dist

### 安全加固（第二批）

- **【高危】WebSocket 会话属主校验（H-1）**：`litigation_consumer` / `mock_trial_consumer` 的 `_get_session` 原先只按 `session_id` 查存在性，任意已认证用户连接 `ws/.../sessions/<他人 id>/` 即可读取案情（案件名、案由、诉讼标的额、全部当事人及诉讼地位）并在他人会话上驱动 LLM 生成文书。同资源的 HTTP API 本来就有属主校验，两条链路防护不一致，WS 成了绕行通道。现与 REST 同口径：非 `is_superuser` / `is_admin` 按 `user_id` 过滤；`user` 缺失时 fail-closed（按 `user_id=None` 过滤，必然查不到），不再因 `user is None` 跳过过滤；查不到与无权限都统一 4004，不泄露会话是否存在
- **【中】LLM 出站 TLS 校验（M-3）**：`llm_preflight.py` 移除无条件 `check_hostname=False` / `verify_mode=CERT_NONE`——LLM 请求头携带 `Authorization: Bearer <API Key>`，连通性检查没必要每次都裸奔发 Key。`openai_compatible._ssl_verify()` 在非 DEBUG 下忽略 `LLM_SSL_VERIFY=false` 并 `logger.warning`，防止运维误设导致全部 LLM 流量可被 MITM 截获
- **【中】ICS 日历订阅缓存头（M-4）**：`Cache-Control` 由 `public` 改 `private, max-age=14400`。ICS 内容（开庭时间、案件安排）是个人数据，`public` 会让共享缓存/公司代理把一个人的日程暴露给同缓存域的其他请求
- **【中】收件箱列表 limit 收口（M-6）**：`limit` 收敛到 `[1, 1000]`。原先 `limit<=0` 跳过切片 → 全表序列化（每行还附带 7 个 draft_state resolver 的 N+1 查询），用户上传大量材料包后可自我放大为 DoS
- **【中】案件文件夹 ZIP 解压防护（M-7）**：`folder_generation_api` 的裸 `zipfile.extractall` 改为 `FolderFilesystemService().extract_zip_bytes()`，接上既有的 `ensure_zip_within_limits`（解压炸弹）+ `sanitize_zip_member_path`（Zip Slip）。zip 内文件名由 `case.name` 间接可控，原先可写到绑定目录之外
- **【中·新增发现】合同归档学习规则改落 JSON**：`_learned_rules.py` 原先把 DB 规则（含用户可影响内容）用 f-string 拼成 Python 源码落盘、再 `importlib.reload` 导入执行——这是一条远程代码执行路径。已实证旧代码会产出 `["x"] if __import__("os").system("echo PWNED > /tmp/x") else [""]` 这样的活条件表达式。现改为 `_learned_rules.json` + `json.dumps`，加载走 `json.loads`，删除 `importlib.reload`；既有 13 条规则经 `ast.literal_eval` + `json.dumps` 转换

## 未随本版处理（需业务决策或独立排期）

- **reminders 全局提醒权限（M-1）**：无关联目标的全局提醒对所有登录用户可读/改/删。报告自身标注「需先与业务确认语义再改」——若本意是团队共享，只需把写操作收敛到创建人；若是个人日程，则 service 层加 `created_by` 过滤。需业务确认，且要动模型
- **JWT 经 `?token=` 查询参数传递（M-2）**：会落入 nginx access log / 浏览器历史 / Referer。整改需在 nginx 日志脱敏或改短时一次性下载票据，涉及 `deploy/`（该目录被 gitignore，改动仅存在于本地，不入库）
- **ICS Token 无过期（M-4 第 2 条建议）**：需给 `CalendarFeedToken` 加 `last_used_at` + 过期字段，涉及迁移
- **验证码端点匿名刷量（M-5）**、**Refresh Token 30 天无轮换无黑名单（M-8）**：前者需定配额口径，后者需启用 `ROTATE_REFRESH_TOKEN` + `token_blacklist`（前端跨 tab 刷新租约代码已为此做好准备）
- **本地部署配置改动不入库**：`deploy/nginx/nginx.conf` 的安全响应头（CSP / X-Frame-Options / nosniff / Referrer-Policy / Permissions-Policy）与 `.map` deny 规则、运行时目录 19 个残留 `.map` 文件的清理，都只作用于本机
