## 后端

### 安全加固：全局提醒写权限收敛（M-1）

按业务确认的语义（**团队共享**）实现：读保持全员，写收敛到创建人与管理员。

- **`Reminder` 新增 `created_by` FK**（迁移 `0011`）+ 存量数据回填（迁移 `0012`）。此前「创建人」只存在于部分内部路径写入的 `metadata["created_by_user_id"]`，既无约束也可能缺失，不能作为权限判定依据。回填口径：metadata 有该键且用户仍存在才填，其余保持 NULL 由管理员兜底（fail-closed）
- **新增 `services/reminder_access.py`** 集中判定：`is_admin_user`（注意 `is_staff` 不算管理员，与 message_hub 同口径）+ `can_write_reminder` + `ensure_can_write_reminder`。关联了合同/案件/案件日志的提醒，写权限仍由调用方已做的 `AccessPolicy` 决定，本模块不重复判定，保持原有行为不变
- **四个写端点接入**：`update_reminder` / `delete_reminder` / `complete_reminders`（批量完成同样是写操作）/ `create` 记录 `created_by`
- **`ReminderOut` 增加 `created_by` 字段**：前端据此置灰不可编辑的行——否则用户点了才收到 403
- `calendar_month_service` 读过滤改为 `created_by_id OR metadata` 双匹配，回填完成前不丢可见性
- admin 日历新增提醒、`document_recognition` 确认日期候选时补记 `created_by`

### 安全加固：Refresh Token 轮换 + 黑名单（M-8）

- **`SIMPLE_JWT` 启用 `ROTATE_REFRESH_TOKENS` + `BLACKLIST_AFTER_ROTATION`**，`INSTALLED_APPS` 增加 `ninja_jwt.token_blacklist`。原先 refresh token 被盗后有 30 天窗口且每次刷新不轮换，可无限静默续期；现在每次刷新都签发新 refresh、旧的立即进黑名单，二次使用即被拒
- 实测确认 ninja_jwt 的 `set_jti`/`set_exp`/`set_iat` 只重置这三个 claim、**不清空其他 claim**，故 `pwd_ver` 会被轮换后的新 refresh 自动继承，「改密即失效」的既有语义不受影响——已在 `jwt_password_binding` 注释中记录该依赖，防止未来上游改动破坏它

### 连带修复（本轮实测暴露，非报告列出）

- **扫码登录 500**：安装 `token_blacklist` 后 `RefreshToken.for_user()` 会写 `OutstandingToken`，在 async 上下文直接调用抛 `SynchronousOnlyOperation`（`token_exchange_service` 直接崩）。已包 `sync_to_async`。另一个铸造点 `passkey_service` 是同步函数，不受影响
- **前端刷新掉线**：`refreshWithLease()` 原地把响应里的新 refresh 丢掉、回存旧 token——轮换开启后下一次刷新必然拿到「Token is blacklisted」而静默掉线。改为落库 `response.refresh`（后端未返回时沿用旧的，保持兼容）。跨 tab 租约机制的注释也从「防御未来开启轮换」更新为「轮换下是必需」

## 已知环境问题（与本分支改动无关）

- 本机 PostgreSQL 残留 47 个 `test_test_*` 数据库（历史 pytest 遗留）。其中一个 `test_test_fachuan_dev` 会让 E2E 套件在建库阶段直接 `DuplicateDatabase` 失败。首次全量跑 E2E 需先清理或换 `DB_NAME`
- **E2E 套件无法连续跑**：`admin_page` fixture 每个用例都登一次 `/admin/login/`，而限流是 `AUTH_REQUESTS=5 / 60s`——一个文件跑到第 3 个用例就开始撞限流，表现为 `Locator.fill` 超时（`#id_username` 找不到，因为页面变成「请求过于频繁」）。已在干净 `main` worktree 上复现同样失败，确认是套件自身设计问题。规避：逐用例跑并间隔 70s，或临时调高 `AUTH_REQUESTS`
