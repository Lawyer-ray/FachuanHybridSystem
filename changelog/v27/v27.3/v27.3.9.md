## 后端

### 安全加固配套：油猴脚本接入验证码识别（commit `3a575a97a`）

v27.3.8（M-5）把 `/api/v1/automation/captcha/recognize` 改为要求 `X-Captcha-Secret` 共享密钥，当时「仓库内无 HTTP 调用方」的假设不成立——本机 Chrome 有油猴脚本在调这个端点，重启后端后立即表现为每 5 秒一次 403（`captcha_recognize_secret_not_configured`）。

- **`CORS_ALLOW_HEADERS` 放行 `x-captcha-secret`**：脚本跨域携带自定义头会触发 CORS 预检，未放行时 `OPTIONS` 直接失败，请求到不了鉴权逻辑。放行本身无安全影响——头值不匹配时端点仍 403
- **`.env.example` 补 `CAPTCHA_RECOGNIZE_SECRET` 文档**：生成命令、fail-closed 行为、外部脚本接入说明，避免部署时遗漏配置

### 修复：测试环境禁止真实入队 Django-Q 任务（commit `114b97842`）

**测试进程与开发栈（uvicorn:8002 / qcluster）共用同一个 Redis broker**，测试里 `submit_task` 会把任务真实写进队列被 qcluster 捞走执行。实际爆点：`test_recognize_document` mock 的 `task.id = 1` 撞上 7 月的存量任务 #1（其 PDF 文件早已丢失），2026-10-09 该任务被测试**三次重执行**并报 `FILE_NOT_FOUND`，服务端日志混入 16 字节假 PDF 与 `unittest.mock` 堆栈，任务状态被测试改写为 failed。

- 根 `conftest.py` 新增 autouse fixture：monkeypatch `django_q.tasks.async_task` 为 no-op（返回假 ID）。提交方在调用时才 import，patch 能生效
- 全仓库核查确认无测试依赖真实入队（均为 mock service 层或进程内直调任务函数）；tasking 全量单测 + 文书识别 API 集成测试通过
- 需要验证任务执行逻辑的测试应直接调用任务函数本身

### 修复：证件待上传占位行存 NULL（commit `3f66c7bb0`）

`ClientIdentityDoc.file_path` 有唯一约束（`uniq_clientidentitydoc_client_file_path`），而 Django admin inline 保存多个新证件行时先整批 INSERT 空占位、文件随后回填——占位行存空串 `''` 时第二行即撞唯一约束（admin 实爆复现）。

- `file_path` 改可空（对齐 DB 实际列），save 钩子空串归一 NULL，同 `Client.id_number` 既有范式
- `resolve_media_url` 注解放宽接受 `None`
- 补 NULL 语义回归测试（含 admin inline 双新增行用例）
- 迁移 `0017` 仅 `AlterField` 元数据对齐（**已在开发库应用**）

## 运维注意

- **部署到任何环境都必须配置 `CAPTCHA_RECOGNIZE_SECRET`**（强随机值），否则验证码识别端点整体 403。外部脚本（油猴等）需同步配置该值到请求头 `X-Captcha-Secret`
- 油猴脚本本体在 `extensions/chrome/法院网站验证码识别.js`（不入库），更新 `CONFIG.SECRET` 后生效
- 测试不再产生真实队列任务后，开发栈日志不应再出现 `unittest.mock` 堆栈或假文件名（`document.pdf` 16 字节）的识别请求；若再现说明有测试路径绕过了根 conftest 的防护
