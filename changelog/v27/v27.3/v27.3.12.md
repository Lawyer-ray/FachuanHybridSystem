# v27.3.12

分支 `fix/backend-startup-pg18-diagnosis`：后端启动 PostgreSQL 自愈预检 + Django 安全补丁 + Admin 其他工具入口整理。

## 后端

### 新功能：PostgreSQL 自愈预检（scripts/ensure_postgres.sh）

2026-10-11 事故复盘：Mac 关机流程被打断致 PostgreSQL 优雅关闭未完成即断电，残留 `postmaster.pid` 锁文件；重启后该 PID 被系统复用给无关进程，PG 自带的 `kill(pid,0)` 探活被骗过，launchd 无限重试全部撞死在 `lock file already exists`，`make backend` 连接被拒刷屏。

- 新增 `scripts/ensure_postgres.sh`：数据库正常时静默通过（约 0.2s）；未就绪时自动诊断，`postmaster.pid` 记录的 PID 已死或属于非 postgres 进程（按 `ps -o comm=` 进程名复核，比 PG 自带探活更强，可识别 PID 复用）即删除过期锁文件并 `brew services restart`，等待就绪最长 30s
- 接入 `backend/Makefile` 的 `migrate` 目标（覆盖 `run-dev` / `qcluster` 等全部后端入口）与根 `Makefile` 的 `start` / `prod-restart`（公网栈）
- 兼容 macOS bash 3.2：变量一律 `${VAR}`（`$VAR` 紧跟全角字符会把多字节尾部误并入变量名报 unbound variable）；`brew services list` 空格对齐列用 awk 解析

### 新功能：Token 黑名单收纳进「其他工具」

`token_blacklist`（ninja_jwt.token_blacklist，含 OutstandingToken / BlacklistedToken）原为侧边栏顶级分区，现与其他工具统一：`_OTHER_TOOLS_APPS` 新增入口，`_HIDDEN_APP_LABELS` 隐藏顶级分区，`/admin/token_blacklist/` 直链保留。

### 修复：「其他工具」OA 入口去重

OA 立案 / OA 盖章两条目 `app_label` 同为 `oa_filing`，hub 页对同 app 条目各自全量自动发现子模型且卡片主链接被覆盖为 `/admin/oa_filing/`，导致两张卡片渲染内容完全相同。删除「OA 立案」条目仅保留「OA 盖章」；oa_filing 三个 session（filing/stamp/archive）直链不受影响。

## 依赖变更

### Django 6.1.1 → 6.1.2（安全补丁）

6.1.2（2026-10-06）修复 3 中危 + 1 低危 CVE：

- CVE-2026-84429：`parse_header_parameters()` 二次方复杂度 DoS，经 `Accept`/`Content-Type` 头未认证可触发——公网栈经 CF Tunnel 暴露，属真实攻击面，本项目受影响
- CVE-2026-77050 / CVE-2026-87890 / CVE-2026-87975：本项目无语言变体缓存滥用、无 GIS/raster、自定义主键均为 `UUIDField(editable=False)`，不受影响
