## 为什么是它（三条硬约束全过）

| 约束（`apps/agent/README.md §2`） | `claude-agent-sdk` 的满足方式 |
|:-|:-|
| 工具调用前能**阻塞**等人工审批 | `can_use_tool` 是 `async` 回调，实测卡 300s 不超时、不取消 |
| 能挂起等外部系统决策 | 回调内 `await request_approval(...)`，复用现有审批单与分级 |
| 能挂共享 MCP | `mcp_servers` 支持 `type="http"` + 自定义 headers |

它跟 pi 是同一类东西（拉 CLI 子进程、把消息流回 Python）。**在四栏 OpenAI 兼容
通道之外多一条 Anthropic 通道**，是它进入并答的唯一理由——同样的问题换协议栈跑，
差异才看得出是模型问题还是 harness 问题。

## 四条网关接线事实（都是实测，不是推断）

1. **`ANTHROPIC_BASE_URL` 不能带 `/v1`**。库里 `LLMProvider.base_url` 是
   `http://152.16.10.110:4000/v1`，而 CLI 自己追加 `/v1/messages` → 照抄会得到
   `/v1/v1/messages`（404）。`anthropic_base_url()` 负责剥尾，有参数化用例守着
   （含 `.../litellm/v1` 只剥最后一段的用例）。
2. **只有名字命中 `anthropic` 的模型可走这条通道**。实测 `glm53` 在
   `/v1/messages` 上把思考塞进 `type:"text"` 块 → **正文为空**（3/3 次空回合）；
   `kimi-2.6(Anthropic)` 干净。`select_anthropic_model()` 强制过滤；显式选了
   不兼容模型时**报错而不是回落**（静默换模型会让账目与用户认知同时错）。
3. **审批回调会被三种配置静默跳过**：`permission_mode="bypassPermissions"`、
   整工具级 `allowed_tools`、settings 文件里的 `permissions.allow`。三者都写死
   在后端常量里，不暴露给调用方。
4. **`env` 是叠加语义**（与 codex 相反）：宿主 `ANTHROPIC_*` 与代理变量会渗进
   子进程。`build_env()` 显式覆盖 base_url / key / model / config dir，并把
   6 个代理变量置空——内网网关 + 本机 Clash = 502 无 body（`dsh_config` 的老教训）。

## 已知取舍与边界（都是"为什么不做"）

| 边界 | 为什么不做 |
|:-|:-|
| `steer=False`（不支持运行中插话） | SDK 有 `client.query(priority=...)`，但语义是「可能被并入当前 turn」，与 pi 的 `queued` 不同，且需要接 `LiveBackendHandle`。声明 `True` 会让前端渲染出一个「敲进去也没人接」的插话框。**接线并验证后再改。** |
| 工具面默认 `lite` 档 | Anthropic 协议的 `tools` 声明比 OpenAI 通道更占预算（full 档实测 8.3 万 token/轮），而这条通道只在 lite 档验过。可用 `FACHUAN_CLAUDE_TOOL_TIER=full` 打开。 |
| `compaction=True` 但事件面无压缩信号 | CLI 自带 autocompact，编排层不必再渲染 transcript；代价是「刚压过」这件事前端看不到，只能从 `usage` 看水位。 |
| 没接 `codex-sdk` | 它的 `ApprovalMode` 只是把字符串写进 config，headless 下 stdin 已 `end()`，**没有任何可回写的审批通道**。律所场景不能上。要走审批只能改用 `codex app-server`（另一条路，未做）。 |
| 没做子 agent（`AgentDefinition(background=True)`） | SDK 支持，但需要新的编排语义与 UI；本期只做「第五栏能跑、能拦」。 |
| CLI 会往 stderr 打一行 `[claude-code:unrecognized_model]` | CLI 不认识非 Anthropic 官方模型名，属提示音；**不影响结果**（正文与 usage 都正常）。没有关掉它的开关，接受为已知噪声。 |
