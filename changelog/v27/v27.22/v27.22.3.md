# v27.22.3 · 会话进 URL（`/assistant/:sessionId`）：可复制、可刷新、可贴给别人

> 承 `v27.21.8`（copilot 交互手势）那条前端线的下一次迭代。纯前端，不动后端契约。
> 版本判定：就地顺延第三位。理由是 §1.2 的判据——同一批用户动作（在 AI 助手页里切会话）、
> 同一批文件（`frontend/src/app` + `features/copilot`），不是另一条能力轴。

## 一句话定位

| 之前 | 现在 |
|:-|:-|
| 会话只活在 store + localStorage，URL 永远是 `/assistant` | URL 就是会话：`/assistant/<sessionId>` |
| 律师没法说「是这个会话要改」，链接也贴不出去 | 复制地址栏即可；刷新回到同一条；后退回到进助手之前那一页 |
| 深链打开 `/assistant/<id>` 无处理（渲染空对话） | 首帧信 URL，切到该会话；坏 id 退回 `/assistant` 并提示 |
| 壳层抽屉判据是 `pathname === assistant()` 精确等号 | `isAssistantPath()` 前缀判据（否则 `/assistant/<id>` 会再叠一层抽屉，同屏两个输入框） |

## 三条硬约束（漏一条就是真故障）

1. **一律 `replace: true`**：切会话不是导航，不该把后退栈塞满——连续点五条会话后按一次
   后退，应回到进助手之前那一页，而不是倒着回放刚才点过的会话。
2. **两侧都先比再写**：写 URL 前比 `pathname`，写 store 前比 `sessionId`。少一边就是
   `store → URL → store → …` 的乒乓（④ → render → ③）。
3. **首帧不能清空 store**：`/assistant` 上 `paramId` 为空**不等于**「用户开了新对话」。
   首帧只定一次权威方向：
   - URL 有 id（别人贴的链接 / 刷新）→ **信 URL**，把会话切过去；反过来信 store 会把
     链接悄悄换成自己上次那个会话；
   - URL 无 id → **信 store**（localStorage 恢复的上次会话）并把 id 补回 URL；
     绝不能反过来清 store，那正好砍掉「刷新回到上次会话」这条既有行为。

## 首帧之后：每轮只回答「这一轮是谁变了」

`syncRef` 记两侧上一轮的取值，同值重跑 = 谁都没变 = 什么也不做，于是 StrictMode 的
双重挂载天然幂等，不需要另外去重。

**坏 id 的三条同时成立才重置**（只凭「不在列表」会误伤两种合法缺席）：

| 条件 | 为什么必须有 |
|:-|:-|
| 该 id 是**打开页面时就有**的（`openingIdRef`） | 刚发第一条消息建出来的会话要等本轮流结束才进列表 |
| 历史确实拉失败（`lastError`） | 列表没加载完不算「不存在」 |
| 列表在 id 就位后加载完，仍查无此 id | 不在最新 100 条里的老会话恰恰是最想贴出去的那种 |

重置只做一半（URL 改回 `/assistant`），store 由「URL 变了」那条分支跟着清——
一条路径只写一个真相，少一处能忘的同步。

## 已知取舍与边界

- **抽屉不调用这个 hook**：抽屉是业务页上的浮层，没有自己的 URL；两边共用同一个 store，
  所以页面切到的会话回抽屉还是同一段对话。
- **不用 `push` 记会话切换历史**：会话切换是「换视角」不是「导航」，`push` 会让后退键
  变成「回放刚才点过的会话」，比没有历史更难用。
- **不在前端做深链权限校验**：后端按 `user_id` 取会话，越权拿不到就是 404；前端只负责把
  坏 id 变成一句可读提示。
- **不给会话 id 另造短码**：`sessionId` 是后端签发的 UUID，`encodeURIComponent` 只在
  拼路径这一处做一次；短码要新建映射表与回收逻辑，本版不值。
