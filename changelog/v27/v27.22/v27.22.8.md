## 已知取舍与边界

- **选 django-q 而不是进程内 asyncio 任务**：项目已有常驻 qcluster（`services/task_runner`
  的后台 agent 任务就跑在上面）；进程内任务会随 worker 重启丢失，取消请求还可能落到另一个
  worker。代价是本地开发必须起 qcluster（`make dev`），否则任务停在「排队中」，10 分钟后
  收口为失败并提示「任务队列服务可能未启动」。
- **跨进程取消靠数据库标志，不靠信号**：排队中直接置 `cancelled`（worker 认领是
  `queued→running` 条件更新，状态一改就领不走）；运行中置 `cancel_requested`，worker 心跳读到
  后取消流水线。多 worker 下这是唯一可靠的方式。
- **关闭页面不取消任务**：结果照样落库，回来能看到；重复点击已由后端去重。把「关页面」当成
  「不要了」会让律师切个标签就白花一遍钱。
- **已经发出的威科同步调用无法中途打断**：取消后任务状态数秒内即为 `cancelled`，但线程里
  那次威科调用会自然结束、结果丢弃。打断它需要威科客户端支持取消，不在本版范围。
- **dsh 不支持隔离运行时报错，而不是退化成普通运行**：它会把历史续写到磁盘且没有删除会话
  的接口；静默退化等于把 🔴3 的污染原样留在 dsh 上。前端下拉同步排除它。
- **pi 只替换 `AGENTS.md`，不替换 pi 自带基础提示**：pi 没有按轮替换 system prompt 的开关；
  改全局配置目录会影响所有会话，所以只在隔离目录里覆盖 `AGENTS.md`。记忆注入按业务方决定
  在隔离运行时关闭（综合是对几栏回答的客观合并，不该带律师个人偏好）；审批 extension 不受影响。
- **pi 的轮数上限靠计数 `turn_start` 事件后 abort**：pi 没有 max-turns 开关。
- **不改评审 `except Exception` 棘轮（`test_exception_ratchet`）**：它只数 `except Exception`，
  覆盖不到 `BaseException`；改为新增综合链路专用的结构门禁，范围更准，不牵动全库计数。
- **会话行右键直接弹删除确认：保留**（业务方确认，不改代码）。
- **单 Key 遇 429 只等一次、最多 10 秒，且在请求线程里等**（业务方决定）：网关要求等得更久就不等，
  直接报限流——在请求线程里干等十几秒比让律师稍后重试更糟。这把 Key 已被池判进冷却时也不等
  （再试也拿不到它）。多 Key 平台从不等待，只换 Key。
- **429 不冷却策略不变**：仍是连续 2 次 Key 侧失败才冷却（对齐 LiteLLM `allowed_fails`，已有用例
  钉住）；改成「一次就冷却」会扩大改动面，而换 Key 重试本来就不依赖冷却。
- **元典 MCP 只能做到「每个 pi 进程一把 key」**：`mcp.json` 的 `Authorization` 在 pi 启动时静态展开，
  同一进程内遇 429 换不了 key。要按调用换，需要 mcp_server 代理元典请求或 pi 支持动态 header。
- **元典总开关只管 agent 侧 MCP 工具，不管元典 REST 案例检索数据源**：后者是律师在检索任务里显式
  选的 source；MCP 工具是模型自己决定调用，律所需要能整体关掉。读开关失败按「开」（真正挂不挂
  还要有 key，与 key 读失败的降级口径一致）。
- **插件声明 `critical` 目前与 `high` 同级**：MCP 注解表达不了「二次确认」，真正的紧急级仍只由
  名字规则判定；支持它需要在 `approval/risk.py` 加登记表并同步 pi 的 `approval-rules.ts`。
- **其他后端的 `_results` 同样只增不删**（pi / antigravity / dsh / openai-agents）：本版只给

  隔离运行，前端按能力过滤；涉及各后端，本版未做。
- **「自动」在 claude-agent 上可能失败**：「自动」= 后端取本轮某栏实际用过的模型，该模型不是
  Anthropic 协议的就会被 claude-agent 拒绝（报可读错误，不会静默换模型）。
