# v27.22.4 · 综合结论改跑 agent（可核引用、可指定运行时、可带评审）

> 承 `v27.22.1`。`v27.22.1` 把窗口与候选截断解决了，但综合结论**仍然是一次裸 LLM 调用**：
> 它没有工具，核不了自己写的法条与案号，`Synthesis.unverified` 因此**恒为 `[]`**
> ——契约里有字段、前端有渲染块，却永远不出现。本版把它交给 agent 运行时。

## 一句话定位

| 之前 | 现在 |
|:-|:-|
| 综合 = 一次裸 `_llm_aggregate` 调用，无工具 | 综合 = 跑**指定 agent 运行时**（默认 `pi`），可调 `verify_citations` / 检索工具 |
| `unverified` 恒空（核不了，也不报没核） | 综合后会跑核验，未核项逐条进 `unverified` |
| 前端只有一个「综合结论」按钮 | 按钮 +「执行 agent」+「模型」+「先评审」三个控件 |
| 综合结果只进 `AgentSynthesis`，历史回放/后续追问里看不到 | 同时写一条 `agent_kind="synthesis"` 的转录行（不占栏） |
| 第二次综合会沿用上一次综合自己的模型 | 综合行被排除出「本轮各栏用过的模型」 |

## 流程（`synthesize` 端点现在的五步）

```
分区候选（empty/failed 丢弃） → (可选)先跑一轮评审 → 组 prompt
→ 跑指定 agent → 核验引用 → 落 AgentSynthesis + 写转录行（写失败只降级）
```

## 三个刻意的口径

| 口径 | 理由 |
|:-|:-|
| **不写 `AgentRun`、不记成本** | 综合是「律师点一次」的动作，成本归因价值低；多一张运行记录会让「本轮几栏 / 多少钱」的统计口径变复杂 |
| **不落成「第 6 栏」** | 综合不是某一栏 AI 的回答。它写成 `agent_kind="synthesis"` 的转录行，`distinctAgentKinds` 会把它排掉（否则多答布局凭空多出第 6 栏），但它仍可被历史回放/检索/后续追问看到 |
| **评审失败不阻断综合** | 评审是「更准」的手段，不是前置条件。判官模型没配、评审报错 → 记 warning、综合照跑（只是少了取舍依据），与「点了综合什么都没出」是两种体验 |

## agent 侧的硬约束（`services/synthesis/agent_runner.py`）

- 默认 `pi`（注册表里最稳的一个），调用方可换成任意已注册 kind；未注册 → `LLMError`
  → API 转 422。
- `SYNTHESIS_MAX_TURNS = 8`：综合是「读五份稿 + 必要时核引用」，不需要几十轮工具循环，
  跑偏时也少烧钱。
- **正文必须含来源锚点 `[来源：`**：缺锚点的文本可能是模型把思考过程当正文吐了，
  也可能是自编了一段没有出处的结论。缺锚点重试一次（`SYNTHESIS_AGENT_ATTEMPTS = 2`），
  仍缺就报错——宁可让律师重试，也不给一份「看不出谁说的」综合稿。
- **`user_token` 铸不出来就整轮拒绝**：不能让综合的工具退回超管服务账号
  （见 `pi/user_token.py` 的 confused deputy 说明）。
- system prompt **全量替换**为 `AGGREGATE_SYSTEM_PROMPT`：pi / claude-agent 这类
  harness 默认是「命令行编码助手」人格（antigravity 就踩过，会自称 DeepMind 的编程助手）。

## 已知取舍与边界

- **不做「综合也能被审批」的单独闸门**：它走的是同一套 `AgentBackend`，高危工具调用
  照样弹审批卡；再叠一层综合审批只会让律师点两次。
- **不做综合的增量流式**：综合是独立请求（不进 SSE），正文一次拿到再落库。要做流式得
  先解决「流到一半失败怎么办」，本版不值。
- **不把评审分数写进 `AgentSynthesis`**：分数是评审的产物，`Synthesis` 契约里没有它；
  需要时前端读评审接口。
- **不自动重试整条综合**：只有「缺锚点 / 空正文」重试一次；其它失败直接报错，让律师
  自己决定是换 agent 还是换模型（自动重试会连乘成本）。
