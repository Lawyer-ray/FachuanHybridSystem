# v27.28.2 · Qoder 成为默认 Agent + 可选它自己的模型 + 多账号共享额度

> **版本判定**：§1.2 同一条线（`v27.28.x` 的 qoder 接入）→ 第三位 +1。

## 一句话

| 之前 | 现在 |
|:--|:--|
| 新会话默认 `pi`（前端「默认」徽标 = 清单第一项，而清单按字母序排） | 新会话默认 **qoder**；`GET /agent/backends` 把默认项排第一，前后端口径一致。`FACHUAN_DEFAULT_AGENT_KIND` 可改，**没注册就自动回退 pi**（不因一个默认偏好让整站起不来） |
| qoder 那一行**没有模型下拉**（模型清单给的是网关的，qoder 云不认识，所以干脆给空） | 17 个它自己的模型（`Auto` / `Ultimate` / `Qwen4-Max` / `Kimi-K3.1-Pro` …），默认 `Auto`，带 10 分钟缓存（`--list-models` 实测 2.5s，不能每次开菜单都问） |
| 全所共用一个 qoder 账号 → 一个人跑长任务就吃掉全所额度 | **账号池**：点一次「登录」往池子里加一个额度容器；一轮用一个、按「最久没用过」轮转；某账号额度耗尽 / 登录失效 → 挂起 10 分钟 + **换下一个账号重跑**（用户只看到慢一点） |

## 为什么这么设计（三个判断）

1. **默认后端 ≠ 会话级兜底**。「qoder 变默认」只影响**新建**会话；已有会话的
   `agent_kind` 是历史事实（`pi`），改默认就换脑子——上下文直接断，且没有任何报错。
   所以 `stream.py` / `multi.primary_kind` / `_to_out` 的兜底**保持 `pi`**，只有
   `session_service.create_session` 用 `default_agent_kind()`。前端的
   `DEFAULT_AGENT_KIND`（= 历史事件没标 `agent` 时按谁算）同理保持不变。
2. **模型来源按后端各自问**（`session_api._models_for_kind`）：pi/dsh/openai-agents/
   antigravity/claude-agent 用 `LLMProvider`（Admin 里配）；qoder 默认用
   `qoder_models`（问 CLI）；`FACHUAN_QODER_MODEL_SOURCE=gateway` 时才回到
   `LLMProvider`（BYOK 直连，需 Qoder 账号的 `allow_byok >= 2`）。
3. **账号是额度容器，人是权限主体**。业务权限仍走共享 MCP 的律师 token（`build_mcp_servers`），
   账号只决定「这次用谁的额度」。所以多账号不需要多套权限，也不会互相看到对方的数据。

## 改了哪些文件

| 块 | 文件 | 内容 |
|:--|:--|:--|
| 默认后端 | `backends/defaults.py`（新）、`services/session_service.py`、`api/session_api.py` | `default_agent_kind()` 单点定义 + 清单排序（默认项第一） |
