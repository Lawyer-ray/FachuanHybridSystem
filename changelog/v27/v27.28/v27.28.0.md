## 为什么档案卡会被撑宽（根因）

`DealDetailPage` 把 `FilePreviewCard` 当 `folderPreview` 塞进 `DetailRail`，而文档栏的
宽度是打在**整张档案卡外层容器**上的：

```
style={{ width: panelEffectiveWidth }}   // 720 起，上限 min(0.78×容器, 容器−560)
```

于是「文档要 700px 宽」直接变成「档案卡 700px 宽」。宽度和文档尺寸是两个正交需求，
绑在同一个 `style` 上就必然出现「期限/当事人被摊平」+「A4 放不下」两个症状。

## 改了什么

- `DealDocLayout.tsx`：三态化 + 四件事
  1. 文档列**始终挂在容器末尾**，靠 `order-first` 排到视觉最前——换 DOM 位次会让 DS
     实例销毁重建，未保存的编辑直接丢；分隔条同样常驻、只用 className 隐显
  2. 新增 `kind` / `widthStorageKey` / `onReview?`：诉讼页按 `picked.kind` 走
     `contract` 或 `case` 通道，两页各记各的宽度偏好
  3. 新增 `immersive`：③ 沉浸态 = 占满整宽 + 一屏高 + **不吸顶**（吸顶会把「想看一眼
     案件链」变成不可达）
  4. 去掉 `focusDoc` 这一维：③ 的两种来由（净宽不足 / 沉浸）排法本来就一样，
     维护两套相似叠法只会在某条路径上把文档排到内容后面去
- `DealDetailPage.tsx`：349 → 279 行。接上 `DealDocLayout`，删掉自己的
  `useResizablePanel` / `ResizeHandle` / 两处 `folderPreview`；判定改用净宽；
  文档并排时抑制超宽屏的 `columns-2` 案件瀑布流（左列只剩 560px，再分两栏必挤成竖排）；
  `main` 补 `@container`（两栏栅格是容器查询，量的是 main 而不是视口）
- `DetailRail.tsx`：`folderPreview` 与 `factsHidden` 两个 prop 退役——档案卡只放事实，
  不再承载文档；文件夹树保留（`folderSelectedSubpath` 高亮当前文件）
- `FilePreviewCard.tsx`：新增「沉浸编辑」开关（`immersive` / `onToggleImmersive`），
  不传就不渲染（保持「该页没这档」的显式语义）
- `use-folder-tree.ts`：展开集合在**首次挂载**时按 `selectedSubpath` 展开祖先链。
  档案卡换位会让树重挂一次，否则律师刚点开的那份文件沉进三层折叠目录里，连
  「下一份」都点不到
- `use-net-width.ts`：删掉已无使用方的 `useDockedViewport`（净宽判定不再需要视口门槛）
- 非诉页同步接上沉浸态（同一个组件、同一条判定，不留半截）

## 已知取舍

- **档案卡换位**：展开文档后档案卡沉到内容列底部（而非留在右侧变宽）。律师读文书时
  偶尔要对照期限/当事人，此时要么滚一下、要么开 AI 助手并排——但换来的是文档终于
  有整屏高度。极端宽屏若需要三栏并存，应作为独立需求再做，不靠把档案卡拉宽实现。
- **不做浮层式全屏**：页面 `<main>` 带 `app-page-enter` 进场动画（`transform` + fill-mode
  `both`），祖先带 transform 就是 `fixed` 的包含块，`inset-0` 会变成「整页高」；portal
  到 body 又会换父节点、编辑器重开。沉浸态因此用布局实现，不是遮罩。
- **沉浸态不接 Esc**：焦点在 DS iframe 里时 Esc 归编辑器，宿主收不到；退出靠卡片头部的
  可见按钮，不做「有时灵有时不灵」的快捷键。
