# v27.28.1 · 详情页交互审计整改：不再静默丢改动，也不再假装一切正常

> **版本判定**：§1.2 同一条线（`v27.28.0` 的详情页交付）→ 第三位 +1。

## 一句话

| 之前 | 现在 |
|:--|:--|
| 在画布里改了半小时，随手点 X / 点另一份文件 / 关页签——改动全没，全程零提示 | 头部挂「未保存」标记；关文档、换文件前弹一次确认；关页签有原生提示 |
| 保存按钮的 spinner 是死分支（`busy` 在同一 tick 被清掉），连按 ⌘S 会重复 forcesave、叠一摞「已提交保存」 | 保存期间真忙、按钮真禁用、提示用固定 id 去重 |
| pdf / 图片上按 ⌘S 被 `preventDefault` 吞掉，什么都不发生 | 明确说一句「该格式不支持原地保存，请用下载」 |
| 文档打开失败只能关掉再点开 | 画布里有「重试」；卡片底部不再谎报「正在打开文档…」 |
| 文件夹树里把正在预览的文件改名/删除：标题还是旧名、高亮消失、⌘S 打到一个不存在的路径 | 树里改名/删除后自动关掉画布并说明原因 |
| 案件文件夹「不可浏览」（硬盘掉了/没权限）显示成「文件夹是空的」；绑定查询失败彻底静默；在途时先闪一下假空态 | 透出后端原因；失败给一行提示 + 重试；在途不抢先判成「没有绑定」 |
| 发票列表读取失败当「没有发票」，还弹「拖入上传」；删除发票一键生效且连磁盘文件一起删 | 失败给错误 + 重试；删除要行内二次确认（和文件夹删除同一口径）；一行在飞时其它行一起置灰 |
| 拖自己树里的目录/文件（给 AI 的引用）经过树时投放环亮起，松手什么都不发生 | 只对外部文件亮投放环 |
| 文档栏宽度偏好：首帧就把默认 720 写进 localStorage，第二次访问起再也不按容器自适应 | 没拖过就不落盘 |

## 怎么查出来的

按 CLAUDE.md 的默认工作模式，把「详情页交互不合理」拆成三个互不重叠的切片，
派三个**只读** reviewer 并行核验（左列案件链 / 右栏档案+文件夹树 / 文档栏与预览卡），
每条结论都要求带 `file:line` 证据并标注成立·部分成立·不成立。共 30 余条候选，
逐条回到代码复核后再动手——其中「已排除」的 15 条不成立（避免把没问题的东西改坏）。

## 改了什么

**文档链路**

- `OfficeView`：新增 `onDocumentStateChange` → `onDirtyChange`（两种 DS 版本口径都认：
  `event.data === true` 与 `{status:true}`）；新增 `onStateChange`；error 面板加「重试」
  （换 key 重挂，与僵死探活同一个入口）
- `FilePreviewCard`：未保存标记 + `beforeunload` + 卸载时回报「已不再脏」；
  底部文案按画布真实状态说（就绪 / 打开失败 / 未启用 / 正在打开）；
  「AI 改写」没框选时给一句提示（插件消息本来就带 `explicit`）；头部 `flex-wrap`，
  面板拖到最窄也不会把「沉浸 / 关闭」裁掉
- `use-doc-dirty-guard` + `UnsavedChangesDialog`（新）：脏标记走 ref（事件回调里读得到
  点下去那一刻的值），破坏性导航一律 `guard(action)`；**不做「保存并离开」**——
  forcesave 的落盘在回调里，离开时等不到
- `use-folder-save`：`savingRef` 拦同帧重入、`busy` 保持到落盘核实那一刻、
  toast 固定 id、⌘S 三种情况都有话说、下载失败 `toast.error`
- `use-resizable-panel`：`userAdjusted` 之前不落盘（这条 bug 非诉页也一起受益）
- `DealDocLayout` / 两个详情页：接 `onDirtyChange`；`closePreview` / `openPreview` /
  打开合同与案件文件 / 生成文书成稿回落，全部走脏标记拦截

**文件夹树与案件卡**

- `use-folder-tree` → `FolderTree`：新增 `onEntryMutated`，改名/删除成功后上报
  `{kind, ownerId, from/to|subpath}`；页面据此关掉指着旧路径的画布
- `FolderNodeList`：`browsable=false` 透出后端 `message`，不再冒充「文件夹是空的」
- `CaseSection`：默认视图按 `is_accessible` 判（不是「有绑定就进文件夹」）；
  绑定查询在途显示占位、失败给重试；日志附件 `media_url` 为空时不是按钮
- `UseFolderDrop`：拖拽 `types` 含内部引用 MIME 时不 preventDefault、不亮投放环
- `FolderFileRow`：把文件行已有的 `size/modified_at` 带给预览卡（底部元信息此前恒空）
- 行内「重命名 / 新建子夹 / AI 审查」补 `group-focus-within:flex`（键盘聚焦也能出来）
- `DetailRail`：`folderSelectedSubpath` 明确要求调用方按 kind 过滤（案件文件同名
  subpath 会亮错合同树的行、还会强行展开同名目录）

**收款 / 发票**

- `RailFees` / `InvoicePoolDialog`：读取失败不再当空态；在途不再空白
- `InvoicePoolDialog`：删除改行内二次确认（记录 + 磁盘文件都会被删，无撤销）；
  文案直接标「删除？」
- `rail-invoice`：新增 `locked`，一行在飞时其它行一起禁用（此前点了直接 return，像坏了）
- 记收款保存后改用 `refetchContractAndCases`（与「关联发票」同口径），
  退回工作台列表不再是 60s 旧数

## 明确没改（需要你拍板 / 另有归属）

| 事项 | 为什么留着 |
|:--|:--|
| 页头「＋ 记项目日志」「＋ 新增期限」「＋ 新建X案件」仍是占位（点了弹「开发中」） | 这是**功能没上线**，不是交互 bug。改成 disabled 是产品取舍（要不要继续吊着入口），我不替你决定 |
| 「整页编辑器」(`?file=`) 没有任何入口 | `FilePreview` 整套（逐条采纳 / 版本历史 / 定位）只能手改 URL 到达。要么给它加入口，要么删掉——但现在「沉浸编辑」已经覆盖了「要更大画布」这个需求，倾向删，等你点头 |
| 行内新建/重命名输入框失焦即取消 | 触屏没有 Enter 可依赖，确实会丢输入。改法有两种（失焦提交 / 加 ✓✕ 按钮），影响面到新建文件夹，值得单独一轮 |
| 时间轴把相同正文的日志合并成一条并覆盖为最新日期（`×N`） | 有意的设计（避免糊屏），但确实看不到第一次发生的日期。要改得先定「合并行怎么展开」 |
| 记收款弹窗按 Esc / 点遮罩会整份 reset | 「取消直接关」是有测试锁定的刻意设计；只有误触遮罩那条路无保护，改动会碰现有交互契约 |
| 文档栏与档案栏在 ②态不能三栏并存 | 上一版（`v27.28.0`）已说明：极端宽屏要三栏是独立需求 |
