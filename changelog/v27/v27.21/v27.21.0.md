# v27.21.0 — 第四个 agent（Google Antigravity）：同一问题可以四栏并答

> 承接 `v27.19.2`（第三个 agent「openai-agents」+ 多答收敛到 N 栏）。多答的编排层与
> 渲染层当时就已经是 N 栏设计、上限写着 4（`services/chat/multi.py` 的
> `MAX_ANSWERS`、`domain/dual.ts` 的同名常量），**差的只是「第四个真实后端」**——
> 前端 `AnswerAgentMenu` 本来就是按 `GET /agent/backends` 渲染的，注册进来就有得选。

## 做了什么

新增 `antigravity` 后端（`backend/apps/agent/backends/antigravity_backend.py`），
`kind = "antigravity"`，注册进 `registry` 后 `/api/v1/agent/backends` 自动多一项：
律师在「跑哪几个 AI」菜单里勾满 4 个，同一问题就是四栏并答。

### 三个 SDK 缺口 + 填法

| 缺口 | 事实（实测） | 填法 |
|:--|:--|:--|
| **不带鉴权** | `LocalOpenAIAgentConfig` 只有 `base_url`；wire 上**没有任何 auth 头**（config 字段 / `OPENAI_API_KEY` / `api-key` 三种都试过） | `backends/antigravity_gateway.py`：本进程内起一个只绑 `127.0.0.1` 的反向代理，按**一次运行一个随机 token** 注入 `Authorization: Bearer <该栏的 key>`。key 不进 URL、不进日志；运行结束即注销，TTL 兜底 |
| **不走 Gemini 原生** | 网关（`LLMProvider.base_url`）是 LiteLLM → vLLM，`:generateContent` 一律 404 | 同上，只走 OpenAI 兼容通道 |
| **默认是「代码 agent」** | 默认 18 个内置工具（文件读写 / `run_command` / 子 agent / 联网）+ DeepMind 身份提示词；传 `str` 只「追加一节」，身份不换 | 内置工具全关（`enabled_tools=[]`）、`enable_subagents=False`、系统提示用 `CustomSystemInstructions` **全量替换** |

### 工具面：默认 `lite`，eager 原生工具

harness 的 MCP 只有两条通道：惰性 `call_mcp_tool`（模型得先用 `view_file` 读
`<appDataDir>/brain/<conv>/mcp/<server>/<tool>.json` 才知道参数）或
`force_all_tools_eager=True` 把服务端 `tools/list` 全部注册成 `mcp_<server>_<tool>` 原生工具。

本后端没有文件工具面，惰性通道走不通 → **恒 eager**，并用 `x-fachuan-tool-tier`
请求头把工具面压到 `lite`（61 个直连工具 / 1.1 万 token；`full` 是 424 个 / 8.3 万 token）。
`delete_case` 这类工具在工具面上就摘掉（`disabled_tools`），不靠审批兜底。

### 审批闸门：挂在 `PreToolCallDecideHook`

分级复用 `services/approval`（与 pi / dsh / openai-agents 同一张审批卡、同一份阈值），
拒绝走 `HookResult(allow=False, message=...)`——工具不执行、本轮继续，而不是抛异常让
harness 把它记成工具故障。工具名做了**解包**：eager 原生工具与惰性 `call_mcp_tool`
两种形状都还原成真实工具名再判风险（不解包的话闸门只看得到壳名 → 静默判低危）。

### 顺手收敛的一处抽象

「从 `LLMProvider` 解出 `(base_url, key, model)`」原本在 `openai_agents_backend` 与
`dsh_config` 里各有一份，接第三个、第四个后端时只能靠「照抄上一份」。这次收进
`gateway_cache.resolve_gateway_target()`（+ `GatewayTarget` 类型：`repr` 隐去 key），
四个后端共用一份口径：模型分辨率、`RunContext.api_key` 有值就不再轮转、三项缺一律
判不可用。`openai_agents_backend.gateway_from_settings` 改为委托，对外签名不变。

- 无 Google 凭证可跑（Gemini / Vertex 端点在境内不可达，实测 `curl` 超时）；

- 律师看到的是「法穿律师助理」而不是「DeepMind 编程助手」（身份替换生效）。

## 兼容性与风光

- **能力声明如实**：`streaming/tool_calls/approval/compaction=False/steer=False/concurrent_in_session=True`。
  没有插话接口就不声明 `steer`（前端会自动隐藏插话框，而不是渲染一个敲进去就被丢弃的输入框）。
- **本后端不发 `done`**：与 `pi_backend` 同口径，`done` 由编排层铸造（单栏只允许一条；
  `openai_agents_backend` 自造 `done` 会让单栏出现两条，属既有 bug，未在本版处理）。
- **vLLM 兼容补丁**：本轮没有工具时 harness 仍发 `tool_choice: "auto"`，vLLM 直接 400
  （`When using tool_choice, tools must be set`）。代理层在「`tools` 为空且带
  `tool_choice`」时摘掉该字段，有工具时不动。
- **依赖**：`google-antigravity==0.1.24`（Apache-2.0，随 wheel 分发 Go 二进制，仅
  macosx/manylinux/musllinux/win 轮子）。与现有钉版无冲突（`mcp<3` / `protobuf>=7.35`
  均满足）；SDK 缺失时注册表静默降级，其它三个后端不受影响。
