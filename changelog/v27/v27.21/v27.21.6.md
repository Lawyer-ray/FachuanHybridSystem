# v27.21.6 — Copilot 输入区收敛与工具行密度：把「已完成」×16 与满屏转义噪声清掉

> 承 `v27.21.5`。纯前端。两条都来自律师本人的使用反馈，不是代码洁癖。
>
> 反馈原话：
> 「右上角可以选单个 AI agent，左下角可以多选，是不是右上角显得很没意义？」
> 「调用工具太占空间了…明明只有几颗字，完全可以很多标签自动换行啊」
> 「工具调用结果不需要显示文字，用打勾或者打叉来表示结果我会自己点开」
> 「不应该再点击查看原文，点击后直接展示原文即可，而且原文有些 html 换行，你得帮我渲染出来」

## 一、工具行密度（问题二）

### 病
单栏对话里 16 条工具调用各占一个整行 `<details>`，约 450px，每行有效信息只有工具名 + 耗时，
而「已完成」重复 16 次。点开后还要**再点一次**「工具返回原文」才看到内容。

### 改
| 项 | 改法 |
|---|---|
| 折叠态 | 单栏**连续** tool 消息聚成一段，收进 `flex flex-wrap` 的 chip 流（`AnswerGroupView` 聚段 + `ToolChipList`）。16 条 → **约 4 行**（≈104px，省 77%） |
| 展开态 | chip 加 `open:basis-full` 独占整行；删掉原 `max-w-[min(420px,70vw)]` / `min(560px,80vw)` 窄上限，原文可用整行宽 |
| 状态文字 | **五态一律只出图标**（绿勾 / 红叉 / 灰横线 / 转圈 / 灰点），可见文字为零；状态词进 `sr-only`，读屏不丢 |
| 二次点击 | 删掉 `ToolRow` 内层 `<details><summary>工具返回原文</summary>`，展开直接见原文 |
| 展开指示 | summary 补 chevron（`group-open:rotate-90`）——原先 `list-none` 去掉了原生三角却没有任何替代 |
| 换行均衡 | `flex-wrap: balance` 用 `supports-[flex-wrap:balance]` 守卫。裸写在 Firefox/Safari 是无效取值，会把 `nowrap` 拉回溢出（实测 Tailwind 4.3.5 生成顺序里裸 arbitrary property 还会被 `.flex-wrap` 覆盖） |

### 为什么不是简单「换成 ToolChips」
`ToolChips` 的换行 chip 本来就有，但只服务多栏。单栏刻意用整行，`ToolRow` 文件头写明理由是
「返回值常常要看，chip 太窄」。本版**保住这个理由**（展开即整行、删窄上限），只把折叠态压成 chip。

## 二、原文归一化（用户说的「html 换行」）

### 取证（只读查开发库 `fachuan_dev.agent_agentmessage`，679 条 tool 消息）
```
MCP 信封 repr  {'type': 'text', 'text': '…'}   257 条
含字面 \n 转义                                  347 条
含 HTML 块标签（<br>/<p>…）                       4 条   ← fetch_url 的网页标题
```
样本（`search_cases`）：
```
{'type': 'text', 'text': '{\n  "total": 1,\n  "items": [\n    {\n      "id": 304,…
```
`\n` 是**字面反斜杠 + n**，所以 `<pre>` 里显示的是一大片转义噪声——这才是「看起来像 HTML 没渲染」的真因。
另有 4 条确有 HTML 标签（`fetch_url` 把网页标题里的 `<br>` 原样带回来）。

### 改
新增纯函数 `domain/tool-content.ts :: formatToolContent()`，三步：
1. **拆 MCP 信封**（只认 `{'type','text'}` 这一种已知 repr 形状，**不用 `eval`**）
2. **解字面转义**（`\n \t \r \" \\`）；整段是 JSON 字符串体时先试 `JSON.parse`
3. **JSON 美化**（`JSON.stringify(v, null, 2)`）——律师真正读得懂的形状
4. **HTML/实体兜底**（块级结束标签转换行、剥其余标签、解码命名与数字实体、3+ 换行折 2）

**红线**：不用 `dangerouslySetInnerHTML` / `innerHTML` / `eval` / `new Function`。工具返回值当 HTML 注入
是安全问题，且有 CodeQL 门禁。8000 字符截断信封（`list_reminders_by_target` 就是）必须不炸。

## 三、agent 控制点收敛（问题一）

右上那个「锁标签」在已有会话时信息量只有一个词，却长得像个可点的按钮——两处控件其实**不重复**
（右上 = 会话级 `agent_kind`，不可换；左下 = 本轮多答），但外形相同、分处两极，读起来像矛盾。

| 位置 | 改法 |
|---|---|
| 右上 · 已有会话 | 删掉锁标签，后端名改为标题后缀 `AI 助手 · antigravity`（muted 文本，不可点） |
| 右上 · 新对话 | **保留下拉**——唯一能定 `agent_kind` 的入口；「为什么不能中途换」移到新对话 tooltip |
| 左下 · 未选 agent | 触发器收成纯图标，省约 60px 输入宽度；信息由 `aria-label` + 菜单徽标承载 |
| 左下 · 选 1 / ≥2 | 图标 + 后端名 / 图标 + `N 个 AI` |
| 左下 · 菜单首项 | 徽标 `默认` → `默认 · <后端名>`，锁标签删掉后信息不丢 |
