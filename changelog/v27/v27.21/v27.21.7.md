# v27.21.7 — agent 选择只留一个入口：会话归属由本轮勾选推导

> 承 `v27.21.6`。纯前端。用户第三次反馈的同一个问题：
> 「还是有两个地方可以选呀，这样逻辑不就重复了吗」（附截图：右上已选 DeepSeek Harness、左下「已选 0 个」）

## 上一版为什么没收干净

v27.21.6 只删掉了**已有会话**的锁标签，刻意保留了**新对话态**的右上 `AgentBackendPicker`——理由是
「它是唯一能写 `agent_kind` 的入口」。结果同一份 4 项后端清单在新对话态出现两次。

而且它们**会互相打脸**：右上写的是会话归属（`selectedAgentKind` → `agent_kind`，建完不可换），
左下写的是本轮参与者（`answerAgents`）。截图那一刻若在左下勾 `Pi`，这一轮跑 Pi，
但会话归属仍是 DeepSeek Harness——**用户以为选中的那个，并不是真正在管事的那个**。
这不是冗余，是语义陷阱。

## 改法：composer 成为唯一控制点

`agent_kind` 不再由独立控件写入，改为**由本轮选择推导**（`store/turn.ts`）：

```ts
const ownerKind = resolveAnswerAgents(pre)[0] || pre.selectedAgentKind
```

| 情形 | 会话归属 |
|---|---|
| 勾 1 个 | 就是它（本轮唯一参与者，语义自洽） |
| 勾 2+ 个 | 第一个（`answerAgents` 顺序 = 栏的左右顺序） |
| 一个都不勾 | `selectedAgentKind`（`loadBackends` 解析出的部署默认） |
| 勾了不可用的（缺 SDK / `available: false`） | **不会成为归属**，回落到本轮真实参与者 |

**必须用 `resolveAnswerAgents(pre)` 而不是裸 `answerAgents`**：前者会剔掉不可用与不支持流式的后端。
裸取会把「一个缺 SDK 的后端」写成会话归属，表现为建完会话整轮失败，且只在特定平台缺依赖时才复现。

## 删除与收敛

- 删 `components/AgentBackendPicker.tsx` 与其 dom 测试（6 条用例）。
- `CopilotHeader` 新对话态**不再渲染任何后端选择控件**；已有会话的标题后缀 `AI 助手 · antigravity` 保留。
- 5 处 docstring 里的 `AgentBackendPicker` 引用改指 `AnswerAgentMenu`（含 2 处 dom 测试的 mock 注释）。
- `store/answers.ts` 的过期 docstring 改正：`selectedAgentKind` 现在只是「一个都不勾」时的回退值。
- 菜单底部补一句规则说明，用户不用猜归属怎么定。
