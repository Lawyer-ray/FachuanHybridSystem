# v27.21.8 — Copilot 交互：菜单关闭时机 + 会话行鼠标手势

> 承 `v27.21.7`。纯前端。两条都来自律师本人的操作反馈。

## 一、多选 AI 菜单的关闭时机

反馈原话：「应该是点击空白区域才关闭，勾选不需要默认关闭，毕竟还要切换模型什么的」

### 病
该菜单**原本没有 outside-click 监听**（`rg useEffect|addEventListener` 零命中），只有
「点行内勾选」和「再点触发器」两条关闭途径。于是勾完 `Pi` 想接着给它选模型时，菜单已经关了——
勾 2 个以上要来回开合好几次。

### 改
| 操作 | 改后 |
|---|---|
| 勾选一行 | **不关闭**；底部「已选 N 个」当场更新；该行模型下拉立刻可用 |
| 点开某行模型下拉 / 选模型 | 不关闭父菜单（模型下拉只关自己那层） |
| 点菜单**内部**空白（底部文案） | 不关闭 |
| **点菜单外部空白** | 关闭（新增） |
| `Escape` | 关闭 + 焦点还给触发器（新增；原先 `role=listbox` 零键盘处理） |
| 再点触发器 | 关闭（保留） |

实现：删掉 `AgentRow` 的 `onRowPicked` 机制；`document` 上挂 `pointerdown`（**不是 `click`**——
后者会被行内点击冒泡误判），`rootRef.contains` 为假才关，且只在 `open` 时挂、关闭时摘。

## 二、会话行的鼠标手势

反馈原话：「双击是重命名，右键直接触发删除弹窗，单击是点击进入，无需默认右键网页菜单」

### 病
`SessionRow` 里双击与右键**都是零处理**；右键弹的是浏览器默认菜单。重命名与删除只能靠 hover 才出现的铅笔/垃圾桶。

### 改
| 手势 | 改后 |
|---|---|
| 单击行 | 进入（保留） |
| **双击行** | 进入行内重命名，输入框**自动全选**原标题（否则改名要先手动删旧标题） |
| **右键行** | `preventDefault` 屏蔽浏览器菜单 + 直接弹**已有的**删除确认（`DeleteSessionDialog`，带取消与在途禁用） |

三个实现约束：
1. **`preventDefault` 只在该行容器上**，不全局屏蔽 `contextmenu`——否则正文区的复制/翻译/检查也一起没了。
2. **铅笔/垃圾桶按钮隔离双击与右键**（各挂同一 `stopPropagation` handler）。不隔离就会出现
   「点垃圾桶 → 又弹一次确认」「双击垃圾桶 → 顺带进重命名」。按钮上只 `stopPropagation` 不
   `preventDefault`：右键按钮时浏览器菜单照常，用户要的是**行级**手势。
3. **hover 的铅笔/垃圾桶保留**：双击与右键是鼠标专属手势，键盘与触屏用户只有这两个按钮可达。
   删掉等于把重命名/删除变成鼠标专有功能。

## 三、顺带修掉一颗地雷

`AnswerAgentMenu.dom.test.tsx` 原先 5 处把上限写成字面量 `4`。产品常量 `MAX_ANSWERS` 一变，
五条**无关**用例一起红，而下一个人会以为是菜单坏了。改为 `quota(n)` 辅助函数跟着
`MAX_ANSWERS` 算，并把「选满置灰」那条改成按常量造 `MAX_ANSWERS+1` 个后端。
