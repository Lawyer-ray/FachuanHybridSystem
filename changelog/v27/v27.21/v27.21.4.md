## 病：一次清点 18 个 worktree / 1.9G，全部是「开了没合、合了没删」

实测（2026-11-21）：

| 组 | 数量 | 内容与主线的重合度 | 结论 |
|:-|:-|:-|:-|
| `lane/adj-a1..a9`（多答裁决） | 9 | 新增行 **95.8–99.7%** 已在 `origin/main` | 已 squash 合并，worktree 是残留 |
| `integ/copilot-upgrade` + `lane/copilot-*` | 5 | **98.3–98.6%** 已在 `origin/main` | 同上（其中一条自己带了 revert） |
| `lane/moa-*` + `feat/moa-visible` | 4 | **2.1–12.3%** | **真未合并**（`synthesis_api.py` / `models/synthesis.py` / `0026` 迁移在 main 里不存在） |

三条根因：

1. **规范只写了「开」**：`CLAUDE.md` 有「每个 writer 独占 worktree + 独立分支」，
   但没写「谁负责合回来、谁负责回收」。而「自动 commit」规则只管「写进当前分支」，
   于是 worker commit 到 `lane/x` 就合规地「完成」了——内容停在一个没人知道的指针上。
2. **squash 合并 + 浅克隆 = 「已合并」不可判定**：squash 后 patch-id 全变；`.git/shallow`
   里有 2 个 graft 边界（main 只 graft 到 5 个提交），`git branch --merged` /
   `git cherry` 给出的是**假结论**（实测被它骗过一次：报「151 条补丁没进 main」，
   实际内容 98% 已在 main）。人不敢删 → 永久堆积。
3. **一条护栏都没有**：`scripts/` 里没有 worktree 相关脚本，`_wt/` 还在仓库目录之外，
   `git status` / `pr-ready` / pre-commit 全都看不见它。

## 药：一条规范 + 一个护栏脚本 + 归档习惯

### 1. 规范（写入 `CLAUDE.md` §火力全开 2.1，跨域规则归口本文件）

**worktree 三段闭环：开 → 收 → 验**

- **开**：简报必须写明「改动范围 / **交付物形态** / 验收命令」；
- **收**：**主会话**在任务结束前 apply patch 或 cherry-pick，**一次 commit** →
  `git worktree remove` → 分支先 `git bundle` 归档再删；
- **验**：`make guardrails` 无 FAIL、`git worktree list` 除主工作区外为空。

并明确**两种交付物形态**（默认 patch）：`patch`（detached worktree，worker 不 commit，
零遗留物）vs `commit + 分支`（需跨模块/开 PR/多轮迭代/保留中间提交时用，
但合并债风险自负）。同时立三条禁令：不许把「commit 到 lane 分支」当完成、
清理前必须 bundle 归档、浅克隆下不许用 `--merged/cherry` 判合并。

### 2. 护栏：`scripts/check_worktrees.mjs`（挂进 `make guardrails` + 新增 `make worktrees`）

判据分两类。**能确证「已合并」的**：`git merge-base --is-ancestor <branch> HEAD`
（真 merge 而非 squash 进来的分支是 HEAD 的祖先，这个判定**在浅克隆里也成立**）。
squash 合并的判不出来，退回到**可确证的三件事**：

| 情况 | 判定 |
|:-|:-|
| 目录已不存在（只剩 git 元数据） | FAIL → `git worktree prune` |
| **已跟踪文件**有未提交改动 + 分支未推送 | FAIL（改动只存在于这台机器） |
| 分支从未推送 + 空闲 > `FACHUAN_WORKTREE_MAX_AGE_DAYS`（默认 7 天） | FAIL |
| detached + 空闲超阈值 | FAIL（detached 只能当场交付 patch） |
| 分支已是当前分支祖先（真 merge 进来） | WARN「可回收」（有已跟踪改动则 FAIL） |
| 只有未跟踪文件（构建产物/本地 docs） | WARN（不算「改动丢了」） |
| 有进程 cwd 在里面（`lsof -a -d cwd`） | WARN 且**不判 FAIL、不打印回收命令** |
| 已推送 + 空闲 > 2×阈值 | WARN（内容有远端备份，可回收） |

细节：空闲天数取 `min(最后提交距今, .git/worktrees/<id> 的 mtime)`——只用提交时间会把
「今天刚 checkout 的老提交」误判成很老，只用目录 mtime 又会漏掉「只改文件没提交」。
浅克隆时脚本会显式警告并给出 `git fetch --unshallow`。

### 3. 归档（让「删」不再不可逆）

```bash
git bundle create ../_wt/archive-$(date +%Y%m%d).bundle --branches
git bundle verify ../_wt/archive-$(date +%Y%m%d).bundle
```
本次实测：**33M / 20 个分支**，`The bundle records a complete history.`
