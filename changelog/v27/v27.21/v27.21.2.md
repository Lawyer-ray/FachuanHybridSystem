**两处刻意的诚实设计**（都写在模块 docstring 里）：

1. `clusters=[]` + `clusters_error=""` = 没跑；`clusters_error` 非空 = 跑了但失败。两种「没有簇」不许混成一个。
2. `Synthesis.dropped` 的三个原因（`empty` / `failed` / `too_long`）**全部可达**：超过 6 千字截断并标注（仍在 `lanes_used`），超过 2.4 万字整栏丢弃（`too_long`）。一个封闭集里存在却永不产出的取值，等于契约在说假话。

## 真机/整合阶段抓到的 7 个缺陷（全部已修 + 有回归用例）

| 缺陷 | 症状 | 根因 | 修法 |
|:--|:--|:--|:--|
| **思考过程被当正文** | 律师看到的是一段没写完的自我对话 | 推理型模型把 CoT 写进 `content`，而 `LLMResponse` 没有 `finish_reason`，代码无从判断 | `validate_reply`：`completion_tokens` 顶到上限 = **没写完**（不是干净结果）；正文里一个 `[来源：` 都没有 = 不像结论。两者都触发重试，第二次追加「第一句就是结论正文」加强语；两次不成 → `LLMError` 带明确原因（**绝不当结论展示**） |
| **2048 的预算根本不够** | 两个模型都顶格，正文零字 | 只按「正文 ≤1200 字」估 token，没给推理预算留位置 | 8192（上限是闸门不是开销，按实际 token 计费） |
| **worktree 里 `openapi.json` 会被静默刷成残废** | 重生成后少了 15 条路径 / 14 个 schema（全是被排除的插件路由） | `backend/plugins` 是私有子模块，worktree 里没 checkout；`check-openapi-fresh.sh` **按设计**在缺插件时排除那批路径，于是它照着排除规则报了「删除 0 条」 | 生成前先把插件树恢复到钉住的 `50ab357`；本次产物 diff 只剩「3 条新路径 + 6 个新 schema，删除 0 条」 |
| **共识永远判不出来（最狠的一条）** | `/review` 每轮都返回 `clusters=[]` + 「未成团：6/6 判不了」 | `make_entails` 少了「栏名 → 正文」表，而 `cluster_answers` 传的是**栏名**：送进 prompt 的只有 `pi` / `dsh` 两个词，模型老老实实回 `{"entails": null, "why": "两段仅为名称"}`。**单测也把栏名当正文用，所以缺陷在测试里同样"对"**（9 处 `make_entails([...], call_judge=judge)` 都是同一形状） | `SyncEntails` 加 `texts` 映射；栏名对不上正文时直接记 `empty`、不把空串送去问模型；测试补 `LANE_TEXTS` + 两条回归用例（断言 prompt 里出现的是正文、且 `BEGIN ANSWER 1]\npi` 不出现） |
| **判不了 vs 没按契约答，混成一个原因** | 6 条全报 `parse_failed`，看不出该改口径还是改预算 | `parse_entails` 对「JSON 里 `null`」与「整段不是 JSON」都返回 `None` | 新增 `judge_undecided` 原因（用 `_ENTAILS_KEY_RE` 判断它到底有没有按契约出现那个键） |
| **4 个并发 judge 在 HTTP 里全军覆没** | 同一请求里串行打分 21 条全好，并发的判等 6/6 `judge_error`；独立脚本同参数全绿 | 并发首调撞上 `LLMService.create()` 里的同步 ORM 读配置 → `SynchronousOnlyOperation` → fallback 吞成「后端不可用,跳过」 | 并发前 `warm_async_service()` 预热；`ENTAIL_CONCURRENCY` 4 → 2 |
| **窄 except 的注释把棘轮顶爆** | `except Exception count 1604 > 1602` | 棘轮是按**行正则**扫全仓，注释里出现那两个字面也会计数 | 把两处新注释改写成「宽 except 基类」。**没有**顺手改掉 main 上那条同类旧注释——那等于给棘轮放水（计数必须仍等于基线 1602） |

## 已知取舍与边界（每条都给「为什么不做」）

1. **`unverified` 恒为空**：接真 lookup 需要「引用库查询」注入，空实现会把**每一条**引用都打成
   「本轮无核验命中」，比空列表更误导律师。本轮只产出 `citations`（来源锚点，不是核验结果）。
2. **不做 rubric / judge 模型选择器**：前端取 `options.rubric_ids[0]`，judge 传整份清单
   （后端语义 = 第一项主用、其余作换模型重试）。契约没要求，不加半成品。
3. **`turn` 算不出时连按钮都不给**（>200 条历史未翻到顶）：POST 需要正确轮次，猜轮次会把评审
   快照写到错轮。要不要「按最新一轮跑」是产品决定，本轮不擅自放开。
4. **综合模型不可选**：`resolve_model` 取请求 → 本轮各栏第一个模型。想指定非推理模型需要 UI
   选择器，属下一步。
5. **判等的 token 成本没进 `Review.tokens`**：该字段语义是「打分阶段成本」，改它会动既有口径；
   调用仍在 LLM 账本里（`caller="agent.review.judge"`）。
6. **单轮成本实测算术**：3 栏 = 打分 21 次 + 判等 6 次 = 27 次 judge 调用（最坏 120s 阶段闸门，
   典型约 6s）；综合结论 1 次 ≈ 3.2k in / 3.7–6k out。所以**两个按钮都必须手点**。
7. **`test_agent_memory.py::test_cleans_up_dirty_schedule_from_old_bug` 单跑通过、整文件跑失败**：
   django-q `Schedule` 行在同模块用例间泄漏，与本批改动无关（本批没碰 `memory_tasks`）。
