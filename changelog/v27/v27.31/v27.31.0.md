# v27.31.0 · 律师自己的技能：`/skill:名字` 可以是他自己写的那一条

> **版本判定**：§1.1-A 换主题线。前一条 `v27.30.0` 是**列表接口性能 + 加载态视觉**
> （另一批文件、另一类用户动作、另一个验收口径）；本次是**用户可写的 Agent 技能**
> （输入框 `/skill:` 协议、物化注入、技能抽屉）→ 次版本 +1。

## 一句话

以前 `/skill:` 后面只能跟四个随代码发布的内置技能；现在律师可以在 Copilot 里新建、
编辑、启停、复制自己的技能，**存完下一轮对话就能用 `/skill:名字` 点名**——不用改代码、
不用重启、不用找开发。

## 用户拿到的四件事

| 之前 | 现在 |
|:-|:-|
| 技能 = 4 个内置（`deadline-queries` / `list-projection` / `materials-parsing` / `web-research`），改一个字都要发版 | 个人技能库：新建 / 编辑 / 删除 / 启停 / 「复制为我的」，改完**下一轮生效** |
| `/` 菜单里 4 条技能，分不清是谁写的 | 每条带 `我的` / `系统` 徽标；同名可区分 |
| 想按自己的习惯走（先结论后理由、按某格式列争点），每次都要在对话里重讲 | 写成技能后，pi 在每轮 system prompt 里看到它的名字与描述，可自主加载；也可 `/skill:名字 参数` 强制加载 |
| 内置技能只能看不能改 | 「复制为我的」→ 在自己那份上改，不动全所共享的那份 |

## 五个架构决策（为什么这么切）

1. **身份 `key` 与命令 `name` 拆开**：`key = builtin:<name>` / `skill:<uuid>`，`name` 只是 slug。
   三级作用域（个人/团队/所内）必然出现同名，用名字做身份等于给未来埋一次主键迁移。
   `AgentSkillPreference` 从 `skill_name` 迁到 `skill_key`（手写六步迁移，见下）。
2. **单一解析入口 `resolve_for_user()`**：可见集 → 按 `name` 级联（`个人 > 团队 > 所内`，内置名保留）
   → 偏好过滤。P0 只有个人级，但级联与 `shadowed` 结构先立住；以后开团队/所内**不改表**。
3. **frontmatter 白名单**：物化文件只写 `name` / `description` 两个字段，`description` 用
   `json.dumps` 序列化。用户提交的 `allowed-tools`（pi 的「实验性预授权工具列表」）**一律丢弃**——
   放行它等于让技能自己关掉高危审批。渲染函数是唯一写盘点，白名单钉在那里，并有单测钉死。
4. **DB 是权威、磁盘只是注入缓存**：写库后 `transaction.on_commit` 才物化到
   `$FACHUAN_AGENT_HOME/skills/<user_id>/<name>/SKILL.md`（目录 0700 / 文件 0600，临时文件 + `os.replace`）；
   落盘失败只告警不回滚 DB，下一轮跳过该技能，`manage.py skills_reconcile` 可重建。
5. **不改 `pi` 一个字节**：`enabled_skill_paths()` 公开签名与语义不变（内置目录 + 个人目录），
   `pi_backend.py:166-169` 的调用一行没动；注入仍走 `--no-skills` + 逐个 `--skill <dir>`。

## 表结构与迁移

`AgentSkill`（P0 只写 `scope=lawyer`）+ `AgentSkillRevision`（保存快照，留最近 20 版）。
**预留**：`scope` / `status` / `team` / `law_firm` 字段与 team、law_firm 两条唯一约束现在就建——
将来加团队/所内技能不改表、不改主键；等有重复数据再补约束就要停机清洗。

`0031_personal_skills` 是**手写迁移**（自动生成会丢数据）：`AddField skill_key` → 清旧唯一约束 →
`RunPython` 回填 `builtin:<name>` → `RemoveField skill_name` → `AlterField` → 建新唯一约束。
第 2、3 步刻意互换顺序：反向迁移按操作逆序执行，先回填再建约束会在「同一用户多条偏好」时撞唯一键。

**撞号与执行**：原编号 0030 与并行 lane 已提交的 `0030_uiaction_unsettled_unique` 撞号 → 本迁移改依赖它并排
`0031_personal_skills`（未上线、未推送，纯本地改名）。开发库上：删掉旧的 `0030_personal_skills` 记录 →
`migrate agent 0030_uiaction_unsettled_unique`（真跑，加部分唯一索引，先查过 `outcome='unknown'` 无重复）→
`migrate agent 0031_personal_skills --fake`（表已由旧编号建好，**只补记录不重复建表**）。
之后 `scan_migration_anomalies` → 无孤儿/无重复/无未应用；`make migrate-check` 3/3。
执行前 `agent_agentskillpreference` 为 **0 行**，回填为 no-op（行数 0 → 0，无数据改写）。

## 复核后的两处修复（reviewer 阻断项）

1. **迁移反向在有存量偏好行时会失败**：`RemoveField(skill_name)` 的逆向是 `AddField`，字段定义取自前一步状态；
   0014 里该字段是 `blank=False` 无默认，Django 会生成 `ADD COLUMN ... NOT NULL`（无 DEFAULT）。
   修法：在 `RemoveField` 前插一条 `AlterField(blank=True, default="")`（只改迁移状态、不改 DDL）。
   证据：`manage.py sqlmigrate agent 0031 --backwards` → `ADD COLUMN "skill_name" varchar(64) DEFAULT '' NOT NULL`；
   并补了一条结构测试钉住「RemoveField 前必须是带默认值的 AlterField」。
2. **`/管理技能` 在侧栏收起/窄屏时静默无效**：抽屉原先挂在 `SessionSidebar` 里，而侧栏是条件渲染。
   修法：抽屉改挂页面层（`CopilotPanel` / `AssistantPage`，Sheet 自带 portal），侧栏只留按钮；
   补 `CopilotPanel` 的挂载断言，`SessionSidebar` 的用例改为只测「点了有没有写开关」。

顺带修掉的：`enabled_skill_paths` 不再建目录（拆出只读 `root_path`，`mkdir` 异常不再打断整轮对话）；
配额检查移进事务并加 `pg_advisory_xact_lock`（并发创建不会破 20 上限）；落盘前拒绝 symlink 目录；
新建成功后切回「我的」tab；校验失败聚焦首个错误字段。

`migrate agent 0029` 回滚——那会删表并丢用户已写的技能。
