# v27.14.7 · 日历事项关联案件/合同三处断链 + 行为推断定时任务每日必失败

本分支（`fix/agent-memory-derive-schedule-args`）共 2 个提交，两个互不相关的缺陷：

1. **日历事项关联断链** —— 文书识别生成的期限事项在日历上永远「未关联案件」，
   且用户没有任何补绑入口（三处独立断点）；
2. **行为推断定时任务** —— django-q 每天执行一次、每次都 `TypeError`，
   且脏调度记录永久残留，改代码也不生效。

---

## 后端

### 修复

#### 日历事项关联案件/合同：三处断链

**现象**：日历上文书识别生成的期限事项显示「未关联案件」，按钮永久灰掉。
实测文书识别任务 #25 生成的三条提醒（#183/#184/#185）
`contract_id` / `case_id` / `case_log_id` **全为空**。

根因有三层，彼此独立：

**① 确认日期时关联锚点只认 `case_log_id`**

`date_candidate_service` 写提醒时只传 `case_log_id=task.case_log_id`。
实测时序：

```
11:49:11  任务 #25 创建
11:49:55  识别完成
11:50:29  ← 提醒 #183/184/185 创建，此刻 task.case_log_id 仍是 NULL
11:50:37  ← 案件日志 #427 才落库
```

这 8 秒窗口里 `task.case_log_id` 为空，提醒就建成了三字段全空的孤立提醒。
对照组任务 #22 是「先绑定后确认」，提醒就正常带上了 `case_log_id=338`。

修复：按优先级回落取关联锚点 —— `case_log_id` → `case_id` → 独立提醒。
用 `if/elif` 提前 return 保证**只选一个**锚点，从构造上不触碰 Reminder 的
「`contract_id` / `case_id` / `case_log_id` 三者最多绑一个」约束。

任务已绑定案件但日志尚未落库时，挂案件本身是完全正确的归属；
两者都无才是真正的独立提醒（快捕获场景，不强制选案，行为不变）。

`_find_existing_reminder` 的查重域**刻意不扩到 `case_id`**（属语义变更）：
该域回收的是「存量自动写入的旧提醒」（按案件日志时间比对），而 `case_id` 域里
混着任务自己确认过的及其他模块建的整案级提醒。放宽后确认日期可能复用一条同刻
但来源/语义不同的提醒，候选行 `reminder_id` 会指向**不是本功能创建的** reminder，
撤销路径按 `metadata["source"]` 判定后被 `NOT_REVOKABLE` 拦住，用户反而无从清理。
宁可多一条挂在案件上的提醒，也不改语义。

**② 日历视图 `case_id` 不回溯 `case_log.case_id`**

`calendar_view_service` 只读 `reminder.case_id`。但 Reminder 的关联是三选一，
**文书识别链路只写 `case_log_id`**，`reminder.case_id` 恒为 None——
于是所有日志绑定的提醒 `case_id` 都是空，前端「打开案件」按钮永远灰掉，
即使律师本来就能看到那条日志所属的案件。

修复：新增 `_case_id_of()`，取值链 `reminder.case_id` → `case_log.case_id` → `None`。
读 `case_log.case_id`（本地标量列）而非 `case_log.case.id`，日志未挂案时
也不触发额外查询（查询侧已有 `select_related("case_log__case")`）。
`case_log` / `case_log.case` 都可能为 None，一律 `getattr` 兜底——宁可按钮灰掉也不抛。

顺带修掉一个隐患：`merge_events` 的补全判断 `if not hit.case_id` 改为
`if hit.case_id is None`，避免把合法的 `0` 当缺失值。

> **这条是唯一对存量数据立即生效的修复** —— 它改的是读取路径而非写入路径。
> 例如任务 #22 的提醒 #177/#178（有 `case_log_id=338`）日历上「打开案件」
> 按钮会立刻变为可用，点击跳到案件 #304。

**③ 编辑表单不能改关联对象**

前端 `UpdateReminderIn` 只声明了 `reminder_type / content / due_at` 三个字段，
`EventEditForm` 注释明确写着「关联对象不在此改」。用户看到「未关联案件」
**没有任何补救入口**，只能删了重建。

而后端 `ReminderUpdate` schema 本就支持 `contract_id / case_id / case_log_id`
（走 `schema_to_update_dict` + `exclude_unset` 部分更新），只差前端没暴露。

修复：`UpdateReminderIn` 扩展出三态语义，靠两个可选字段区分：

| 传参 | 请求体 | 后端效果（`exclude_unset`） |
|---|---|---|
| 都不传 | 不含任何关联字段 | 原绑定保留 |
| `target_type` + `target_id` | 只填对应那一个 id | 换绑 |
| `clear_target: true` | 三个 wire 字段全为 `null` | 解除绑定 |

`fieldByTarget: Record<TargetType, ...>` 穷举表与 `createReminder` 同构，
三个 key 必须写全，拼错编译期就报。`target_type` / `target_id` / `clear_target`
是前端入参形状，解构后**绝不进 wire**（测试断言了这一点）。

**为什么支持解除绑定**：若只做「不传即保持」，「绑错了」仍然只能删了重建——
正是本 bug 抱怨的那类死路。后端 `_apply_update_fields` 对显式 null 走
`normalize_target_id` → None 并重算互斥校验，链路已通，无需后端改动。
`target_type=null` 不能表达解除（它同时被读成「不传」），所以必须用独立布尔标志。

`EventEditForm` 新增「关联对象」栏（位于「内容」与「日期/时刻」之间），
交互复用新增弹窗那套：关键字联想 → `GET /reminders/target-options` → 选中即绑定。
未绑定时两栏都退回「未关联」，不留空白；选/解绑后收起检索框改回展示行，
点「修改」再展开。保存成功 toast 把改过的关联对象写在后面，让用户一眼确认真的换绑了。

> 回显兼容：生成物把 `target_type` 声明为裸 `string`，后端 `_target_of` 给的是
> **中文标签**（「合同」「案件」「案件日志」）而非枚举码。两种写法都收
> （`echoTargetType`），未知值一律当未关联——回显宁可留空，也不猜错绑定。

#### 行为推断定时任务每次触发都 `TypeError`

**现象**：django-q 每天执行一次 `agent:derive_behavior_memories`，每次都失败：

```
'apps.agent.services.memory_tasks.dispatch_behavior_derivation' 失败
TypeError: dispatch_behavior_derivation() takes 0 positional arguments
           but 1 was given
```

**根因①**：`ScheduleQueryService.create_interval_schedule` 把 `args` 字符串当
**位置参数**传给了 `django_q.tasks.schedule(func, *args, **kwargs)`。该函数第二位起
是「任务函数的位置参数」，**不是** `Schedule.args` 字段，也**不会**自动序列化回该字段。
于是：

- 空参数 `args=""` 落库成 `Schedule.args="''"`
- 调度器触发时 `ast.literal_eval("''")` → `('',)` → 单值包 tuple 规则不变
- 把这个空字符串当作第一个位置参数塞进零参任务 → `TypeError`

单值 `"a"` 同样有问题：落库成裸 `args="a"`，`literal_eval` 直接抛
`ValueError: malformed node or string: <ast.Name>`。

**根因②**：`_register_schedules` 用 `schedule_exists(name)` 做守卫，
只要记录存在就永不重建。所以**脏记录会永久残留，修了代码也不生效**。

**修复**：

- `create_interval_schedule` 改为直接构造 `Schedule` 行：`args` 存调度器看得懂的
  **源码字面量**（单值 `"'a'"`、多值 `"'a', 1"`），空参数存 `None`。
  同时保留 django-q 原有的同名 schedule 冲突校验（`IntegrityError`）。
- `_register_schedules` 增加自愈：发现同名调度携带了非空 `args`（旧 bug 留下的
  脏记录）先删除再重建，其余情况保持幂等。
