# v27.14.5 · 修复 OA 立案把「案件标的合同」错当委托代理合同上传

## 问题

合同 445（张某诉某公司买卖合同纠纷）
在「立案」页点「OA系统立案」时，上传的附件是
**`01-采购框架协议（含采购供货协议+廉洁自律协议）24.11.18.pdf`** ——
这是**当事人之间买卖交易的标的合同**（本案的争议对象本身），
而不是律所与委托人签的**委托代理合同**。

正确文件是 `1-律师资料/1-合同/1-民商事合同（…买卖合同纠纷）V2_20261103.docx`。

## 根因（两个缺陷叠加）

`resolve_filing_attachments` 的二级来源会扫描合同绑定的案卷文件夹，
再用 `_is_contract_original` 判定「哪些文件算合同正本」。这个过程有两处错：

### 1. 把「客户送来的标的合同」也认作正本

旧规则：**位于「合同」开头的文件夹段内 + 文件名含「合同」/「协议」 = 正本**。

但标准案卷结构里有**两个独立的「合同」区**（`folder_template/default_templates.py`
的「合同文件夹」模板）：

```
1-律师资料/1-合同/      ← 律所与委托人签的委托代理合同（立案该传这个）
2-客户资料/…/02-合同协议/ ← 当事人之间交易的标的合同（本案证据，不该传）
```

`02-合同协议` 同样满足「合同区 + 含协议」，于是采购框架协议、保密协议、
质量保证协议全部被判成正本。445 实际命中 **9 个候选，其中 8 个是错的**。

### 2. 排序把 pdf 当第一优先级，压过「是不是委托代理合同」

```python
# 旧：pdf 优先于一切，mtime 只在同后缀间比较
key=lambda item: (item["path"].suffix.lower() == ".pdf", item["mtime"])
```

律所的委托代理合同是 `.docx`，客户送来的框架协议恰好有 `.pdf` 版。
即使前一步筛对了候选，**pdf 也会稳压 docx**。445 里委托合同 mtime 更晚
（11-03 14:27）仍败给 11-02 18:23 的 pdf，正是这个键序造成的。

这已是同类问题的第 4 次（前三次：373 执业证、342 代付款说明、案由目录名带"合同"）。
每次都是往关键词表里补一条，但都没触及「合同区不止一个」这个结构性前提。

## 修复

### `_is_contract_original`：先排除当事人材料区

```python
_CLIENT_MATERIAL_ZONE_KEYWORDS = ("客户资料",)
...
# 当事人材料区优先排除：那里的「合同」是案件标的的合同，不是委托代理合同
if any(seg in _CLIENT_MATERIAL_ZONE_KEYWORDS for seg in segments if seg):
    return False
```

必须在合同区判定**之前**拦截——否则它同样满足「合同区 + 含合同/协议」。
口径与 `folder_scan_service._GLOBAL_EXCLUDE_DIR_KEYWORDS` 既有的
`("客户资料",)` 保持一致（那里注释已写明「客户资料是当事人身份材料」），
不引入新约定。

### `_pick_latest_contract_file`：把「是不是委托代理合同」提到第一优先级

```python
key=lambda item: (_retainer_score(item), item["path"].suffix.lower() == ".pdf", item["mtime"])
```

`_retainer_score` 打分：文件名命中委托类关键词（委托代理合同 / 民商事合同 /
委托合同 / 服务合同 / 法律顾问 …）**2 分**，位于律所文书区（`律师资料`）**1 分**。

设计上刻意做成**加权而非白名单**：命不中时为 0 分，排序退回原来的
`(pdf, mtime)` 语义，所以对「文件名没有委托类关键词」的普通场景**行为不变**。

## 影响面

只改 `apps/oa_filing/services/filing_attachment_service.py` 一个文件，
仅影响 OA 立案/盖章/归档的附件来源解析，不动上传、归档、合同库任何逻辑。
