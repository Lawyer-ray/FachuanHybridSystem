# v27.14.9 · 当事人证件既存不下去也删不掉（法人主体持身份证）

后台当事人编辑页（`/admin/client/client/<id>/change/`）里，一条历史证件数据让整张
表单变成死局：**点保存没反应，勾删除也没反应**，页面重渲染回到原样，只多一行红字。

本分支（`fix/admin-client-id-doc-change`）修掉这个死局，并补上把同类脏数据自动归并的
数据迁移。

---

## 后端

### 修复

#### admin inline 勾了「删除」的行照样被 Model.clean() 拦住

**现象**：某个法人主体当事人名下有一条 `doc_type=id_card` 的证件行。
打开编辑页，勾上该行的「删除」再保存 → 页面刷新回来，什么都没变；
直接点保存 → 同样什么都没变。

**根因**：证件类型与主体类型的匹配校验写在 `ClientIdentityDoc.clean()` 里：

```python
if self.client.client_type in {LEGAL, NON_LEGAL_ORG} and self.doc_type not in self._LEGAL_DOC_TYPES:
    raise ValidationError({"doc_type": "Invalid doc type for organization"})
```

而 Django（6.1.2）对 inline formset 的**每一行**都会在 save 之前跑
`_post_clean()` → `instance.full_clean(exclude=...)`；`exclude` 只排除「不在表单上的字段」，
**从不排除勾了 DELETE 的行**。DELETE 标记要到 `save_existing_objects()` 才生效
（`if form in forms_to_delete: delete_existing(obj)`），赶不上校验。

于是那条脏行每次都抛 `ValidationError` → 整个 formset `is_valid()` 为 False →
POST 返回 200 重渲染，**主表和其它证件行的改动也一起被丢弃**。

**修复**：把校验从 Model 层下沉到表单层。

- `ClientIdentityDoc.clean()` → 改名 `validate_doc_type_for_client()`，
  Model 不再自动触发校验（符合四层架构「Model 只放字段定义与只读派生」）。
- `ClientIdentityDocInlineForm.clean()` 里调用该方法，并在 `cleaned.get("DELETE")` 为真时跳过。
- 校验本身没有放松：不勾删除的非法行仍然报错（有回归测试锁定）。

#### 数据迁移 0018：归并历史脏行，且不丢真实文件

只改代码还不够 —— 那条脏行仍然存在，而且**改类型也救不回来**：
`(client, doc_type)` 有唯一约束，法人主体只允许 `business_license` / `legal_rep_id_card`，
两个槽位都已被占。

新增 `apps/client/migrations/0018_fix_identity_doc_type_mismatch.py`，按「不丢文件」原则归并：

1. 扫描全部证件行，找出 `doc_type` 与 `client.client_type` 不匹配的行；
2. 目标类型槽位空闲 → 直接改类型；
3. 目标槽位已被占 → 比较两边文件的**磁盘存在性**：
   - 脏行有真实文件、目标行没有 → 把文件路径迁移给目标行，删掉脏行；
   - 脏行没有文件（纯占位）→ 直接删；
   - 两边都有文件或都无法判定 → **只记录告警，不擅自删除**，留给人工。

迁移的顺序是被两个唯一约束夹出来的（踩过才知道）：

- 直接改脏行的 `doc_type` → 撞 `uniq_clientidentitydoc_client_doctype`（目标槽位已占）；
- 先把路径写给目标行 → 撞 `uniq_clientidentitydoc_client_file_path`（脏行还持有它）。

唯一安全顺序：**先删脏行释放路径 → 再把路径写到目标行**。

本次实跑结果：法人身份证文件从被错标成 `id_card` 的行
归并到 `legal_rep_id_card` 槽位，脏行删除，PDF 文件保留在原路径。
全库复核：不合规行数 0，证件总数 55 → 54。

### 测试

新增 `tests/ci/unit/client/test_identity_doc_type_mismatch.py`（6 个用例），锁定：

- 校验方法本身对各种主体/证件组合的判定不变；
- **`Model.full_clean()` 不再因类型不匹配抛错**（这是死局的直接成因，重点回归点）；
- 勾了删除的非法行 formset 判定为 valid，且 save 后确实被删除；
- 不勾删除的非法行仍然报错（防止把校验整体关掉）。

`test_client_model_extended.py` 里 11 处 `doc.clean()` 调用同步改为新方法名。
