# v27.14.12 · 快递查询支持多人多账号（一人一份扫码登录态）

改造前，EMS / 顺丰的登录态全部压在**一个共享目录** `browser_profiles/express` 上。
不管谁用，都是同一份 Cookie——两个人的扫码会互相顶掉，等于事实上只能单人使用。

本分支（`feat/express-multi-account`）把「一个目录」拆成「一人一承运商一个目录」，
并顺带修掉一个更严重的问题：**未登录时任务会死等 300 秒**，8 个 worker 很快被堵死。

---

## 后端

### 新增

#### `ExpressSession`：把扫码登录态变成可管理的记录

一人一承运商最多一份会话，对应磁盘上一个独立浏览器目录：

| 律师 | 承运商 | 目录 |
|---|---|---|
| 张三（id=12） | EMS | `browser_profiles/ems_12/` |
| 张三（id=12） | 顺丰 | `browser_profiles/sf_12/` |
| 李四（id=15） | EMS | `browser_profiles/ems_15/` |

状态只有三种，流转简单：

```
empty ──扫码成功──> active ──Cookie 失效──> expired
  ^                                           │
  └────────────── 重新扫码 ──────────────────┘
```

约束 `uniq_express_session_lawyer_carrier` 在数据库层面保证「一人一承运商一份」，
不会因为并发或误操作产生重复。

#### 会话服务（`session_service.py`）

- `resolve_session(task)`：按任务创建人解析会话
- `session_lock(session)`：**同一会话串行化**——防止同一律师的两个任务同时操作
  同一浏览器导致 Cookie 互踩。拿不到锁直接报错，不无限排队
- `mark_login_success / mark_login_expired / mark_verified`：状态流转

#### Admin「快递账号会话」

新增管理页面，可直接看到每个律师在各承运商的登录状态，并提供两个动作：

- **打开浏览器扫码登录**：投递后台任务，弹出有头浏览器等扫码
- **标记为已失效**：强制下次查询要求重新扫码

状态用颜色标记（绿色已登录 / 红色失效 / 灰色未登录），一眼看清谁需要扫码。

### 修复

#### 未登录时死等 300 秒，堵死 worker

**现象**：律师没扫码时提交任务，worker 被占满 5 分钟才报超时。Q_CLUSTER 只有
8 个 worker，几个这样的任务就能把整个队列堵死。

**根因**：`ems_handle_agreement_and_wait()` 和 `_wait_for_sf_login()` 都是
**无条件等满 300 秒**，不管有没有人在扫码。

**修复**：新增「先探测，再决定」逻辑。

- `is_ems_logged_in()` / `is_sf_logged_in()`：轻量探测当前是否已登录
- `query_ems(..., allow_interactive_login=)` / `query_sf(..., allow_interactive_login=)`
- 后台任务传 `allow_interactive_login=False`：未登录时**立刻抛
  `ExpressLoginRequired`**，由上层把任务转为「等待登录」并**释放 worker**

结果：未登录的任务秒级返回，不再占用 worker 五分钟。

#### 查询中登录失效的处理

原先会话过期只会在跑完 300 秒后报超时；现在若查询途中发现未登录，
会话被标记为 `expired`，任务转为「等待登录」，律师扫码后重试即可。

### 数据迁移

`0008_migrate_legacy_express_profile`：把改造前的共享目录 `express/` **复制**给
「历史任务最多的律师」（没有则取超级管理员），登记为一个 `active` 会话。

- 每人各自保留一份，互不影响
- 旧目录**原样保留不删除**，复制失败时仍有回退余地
- 未继承到登录态的律师，扫一次码即可

### 测试

新增 `test_express_session_service.py`（11 项），覆盖：

- 会话解析幂等、`profile_key` 按人按承运商隔离
- 锁的互斥性、退出后释放、异常时也释放
- 三种状态流转
- 数据库唯一约束生效

`test_express_tasks_browser_query.py` 重写，新增登录态门禁测试：

- 无可用会话 → **不启动浏览器**，直接转「等待登录」
- 查询中抛 `ExpressLoginRequired` → 会话标记失效、任务转「等待登录」

### 已知限制

- **每个律师首次使用仍需扫码一次**（迁移已继承旧登录态的人除外）
- 扫码时需要有头浏览器，因此必须在能显示窗口的环境执行
- 一份扫码只能自己用，不支持所内共享（按当前需求设计）
