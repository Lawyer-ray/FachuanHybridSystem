# v27.14.0 — 合同修改闭环：结构化修订清单、版本链、文件夹预览与原地保存

打通「客户来件 → 预览 → AI 审查 → 律师逐条决策 → 原地改存」全链路。此前链路
在四处断开：修订清单没有后端端点、归案后无下一步、客户交代只弹了个 toast、
文件夹里的 docx 点开只能下载。

## 前端

#### 新功能

- **合同复审工作台**（`features/contract-review`）：三栏布局——左 AI 建议清单（等级 + 原文红删线 → 改法绿底 + 依据 + 定位/采纳/驳回）、中 OnlyOffice 画布、右版本链/AI 对话。采纳/驳回走乐观更新 + 失败回滚，律师点下去即时生效。
- **发起审查抽屉**：先定我方立场（决定全部建议方向）、再勾审查范围、再写客户特别交代，最后才让 AI 跑。反过来的旧形态（AI 先按某个立场算完再问「是吧？」）立场选错就整批返工。
- **版本链面板**：按序号展示「客户来稿 → AI 修订版 → 律师编辑版」，含来源色标与作者。此前这些信息只活在文件名（`[修订版]V1_日期`）里，改名就断链、排序只对同一天有效。
- **合同文件夹预览整页化**（`FilePreview`）：点文件行就地 OnlyOffice 渲染，不再是右侧窄抽屉 + 半透明黑遮罩（文档被挤在右侧、左半屏被遮罩白占，且压在列表上的黑底像报错弹层）。顶栏：返回 / 文件名 / 保存 / 另存为 / 下载 / AI 审查。
- **原地改、原地存**：`⌘S` 或「保存」覆盖原文件（带 mtime 乐观锁，两人同开时后者得 409 并提示「文件已被他人修改」）；「另存为」默认 `原名[修订版]V1_<今天>.docx`，不动原文件。
- **归案 → 发起审查**：材料预处理阅读器归案后直接打开审查抽屉（此前归案只写 `draft_state` 然后关窗，是条死路）。

#### 修复

- **预览没有真路由**：改为 URL 驱动（`?file=<subpath>&mtime=<ts>`），刷新/后退/分享均可回到同一份；关闭用 `replace`，后退不会在历史里压一条。用 query 而非路径段是因为 subpath 含 `/` 与中文，塞进路径段要处理 `%2F`。
- **`text-faint` 类不存在**：`ReviewLaunchDrawer` 与 `RevisionList` 用了未定义的 `text-faint`，渲染成意外的纯黑小字；改用 `text-muted-foreground/70`。
- **「决定全部建议方向」徽章对比度 1.9:1**：`#eab308` on `#fefce8` 远低于可读阈值；改 `#a16207`（约 5.5:1）并补竖向内边距。
- **序号码过重**：三个纯黑实心数字圆圈压过标题文字，改浅灰底（`bg-secondary`）。
- **选中态双层描边**：`border-foreground` + `inset shadow` 同时加 1px，实际渲染 2px 发脏；去掉 shadow。

#### 测试

- `FilePreview.dom.test.tsx`（11 例）：编辑模式、`⌘S`、mtime 传递、另存默认名、取消不发请求、非 docx 只读、Esc/返回。
- `VersionChainPanel.dom.test.tsx`（7 例）：空链说明、序号/来源/作者、文件被清理仍保留节点、计数按钮。
- `RevisionList`/`ReviewLaunchDrawer`/`use-revisions` 测试补齐清单与决策契约（`ResolveResult` 字段名对齐后端的 `revision_id`）。
- `FolderTree.dom.test.tsx` 补「传 `onOpenFile` 时不走 `window.open`」。

## 后端

#### 新功能

- **结构化修订清单**：`ReviewRevision` 模型（kind / severity / title / original / suggested / reason / paragraph_index + status / reject_reason / decided_at）+ 迁移 `0015`；`_persist_revisions` 把 `ReviewResult` 落成行（等级从 `【高/中/低】` 解析、标题剥标记与「依据：」后截到首个句末标点）。
- **清单端点**：`GET /{task_id}/revisions`（含 total/pending/accepted/rejected 计数）、`POST /{task_id}/revisions/{revision_id}/resolve`（accept / reject 可带理由 / reset）。越权 403，跨任务 revision 一律 404。
- **客户特别交代**：`ReviewTask` 新增 `client_note` / `client_demands` / `our_client_name` / `stance_basis`（迁移 `0016`），并拼进 `_build_revision_prompt`——此前字段没落库、也没进 prompt，律师写了等于白写。
- **人工修订回流**：`docx_revision_reader` 解析产物里的 `w:ins`/`w:del`（相邻 del+ins 配成一条、纯删除/纯插入各算一条、遍历 `body.iter(w:p)` 以覆盖表格内段落），保存回写时以 `kind=manual` 落库（迁移 `0017`）。跳过作者等于 `reviewer_name` 的痕迹，避免与 AI 条目重复。
- **版本链**：`DocumentVersion` 模型（parent 指向改自的那版、task 内单调 `version_no` + 唯一约束，迁移 `0018`）+ `GET /{task_id}/versions`。
- **文档内容版本**：`GET /{task_id}/content-version`——只看 `EditorSession.saved_version`（文档内容真的变了），不看 `acceptedCount`。
- **文件夹原地保存 / 另存为**：`folder-save`（覆盖写，原子替换 `os.replace`，带 `expect_mtime` 乐观锁 → 409）与 `folder-save-as`（同目录、同名自动加序号）。产品决定不保留备份，版本追溯走 `DocumentVersion`。
- **OnlyOffice 业务域注册表**（`services/domain_registry.py`）：把分散三处的 `"contract_review"` 硬编码收敛为 `OODomain`（路径正则 / 取文件钩子 / 保存回写钩子 / 属主判定 / 主键类型）。新增 `contract_folder` 域让 DS 能直接拉文件夹内文件；起诉状等新业务域只需 `register_domain`。

#### 修复

- **`upload_contract` 用 `thread_sensitive=False`**：数据库写入被丢到 worker 线程，看不到请求事务里未提交的用户，生产表现为外键报「用户不存在」；改 `True`（与仓库其他异步 API 一致）。
- **`download-original` 被截成 `download`**：路径正则分支 `(download|download-original)` 从左到右匹配，`download` 在前会把原稿请求当成修订版（取错文件）；调整分支顺序。
- **正则 `$` 锚定挡住真实路径**：下载路径带 `?fn=合同.docx`，锚定后整条不匹配，代理 404；改为 `(?:\?|$)`。
- **文件夹文件双层 URL 编码导致 404**：`folderFileUrl` 先 `encodeURIComponent`，`editor-config` 的 `file_url` 又包一层，DS 只解外层 → 后端拿到字面 `%E5%90%88...` 拼路径必 404（表现为「文档打开失败」）；回写路径解一次还原真实文件名。
- **保存回写跳过非 review 业务域**：`handle_save_callback` 此前直接拒绝 `task_type != "contract_review"`，改为查注册表并统一钩子签名 `(session, data, version_tag)`。

#### 测试

- 新增 78 例：`_persist_revisions` 落库与重跑语义（3）、清单/决策/撤销/权限/404（10）、客户交代进 prompt（4）、修订读取器与人工回流（9）、版本链与服务（10）、业务域注册表（10）、`contract_folder` 域与回写（7）、文件夹保存/另存为磁盘语义（13）、修订链路集成（13）。
- 回归修正：`test_contract_review_api_service` 的流水线测试补 `_persist_revisions` 打桩（该类验证的是编排，不是持久化内部）。

#### 说明

- **重跑语义**：`_persist_revisions` 只清同来源的 `pending` 行，`accepted`/`rejected` 一律保留——律师的判断不是 AI 的中间产物，重跑一次就抹掉等于逼他每次从头复核。
- **采纳不改文档**：`resolve` 只改状态；文档侧痕迹由 OnlyOffice 编辑器写入。后端不碰 docx 产物，避免与编辑器互相覆盖。
- **预览不接回写与原地保存的区别**：DS 回写统一走 `contract_folder` 域的 `adopt_edited`，从 `session.source_path` 反解 contract + subpath 覆写原文件（解析失败即报错让 DS 重试，绝不猜目标）。
- **原型冻结**：`frontend/prototype/2026.10.01-合同修改原型讨论/` 的 HTML 标注为设计稿存档，真实现全部收口到 `frontend/src/`。
