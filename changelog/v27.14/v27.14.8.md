# v27.14.8 · 日历弹窗溢出/标题错位 + 卡片看不到事项本身

本分支（`fix/dialog-width-overflow`）共 3 个提交，全部集中在前端日历这一块，
是同一类病根的三种表现：**超长的合同/案件名把「做什么」的信息挤掉了**。

1. 新建安排弹窗被长合同名撑出视口，保存按钮点不到；
2. 编辑弹窗标题变成整段合同名，看不出自己在编辑；
3. 日历卡片只显示合同名，看不到这条安排要做什么。

顺带修掉一处全项目性的配置问题：调用方写的弹窗宽度在 ≥640px 视口全部失效。

---

## 前端

### 修复

#### 新建安排弹窗被长合同名撑出视口，保存按钮点不到

**现象**：日历点空白格新建安排，关联一个名字很长的合同后，弹窗整块内容向右
溢出，右侧控件与「保存」按钮被推出视口，按钮点不到。

**根因**：`DialogContent` 是单列 `auto` grid（只有 `grid`，未声明
`grid-template-columns`），`auto` 轨道的 min 尺寸取内容的 **min-content**。
关联对象选中态那行是 `truncate`（= `white-space: nowrap`）的长合同名，不可断行，
把轨道撑到 **523px**，远超弹窗可用宽度。

内层虽然写了 `min-w-0 flex-1 truncate`，但 `min-w-0` 只作用于 flex 子项，
**管不到外层 grid 轨道** —— 轨道的 min-content 仍是那串不可断行文本。

**修复**：`DialogContent` 加 `grid-cols-[minmax(0,1fr)]` 把列 min 钳到 0，
内层 `min-w-0 + truncate` 才真正生效。同修法见 `PaymentDialog`（那里已有注释
记录了同一个坑）。

同时加 `max-h-[calc(100%-2rem)] overflow-y-auto`：内容多或视口矮时内部滚动，
避免底部按钮被纵向顶出。

**顺带**：类型下拉 / 内容 / 时刻三个控件补 `w-full`。原本只有关联对象输入框有，
导致这几项右侧留白、与相邻控件不齐。

#### 编辑弹窗标题被整段合同名占满

**现象**：点开事项 → 编辑，标题位置显示的是整段合同名，换行撑满头部成两行，
「编辑安排」这个语义完全没有传达 —— 用户看不出自己是在编辑。

**根因**：`EventDetailDialog` 的 `DialogTitle` 一直是 `{event.title}`，
而 `event.title` 的口径是「关联对象名优先」
（`calendar_view_service: title=target_name or content`），绑长合同后标题
就变成整段合同名。

**修复**：编辑态标题固定为「编辑安排」，合同名只留在「关联对象」字段里
（那里本来就有一份）。删除线样式只在详情态生效。

**顺带**：`DialogContent` 补 `grid-cols-[minmax(0,1fr)]` 与
`max-h`/`overflow-y-auto`，与上一个问题同一病根。

#### 日历卡片只显示合同名，看不到这条安排要做什么

**现象**：日历格子里只有「09:00」+ 一截合同名，看不出这条安排具体要做什么。
点开详情也一样，用户无从判断该怎么行动。

**根因**：后端 `CalendarEventItemOut.title` 的取值口径是
「关联对象名优先，取不到才退回 `content`」
（`title=target_name or content`）。

这对**庭期**是对的 —— 案名比「开庭」两个字有信息量。但对**自定义事项 / 期限**
就反了：`content` 才是「要做什么」（如「和客户碰头」「提交证据目录」），
关联对象只是它挂在哪。绑上长合同名后，行动项被彻底挤掉。

| 场景 | content（要做什么） | target_name（挂在哪） | 修复前显示 | 修复后显示 |
|---|---|---|---|---|
| 自定义事项 | 和客户碰头 | 长合同名 | 长合同名（行动项丢失） | **和客户碰头** + 副标题合同名 |
| 庭期 | 开庭 | 案名 | 案名 | 案名（不变） |
| 期限 | 补正/材料提交期限：… | — | content | content（不变） |

**修复**：`api-meta.ts` 新增两个纯函数，按 `kind` 分流：

```ts
// 庭期（court）：维持 title（案名优先），行为不变
// 其余：content 与 target_name 不同就用 content 作主标题
export function cardTitle(e: CalendarEvent): string
// 主标题让给 content 后，关联对象作为归属信息补一行；与主标题相同则不重复
export function cardTargetLine(e: CalendarEvent): string
```

**后端 `title` 语义保持不变** —— admin 日历等其它消费方仍在用「案名优先」的口径，
只在日历卡片这一展示层做分流。

改动位置（4 处展示面）：

- `DayCell.tsx` —— 桌面事件行（并补一行关联对象，原先完全没有）/ 手机圆点标题 /
  悬停摘要
- `DaySheet.tsx` —— 当日抽屉主标题 + 关联对象行
- `EventDetailDialog.tsx` —— 详情态标题，关联对象行改用 `cardTargetLine` 判定
  （原先按 `target_name !== title` 判断，标题口径变了会漏）

#### 调用方写的弹窗宽度在 ≥640px 视口全部失效（全项目性）

**问题**：`DialogContent` 基类带 `sm:max-w-lg`（512px）。`tailwind-merge`
视其与非变体的 `max-w-[380px]` 为**不同语境**而不合并（一个带 `sm:` 前缀、
一个不带），而媒体查询规则在产物 CSS 里排得更靠后 → 后出现者赢，
调用方写的宽度一律被撑成 512px。

`PaymentDialog` 的注释里已经记录过这个坑（「必须带 `sm:` 前缀才能覆盖基类的
`sm:max-w-lg`」），但仍有 7 处调用方是裸 `max-w-*`。

**修复**：7 处统一改成 `sm:max-w-[X]`（与 main 上已正确的 9 处调用方写法一致）：

| 文件 | 宽度 |
|---|---|
| `EventDetailDialog` | 440 |
| `AddReminderDialog` | 380 |
| `BindProviderDialog` | 380 |
| `NewProjectDialog` | 620 |
| `AppNavbar` | 360 |
| `MemoryPromoteDialog` | `min(720px, calc(100vw-2rem))` |
| `ReviewWorkbenchPage`（AlertDialog） | 360（另加 `max-w-none` 抵消 `data-[size=default]:sm:max-w-lg`） |

小屏（<640px）仍走基类的 `calc(100%-2rem)`，即满宽留 1rem。

> **为什么没有改基础组件**：曾考虑直接去掉基类的 `sm:max-w-lg`，但那会破坏
> main 上 9 处依赖 `sm:max-w-*` 覆盖的调用方，以及 `PhaseDesignDialog` /
> `PhaseCreateDialogs` 靠 `sm:max-w-none` 抵消基类宽度的写法（它们都靠媒体
> 查询排在 `sm:max-w-lg` 之后才能生效）。改动面远大于收益，保持基类不动、
> 统一调用方写法是风险最低的解。
