# v26.54.8

## 担保流程优化（gTwo / gThree）

### gTwo 申请人信息填写

- **手机号兜底**：当申请人/被申请人只有座机号码（非合法手机号）时，自动用本案主办律师的手机号填入，避免 gTwo "手机号码"字段校验失败无法保存
- **多律师支持**：gTwo 现在支持填写所有指派律师的代理人信息（原来只填第一个）
  - 遍历 `case.assignments` 获取所有律师
  - 每个律师各自打开一个代理人对话框填写
  - 修复了多律师场景下 `target` 名称匹配问题（`plaintiff_agent_0`/`plaintiff_agent_1`）
- **默认选中阳光财产保险**：保险公司在询价结果中存在"阳光财产保险股份有限公司"时优先选中（不再默认选中平安）
- **财产线索价值平分**：多条财产线索时，保全金额按线索数向下取整平分（如 100,000 ÷ 3 = 33,333/条），确保总和 ≤ 原始金额

### gThree 身份证明材料上传

- **精确匹配当事人材料**：新增 `_build_party_material_map` 通过 `CaseMaterial.parties` M2M 和 `ClientIdentityDoc` 构建 {当事人: {类型: [文件路径]}} 映射
- **严格区分材料类型**：
  - 法人申请人 → 法定代表人身份证明书 + 营业执照（来自 `ClientIdentityDoc`）
  - 法人被申请人 → 营业执照
  - 自然人 → 身份证
  - 律师 → 律师证（`Lawyer.license_pdf`）+ 所函 + 授权委托书
- **宁可不传不乱传**：找不到对应材料时留空，不使用其他当事人的材料
- **向后兼容**：无 `party_material_map` 时 fallback 到原有关键词匹配

### 快递查询

- **强制有头浏览器**：快递查询不再受系统配置 `PLAYWRIGHT_HEADED` 控制，始终使用有头模式（需要用户扫码登录）
- **修复 async ORM 异常**：`profiles.py` 的 `_apply_headless_override` 在 async 上下文中调用同步 ORM 会抛 `SynchronousOnlyOperation`，改为 `except Exception` 捕获
