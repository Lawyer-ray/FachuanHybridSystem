# v27.11.3 — AI 直改免重载落修订；项目页助手自动弹出并沿用最近会话

两个都来自 2026-10-26 晚用户实测反馈（某非诉专项合同详情页）：

1. 「确实改了，但是每次改完都强制刷新，体验感太差了」——AI 落盘修订后画布整页重载；
2. 「理论上所有 projects 里面的 AI 助手，都应该自动弹出最近的会话，沿用最近会话，除非用户点击新会话」——每次进项目页都是空白新对话。

## 前端

#### 新功能：AI 直改**就地落修订**（不再强制刷新画布）

- **信号带上原文/改写全文**：`rewrite_folder_file` 的 tool_result 在 SSE 里被截到 2000 字，读不回正文；调用参数（tool_call arguments）却是完整到达的。`turn-handlers` 按 `tool_call_id` 记下参数，落盘成功时并入 `file-rewritten` 事件（`domain.extractRewriteArgs` / `parseFileRewrite` 扩展）。
- **新钩子 `useLiveRewriteApply`**（FilePreviewCard 与整页 FilePreview 均接线）：向 OnlyOffice 插件桥发 `apply-revision {orig, sug}`，DS 内核开修订模式定位替换，**画布里直接长出修订痕迹**——不重载、不丢滚动位置。插件握手态与 `applied` 回执都直接听 window 消息，不依赖组件转发。
- **两级刷新策略**（`use-rewrite-refresh` 重构）：事件串行排队（插件是单槽回调，连发会互相顶掉）；优先就地落笔，插件未握手 / 原文找不到（画布展示的是「删除线+插入」带痕文本，跨修订边界的选区与接受修订视图不逐字一致）/ 内核超时，**自动降级为原来的换 key 重载**（nonce 路径原样保留）。降级与就地两条路的 toast 文案区分。
- **后端 key 轮换不动**：就地落笔只影响当前画布；之后的每次打开仍拿新 key 重拉盘上文件，两侧行为一致。

#### 新功能：项目页助手自动弹出 + 沿用最近会话

- **`store.enterContext` 自动恢复**：进业务范围（案件/合同页）先拉该范围会话列表（按 `updated_at` 降序，第一条即最近），有就切过去，没有才落空白新对话；「新对话」仍只能由律师主动点。拉取失败按无历史处理，不阻塞进页。
- **竞态防覆盖**：新增模块级 `sessionEpoch`（任何切换/新建会话 +1，覆盖 `switchSession(null→null)` 这类 sessionId 比对挡不住的隐形路径），恢复请求回来发现纪元变了就作废——拉取期间律师点的新对话/切的会话/发的消息优先。
- **进项目详情页自动弹出面板**（`useDealCopilotContext` 调 `openCopilot`）：同一委托的数据刷新不重复弹（ref 记已弹过的 id），律师手动收起后保持收起，切到别的委托再进才重新弹。
- 两类入口（诉讼 DealDetailPage / 非诉 NonLitDetailPage）共用该绑定，行为一致。

#### 测试

- `domain.test.ts`：`parseFileRewrite` 带参/缺参两条路 + `extractRewriteArgs` 各形状（对象 / JSON 字符串 / 坏形状）。
- `store.sessions.test.ts`：自动恢复最近会话、无历史落空白、拉取失败不阻塞、拉取期间点新对话不被覆盖、同范围重进幂等短路。
- Playwright E2E（/tmp 脚本，双场景）：①冷进 /projects/393 面板自动开、最近会话被选中、欢迎页不出现；②模拟落盘信号 → 插件回执 `applied.ok=true`、画布 iframe 同一元素存活（editor-config 数不变）；③缺参信号 → 正常降级换 key 重载；④真实 AI 轮（自然语言指令）→ 就地落笔成功且画布零刷新。全项通过。

无改动（就地落笔走 DS 插件桥，落盘与 key 轮换链路沿用上一版）。
