# v27.11.2 — 本地残留文件入库防护：误生成的 `~` 目录与 `mock.log` 加入忽略

不是功能变更，是**防止手误把本地垃圾提交进仓库**。两个残留都在仓库根目录躺了很久，`git status` 一直有噪音（虽然它们本来就是未跟踪状态，不影响提交），真正的风险是 `git add .` / `git add -A` 时被一起带进去。

## 仓库

#### 忽略规则

- **根 `.gitignore` 补两类本地残留规则**：
  - `**/~/` —— 误生成的 `~` 目录（当前根目录那个里装的是 `~/.claude/plugins/` 的内容，由某次 `mkdir ~` 或路径展开失误造成）。原有规则只有 `/~~/`，只拦根目录一级；工具在**各级 cwd**（如 `backend/`）下犯同样的错时拦不住。
  - `/mock.log`、`/mock_done.py` —— 一次性脚本产物。现有内容是一条 Python 报错：`can't open file '.../mock_done.py'`，说明当时调脚本时把标准错误重定向进了 `mock.log`，脚本本身并不存在。
- 两个残留从未入过库（`git log --all -- <path>` 均无记录），也没有被任何代码引用，所以本版只加忽略规则，**不删除文件、不改动任何业务逻辑**。

#### 已确认无需额外动作

- `mock.log` 本来就被通用规则 `*.log` 覆盖，本版用 `/mock.log` 把它显式点明——原规则太宽（任何人都能靠它藏一个日志文件进忽略区），显式条目让意图可读，也避免哪天 `*.log` 被收紧时回归。
- `backend/` 下的同名残留已由 `*.log` 覆盖，不需要重复声明。

#### 说明

- 不加 `!.gitignore` 之类的反向例外；本版刻意只做最小改动，规则集中在既有「误生成的产物」注释段落下，方便以后继续追加同类条目。
