### 修复

#### fix(document_recognition): 修复 managed=False 表导致的偶发 flush 错误

**问题**

`automation_documentrecognitiontask` 表由 automation 应用原始 SQL 迁移创建，数据库层实际存在指向 `cases_case` / `cases_caselog` 的真实外键约束，但 Django 侧该模型此前 `managed=False`，被排除在 `flush`/`TRUNCATE` 集合之外，导致 CI 中截断被引用表时偶发：

```
psycopg.errors.FeatureNotSupported:
cannot truncate a table referenced in a foreign key constraint
```

**修复**

1. 将 `DocumentRecognitionTask` 模型的 `Meta.managed` 改为 `True`，纳入 `flush` 截断集合。
2. 新增手写的**仅状态级**迁移 `document_recognition/0002_documentrecognitiontask_managed_and_fk.py`：用 `SeparateDatabaseAndState`（`database_operations=[]`）把从未进入迁移图谱的 `case` / `case_log` 两个 FK 字段登记进图谱，避免对已存在的真实列发出冲突的 `AddField` DDL，同时保证模型与迁移图谱一致、`makemigrations --check` 通过。

**验证**

- `manage.py check`：System check identified no issues。
- `makemigrations --check`：No changes detected。
- 步骤 16 单元覆盖率：**28,243 passed**，带真实 FK 约束的测试库上 flush 错误消失。
