## 后端

### 修复

#### fix(oafiling/jtn): 立案「添加委托方」按钮位移 + 委托方选择定位鲁棒性加固

> 来源提交：`1333ffdd9`、`c801f84ae`

**背景**

金诚同达 OA 立案页 HTML 结构更新（按钮所在 div 层级位移），导致原绝对 XPath 失效：按钮从 `div[5]` 挪到 `div[6]`；同时立案弹窗 iframe 与其内部的创建客户 iframe 均为异步插入，在 OA 响应较慢时会晚于固定等待才就绪，触发一连串偶发错误（`form1/div[3] not found`、`$ is not a function`、`js_code is not defined`、`iframe 未找到` 等）。

**修复**

1. **按钮位移**（`constants.py`）：委托方按钮 XPath 从 `div[5]` 更新为 `div[6]`。
2. **按钮定位回退**（`playwright_filing.py`）：绝对 XPath 未命中时，回退到按文案 `#wrap >> a:has-text("委托")` 定位；仍找不到才报错，避免硬性依赖 DOM 层级。
3. **弹窗点击重试**（`playwright_filing.py`）：点击「添加委托方」后若客户搜索弹窗 iframe 未出现，最多自动重击一次（覆盖点击事件偶发未生效）；多次仍未出现才抛清晰错误，不再误报「结构变更」。
4. **弹窗 iframe 轮询等待**（`playwright_helpers.py` `_find_latest_client_iframe`）：去掉原本「查不到就回退到假 ID `layui-layer-iframe100002`」的危险逻辑（正是产生误导性 `form1/div[3] not found` 的根源），改为轮询等待最新 `layui-layer-iframe` 真正出现（约 12s），等待超时返回 `None` 并打印页面真实 iframe 列表，由调用方决定是否重试。
5. **创建客户 iframe 定位与执行**（`playwright_helpers.py` `_eval_create_iframe`）：
   - 定位方式由 `iframe[src*="CreateCustomer"]` 改为 **id 最大的 `layui-layer-iframe` + 表单 `#customer_Type` 已渲染**双重判定。原方式依赖 src 里出现 `CreateCustomer`，但 OA 慢加载时该值最后才写入，导致整个等待窗口内一直匹配不到。
   - 等待 iframe 的 jQuery 就绪后再执行，修复 `$ is not a function`。
   - 修复 JS 拼接错误（原实现把 `js_code` 误作普通文本注入，触发 `ReferenceError: js_code is not defined`）。
   - 以哨兵 `__NO_IFRAME__`（iframe 未找到）/ `false`（jQuery/表单未就绪）区分「未就绪」，而 js_code 执行成功返回 `undefined` 时视为成功（不再误重试），避免误判 `None` 为「未找到」。
   - 等待窗口延长至约 24s；超时前 dump 当前 iframe 列表到日志，便于区分「加载过慢」与「结构变更」。

**验证**

- 用真实 OA 登录态实测：指定天然人委托方（natural）全流程跑通（搜索该委托方未命中 → 进入创建客户 → 填充必填字段 → 提交），无页面 JS 报错；弹窗偶发失效能被自动重击兜底，创建客户 iframe 定位不再超时。
- `ruff check` / `ruff format` 通过（`playwright_helpers.py`、`playwright_filing.py`）。

**改动文件**

| 文件 | 改动 |
|------|------|
| `backend/apps/oa_filing/services/oa_scripts/jtn/filing/constants.py` | 委托方按钮 XPath 由 `div[5]` 更新为 `div[6]` |
| `backend/apps/oa_filing/services/oa_scripts/jtn/filing/playwright_filing.py` | 按钮绝对路径未命中时回退文案定位；弹窗未出现自动重击一次 |
| `backend/apps/oa_filing/services/oa_scripts/jtn/filing/playwright_helpers.py` | 重写 `_eval_create_iframe` 定位与等待逻辑；`_find_latest_client_iframe` 改为轮询等待并返回 `None` |

#### feat(documents): 默认代理事项规则新增劳动仲裁、行政复议两条模板

> 来源提交：`f85d8941d`

**变更**

`proxy_matter_rule_init_service.py` 的 `DEFAULT_PROXY_MATTER_RULES` 新增两条默认代理事项规则，覆盖此前缺失的争议解决类型：

1. **劳动仲裁（civil / labor_arbitration / applicant）**：代为提出、撤回仲裁申请，代为承认、放弃、变更、增加仲裁请求，代为进行庭内或庭外和解，参与调解并签署调解协议/调解笔录，签收仲裁文书及办理相关程序性事务。
2. **行政复议（administrative / administrative_review / applicant）**：代为提出陈述、申辩意见，提交/补充/调取证据材料，接受行政询问、沟通、答复事宜，签收领取送达法律文书及回执。

两条优先级（`priority: 100`）与既有规则一致。

**验证**

- 规则以 seed 形式写入，首次初始化后默认代理事项内容覆盖劳动仲裁与行政复议两类场景；字段结构（`case_type`/`case_stage`/`legal_statuses`/`items_text`）与既有 `ProxyMatterRuleSeed` 对齐。
