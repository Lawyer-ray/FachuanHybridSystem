### 1. 文档解析：新增 TextinParse 后端（与 MinerU 平行）

#### 背景

原有解析后端仅支持 MinerU（云端）和本地方案（PyMuPDF/PaddleOCR）。新增 TextinParse（合合信息）作为第二套云端解析后端，与 MinerU 共用同一套 Task / Admin / API / Workbench 体系，用户可按需切换或作为备份方案。

#### 改动内容

**新增 TextinBackend**（`services/backends/textin_backend.py`，+545 行）

- 基于 `xparse-client` SDK，支持 PDF / DOC / DOCX / PPT / PPTX / XLS / XLSX / 图片 / OFD / RTF / HTML / CSV / TXT 等格式
- 自实现轮询逻辑覆盖 SDK 全部终态（completed / partial_completed / failed / stopped / deleted），避免 SDK 内置 wait_job 对部分终态导致超时死等
- 13 种异常类型映射：认证失败、余额不足、密码保护、文件损坏、不支持的格式、文件过大、限流、请求超时、API 错误、配置错误等
- 异步方法 `aparse_document` / `aextract_text` 通过 `asyncio.to_thread` 将同步 SDK 卸载到线程池
- 凭证从 `SystemConfig` 读取（`TEXTIN_APP_ID` / `TEXTIN_SECRET_CODE`），不硬编码

**全链路接入**

| 组件 | 改动 |
|------|------|
| `ParserFactory` | 新增 `"textin"` 分支，按需实例化 TextinBackend |
| `parsing_api.py` | `parse_document` / `extract_text` 全程支持 `backend="textin"`；`TaskStatusResponse` 支持 textin 任务状态查询 |
| `document_parsing_admin.py` | Admin 上传增加 `backend` 表单字段，支持选择 auto / textin / mineru |
| `workbench.html` | 后端选择改为二选一（MinerU / TextinParse），默认 MinerU |
| `schemas.py` | `backend` 字段枚举增加 `textin` |
| `exceptions` | 新增 `TextinAPIError` 异常类 |

**新增依赖**

- `xparse-client>=0.3.0`（`pyproject.toml` / `uv.lock`）

#### 兼容说明

- 默认值不变：`backend="auto"` 仍走原有逻辑
- 显式指定 `backend="textin"` 时走异步路径（含 HTTP 上传 + 轮询）

### 2. 文档解析：修复 Ninja API multipart 上传时 backend 等参数无法解析

#### 问题

通过 frontend workbench（HTML form multipart）调用 `/parse` 时，`backend`、`extract_tables` 等参数由 Ninja `File(...)` + Schema `body` 接收，但 multipart form 字段与 JSON body 混用导致参数丢失，实际始终使用默认值。

#### 修复

在 `parsing_api.py` 中新增 3 个 helper：

- `_form_str(request, key, default)` — 字符串参数
- `_form_bool(request, key, default)` — 布尔参数（支持 "true"/"1"/"yes"/"on" → True）
- `_form_int(request, key, default)` — 整数参数

**解析优先级**：multipart form 字段（`request.POST`）优先 → JSON body 其次 → 默认值兜底。

两个端点均修复：

- `POST /parse`
- `POST /extract_text`

使 workbench 的反选框和 backend 选择器实际生效，与 admin `upload_view` 的解析逻辑保持一致。

### 4. 文档解析：解析结果过滤页眉页码避免污染正文

#### 问题

实测发现两个后端的解析结果会混入页眉、页码，污染正文影响办案：

- **TextinParse**：`_extract_text_from_elements` 原用 `type=="text"` 匹配元素类型，但 SDK 实际返回 `NarrativeText` / `Title` / `Footer` / `Header` 等类型，导致正文提取失败并 fallback 混入页码（Footer）和页眉（Header）
- **TextinParse markdown**：服务端返回的 markdown 字段仍包含页眉文本和页码（HTML 注释、独立数字行）
- **MinerU**：`content_list.json` 有 `header` / `footer` / `page_number` 类型，`type=="text"` 已排除这些，但**部分页眉被误识别为 `text` 类型**（标点变体"大笨蛋，蠢猪" vs "大笨蛋、蠢猪"），导致泄漏
- **MinerU markdown**：直接读取 md 文件，包含页眉页码残留
- **TextinParse element.text**：加粗文本被转成 `**bold**` markdown 语法，污染纯文本

#### 修复

**TextinParse**（`services/backends/textin_backend.py`）

- `_extract_text_from_elements` 改为白名单匹配 `NarrativeText` / `Title`，排除 `Footer`（页脚/页码）和 `Header`（页眉）
- 新增 `_collect_header_texts` 从 elements 收集 Header 文本
- 新增 `_clean_page_artifacts` 清理 markdown：HTML 注释、独立数字行、已知页眉文本行
- 新增 `_strip_markdown_emphasis` 去除纯文本中的 `**bold**` / `*italic*` / `__bold__` / `_italic_` 标记（保留内部文字）

**MinerU**（`services/backends/mineru_backend.py`）

- `_extract_text_from_content_list` 新增归一化匹配（`_normalize_text` 去标点后比较），过滤被误识别为 `text` 类型的页眉
- 新增 `_collect_header_texts_from_content_list` 收集 header 文本
- `_clean_page_artifacts` 新增 `exclude_lines` 参数删除已知页眉文本行
- 同步路径 `_parse_result_zip` 和异步 `_parse_zip_content` 均覆盖 header 文本收集 + markdown 清理

#### 实测验证

| 文档 | 后端 | 修复前纯文本页眉 | 修复后纯文本 | 修复后 markdown |
|------|------|----------------|------------|----------------|
| 9页合同（页眉"大笨蛋，蠢猪"） | TextinParse | 0 次 | 0 次 ✓ | 0 次 ✓ |
| 9页合同（页眉"大笨蛋，蠢猪"） | MinerU | 3 次 | 0 次 ✓ | 0 次 ✓ |
| 15页判决书（无页眉） | TextinParse | - | 正文完整 ✓ | 无页码 ✓ |
| 15页判决书（无页眉） | MinerU | - | 正文完整 ✓ | 无页码 ✓ |
| 办案小结（含加粗签字） | TextinParse | `**` 4 次 | `**` 0 次 ✓ | 保留加粗 ✓ |

### 5. 文档解析后端：代码解耦、工厂注册表化、能力自描述、测试补全

#### 问题

集成 TextinParse 后，两个云端后端之间存在字节级重复代码（页眉页码清理、markdown 去标记），且 API 层与工厂层硬编码后端名称集合，新增后端需改动多处分支，违反开闭原则。

#### 改动内容

#### 优化：提取公共模块 `_page_artifacts.py`

- 新增 `services/backends/_page_artifacts.py`，统一 TextinParse 与 MinerU 的页眉页码清理逻辑
- 4 个公共函数：`clean_page_artifacts`、`collect_header_texts`、`normalize_text`、`strip_markdown_emphasis`
- 两个后端改为调用公共函数，删除各自的 `_clean_page_artifacts` / `_collect_header_texts` / `_normalize_text` 重复实现

#### 优化：Protocol 新增后端能力自描述 `requires_async_execution`

- `IDocumentParserProtocol` 新增 `requires_async_execution: bool` 属性
- 云端后端（MinerU / TextinParse）声明 `True`，本地后端（LocalBackend）声明 `False`
- `DocumentParserService` 添加属性代理，API 层通过 `get_document_parser(backend).requires_async_execution` 动态判断
- 移除 `parsing_api.py` 中硬编码的 `_ASYNC_BACKENDS = {"mineru", "textin"}`，解决 auto 模式下无法预知后端导致的同步/异步判断错误

#### 优化：ParserFactory 改为注册表模式

- 新增 `_BACKEND_REGISTRY` 注册表（backend name → 后端类路径），延迟 import 避免循环依赖
- 新增 `_load_backend_class` / `_instantiate` 方法，统一后端类加载与实例化（含 timeout 参数处理）
- 移除 if/elif 分支，新增后端只需在注册表加一行

#### 优化：删除死代码、统一类型注解、简化异常

- 删除未使用的 `base_backend.py`
- 删除两个后端的异步方法（`aparse_document` / `aextract_text` / `_aupload_file` / `_apoll_batch_result` / `_aparse_result_zip` / `_parse_zip_content`）及相关 import
- 统一类型注解为现代语法（`dict` / `list` / `str | None`），移除 `Dict` / `List` / `Optional`
- 异常类 `MineruAPIError` / `TextinAPIError` 移除未使用的 `status_code` 字段

#### 新功能：补全 TextinBackend 单元测试

- 新增 `tests/ci/unit/document_parsing/test_textin_backend.py`（59 个测试）
- 覆盖初始化、create_job、poll_job（completed/partial_completed/failed/stopped/deleted/timeout）、extract_text_from_elements（页眉页脚过滤、markdown 去标记、fallback）、parse_result（页码/HTML 注释/页眉行清理、httpx 异常、JSON 解析失败）、extract_text、parse_document 端到端、_wrap_sdk_error（10 种 SDK 异常映射）
