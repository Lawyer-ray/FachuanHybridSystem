### 后端

#### 优化：归档分类关键词规则全面补全

分析 62 份已归档合同中用户手动上传的文件名模式，补全「从合同文件夹同步」和「从案件材料同步」两个入口的分类关键词规则，使自动同步能覆盖更多真实文件名场景。

**constants.py**（`CASE_MATERIAL_KEYWORD_MAPPING` + `ARCHIVE_SUBITEM_ORDER_RULES`）

- 授权委托材料（nl_12 / lt_20 / cr_18）：补充「执业证、身份证明、法定代表人、营业执照、身份证、户口本」等关键词，与文件夹同步规则对齐
- 起诉书项（lt_7 / cr_11）：补充「执行申请书、强制执行申请书、续封申请、不起诉申请」
- 调查材料项（lt_10 / cr_8 / nl_9）：补充「证据明细、调查笔录、调查令、追加第三人、网络查控、催促执行、中止执行」
- 保全申请项（lt_11）：补充「财产保全、诉讼保全、证据保全、限制高消费、取保候审、查封清单、缴费通知、诉前调解告知、受理通知书、交费通知、告知书」
- 判决书项（lt_17 / cr_14）：补充「终本裁定、执行裁定、查封裁定、解除查封、撤诉裁定、刑事判决」
- 会见笔录项（lt_9 / cr_7）：补充「会见笔录、会见当事人、会见被告人」
- 新增 `ARCHIVE_SUBITEM_ORDER_RULES` 子项排序规则：lt_17、cr_14、lt_10、nl_9、cr_8、lt_11，控制同一归档项内多个文件的排列顺序

**archive_classifier.py**（`_FILENAME_KEYWORD_TO_ARCHIVE_CODE` + `_FOLDER_KEYWORD_TO_ARCHIVE_CODE`）

- 文件夹关键词补充「所函、律师证、执业证」匹配授权委托材料
- 文件名关键词与 `CASE_MATERIAL_KEYWORD_MAPPING` 保持一致
- **修复误分类**：lt_5/cr_5（发票）调整到 lt_4/cr_4（委托合同）之前，避免案名中含「合同」（如"购房合同案"、"合同诈骗案"）的发票文件被误匹配到委托合同项
- 委托合同关键词细化为「委托合同、委托代理合同、委托协议、合同正本」，提高匹配精度

#### 优化：归档分类单元测试覆盖真实文件名模式

新增 3 个测试类共 25 个测试用例，基于真实归档文件名验证分类准确性：

- `TestRealArchiveFilenamesLitigation`：执业证、法定代表人身份证明、营业执照、起诉状、证据清单、财产保全申请书、判决书、调解书、撤诉裁定、查封裁定、传票、开庭通知、受理通知书、发票、调查笔录
- `TestRealArchiveFilenamesCriminal`：刑事判决书、辩护意见、律师会见笔录、授权委托书、认罪认罚起诉书
- `TestRealArchiveFilenamesNonLitigation`：授权委托书、所函、执业证、法定代表人身份证明、营业执照、发票、律师函

使用 monkeypatch autouse fixture 隔离学习规则（`_LEARNED_CODE_RULES` + `_match_by_db_learned_rules`），确保测试只验证硬编码规则，不受 DB 学习规则干扰。
