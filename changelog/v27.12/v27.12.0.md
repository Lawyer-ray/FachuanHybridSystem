## 前端

### 新功能

- **合同文件夹「另存为」上线**：文档预览顶栏新增「另存为」按钮，存成 `原名[修订版]V1_YYYYMMDD.docx`（如 `顾问合同[修订版]V1_20261027.docx`），**原文件不动**；「保存」仍是原地覆盖。

  此前 `save-as-name.ts`、`api.saveFolderFileAs`、后端 `/folder-save-as` 三件套都已写好，但界面没有按钮，且两个测试专门断言「按钮不存在」——属半成品状态，长期携带约 150 行死代码。现补齐 UI 并打通整条链路（详见后端节）。

  只对**合同文件夹的 docx** 开放：案件侧没有该系列端点，非 docx 打开的是只读 `view` 模式，给按钮就是假按钮。

- **落地 `app/` 目录**（CLAUDE.md 里一直是「有需要才建」的愿景目录）：`app/paths.ts` 路径常量、`app/preload.ts` 懒加载与预载、`app/router.tsx` 路由表、`app/shell/AppShell.tsx` + `use-copilot-shell.ts` 壳层。`App.tsx` 从 363 行收敛到 16 行。

  顺带把 `Reader.tsx` 与 `ContractFileOverlays.tsx` 里**各自独立手拼**的 `/projects/{id}/review/{taskId}` 收口为 `projectReview(id, taskId)`——此前路由一旦改名就会静默断链。

### 修复

- **跨 tab 刷新 token 会二次使用已拉黑的 refresh，导致静默掉线**（`lib/api.ts`）：等待其他 tab 刷新的 3s 超时后不做校验就自行刷新。若对端刷新失败（没写入新 token），本 tab 会拿**已被对端消费并拉黑**的旧 refresh token 再刷一次，在 `BLACKLIST_AFTER_ROTATION` 语义下必然失败 → 清空令牌 → 用户被踢下线。现等待结束后先比对 refresh token 是否已轮换，未轮换则返回 `null` 走会话过期路径。
- **401 时若已在登录页，页面永久卡死**（`lib/api.ts`）：给 `window.location.href` 赋一个**相同**的相对路径不会触发导航也不会重载，而 `resetAllClientState` 是 fire-and-forget；结果是用户停在登录页、无任何提示。现登录相关路由（`/login`、`/social-callback`）改用 `location.reload()`。`/social-callback` 必须排除——那页本身就在换 token，跳进去是死循环。
- **附件上传在途未上锁，`send` 可重入**（`copilot`）：`uploadingAttachments` 在 await 结束后立刻置 `false`，而消息入列在此之前；期间发送/回形针/后台模式三个按钮同时解锁，二次提交会把同一批附件上传两次、两条消息塞进转录。现加贯穿全程的 `sending` 锁，所有 early-return 路径都清。
- **流式对话每 delta 全量重渲染整段转录**（`copilot`）：`Bubble` / `ToolRow` / `ThinkingBlock` 均未 memo，一个 800-delta 的回答 × 200 条历史 ≈ 16 万次 Markdown 树重建，主线程被吃满。三个组件加 `memo` 后未变消息自动 bail out（`message` 引用稳定）。
- **业务归属锚点被展示层截断丢掉 id**（`copilot`）：出站锚点形如 `[当前业务：本委托「X」 contract_id=393]`，展示侧 `truncate` 把尾部的 `contract_id=393` 截掉——这恰恰是唯一机器可读的归属信息。现锚点结构化为 `{kind, title, refId}`，出站构造与历史回放共用同一对互逆函数，展示为「本委托 · 名称 · #393」，id 单独且不设 `truncate`。
- **`FolderTree` 拖拽高亮每帧闪烁**（`workbench`）：`onDragLeave` 无条件清空 `dropOn`，而行内还有箭头/图标/名称/hover 按钮组等子元素，在子元素之间移动会冒泡出 dragleave，紧接着 `onDragOver` 又设回来 → 每帧两次 setState。现改为 `currentTarget.contains(relatedTarget)` 判定，`relatedTarget === null`（拖出窗口）仍按真离开处理。
- **点「新建子文件夹」反而把目录收起**（`workbench`）：`toggle` 对已展开目录是「收起」，输入框只在展开时渲染，于是挂到已收起的子树里完全不可见。现改为 `if (!open.has(subpath)) toggle(subpath)`，与同文件上传路径的既有正确写法一致。
- **自动分段连点两次会重复提交云端任务**（`material-prep`）：`cancelled` ref 只挡卸载不挡重入，两次运行交叉覆盖进度、两轮 `update` 顺序不确定地写入不同分段。现改用已有的 `usePollSession` lease 会话号机制，旧循环自动失效。
- **提醒的行内编辑被 refresh 静默回滚**（`document-recognition`）：`baseRows` 依赖候选签名但计算体读 `task`，配 `eslint-disable` 压住告警；用户改完时间/类型后 refresh 会清空 overrides 并从未编辑的 task 重建。现改为「用户编辑永远赢过服务端快照」，并去掉 disable。
- **复审工作台 4 个核心异步读绕开 react-query**（`contract-review`）：手写 `useState`+`useEffect`+`cancelled` 旗标，丢掉 `signal` 取消/`retry`/`staleTime`/缓存共享，`invalidateQueries` 无处可调，组件卸载后仍 `setState`。现全部迁到 `useQuery`/`useMutation`，并删掉 4 个只为驱动 effect 的 `useCallback`。
- **复制按钮在非 HTTPS 部署下必抛 TypeError**（`material-prep`）：`ShareLinkDialog` 直接调 `navigator.clipboard.writeText` 且**没有可选链**，内网 http 访问时 `navigator.clipboard` 是 `undefined`，点按钮直接崩而不是走到 `.catch`。现走 `lib/clipboard`（含 `execCommand` 兜底）。
- **文件大小在本站各处显示不一致**：存在 4 份互不等价的 `formatBytes` 副本，其中 2 份没有 GB 档——500MB 在 AI 助手附件芯片里显示成 `512000.0MB`。现统一到 `lib/format.ts`。
- **下载全部泄漏 ObjectURL**：5 处手写 `blob → <a download> → click` 均未见 `revokeObjectURL`。现统一到 `lib/download.ts` 的 `saveBlob`/`downloadUrl`，点击后 revoke。
- **英文技术错误直弹给律师**：15 处用 `e instanceof Error ? e.message : fallback`，会把 ky 的 `Request failed with status code 500` 当成用户文案。`lib/errors.ts` 的 `errMessage` 早已刻意不用 `HTTPError.message` 并写明了理由，这 15 处属绕开规范的第二套实现。现全部改回 `errMessage`。
- **拖拽被系统手势打断后整页无法选中文字**：copilot 两个 resize hook 只挂 `pointerup`，触摸/通知遮罩打断时浏览器只发 `pointercancel`，导致监听器与 `body.style.userSelect='none'` 双双残留。现补 `pointercancel` 并抽 `lib/drag-listeners.ts`；顺带修掉 `use-split-drag` 硬写 `''` 复位（会抹掉页面上已有的 cursor 样式）的缺陷。
- **「另存为」注释谎报安全性**：`FilePreview.tsx` 声称保存「带 mtime 乐观锁防并发覆盖」，实际走 DS forcesave 回调、`adopt_edited` 是 `expect_mtime=None`。注释已改为如实描述。
- **提醒弹窗关闭后表单不重置**、`ReviewWorkbenchPage` 用 `window.confirm`（全站唯一一处）等交互问题一并修正。

## 后端

### 新功能

- **`POST /api/v1/contracts/{contract_id}/folder-save-as-intent`**（`apps/contracts/api/contract_folder_browse_api.py` + `apps/onlyoffice/services/callback_service.py::register_save_as_intent`）：登记「下一次保存另存为新文件」的一次性意图，**只登记不写文件**。

  为什么需要这个端点，而不是像 `folder-save-as` 那样直接传字节：OnlyOffice 社区版不暴露 `downloadAs`（`Asc.editor` 上只有私有 `forceSave*`），浏览器拿不到编辑后的文档字节——字节只存在于 DS 那边，只能等 status=2/6 回调带 `url` 时由后端下载。于是「这次保存要另存」这个决定必须提前登记在编辑器会话上，让落盘那一刻（`domain_registry._adopt_edited`）才知道目标文件名。

  `name` 过与 `save_new_file` **同一串**清洗（`_clean_entry_name` → `sanitize_file_name`），不信任前端：此处虽不落盘，但名字会被落进会话、最终成为磁盘路径部件，`../`、绝对路径、控制字符必须在这一步就拒掉，而不是等到回调时才失败（那时错误对用户不可见）。

  权限口径与 `folder-save` 完全一致，走同一个 `_call_service`（`resolve_file` → `ContractAccessPolicy`），不自建第二套判断。

- **`EditorSession.pending_save_as_name`**（`apps/onlyoffice/models.py`，迁移 `0005`）：一次性意图字段。

  落盘逻辑改为：意图非空 → `save_new_file()` 写新文件、原文件不动、**成功后**清空意图；意图为空 → 保持原有 `save_file_content()` 原地覆盖。落盘失败**故意不清空**意图——否则 DS 重试时会把「另存」降级成「覆盖原稿」。

  存量行默认空串 = 老语义「原地覆盖」，无需回填（实测 9 行存量会话全部为空串，行为完全不变）。

- **`find_session_for_source()`**：按 `task_type + user + source_path 逐字相等` 查找编辑器会话。不按 `task_id` 查——派生入口有两处，口径可能不同。
