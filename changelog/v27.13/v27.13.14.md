## 需求

三条都是「演示时看着像没生效」的可用性问题，根因各不相同：

1. 合同复审里点「插入」采纳建议，后端确实改了 docx，**画布却停在改前**——律师以为按钮坏了。
2. 跨境审查的域外法查明只回最终结论，律师看到「已取到原文」**无从判断是真连了 BARLC 还是编的**。
3. 合同复审页右栏自带一个「法穿 AI 助手」，全局面板又自动弹出，**两个助手并排**，不知道该跟哪个说话。

## 后端

### 修复 · 划词直改后 `content_version` 不变导致画布不重建

`apps/contract_review/services/review/review_task_edit_service.py`

前端画布是重建还是复用，**只看 `content_version`（= `EditorSession.saved_version` + 产物名）**。而 `saved_version` 原本只在 OnlyOffice 保存回写（`status=2/6`）时才 +1。

划词直改是**后端直接改 docx**，不走编辑器保存，于是形成一条死链：

```
文件确实变了 → saved_version 没变 → content_version 没变 → 画布不重载 → 律师看到改前版本
```

落盘后补一次 `saved_version = F('saved_version') + 1`，让「后端写入」与「编辑器保存」在版本语义上等价。

**同时修掉一个静默坑**：`task.id` 是 `UUID` 对象，而 `EditorSession.task_id` 是 `CharField`。直接传 UUID 进去 `filter()` **匹配 0 行且不报错**，表现和上面的 bug 一模一样（文件改了、画布不刷新），排查时极易误判。已显式 `str(task.id)`。

编辑器还没打开过（无会话记录）时补建一条 `saved_version=1`，否则 `content_version` 恒为空，画布永远不会重建。

### 新功能 · 域外法查明返回调用轨迹

新增 `apps/legal_research/services/foreign_law_trace.py`：

| 组件 | 作用 |
| --- | --- |
| `step_trace()` | 旁路埋点上下文管理器，记录单步入参 / 返回摘要 / 耗时；异常记 `ok=False` 后**继续抛出**，不吞异常、不改变原链路语义 |
| `build_verify_trace()` | 由 `asean_law_verify` 的最终结果**反推**六步轨迹 |

六步：`接入 BARLC` → `登录域外法查明服务` → `检索法典` → `拉取正文` → `切分条款并定位` → `取回条文原文`。

反推的依据是「结果本身能说明什么」：有 `section_text` 才认为检索 / 取正文 / 定位成功，`law_title` 为空即判定未检索到。**因此不会出现「过程全绿但最终失败」的自相矛盾展示**。真实逐帧 trace 需要在 MCP 插件内埋点，属后续事项。

`POST /api/v1/legal-research/foreign-law/verify` 响应新增 `total_ms`（总耗时）与 `trace`（步骤清单）。

### 修复 · Ninja 按 schema 过滤会静默丢弃未声明字段

`apps/legal_research/schemas/foreign_law_schemas.py`

`ForeignLawVerifyOut` 必须**显式声明** `total_ms` / `trace`。Ninja 拿 response schema 过滤返回字典，未声明的键被静默丢掉——不报错、不告警，表现为「后端明明赋了值，前端拿不到」。这两条注释写进 schema 里了。

## 前端

### 修复 · 划词直改落盘后画布刷新

配合后端的 `saved_version` bump，`onApplied` 触发 `contentVersionQuery.refetch()`，DS 画布重新取文件看到修订。

### 新功能 · 建议卡一键送进右栏 AI

`features/contract-review/components/ReviewAssistant.tsx`、`ReviewWorkbenchPage.tsx`

原先左栏「定位」只弹一个 toast「可用 ⌘F 查找」，等于没做。

新增 `autoPrompt { text, instruction, seq }`：点「定位」时把**该条建议的条款原文**直接当作选区送进右栏，并自动触发一次 `suggest()`。

- 价值在于**绕开 OnlyOffice 选区桥**——真实选区只存在于编辑器内核，演示时人工框选不稳定，而建议卡本身就带着原文。
- `seq` 递增：同一条建议重复点也能再次触发。
- `pendingAutoRef` 只跑一次：不会因 `instruction` 状态后续变化反复打接口。
- 所有 `selection` 用法改为 `effectiveSelection`（外部带入优先于插件桥），UI 上标注「（来自建议卡）」。

### 新功能 · 渲染 MCP 调用过程

`deal-detail/nonlit/crossborder/ForeignLawVerifyCard.tsx`、`foreign-law-api.ts`

每条核验结果下方新增「MCP 调用过程」面板：步骤序号、成功/失败图标、步骤名、详情、结果、耗时。标题行带工具名 `asean_law_verify` 与 `total_ms`。

### 优化 · 全局 AI 助手默认收起，不再自动弹出

- `app/shell/use-copilot-shell.ts`：不再从 `localStorage` 恢复展开态，**默认收起**。要开自己按 `⌘J`——上次开着不代表这次也要开着。
- `deal-detail/use-deal-detail-page.ts`：`AUTO_OPEN_COPILOT = false`，进合同/案件详情页不再自动弹出。

原因是合同复审页右栏本身就是「法穿 AI 助手」，全局面板再展开会出现两个助手并排。`openedForRef` 的「每个委托只自动弹一次」逻辑保留，方便以后恢复。
