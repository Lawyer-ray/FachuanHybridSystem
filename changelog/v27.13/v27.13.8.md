# v27.13.8 · 客户链接：支持删除（仅创建人或管理员）

## 需求

已作废的链接会一直堆在列表里（截图里 `aaa`、`Test` 两条都成了「已作废」却删不掉）。
原来只有「作废」——它只改状态、留审计痕迹，没有真正移除记录的入口。

## 后端

### 新功能

- 新增 `DELETE /api/v1/inbox/upload-links/{link_id}`，返回 204。

  **权限：仅创建人本人或管理员**。归属校验复用既有的 `get_owned_link`
  （与作废/换发同一口径），非本人且非管理员一律返回 **404** —— 与「不存在」同形，
  不泄露 id 是否存在。

  与「作废」的分工：
  - 作废 = 客户手里的链接立即失效，但记录留着可审计；
  - 删除 = 记录从列表消失。两者都保留，因为已作废的堆多了需要能清掉。

- **已收材料包不受影响**。`InboxMessage.upload_link` 是 `on_delete=SET_NULL`，
  删链接只是把材料包的「来源链接」指针置空，材料本体、归属律师、已归案关系全部保留。

- 实现上先置 `REVOKED` 再删：万一删除失败，链接也已处于不可用状态，
  不会出现「没删掉但客户还能继续上传」的中间态。

## 前端

### 新功能

- 链接卡片新增「删除」按钮：
  - 生效中的行显示 `换发新链接 / 作废 / 删除`；
  - 已作废、已过期的行**只显示「删除」**（不必再作废一次）。

- 删除前二次确认，并说明后果：「删除后「标题」将不再出现在列表里（已收材料包会保留），确定？」

- 非本人/非管理员点删除时，后端 404 被翻译成明确文案
  「无权删除该链接（仅创建人或管理员可删）」，而不是笼统的「出错了」。

## 测试

后端 `test_client_upload_links_api.py` 新增 5 例：

- 创建人可删自己的链接，记录消失且列表不再返回；
- **非本人且非 admin → 404，且记录完好无损**（断言「别人的删除尝试必须没有副作用」）；
- 管理员可删他人创建的链接；
- **删除链接后已收材料包仍然存在**，只是 `upload_link_id` 置空；
- 删除不存在的 id → 404，且不影响任何真实记录。

验证：该文件 16 例全过；`make ci` 全绿（13 项通过 / 0 失败）。

## 说明

- 无数据库迁移（复用既有表）。
- 顺带修掉一处测试质量问题：`test_delete_missing_link_is_404` 原先只断言状态码，
  被 `test_test_quality_ratchet` 门禁拦下（纯状态码断言不计入通过）。已补上
  「库里记录数不变 + 真实链接仍在」的状态断言 —— 只验状态码发现不了
  「返回 404 但其实删错了行」这类更危险的问题。
- 代码里没有按前端角色隐藏删除按钮：权限的权威在后端（404），前端若也做角色判断
  就会出现「两处规则各自演化」的漂移。前端的责任是把 404 解释成人话。
