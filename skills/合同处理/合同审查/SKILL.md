# 合同审查 Skill (V1.0)

专业合同审查，面向中国民商事合同。最终输出带修订标记的 .docx 合同。

> ⚠️ 本工具不构成法律意见，仅供律师作为审查辅助参考。律师分析利弊，客户做决定。

## 触发条件

- 用户说"审查合同""审核合同""合同风险分析""帮我看看这个合同"
- 用户上传 .docx/.pdf 合同文件并要求审查
- 用户说 `/合同审查`
- 用户说 `review contract`

## 输入

| 格式 | 处理方式 |
|------|----------|
| .docx 文件路径 | 直接读取 |
| .doc 文件路径 | 调用 doc转docx 转换后读取 |
| .pdf 文件路径 | 转换为 .docx 后读取 |
| 粘贴的合同文本 | 直接分析 |

## 审查流程

整个流程分两个阶段：**分析阶段**（Claude 完成）→ **确认阶段**（用户交互）→ **输出阶段**（生成 .docx）。

### 阶段一：分析（自动执行）

#### Step 0 — 客户识别

按优先级识别客户：
1. 用户直接告知
2. 合同当事人与已知客户匹配
3. 从文件路径提取
4. 询问用户

记录审查上下文：客户、起草方（我方/对方/第三方）、我方立场（甲方/乙方/买方/卖方等）。

#### Step 1 — 全文通读

通读合同全文，梳理 10 项要素：

| # | 要素 | 内容 |
|---|------|------|
| 1 | 合同主体 | 当事人名称、住所、法定代表人 |
| 2 | 标的 | 交易对象、数量、质量 |
| 3 | 价款 | 金额、币种、支付方式、支付时间 |
| 4 | 履行 | 交付/服务方式、地点、期限 |
| 5 | 验收 | 验收标准、程序、异议期 |
| 6 | 违约 | 违约情形、违约金、损害赔偿 |
| 7 | 终止 | 终止条件、提前终止、清算 |
| 8 | 担保 | 保证、抵押、质押 |
| 9 | 争议解决 | 管辖法院/仲裁机构、法律适用 |
| 10 | 附件 | 附件清单、效力优先级 |

#### Step 2 — 效力审查（优先）

> 核心原则：**效力问题优先于条款优化**

| 检查项 | 审查要点 |
|--------|----------|
| 名实不符 | 循环买卖、名为买卖实为借贷、让与担保 |
| 关联交易 | 不合理低价、利益输送、关联方担保 |
| 格式条款 | 排除对方主要权利、加重对方责任、未尽提示说明义务 |
| 审批登记 | 合同效力 vs 物权变动的区分 |
| 合同成立 | 当事人、标的、数量（三要素是否齐全） |

#### Step 3 — 条款审查（正反两面法）

对每项权利义务进行三层审查：

```
正面 → 正常履行时，权利义务是否清晰？
反面 → 无法履行时，救济措施是否明确？
纵深 → 救济不被执行时，还有什么保障？
```

五道门逐项审查：

**Gate 1：主体** — 名称与印章一致性、签署人授权、表见代理风险、一人公司特殊要求

**Gate 2：条款** — 价款支付、交付验收、违约责任、合同终止、担保保险、送达通知

**Gate 3：一致性** — 正文与附件一致、金额/数量/期限前后对应、定义术语一致使用

**Gate 4：立场** — 基于我方立场评估每条条款的风险方向：

| 我方立场 | 关注重点 |
|----------|----------|
| 买方/委托方 | 付款条件严苛、验收标准过高、知识产权归属 |
| 卖方/受托方 | 交付标准过高、违约责任过重、回款保障 |
| 出租方 | 租金调整、解约条件、维修责任 |
| 承租方 | 转租限制、装修补偿、提前退租 |

**Gate 5：缺失保护** — 检查缺少的关键保护条款：

| 合同类型 | 应有条款 |
|----------|----------|
| 买卖合同 | 质量异议期、风险转移、知识产权保证 |
| 服务合同 | SLA 标准、人员变更通知、知识成果归属 |
| 租赁合同 | 维修责任、优先续租、装修处理 |
| 投资协议 | 反稀释、优先清算、信息权、共同出售 |
| 保密协议 | 保密期限、除外事项、违约救济 |
| 所有合同 | 不可抗力、通知送达、争议解决、合同终止 |

#### Step 4 — 风险评估

对每个发现的问题，进行六维评价：

| 维度 | 说明 |
|------|------|
| 风险性质 | 效力/合规/交易结构/争议解决/文本 |
| 风险敞口 | 最坏情况损失（量化到金额或百分比） |
| 发生概率 | 高/中/低 |
| 可规避性 | 可完全规避/可部分缓解/不可规避 |
| 商业权衡 | 风险是否值得承担 |
| 紧迫程度 | 立即/近期/持续监控/长期 |

风险等级：

| 等级 | 标识 | 含义 |
|------|------|------|
| 严重 | 🔴 | 高敞口 + 高概率，必须修改 |
| 重要 | 🟡 | 中敞口或中概率，建议修改 |
| 一般 | 🟢 | 低敞口 + 低概率，可接受 |
| 合规 | ⚪ | 符合市场标准 |

### 阶段二：交互确认（必须等用户确认后才能输出）

**这是必经步骤，禁止跳过。**

完成阶段一的分析后，**不要直接生成文件**，而是：

1. **列出所有发现**，格式如下：

```
## 审查发现

共发现 N 个问题：🔴 严重 X 个，🟡 重要 Y 个，🟢 一般 Z 个。

### 1. 🔴 [条款位置] 问题概述
- **风险**：具体描述
- **建议修改**：修改方案 A（修订模式）/ 批注提示
- **修订方式**：修订模式 / 批注

### 2. 🟡 [条款位置] 问题概述
- **风险**：具体描述
- **建议修改**：修改方案
- **修订方式**：修订模式 / 批注

...
```

2. **询问用户**：
   - "以上是本次审查发现的 N 个问题。请确认：
     - 哪些需要修改？（输入序号，如 1,3,5 或「全部」）
     - 哪些需要跳过？（输入序号或「无」）
     - 对某个问题有不同意见？请直接说明（如「第 2 条改为：xxx」）"

3. **处理用户反馈**：
   - 用户确认的 → 标记为「待执行」
   - 用户跳过的 → 标记为「已跳过」
   - 用户有修改意见的 → 按用户意见调整方案，再次列出调整后的结果请用户确认
   - 如用户有新意见，**再次确认**，直到用户说「确认」「可以了」「就这样」
   - **禁止在用户确认前生成 .docx 文件**

### 阶段三：输出（用户确认后执行）

#### 输出文件

仅输出一个文件：

```
{原文件名}[修订版]V1_{YYYYMMDD}.docx
```

示例：`买卖合同[修订版]V1_20260801.docx`

- `V1` 是固定版本号
- `YYYYMMDD` 是审查日期
- 如用户指定版本号则使用用户指定的（如 V2、V3）

#### 修订标注规则

所有修订和批注统一使用以下身份：

| 属性 | 值 |
|------|-----|
| 修订作者（Author） | `Lawyer` |
| 批注作者（Comment Author） | `Lawyer` |

#### 修订方式决策树

对每个确认要修改的问题，按以下规则选择修订方式：

```
问题 1：能否直接替我方修改？
  → 是：问题 2
  → 否：用批注

问题 2：是否涉及商业判断？
  → 是：用批注列出选项
  → 否：问题 3

问题 3：对方是否会接受？
  → 很可能接受：修订模式（Track Changes）
  → 可能接受：修订模式 + 批注提醒客户
  → 不太可能接受：用批注
```

**修订模式（Track Changes）适用于：**
- 笔误/错别字/日期格式/过时法律名称
- 对我方有利且对方大概率接受的条款补充

**批注（Comment）适用于：**
- 涉及商业取舍的重大风险
- 条款前后矛盾
- 需要客户决策的多种方案
- 待核实的事实

## 市场基准参考

| 条款 | 标准 | 警示 | 问题 |
|------|------|------|------|
| 违约金比例 | 不超过损失 30% | 30%-50% | 超过 50% 或过高 |
| 质量异议期 | 收货后 15-30 天 | 7-15 天 | 少于 7 天或未约定 |
| 付款期限 | 验收后 30 天 | 验收后 60 天 | 预付全款 |
| 竞业限制 | 1-2 年 + 合理补偿 | 2-3 年 | 超过 3 年或无补偿 |
| 保密期限 | 2-5 年 | 5-10 年 | 永久保密 |
| 自动续期通知 | 提前 60-90 天 | 提前 30 天 | 少于 30 天 |
| 不可抗力 | 列举 + 兜底 | 仅列举 | 未约定 |
| 管辖约定 | 被告住所地/合同履行地 | 约定己方有利 | 约定对方所在地 |

## 可谈判性评级

| 等级 | 说明 | 典型条款 |
|------|------|----------|
| 🟢 高 | 通常可以谈 | 付款期限、质量异议期、保密期限、送达地址 |
| 🟡 中 | 取决于双方地位 | 违约金比例、管辖约定、知识产权归属、竞业限制 |
| 🔴 低 | 很少能改 | 法律强制性规定、行业监管要求、格式合同核心条款 |

## 风险标签体系（15 类）

### 效力与合规（5 类）

| 标签 | 覆盖范围 |
|------|----------|
| 合同效力 | 名实不符、违反强制性规定、恶意串通 |
| 格式条款 | 提示说明义务、排除主要权利 |
| 主体授权 | 印章、签字权限、表见代理 |
| 关联交易 | 利益输送、不公允定价 |
| 合规审查 | 行业准入、外资限制、反垄断 |

### 交易结构与履行（5 类）

| 标签 | 覆盖范围 |
|------|----------|
| 价款支付 | 定价、支付条件、发票 |
| 交付验收 | 交付标准、验收程序、质量保证 |
| 违约责任 | 违约金、损害赔偿、免责事由 |
| 合同终止 | 终止条件、清算、后续义务 |
| 担保增信 | 保证、抵押、质押、保证金 |

### 争议解决与文本（5 类）

| 标签 | 覆盖范围 |
|------|----------|
| 争议解决 | 管辖、仲裁、法律适用 |
| 知识产权 | 权属、许可、侵权责任 |
| 定义附件 | 术语定义、附件效力、一致性 |
| 文本一致 | 正文与附件、金额/期限前后对应 |
| 文字格式 | 错别字、日期格式、条款序号 |

## 硬约束

1. **禁止**跳过全文通读直接审查
2. **禁止**跳过效力审查
3. **禁止**先写意见再补法律依据
4. **禁止**修改原始合同文件（必须另存为新文件）
5. **禁止**在用户确认前生成最终 .docx 文件
6. **禁止**给出笼统的"高风险"评价（必须六维评价）
7. **禁止**给出"签/不签"的结论性建议（律师分析利弊，客户做决定）
8. **禁止**引用不存在的法条或案例
9. **禁止**跳过一致性审查（正文 vs 附件、金额/期限前后对应）
10. **禁止**以非 "Lawyer" 身份添加修订或批注

## 风险提示用语

| 风险等级 | 措辞风格 |
|----------|----------|
| 🔴 严重 | "本条款存在重大法律风险，建议修改为：[具体方案]。理由：[法律依据]" |
| 🟡 重要 | "本条款对我方不利，建议修改为：[具体方案]。如对方不同意，可考虑：[备选方案]" |
| 🟢 一般 | "本条款基本合理，建议关注：[注意事项]" |
| ⚪ 合规 | "本条款符合行业惯例/法律规定" |
